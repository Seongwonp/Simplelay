# 결선 발표 웹 슬라이드

PPT 대신 브라우저로 띄우는 결선 발표 슬라이드다. 본 발표 19장(목표 합계 8:46, 10분 중 남는 시간은 시연 여유) — 1막 민지 씨의 문제 · 2막 시연 장면과 실제 기록 · 기술 2장(간단한 구성, 소비전력) · 어디까지 확인했나 · 3막 제품·설계 차이·다음 단계.
그 뒤에 질의응답용 부록 9장(예상 질문 10 · 안전 계약 · 기기 안 판단 범위 · 습관 판단 규칙 · 시스템 구성 상세 · CT 측정 상세 · 누름 장치 · 자동 시험 · 한계와 다음 단계)이 붙는다.
무대 표기는 날짜 '10월 28일', 시각 '밤 12시 30분'처럼 말로, 단위는 '100 W'·'220 V'처럼 띄어 쓴다(ms·Hz·mV는 부록에만).
대본은 [script.md](script.md)(발표자 창과 같은 문장, 원본 데이터는 [slides.js](slides.js)). 본체 미연결 때 쓰는 실제 기록 스냅숏은 [records-data.js](records-data.js)(2026-11-03 조회).

## 실행

1. 환경 변수 두 개를 정한다(값은 저장소에 적지 않는다).
   - `SIMPLELAY_HUB_URL` — 본체 주소(예: `http://<본체 주소>:8000`)
   - `SIMPLELAY_API_KEY` — 본체 API 키
2. 이 폴더에서 `python serve.py` (파이썬 표준 라이브러리만 쓴다. 포트는 기본 8765, 바꾸려면 `DECK_PORT`).
3. 브라우저로 `http://localhost:8765/` 를 연다. 본체 없이 띄우면 각 장이 '미리보기' 또는 '11월 3일 기준 실제 기록'으로 보인다.
4. 무대 창에서 **P** → 발표자 창(대본·다음 장·경과 시간·본체 연결 상태·장 목록). 무대 창은 **F**로 전체 화면.

| 키 | 동작 |
|---|---|
| → · PageDown · Space · 클릭 | 다음 장 |
| ← · PageUp | 이전 장 |
| Home · End | 처음 · 마지막(부록 끝) 장 |
| F | 전체 화면 |
| P | 발표자 창 열기 |
| E | 대체 장면 켜기/끄기 — 전자레인지 장: '11월 2일 실측', 모은 기록 장: '11월 3일 스냅숏' |

두 창은 같은 브라우저의 BroadcastChannel로 맞춰진다 — 발표자 창에서 넘기거나 장 목록을 눌러도 무대가 넘어간다. 부록은 발표자 창 목록의 '부록' 아래에서 바로 고른다.
발표자 창은 무대 창과 같은 주소에서 열어야 한다(파일로 직접 열면 동기화가 안 될 수 있다).

## 본체 값(읽기 전용)

무대 페이지는 같은 출처의 `/api/*` 만 부른다. `serve.py`가 이를 본체로 전달하면서 서버 쪽에서 `X-API-Key`를 붙인다 — 키는 HTML·JS에 들어가지 않는다.

- **GET만 전달한다.** POST·PUT·DELETE 등은 405로 거절한다. 이번 판은 기기를 움직이는 요청을 보내지 않는다.
- GET이라도 슬라이드가 읽는 경로만 전달한다: `/health` · `/status` · `/presence/room` · `/learning` · `/history` · `/jobs/{id}`. 나머지는 404.

| 장 | 읽는 값 | 미연결·실패일 때 |
|---|---|---|
| 집에 왔을 때 | `/presence/room` 의 `enabled`·`camera_enabled`·`state`(present·idle·away·unknown) | '미리보기' 그림 |
| 모은 기록 | `/history?limit=200` 의 성공 기록 — `finished_at`·`execution_mode`(real만 색, mock·unknown은 회색 '모의')·`purpose`·`detail`·`appliance_name`(켜기·끄기·바람·전자레인지 분류) | 11월 3일 스냅숏(`records-data.js`) |
| 알아채는 방법 | `/learning` 의 `routines[]` 중 `established` — `when_text`·`recent_days`·`distinct_days`·`occurrences` | 11월 3일 스냅숏의 습관 3개 |
| 늘 하던 일 | `/learning` 의 `routines[]` — `recent_days`·`usual_time`·`when_text`·`established`·`state`. `captures/habit-1105.png` 가 있으면 카드 위에 그 캡처를 띄우고, 발표자 창은 캡처를 말하는 대본으로 바꾼다(없으면 무대에 아무것도 안 보이고 캡처 없는 대본) | 11월 3일 스냅숏의 '낮 12시 59분쯤 켜기' |
| '네'를 누르면 | `/status` 의 `running`·`last_route`·`last_receipt`·`last_confirmation`·`last_outcome`·`last_detail`, 실행 중이면 `/jobs/{job_id}` | 큰 '예시 화면' 띠를 붙인 그림 |
| 저녁 전자레인지 | 실시간 소비전력(W)을 주는 본체 GET 경로가 아직 없다 → 연결 여부와 관계없이 '측정값으로 다시 그린 소비전력'(표제·아래 글에 그렇게 적는다) | 같음 |
| 마음이 바뀌면 | `/presence/room` 의 `camera_enabled`(카메라 스위치만, 자동 실행 스위치는 그림) | '미리보기' 그림 |

'실제로 있었던 일'(10월 28일 밤 + 제안과 대답 숫자)과 '어디까지 확인했나'는 본체 기록에서 옮긴 고정 값이다(11월 3일 기준, 근거 [CT 반복·실제 기록 devlog](../../docs/devlog/devlog_2026-11-03-ct-repeat-deck.md)).
`/history` 는 본체가 실행한 기록(승인·자동 실행·직접 조작)이다. LG 앱에서 직접 쓴 기록만 따로 주는 GET 경로는 없어, 그 기록은 스냅숏에만 있다.

오른쪽 위 표시는 `/health` 로 4초마다 확인한다(본체 연결됨 / 본체 미연결 · 미리보기). 미리보기 값에는 늘 '미리보기'가 붙는다.
전자레인지 그래프는 여러 날의 측정값으로 다시 그린 그림이다(가열 중 센서 출력 10월 30일, 시작 순간 11월 2일, 1분 가열 네 번 11월 2~3일). E를 누르면 처음부터 다시 그리고 '지금 값이 아닙니다'를 붙인다.

`slides.js` 와 `index.html` 의 장 목록이 어긋나면 발표자 창 위쪽에 빨간 경고가 뜬다.
시연 장(사람 감지·습관 카드·'네' 단계·폰에 글로·전자레인지)에는 발표자 창 대본 아래 '안 되면' 한 줄이 따로 뜬다(`slides.js` 의 `fallback`).
