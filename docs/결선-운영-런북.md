**【미확인】** 표시는 코드는 있지만 실기기에서 아직 해 보지 않은 절차다.

## 2. 네트워크 계획

시연장 Wi-Fi는 쓰지 않는다. 전용 공유기 하나에 모든 것을 붙이고 **고정 IP**를 준다. 공유기의 DHCP 예약으로 고정한다.

| 장치 | 연결 | 주소(예시 — 실제 값은 공유기 설정과 기기 env에만) | 쓰는 포트 |
|---|---|---|---|
| 전용 공유기 | — | `<GW>` (예: 192.168.50.1) | — |
| RPi5 | LAN | `<RPi5>` (예: .10) | 8000(백엔드) |
| RPi4 | LAN | `<RPi4>` (예: .11) | 7000(LAN 시험 배선일 때만) |
| 운영 노트북 | LAN | `<OPS>` (예: .20) | — |
| 시연 폰 | Wi-Fi | `<PHONE>` (예: .30) | — |
| ESP32 콘센트 모듈 | **RPi4 USB 시리얼**(네트워크 아님) | — | RPi4 env `SIMPLELAY_OUTLET_PORT`·`_BAUD`. 【HW 대기】 |

- **주소를 바꾸면 고칠 곳이 셋이다.**
  1. RPi5 env의 `SIMPLELAY_UART_PORT=socket://<RPi4>:7000`(LAN 배선일 때만)
  2. 폰 허브 주소
  3. 여러 네트워크에 붙은 허브라면 `SIMPLELAY_PAIR_HOST=http://<RPi5>:8000`
- 집에서 쓰는 주소와 시연 주소가 다르면 리허설 한 번을 반드시 시연 주소로 한다.
- 실제 UART 선을 쓰면 RPi5↔RPi4 실행 경로는 LAN에 기대지 않는다. LAN은 폰과 노트북용으로만 남는다. 【HW 대기】 UART 선이 아직 없다.
- 공유기 SSID와 비밀번호는 시연용으로 새로 만든다. 다른 사람의 단말이 붙지 않게 한다. `SIMPLELAY_ALLOW_UNAUTHENTICATED=1`은 시연에서 **절대 쓰지 않는다**(시나리오 v3 §4-14).
- 인터넷은 날씨에만 필요하다(ThinQ는 질의응답용 모의라 인터넷이 필요 없다). 인터넷이 없으면 키오스크는 인사말만 보여 준다(설계). 인터넷 없이도 시연이 끝까지 가는지 리허설에서 한 번 확인한다.

## 3. 설치 30분 체크리스트 (순서대로)

운영 노트북에서 상태를 확인한다. 기기 셸에는 `curl`이 없을 수 있다(BusyBox). PowerShell 예시는 이렇다.

```powershell
$B = "http://<RPi5>:8000"; $H = @{ "X-API-Key" = "<키 — 기기 env에서 읽음, 문서에 적지 않음>" }
Invoke-RestMethod "$B/health" -Headers $H
```

### 3-1. 배치와 전원 (0~8분)

- [ ] 책상 두 개를 배치하고 가전·갠트리·패널을 고정한다(양면테이프).
- [ ] 멀티탭을 나눈다(가전용, 보드·패널용).
- [ ] 공유기 전원을 켜고, LAN을 RPi5·RPi4·노트북에 꽂는다.
- [ ] 패널 케이블 세 개를 꽂는다: micro-HDMI(영상), **USB-C 데이터(터치)**, PD(전원).
- [ ] RPi4 → RPi5 순서로 전원을 넣는다(§3-4 참고).

### 3-2. RPi5 백엔드 (8~12분)

RPi5는 전원만 넣으면 백엔드 컨테이너가 뜬다(`--restart unless-stopped`, 재부팅으로 확인함).

- [ ] `GET /health`에서 `ok: true`를 본다. `act_mode`는 등급별로 다르다.
  - 실물·부분 실물: `uart`
  - 전부 모의: 시뮬레이터 서버
- [ ] `GET /status`에서 `developer_mode: false`를 본다(시연 날 기본값, 실행계획 §3-8).
- [ ] 응답이 없으면 운영 노트북에서 SSH로 `docker ps`와 `docker logs --tail 50 simplelay-backend`를 본다.
  - 기동 로그의 "API 인증: …" 줄로 키가 설정됐는지 확인한다.
  - `qrcode` import 실패면 이미지가 낡은 것이다(`3528fc9` 이전). 이미지를 다시 만든다.
- [ ] **페이싱을 확인한다.** `deploy/run_backend.sh`는 이제 기기 env 파일(`/mnt/rawdata/simplelay/env`)의 `SIMPLELAY_DEMO_PACING`을 따르고, 없으면 **꺼짐**이다(2026-10-06 갭 S9). 스크립트 끝의 `== 시연 페이싱: on|off ==` 줄로 확인한다.
  - 실물·부분 실물: env 파일에 그 줄을 두지 않는다(꺼짐). 시나리오 v3 §4-4.
  - 전부 모의 리허설(보드 백엔드로 모의 실행): RPi5에서 `echo 'SIMPLELAY_DEMO_PACING=1' >> /mnt/rawdata/simplelay/env` → `sh run_backend.sh`. 끝나면 그 줄을 지우고(`sed -i '/^SIMPLELAY_DEMO_PACING=/d' /mnt/rawdata/simplelay/env`) 다시 `sh run_backend.sh`. 버튼 사이 쉼은 `SIMPLELAY_DEMO_PACING_SECONDS`(기본 1.2).
  - 노트북 시뮬레이터(`rpi.simulator_main`)는 이 스크립트와 무관하다 — 셸에서 `SIMPLELAY_DEMO_PACING=1`을 직접 준다.

### 3-3. 키오스크 앱 (12~15분)

- [ ] 부팅 뒤 15초 안팎에 키오스크가 패널에 뜨는지 본다. 감시 컨테이너(`deploy/run_kiosk_watchdog.sh`)가 플랫폼 앱 관리자에게 상태를 묻고, 꺼져 있으면 시작한다.
- [ ] 뜨지 않으면 다음 순서로 원격 시작한다.
  1. 운영 노트북에서 RPi5에 SSH로 들어간다.
  2. 감시 로그를 본다: `docker logs --tail 20 simplelay-kiosk-watchdog`.
  3. 앱 관리자 호출이 실패하면 감시 컨테이너를 다시 시작한다: `docker restart simplelay-kiosk-watchdog`.
  4. 그래도 안 되면 플랫폼 앱 관리자의 시작 명령을 직접 보낸다. 명령과 앱 ID는 **비공개 로컬 메모**에 있다. 저장소에는 없다.
- [ ] 옛 키오스크 앱(같은 이름으로 보일 수 있음)이 아니라 새 앱 ID의 최신 버전(**1.6.0**, 10/6 RPi5에 설치 — 비상정지 띠·루틴 안내 한 줄·인터폰 아이콘)인지 확인한다.
- [ ] 화면 위쪽에 실행 환경 표시가 보이는지 확인한다. 모의면 "모의 실행 · 실제 조작 아님"이 보여야 한다. 모의 표시를 가리지 않는다.
- [ ] 터치를 확인한다. 화면 가운데 버튼 하나를 누른다. 반응이 없으면 USB-C 데이터 선부터 본다.
- [ ] 연결 아이콘 세 개(와이파이, 누름 장치, 플러그)의 상태를 본다. 콘센트 모듈이 없으면 플러그는 "설치 안 됨"이 정상이다. 【HW 대기】
- [ ] 화면 위쪽에 **비상정지 띠가 없는지** 본다. 있으면 §3-7의 래치 해제부터 한다.

### 3-4. RPi4 실행기와 RPi5→RPi4 연결 (15~19분)

- [ ] **RPi4는 루트 파일시스템이 읽기 전용이다.** 그래서 도커 자동 기동을 설정할 수 없다. 부팅 뒤 SSH로 `systemctl start docker`를 먼저 하고, `docker ps`에서 `simplelay-act`가 `Up`인지 본다.
  - 없으면 `sh <데이터 경로>/run_act.sh`를 실행한다(`deploy/run_act.sh`. LAN 배선이 기본이고, UART 선이면 `LINK=uart`).
- [ ] RPi5를 RPi4보다 먼저 띄웠다면 RPi4 연결이 엇갈릴 수 있다. 이때는 `simplelay-act`가 스스로 재시작한 뒤 RPi5 쪽 `docker restart simplelay-backend`를 한 번 더 한다(LAN 배포 로그 §3).
- [ ] **연결을 확인한다.**
  1. `GET /connections`의 누름 장치 항목이 정상(회색)인지 본다.
  2. `docker logs --tail 20 simplelay-act`에 연결 로그가 있는지 본다.
- [ ] **전부 모의·LAN 모의 모션:** 안전한 시험 가전으로 `POST /execute`를 한 번 한다.
  - `/status`가 `succeeded / success / mock / physical / reported`면 통과다(9/30 실기기 확인 형태).
- [ ] **부분 실물:** 【HW 대기】 실행 전에 확인할 것이 있다.
  - RPi4 env에 `SIMPLELAY_MOTION_MODE=serial`과 `SIMPLELAY_MOTION_PORT`가 있는지 본다.
  - 기구 값 `SIMPLELAY_MOTION_*`이 있는지 본다. 없으면 누름을 거절한다(시끄러운 실패).
  - 원점 복귀를 확인한다.
  - 원시 기록기 `SIMPLELAY_RECORDER_PATH`에 파일이 생기는지 본다.
- [ ] **콘센트 모듈(실물 등급):** 【HW 대기】 RPi4 env `SIMPLELAY_L3_MODE=real`·`SIMPLELAY_OUTLET_PORT`가 있는지, `docker logs`에 콘센트 `ready`가 있는지 본다. 릴레이 부팅 기본은 꺼짐이다 — `SIMPLELAY_OUTLET_RELAY_ON_START=1`이 아니면 사람이 켜고, **전자레인지 표시창이 켜졌는지 눈으로** 본다(시나리오 v3 §4-3).
- [ ] `GET /status`의 `estop_latched`가 `false`인지 본다. `null`이면 실행기가 래치를 보고하지 않는 것이다(옛 코드 — 재배포). `true`면 §3-7.

### 3-5. 폰 (19~22분)

- [ ] 릴리스 APK인지, 폰 "데모 모드"가 꺼졌는지 확인한다(시나리오 v3 §4-20).
- [ ] 허브 연결과 API 키를 확인한다. 둘 중 한 방법을 쓴다.
  - **짝짓기:** 키오스크 설정 → 폰 연결하기. 5분짜리 6자리 코드와 QR이 뜬다. 폰 설정 → 허브 → 코드로 폰 연결하기 → 키오스크에서 승인한다. 【미확인】 QR 카메라 인식과 두 기기 LAN 연결은 실기기에서 확인하지 않았다.

### 3-6. 등록 가전과 루틴 (22~24분)

v3 장면은 **등록 가전**(`home_mw`·`washer`·`intercom`)과 **사용자 루틴 4개**로만 돈다. 내장 `microwave`와 `/demo/suggest`는 쓰지 않는다(시나리오 v3 §4-5).

- [ ] `GET /appliances`에 `home_mw`(전자레인지)·`washer`(세탁기)·`intercom`(인터폰)이 있다. RPi5 env `SIMPLELAY_LOCAL_APPLIANCES`에 세 ID가 쉼표로 들어 있다(빠지면 승인 때 412, v3 §4-6).
- [ ] RPi4 실물 결속은 `SIMPLELAY_OUTLET_CHANNELS=home_mw:0,washer:1`, `SIMPLELAY_OUTLET_PRESS_APPLIANCE=home_mw`, `SIMPLELAY_L3_NONE_TARGETS=intercom`. 인터폰 결과는 L3 판정 없음으로 남긴다. [env 예시](../deploy/act-v3.env.example)를 참고하되 실제 CT 배선·모션 보정 전 실물 모드를 켜지 않는다.
- [ ] `GET /readiness/home_mw`·`/readiness/washer`·`/readiness/intercom`이 실행 가능이다. 아니면 `reasons`를 본다.
- [ ] `GET /routines`에 '아침 데우기'·'외출 전 세탁'·'방문자 문 열기'·'세탁 끝 알림'이 **하나씩** 있고 모두 `enabled true`다. 리허설 반복으로 중복 저장됐으면 지운다(`DELETE /routines/{id}`, v3 §4-16 — 중복이면 세탁 완료 알림이 여러 번 온다).
- [ ] 시연 직전에는 루틴을 고치지 않는다(떠 있는 카드 승인이 거절된다, v3 §4-17).
- [ ] **ThinQ(질의응답용, 선택).** v3 본 장면에는 필요 없다(④는 `/demo/appliance-done` 주입). 질의응답에서 ThinQ 장애 주입을 보일 때만 `SIMPLELAY_THINQ_MODE=mock`으로 띄우고 `GET /demo/thinq/fault`가 모두 `normal`인지 본다. 실제 ThinQ 클라이언트는 없다.

### 3-7. 시연 데이터 정리, 래치 해제, 가열 안전 확인 (24~27분)

- [ ] `DELETE /demo/inject-failure` → `{"ok":true}`(남은 주입 제거, 시나리오 v3 §4-13)
- [ ] **비상정지 래치.** `GET /status`의 `estop_latched`가 `false`. `true`면 콘센트 모듈 버튼이 풀렸는지 보고 `POST /stop/ack` → `ok true, latched false`. 버튼이 눌린 채면 `ok false`가 정상이다(자동 해제 없음). 모의 리허설에서 `POST /demo/outlet-estop`을 썼다면 `DELETE /demo/outlet-estop` 뒤 ack. 키오스크 띠·폰 배너가 사라졌는지 본다.
- [ ] `GET /wellness-pause` → `paused:false`. 아니면 `DELETE`
- [ ] `GET /presence` → 부재가 남아 있지 않은지 본다. 필요하면 `POST /presence {"present":true}`
- [ ] `GET /suggestions` → 앞 리허설의 카드가 남았으면 `POST /suggestions/<id>/reject {"mute":false}`로 치운다.
  - 주의: 치우는 것도 이벤트 기록에 남는다. 기록을 비우려면 시연 전용 DB로 시작한다. 방법은 【결정 대기 §8】
- [ ] `POST /demo/alert {"kind":"danger_sound","raised":false}` → 위험 경보 해제(모의·시뮬레이터 모드 전용, uart면 404)
- [ ] **전자레인지 가열 안전 체크리스트**(10/6 결정 — 실제로 데운다). 하나라도 못 채우면 ①은 가열하지 않고 **전원을 분리한 조작부·모형에서 누름만** 보인다(전원이 들어온 전자레인지에서 '시작'을 누르면 가열이 시작된다).
  1. **빈 상태 가열 금지.** 안에 새 햇반(또는 리허설이면 물을 채운 내열 컵)이 들어 있다. 빈 전자레인지로는 시작하지 않는다.
  2. **조리 시간 상한.** 등록한 '즉석밥' 메뉴의 조리 시간이 햇반 포장 표기 시간 안이다. 실제 시간은 리허설에서 재서 여기 적는다 【리허설 때 기입】. 그보다 오래 돌면 비상 버튼을 누른다. 소프트웨어가 가열 시간을 따로 끊는 기능은 없다.
  3. **비상정지 동작 확인.** 설치 때 한 번, 전자레인지를 돌리지 않은 상태에서 비상 버튼 → 릴레이 차단(표시창 꺼짐) → 래치(`estop_latched true`) → 버튼 풀고 `POST /stop/ack` → 릴레이를 다시 켜 표시창이 돌아오는지까지 해 본다(해제 뒤 릴레이를 켜는 실제 절차는 회로 조립 뒤 확인 【미확인】). 【HW 대기】 회로 미조립 — 회로가 없으면 가열하지 않는다.
  4. 문은 닫혀 있고, 환기구 주변이 비었고, 지난 햇반은 꺼냈다. 데운 뒤에는 내열 장갑으로 꺼낸다.
- [ ] 키오스크가 평소 화면으로 돌아왔는지 본다.

## 4. 장면별 진행/중단 판정

등급 정의는 시나리오 v3 §2를 따른다. v3 본 장면은 ThinQ가 필요 없어 **실물** 등급도 원리상 고를 수 있다. 다만 지금 실물로 준비하는 것은 전자레인지 갠트리 1대뿐이고(10/6 결정), 세탁기·인터폰은 조작부 모형이며 그 누름 경로가 미정이다(§8). 그래서 현실적인 조합은 **① 실물 + ②③ 모형(누름 경로가 정해지면 실물, 아니면 모의) + ④ 주입 + ⑤ 실물 또는 화면 정지**다.

**판정 규칙.**
- 설치 끝(15:20)에 아래 "진행 조건"을 하나라도 못 채운 장면은 한 단계 아래 등급으로 내린다. 모든 등급에서 못 채우면 백업 영상으로 돌린다.
- 장면 도중에 등급을 올리지 않는다.
- 장면마다 등급이 다르면 발표자가 장면 시작 때 "이 가전은 오늘 모의로 보입니다"라고 먼저 말한다(v3 §5).

| 장면 | 실물 【HW 대기】 | 부분 실물 | 전부 모의 | 중단 신호 → 대체 |
|---|---|---|---|---|
| ① 아침 데우기(전자레인지 즉석밥 → 시작, 복약 안내) | 원점 복귀 성공, 직전 30분 리허설 3회 연속 누름 성공, `/health.act_mode=uart`, RPi4 `MOTION_MODE=serial`·`L3_MODE=real`·`OUTLET_PORT`, **가열 안전 체크리스트(§3-7) 통과**, 리허설에서 L3 `operation_confirmed`가 한 번 이상 나옴 | RPi4 모의 모션·모의 L3. `wait_until_done`은 "시연 통과". **무대 공통:** RPi5 `SIMPLELAY_ROUTINE_DONE_SENSORS`에 `home_mw`를 넣지 않는다 — 넣으면 햇반 가열이 끝날 때까지 기다려 70초 장면이 끝나지 않는다(시나리오 v3 §1 ①) | 시뮬레이터 서버 응답, 트윈 열림 | 원점 실패나 누름 실패 2회 → 전부 모의로 내리고 "오늘은 모의로 보입니다". L3 미확인이면 루틴이 멈추고 알림함에 남는다 — 그대로 보이고 말한다. 가열 이상(연기·냄새·상한 초과) → **즉시 비상 버튼**, ①을 끝낸다 |
| ② 외출 전 세탁 + 일부러 넣은 실패 → 재시도 | 세탁기 모형의 누름 경로가 정해져 있고(§8 #4) 갠트리 재누름 리허설 통과, RPi4로 주입 전달 확인 | RPi4 모의 모션에 주입 | 트윈 "재시도 1회째", `/status.last_retry_count 1` | 재시도 뒤 안전 정지가 나면 ⑤의 안전 정지 설명으로 돌린다. 시작 확인 근거는 `reported`다. 완료 판정은 별도로 ch1 CT 전력 하강 + 종료음을 교차 확인하며 ④에서는 주입한다 |
| ③ 인터폰 문 열기 | 인터폰 모형의 누름 경로가 정해져 있고 리허설 통과 | 모의 모션 | 시뮬레이터 | 확인 근거 `reported` — "문이 열렸는지는 확인하지 않는다"고 말한다. 실패하면 질의응답으로 미룬다 |
| ④ 세탁 완료 알림(CT 전력 하강 + 종료음) | **모든 등급에서 주입**(무대 세탁기를 돌리지 않음). UART 서버에서는 RPi5 `SIMPLELAY_UART_REHEARSAL=1` + RPi4 리허설 상태(모션 mock·콘센트 fake 또는 없음)일 때만 받는다(그 밖 404, 실물 RPi4면 409 — §8 #2) | 같음 | `POST /demo/appliance-done {"appliance_id":"washer","inputs":["power","beep"]}` → 알림함·키오스크 안내 한 줄 "…(시연 주입)…" | 문장의 "(시연 주입)"을 그대로 읽는다. 알림이 안 오면 `GET /routines`에 '세탁 끝 알림'이 있는지, 보드가 `35213fa` 이후 코드인지 본다. 안 되면 알림함 캡처와 말로 |
| ⑤ 콘센트 모듈 비상정지 → 래치 → 확인 후 해제 | 콘센트 모듈 회로·릴레이·버튼 조립, 설치 때 비상정지 동작 확인(§3-7) 통과, `/status.estop_latched false`로 시작 | 가짜 모듈은 버튼을 누를 수단이 없다 → 키오스크 화면 정지 → "정지됨" | `POST /demo/outlet-estop {"hold_button":true}` → 띠·배너·412 → 버튼 풀기 → `POST /stop/ack` | 래치가 안 풀리면 ⑥으로 넘어가 화면 장면만 한다. 정지 뒤 갠트리가 계속 움직이면 **갠트리 전원 멀티탭 스위치를 끈다**(§5-4). 릴레이가 끊는 것은 전자레인지 전원이지 갠트리 전원이 아니다 |
| ⑥ 사용자 통제(다음에·부재) | 운영자가 수동으로 `POST /presence` | 같음 | 같음 | `PRESENCE_GATING`이 꺼져 있으면 "다음에"만 보인다. 끝에 `present:true` |

**전환 순서.** 실물 → 부분 실물 → 전부 모의 → 백업 영상. 전부 모의로 내릴 때는 운영 노트북에서 시뮬레이터 서버를 띄운다(약 1분, §5-0). 그리고 키오스크·폰 주소를 그쪽으로 돌린다. 시뮬레이터 서버는 DB가 없어 **등록 가전 3개와 루틴 4개를 다시 넣어야 한다**(v3 §3-3, 파일 본문 curl 또는 PowerShell) — 셋업 스크립트를 미리 만들어 둔다. 【미확인】 RPi5 키오스크 앱을 노트북 서버로 돌리는 절차는 시험하지 않았다. 지금 확실한 대체는 노트북 브라우저 `/kiosk/` 웹 빌드다. 단 로컬 `kiosk-web/`이 최신 키오스크 커밋보다 오래됐으면 재빌드가 필요하다(v3 §4-23).

### 5-0. 대체 스위치

| 전체 → 시뮬레이터 | 노트북: `SIMPLELAY_PRESENCE_GATING=true SIMPLELAY_LOCAL_APPLIANCES=home_mw,washer,intercom .venv/Scripts/python.exe -m rpi.simulator_main --host 0.0.0.0 --port 8775` (+ `SIMPLELAY_API_KEY`). 질의응답에서 ThinQ를 보일 거면 `SIMPLELAY_THINQ_MODE=mock`도 | DB·센서·노드가 꺼진 독립 서버다. 트윈 `/simulator/twin`이 있다. 가전 3개·루틴 4개를 다시 넣는다(v3 §3-3) |

### 5-1. 가장자리 스와이프로 키오스크가 닫혔을 때

- **원인.** 창 관리자가 화면 가장자리에서 시작한 터치를 스와이프로 읽어 앱을 닫는다. 앱에는 48px 안전 여백을 두었다.
- **복구.**
  1. 감시 컨테이너가 확인 간격(`SIMPLELAY_KIOSK_CHECK_S`, 기본 10초) 안에 다시 시작한다. **10~15초 기다린다.** 그동안 발표자는 폰이나 트윈으로 말을 잇는다.
  2. 20초가 지나도 안 뜨면 §3-3의 원격 시작 순서를 따른다.
- **예방.** 패널 테두리를 손이 덜 닿게 두고, 발표자는 화면 가운데만 누른다.

### 5-2. 백엔드를 다시 시작할 때

1. RPi5에서 `docker restart simplelay-backend`를 하고 약 5초 기다린다.
2. 노트북에서 `/health`를 확인한다.
3. RPi4 실행기가 가상 시리얼 끊김으로 스스로 재시작한다(설계). 그 뒤 §3-4 연결 확인을 다시 한다. 엇갈리면 백엔드를 한 번 더 재시작한다.
4. **재시작하면 휘발성 상태가 사라진다.** 실패 주입, ThinQ 장애, 부재, 짝짓기 창, 노드 준비 상태가 모두 초기화된다. 비상정지 래치는 RPi4·콘센트 모듈 쪽에 남는다(재부팅에도 유지) — `/status.estop_latched`를 다시 본다. §3-6과 §3-7을 다시 한다.
5. 폰이 "허브에 닿지 않아요"면 앱을 다시 열고 연결 칩을 본다.

### 5-3. RPi4 연결이 끊겼을 때

- **증상.** 키오스크 누름 장치 아이콘에 "!"가 붙는다. 실행이 실패하거나 확인 불가로 끝난다. **결과를 잃으면 확인 불가로 두고 자동 재실행하지 않는다**(설계). 그대로 보여 주고 이유를 말한다.
- **복구.**
  1. LAN 케이블과 공유기 링크 LED를 본다.
  2. RPi4에 SSH로 들어가 `docker ps`를 본다. 도커가 없으면 `systemctl start docker`, 그다음 `run_act.sh`를 실행한다.
  3. 컨테이너가 떠 있으면 `docker restart simplelay-act`를 하고, RPi5 백엔드를 한 번 재시작한다.
  4. §3-4 연결 확인을 다시 한다.
- **2분 안에 안 되면** 전부 모의로 내린다(§4).

### 5-4. 모션 이상 (탈조·벨트 헛돎·원점 상실·이상 소음) 【HW 대기】

1. **즉시 정지.** 키오스크 정지를 누르거나 `POST /stop`을 보낸다.
2. 움직임이 멈추지 않으면 **갠트리 전원 멀티탭 스위치를 끈다.**
   - 콘센트 모듈 비상 버튼의 릴레이는 **전자레인지 전원**을 끊는다. 갠트리 전원은 끊지 않는다. 게다가 회로는 아직 조립 전이다(펌웨어 컴파일까지).
   - `/stop` 응답의 ACK는 물리 정지의 증명이 아니다(증거 대장).
3. 화면 결과는 "정지됨" 또는 "안전 정지"다. "장치를 확인해 주세요" 문구를 그대로 보여 준다.
4. 다시 하려면 갠트리 전원을 넣고, 원점 복귀를 한 뒤 시험 누름 1회를 한다. 시연 중이면 **다시 하지 않고** 전부 모의로 내린다. 하드웨어는 무대에 두고 "오늘은 모의로 보입니다"라고 먼저 말한다.
5. 벨트 헛돎은 엔코더 값과 실제 위치를 어긋나게 한다(10/5 메모). 리허설에서 누름 성공률을 실측해 진행 조건(§4)을 다시 정한다.

### 5-5. Wi-Fi가 끊겼을 때

- **폰만 끊긴 경우.** 키오스크만으로 진행하고, 루틴 '지금 실행'은 운영 노트북에서 `POST /routines/{id}/trigger`로 띄운다(시나리오 v3 §5). 정지는 키오스크나 콘센트 모듈 버튼으로 한다.
- **공유기 전체가 죽은 경우.**
  1. 공유기 전원을 다시 넣는다(약 1~2분).
  2. 그동안 RPi5 키오스크는 같은 기기 루프백이라 계속 동작한다.
  3. RPi4 LAN 배선이면 실행 경로도 끊긴다. 실제 UART 선이면 실행 경로는 유지된다. 【HW 대기】
- **인터넷만 끊긴 경우.** 날씨 안내가 인사말로 바뀐다(설계). v3 본 장면은 영향이 없다.

### 5-6. 그 밖에

| 증상 | 확인 |
|---|---|
| 카드는 보이는데 "지금 실행"이 잠김, 승인하면 412 | `GET /readiness/<id>`의 `reasons`. "아직 기기와 연결되지 않았어요"면 `SIMPLELAY_LOCAL_APPLIANCES`(§3-6) |
| 모든 실행이 412 "비상정지가 걸려 있어요" | 래치가 남음. 버튼을 풀고 `POST /stop/ack`(§3-7) |
| 루틴 '지금 실행'이 409 | "꺼져 있는 루틴" → `enabled`. "자리에 안 계셔서" → `POST /presence {"present":true}` |
| 세탁 완료 알림이 여러 번 옴 | 루틴 중복 저장. `GET /routines`로 세어 지운다 |
| `/demo/appliance-done`이 404 | UART 서버에서 `SIMPLELAY_UART_REHEARSAL=1`을 안 켰거나 보드가 옛 코드다(409면 RPi4가 실물 모드). ④는 시뮬레이터 노트북이나 말로(§4) |
| 첫 실행부터 재시도나 안전 정지 | 남은 실패 주입. `DELETE /demo/inject-failure` |
| 폰 401 | 키 불일치. §3-5 |
| 한글 본문 curl에서 422 | 파일 본문이나 PowerShell을 쓴다(시나리오 v3 §3-3) |

## 7. 철수와 종료

1. `DELETE /demo/inject-failure`, ThinQ 장애 `normal`(썼다면), `present:true`로 상태를 되돌리고, 비상정지 래치가 걸려 있으면 버튼을 풀고 `POST /stop/ack`. 다음 리허설에 남지 않게 한다.
2. 전자레인지 안의 햇반·물컵을 꺼내고(내열 장갑), 가전 멀티탭을 끈다.
3. 갠트리 전원 스위치를 끈다. Z가 올라간 상태인지 본다. 【HW 대기】
4. RPi4와 RPi5를 SSH로 `poweroff`해 정상 종료한다. SD 손상을 막으려고 **전원을 바로 뽑지 않는다.** LED가 꺼진 뒤 전원을 뺀다.
5. 패널과 공유기 전원을 끈다. 케이블은 묶어서 회수한다.
6. 가전·모형 고정 테이프를 떼고 운반한다(벨트 장력 확인).
7. 운영 노트북의 리허설 로그와 원시 기록은 로컬에만 둔다.

## 9. 시연 영상 촬영 목록 — 사용 장면 중심 (2026-10-10)

외부 조언에 따라 다시 짰다. 화면이 예쁜지보다 아래 네 가지를 먼저 보인다.
1. 장치가 가전 어디에 붙는지
2. 사람이 폰·키오스크로 어떻게 쓰는지
3. 실패했을 때 어떻게 다시 하는지
4. 비상정지

목표 길이·촬영 마감·자막 규칙·점검은 [제출 체크리스트](submission/제출-체크리스트.md) §3에 있다. 이 절은 컷 목록만 다룬다.
장면 순서는 [시나리오 v3](archive/본선-시연-시나리오-v3.md) §1을 따른다.

**찍는 원칙.**
- 한 컷에 한 가지만 설명한다. 손·화면·장치가 한 화면에 같이 보이게 찍는다(사람이 누르고 → 화면이 바뀌고 → 장치가 움직이는 순서).
- 장면마다 첫 자막으로 등급(실물/부분 실물/전부 모의)을 밝힌다. 모형이면 "모형"이라고 적는다.
- 주입한 것도 자막으로 밝힌다. 실패는 "일부러 넣은 실패", 세탁 완료는 "시연 주입"이다.
- 화면의 "모의" 표시를 가리지 않는다.
- 갠트리가 없으면 그 컷은 디지털 트윈과 "개념 모션" 자막으로 대신한다. 실물인 척하지 않는다.
- 가열은 §3-7 체크리스트를 통과했을 때만 찍는다. 회로가 없으면 전원을 분리한 조작부·모형에서 누름만 찍는다.
- 사람(가족·지인)을 찍으면 손과 화면만 찍는다. 얼굴이나 개인 물건이 나오면 그 컷은 쓰지 않는다.

## 10. 제출 초안을 로컬에서 PDF로 뽑기 (멘토 의견용)

`docs/submission/개발완료보고서-초안.md`·`작품소개서-초안.md`를 멘토에게 보낼 때 쓴다. 최종 제출 양식(한글/워드)은 따로 편집한다. 아래는 검토용 사본을 만드는 방법이다.

**PDF는 커밋하지 않는다.**
- 저장소 밖 폴더(예: 바탕화면)에 만든다.
- `rpi/tests/test_repo_guard.py`가 추적 중인 `.pdf`를 막는다.
- 보내기 전에 PDF를 열어 개인정보·내부 주소가 없는지 본다.

**방법 1 — VS Code(가장 쉬움).**
1. 초안 파일을 열고 미리보기(`Ctrl+Shift+V`)를 띄운다. 그림은 `img/` 상대 경로로 보인다.
2. 다음 중 하나로 PDF를 만든다.
   - 확장 "Markdown PDF"의 `Markdown PDF: Export (pdf)`를 실행한다. 출력 위치를 저장소 밖으로 바꾼다.
   - 미리보기를 브라우저로 열어 인쇄(`Ctrl+P`) → "PDF로 저장"을 고른다.

**방법 2 — pandoc.** pandoc과 PDF 엔진이 설치돼 있을 때 쓴다. 그림 경로 때문에 `docs/submission`에서 실행한다.

```powershell
cd docs\submission
pandoc 개발완료보고서-초안.md -o "$env:USERPROFILE\Desktop\개발완료보고서-초안.pdf" --pdf-engine=xelatex -V mainfont="Malgun Gothic" -V geometry:margin=20mm
pandoc 작품소개서-초안.md -o "$env:USERPROFILE\Desktop\작품소개서-초안.pdf" --pdf-engine=xelatex -V mainfont="Malgun Gothic" -V geometry:margin=20mm
```

- xelatex가 없으면 HTML로 뽑은 뒤 브라우저에서 PDF로 인쇄한다.
  - `pandoc 개발완료보고서-초안.md -s --resource-path=. -o "$env:USERPROFILE\Desktop\report.html"`
  - HTML을 저장소 밖에 만들면 그림 경로가 끊긴다. 그때는 `--embed-resources`(pandoc 3 이상)를 붙인다.
- SVG 그림은 PDF 엔진에 따라 빠질 수 있다. 빠졌으면 방법 1을 쓴다.
- 쪽수는 최종 양식에서 다시 확인한다. 검토용 PDF의 쪽수는 기준이 아니다.
