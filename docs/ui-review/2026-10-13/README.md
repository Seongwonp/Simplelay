# 실제 화면 캡처 — 2026-10-13 데스크톱 (UI 개편 뒤, 보드 실물)

[10/12 캡처](../2026-10-12/README.md)와 같은 에뮬레이터로 찍은 **수정 뒤** 화면이다.

- 폰: 에뮬레이터, 앱 `0a23d5e` 빌드. 앱 소스는 `af7e2df`까지 바뀌지 않았다.
- 연결: 실제 RPi5 백엔드 → RPi4(Wi-Fi) → ESP32(시험대 펌웨어). **벨트가 없어 모터 축만 돈다.**
- 데이터: 10/12와 같은 시험 가전·기록이다. 전자레인지 4개를 정리하는 데이터 정리는 **하지 않았다**(서버 데이터를 지우는 일이라 사용자 결정이 필요하다). 그래서 전후 비교는 UI 변경 효과만 보여 준다.
- 가린 곳: 설정의 외부 가전 서비스 연결 줄(회색).

## 과업 탭 수 (에뮬레이터)

| 과업 | 탭 | 막힌 곳 |
|---|---|---|
| 루틴 실행 | 홈 '실행하기' → 승인 '지금 실행' = **2** | 없음(유효한 승인 카드가 만들어지는 조건) |
| 실행 중 정지 | 실행 상태 화면 '정지' = **1** | 실행 상태 화면으로 자동 이동한다 |
| 어제 기록 보기 | 기록 탭 = **1** + 스크롤 | 없음 |
| 가전 추가 | 홈 스크롤 → 가전 추가 → 5단계 | 이번에 재지 않음 |

## 찾은 것

1. **모션 걸림 알람이 "눌림 확인 실패"로 보인다(가장 중요).** 원인은 RPi4가 모션 오류를 재시도로 처리하는 것이다. 자세한 내용은 [devlog](../../devlog/devlog_2026-10-13-desktop-board.md) 발견 4. 기록 p04의 "다시 눌러도 확인하지 못해 안전 정지"와 키오스크 k01이 그 결과다.
2. 키오스크가 이전 실행의 결과 화면에 머물러, 다음 실행과 그 정지를 보여 주지 않았다(k01).
3. **글꼴 2.0에서 승인 화면(x04)의 아래 고정 영역이 화면 절반을 차지한다.** 그래서 무엇을 승인하는지(할 일 줄)가 첫 화면에 보이지 않는다.
4. 홈 루틴 줄은 글꼴 2.0에서 "세탁기 1단 / 계"로 단어 중간에서 줄이 바뀐다(x01). 루틴 탭은 "세탁기 / 1단계"로 바르다(x02). 숫자와 '단' 사이에는 결합 문자가 있지만, '단'과 '계' 사이에서 줄이 바뀐다.
5. 가전 타일 상태 줄이 360 폭에서 "연결을 확인해 주 / 세요"로 갈린다(골든 검토).
6. **접근성 트리**(uiautomator):
   - 순서는 제목·허브 → 말로 조작하기 → 제안 카드 → 루틴 → 가전 타일 → 탭바다.
   - 설정 탭은 "설정, 읽지 않은 알림 2건"으로 읽힌다.
   - 루틴 실행 버튼에는 이름이 붙는다.
   - **루틴 세 줄의 글이 하나로 묶여** 한꺼번에 읽히고, 실행 버튼 세 개는 그 뒤에 따로 나온다.
   - 제안 카드 버튼은 이름 없이 "실행하기"다.
   - **실제 TalkBack 제스처로 따라간 낭독은 확인하지 못했다.** adb 스와이프가 다음 항목 제스처로 인식되지 않아 첫 항목에 머물렀다.
