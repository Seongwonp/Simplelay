# 폰 스타일 기반 키오스크 전면 재설계 계획

작성·자료 확인: 2026-10-23. **조사와 계획 단계, 구현·보드 배포 아님.**

## 1. 확정 요구와 목표

폰에서 승인한 민트/짙은 청록, 밝은 바탕, 둥근 카드, 알아보기 쉬운 가전 그림, ‘할 일 먼저’를 키오스크에도 적용한다. 폰을 단순 확대하지 않고 **집에서 쓰는 가전 조작 패널**로 다시 설계한다. 전체 화면의 팔레트·버튼·결과·설정까지 함께 정리한다.

가장 중요한 사용자 지적: **조작 후 처음 화면으로 튕겨 추가 작업을 다시 찾아야 하는 문제를 없앤다.** 동일 가전에서 계속 조작하고 필요할 때만 홈으로 간다. ESP32/HW 코드·통신 인증·승인 의미는 바꾸지 않는다.

## 3. 화면 구조안

- **상단:** SimpleLay, 필요한 연결 상태, 말로 하기, 알림 종+안 읽은 수, 설정. 폰과 같은 의미. 평소 정상 정보는 조용하게, 연결 이상은 명확하게.
- **넓은 화면 왼쪽 탐색:** 홈 / 가전 / 자동 실행 / 기록. 설정은 독립 화면이며 이전 메뉴를 선택 상태로 남겨 설정인 것처럼 오해시키지 않는다. 좁은 화면에서는 하단 탐색으로 재배치하는 안을 검토한다.
- **홈 중심:** ‘무엇을 할까요?’ + 실제 저장 동작 집중 카드 또는 실제 제안. 이어서 등록 가전 카드. 다른 동작 전체로 들어가는 길 유지. 사용빈도를 모르면 ‘자주 쓰는’ 순위라 부르지 않는다.
- **보조 구획:** 실측 온습도·다음 일정. 못 받음/연습/오래된 값 구분. 큰 시계·브랜드 배너가 할 일을 화면 밖으로 밀어내지 않게 한다.
- **가전 조작:** 선택 대상 그림·이름, 버튼/동작 목록, 사진 조작의 대체 목록, 한 주 행동. 가전 바꾸기/홈을 명시한다.
- **실행·결과:** 같은 대상 맥락 안에서 진행·결과를 보여준다. 실행 중 정지 위치는 고정한다. 별도 결과 전면 화면은 필요한 경고에만 사용하고 일상 조작 복귀를 단순화한다.
- **알림/기록:** 새 알림 수와 과거 실행 수는 다르다. 같은 사건을 중복 저장하지 않고 기존 읽음/확인 계약을 조사해 연결한다. 폰과 서버 확인이 공유되는지 실제 계약을 검증한다.

## 4. 연속 조작 계약 — 구현 최우선

1. 진입 시 대상 id·원래 화면·선택 동작을 UI 맥락으로 보존한다. 이전 job을 새 실행으로 재사용하지 않는다.
2. 완료 뒤 ‘같은 가전 계속 조작’을 주 행동, ‘홈으로’를 보조 행동으로 제공한다. 계속하기는 **조작 화면 복귀일 뿐 자동 재실행이 아니다.** 추가 명령은 새 사용자 선택·필요한 승인 후 보낸다.
3. 사용자 조작 중 결과 자동 복귀 타이머가 화면을 빼앗지 않는다. 홈 이동은 명시적 선택이 기본. 표시 휴면은 조작·진행 상태를 지우거나 승인하지 않는다.
4. 실패·미확인·정지 대기에는 성공처럼 ‘한 번 더’ 자동 재전송을 붙이지 않는다. 현재 확인 가능한 조작만 제공하고 정지 경로를 유지한다.
5. 대상 삭제/변경·연결 끊김·폰에서 시작한 실행·다중 가전 동작은 맥락 복원 규칙을 각각 정의한다. 복원 대상이 없으면 가전 목록과 이유를 표시하며 옛 좌표를 실행하지 않는다.
6. 다중 가전 결과는 전체 결과 요약에 남고 사용자가 다음 대상을 고른다. 마지막 가전을 임의로 다시 실행하지 않는다.

코드 조사 시작점: `rpi5-touchscreen-app/lib/screens/kiosk_screen.dart`의 `_doneReturnTimer`, `_holdReturnTimer`, `_doneReturnDuration`, 종료·정지·폴링 경로. **타이머가 있다는 것만으로 현재 모든 현상의 원인이라고 단정하지 않는다.** 먼저 ‘수동 조작→완료→추가 조작’ 재현 테스트를 작성한다.

## 5. 시각 규격 초안과 구조화

- 기준 화면: 제공된 15.8형 1920×1080. Flutter 논리 크기·브라우저 배율·실제 OS 배율을 확인한 후 수치를 정한다. 픽셀만으로 물리 접근성을 보장한다고 주장하지 않는다.
- 민트 배너/청록 주 행동/밝은 중립 카드/가전 벡터를 폰과 공유. 빨강 정지·실패와 노랑 확인 필요는 의미를 유지한다. 그림만으로 on/off를 단정하지 않는다.
- 가전 카드 3열 안부터 시안 검토, 큰 글씨에서는 2열/1열 재배치. 본문·버튼 글자 크기는 기존 [규격 계획](키오스크-디자인-규격-계획-2026-10-15.md)을 출발점으로 실제 패널에서 조정한다. 폰의 작은 본문을 확대 없이 복사하지 않는다.
- 상시 터치 목표 64–88 논리 px 이상을 **초안 목표**로 검토하고 정지는 더 크게 확보한다. 이는 표준 인증 수치가 아니다. 실제 거치 위치에서 손 닿음·오터치·1.5m 가독성을 확인한다.
- `kiosk_screen.dart`에 UI를 추가로 몰아넣지 않는다. shell/navigation, home, appliance control, result/continuation, notification, common artwork/theme를 분리한다. 기존 `widgets/kiosk/idle_view.dart`, `manual_view.dart`, `executing_view.dart`, `done_view.dart`, `hold_view.dart`, `run_frame.dart`는 재사용/대체 범위를 먼저 정한다.
- UI 분리와 상태 전이 변경을 별도 단계/커밋으로 한다. 실행 서비스·타이머·화면 상태의 소유자를 하나로 정하고 여러 위젯이 명령을 중복 보내지 않게 한다.

## 6. 다음 작업 순서와 완료 게이트

1. 폰 가전 그림 통일: [별도 실행계획](가전-그림-통일-실행계획-2026-10-23.md). 현재 지원 종류 전 화면 우선, 확장 카탈로그는 표시/제어 지원을 나눠 진행.
2. 키오스크 상태·탐색·타이머·현재 화면 목록을 작성. 기존 [전면 개편 계획](UI-전면-재설계-계획-2026-10-23.md)의 R7과 [문구 계획](키오스크-문구-개선-계획-2026-10-15.md)을 함께 읽는다.
3. 실제 제어 없는 홈·가전 조작·완료 뒤 계속하기·알림·설정 시안 제시. 기본/큰 글씨/다크 및 정상/끊김/미확인 장면을 포함해 사용자 승인.
4. 공통 색·그림·카드·shell부터 구현, 일상 조작→계속하기 상태 전이를 테스트 기반 적용. 나머지 기록·설정·연습 화면까지 같은 스타일로 전환.
5. 비골든 전체·analyze·렌더 직접 확인 후 골든 비교. 정지·비상정지·승인·연결 실패·폰과 동시 사용·중복 탭·긴 이름·다수 가전·새 종류를 회귀 시험.
6. RPi5 실기기에서 같은 가전 3회 연속 조작과 가전 변경을 검증. **HW 복귀 및 사용자 준비 후에만 실물 명령**을 보낸다. UI 검증만으로 모터 정확도 검증이라 쓰지 않는다.

완료 기준: 처음 보는 사람이 설명 없이 대상 선택→조작→결과 이해→같은 가전 추가 조작을 끝내며 강제 홈 복귀가 없다. 사용자 시험의 실제 성공/혼동을 기록하고 미실시이면 미실시라고 적는다. 운영 배포 전 이전 빌드 복구 경로를 확보한다.

## 7. 내일 시작할 일

- 이 문서와 가전 그림 계획을 먼저 읽는다. 오늘은 계획만이며 새 코드·RPi 배포는 하지 않았다.
- 우선 ‘기기 추가 종류 선택’과 ‘키오스크 조작 후 계속하기’ 두 장면을 기준으로 시안/테스트를 만든다. 새로운 무제한 설정·HW 코드 수정·홈 강제를 끼워 넣지 않는다.
- 카페 화면의 선택/확인 분리, 냉장고 허브의 기기 모음, 스마트홈 패널의 공통 언어만 취하고 정보가 많은 대시보드 자체를 목표로 삼지 않는다.
