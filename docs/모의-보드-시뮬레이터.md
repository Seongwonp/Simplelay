# 모의 보드(Touch Bridge 펌웨어 시뮬레이터)

작성 2026-10-24. **이것은 시뮬레이션이다. 하드웨어 검증이 아니다.** ESP32 없이 RPi4 실행기를 실제 시리얼 규약 모드(`touchbridge-v2`)로 끝까지 돌려 보기 위한 도구다.
모터·엔코더·PID·벨트·SwitchBot 무선은 흉내 내지 않고, HW 담당자가 준 스케치의 USB 줄 형식과 대략의 시간만 흉내 낸다. 여기서 통과한 것은 "호스트 쪽 규약 처리"까지이며, 실제 이동·누름 성공으로 기록하지 않는다.

- 코드: [`rpi/tools/touchbridge_sim.py`](../rpi/tools/touchbridge_sim.py) (표준 라이브러리만 사용), 시험: [`rpi/tests/test_touchbridge_sim.py`](../rpi/tests/test_touchbridge_sim.py).
- 실행기 어댑터(`rpi/controller/touchbridge_motion.py`)의 규약 처리는 바꾸지 않았다. 시리얼 전송이 pyserial URL(`socket://주소:포트`)도 열 수 있게만 했다.
- 펌웨어 원본은 수정·복사하지 않았다(HW 코드는 HW 담당자만 수정).

## 흉내 내는 것

- JSON v2: `home`·`move_only`·`press`·`stop`·`status` → `RECEIVED`·`MOVING`·`POSITIONED`(+1회용 `positionToken`)·`COMPLETED`·`HOMING`·`HOMED`·`PRESSING`·`STOPPED`·`ERROR_*`.
- 텍스트: `P`(상태 줄), `STOP`·`S`·`!`(정지), `G x y`, `T`, `H`, `GT x y`, `Z`, `$H`.
- 시작 때 배너 `Touch Bridge CoreXY v4 ready …`. 실제 보드처럼 **원점 없이** 시작한다(`--start-homed`로 바꿀 수 있다).
- 이동 시간: 스케치 기본 속도 50 mm/s·가속 300 mm/s²로 계산한 사다리꼴 + 정착 50 ms — **추측**(실제 PID 동작과 다르다). 원점 3 s·누름 1.5 s도 **추측**.
- 고장 주입: `--press-fail BOT_BUSY`(모든 누름이 그 결과로 실패), `--press-timeout`(Bot 응답 없음, 8 s 뒤 `ERROR_TIMEOUT`), `--stall-on-move N`(N번째 JSON 이동이 걸림 `ERROR_STALL`).
- 연결은 한 번에 하나. 새 연결이 오면 앞 연결을 닫는다(시리얼 포트를 다시 연 것처럼). `--reset-on-connect`면 연결마다 재부팅(원점 잃음·배너)한다.
- 주고받는 모든 줄을 표준 출력에 남긴다(`docker logs`로 본다).

## RPi4에서 돌리기

전제: RPi4의 `simplelay-backend` 이미지가 이 도구가 들어간 커밋으로 빌드돼 있어야 한다(실행기의 `socket://` 지원도 같은 커밋이다). RPi4 호스트에는 Python이 없으므로 같은 이미지를 컨테이너 하나 더로 띄운다.
HW 인계 동안 실행기를 멈춰 두기로 한 결정이 있으면 그 결정을 먼저 따른다. 실제 ESP32가 USB에 꽂혀 있으면 이 도구 대신 실물을 쓴다.

1. Docker를 켜고 도커 브리지 주소를 확인한다(실행기 컨테이너가 이 주소로 호스트에 닿는다). 보통 `172.17.0.1`이다.

   ```sh
   systemctl start docker
   ip -4 addr show docker0
   ```

2. 모의 보드를 띄운다. 호스트 네트워크를 쓰고, 같은 망 다른 기기에 열리지 않도록 **도커 브리지 주소에만** 묶는다(`0.0.0.0` 금지).

   ```sh
   docker rm -f simplelay-tbsim 2>/dev/null || true
   docker run -d --name simplelay-tbsim --restart unless-stopped --network host \
     simplelay-backend python -m rpi.tools.touchbridge_sim --listen <docker0 주소>:7100 --start-homed
   docker logs -f simplelay-tbsim
   ```

   고장을 넣어 보려면 끝에 `--press-fail BOT_BUSY`, `--press-timeout`, `--stall-on-move 2` 등을 붙여 다시 띄운다.

3. 실행기 env(`/mnt/rawdata/simplelay-act/env`)를 먼저 `env.bak-날짜-tbsim`으로 백업한 뒤 아래 줄로 바꾼다. `SIMPLELAY_MOTION_BAUD`는 실행기가 요구하므로 없으면 함께 넣는다(소켓에서는 값이 쓰이지 않는다).

   ```sh
   SIMPLELAY_MOTION_MODE=serial
   SIMPLELAY_MOTION_PROTOCOL=touchbridge-v2
   SIMPLELAY_MOTION_PORT=socket://<docker0 주소>:7100
   SIMPLELAY_MOTION_BAUD=115200
   ```

   `SIMPLELAY_MOTION_PORT`가 `/dev/…`가 아니므로 `run_act.sh`는 장치를 넘기지 않는다. 링크 키 등 나머지 줄은 그대로 둔다.

4. 실행기를 다시 세운다: `sh /mnt/rawdata/run_act.sh`. `docker logs simplelay-tbsim`에 `client connected`와 `status` 줄이 보이면 연결된 것이다.

## 주의

- 실행기는 모의 보드를 **실제 시리얼 보드와 구별하지 못한다**(`act_info`의 모션이 `serial`로 보인다). 화면·기록·실행 결과가 실물처럼 보일 수 있으므로 시연 영상·제출 서류·실측 기록의 근거로 쓰지 않는다.
- 끝나면 env를 백업본으로 되돌리고 `docker rm -f simplelay-tbsim` 후 `sh /mnt/rawdata/run_act.sh`로 다시 세운다.
- 개발 PC에서는 `python -m rpi.tools.touchbridge_sim --listen 127.0.0.1:7100`으로 같은 것을 띄울 수 있다.
