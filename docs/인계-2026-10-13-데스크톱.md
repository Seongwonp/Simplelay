## 3. 실제 폰 크기 200% 확대

- 지금 위젯 시험의 200% 장면은 대부분 `360×2400`이라 화면 밖으로 밀리는 문제를 잘 못 잡는다. 예외는 홈 `360×780`·200% 한 장면(`home_verify_note_test.dart`) — 루틴 1개·가전 2개·보조 줄만, AppShell·탭바·RunningStopStrip 없음, 버튼 가운데 hitTest까지(실제 탭 동작은 아님). 루틴 행 200% 시험은 아직 `360×2400`이다.
- 일반 폰 높이(예: 360×780, 412×915)와 에뮬레이터의 글꼴 크기 최대 설정에서 아래를 본다.
  - 홈 큰 루틴 카드·실행하기·가전 타일 상태 줄이 잘리지 않는지
  - 루틴 행의 편집/실행하기가 겹치지 않고 줄바꿈되는지(둘 다 48 이상)
  - 기록 행의 제목 → 결과 → 다음 행동이 읽히는지
  - **실행 중 정지 줄(RunningStopStrip)이 스크롤·확대에서도 항상 보이고 눌리는지**
- 문제가 있으면 위젯 시험에 그 크기 장면을 더해 고정한다.
- 홈 타일 최신성(검토 M1·M3)도 에뮬레이터에서 본다: 연결을 유지한 채 비상정지를 걸면 타일이 "확인하는 중이에요" → "준비가 필요해요"로 바뀌는지(5초 조회 주기만큼 늦다), 서버 재시작 뒤 확인 주행 보조 줄이 "확인 주행 기록이 없어요"로 바뀌는지(폰이 끊김을 본 경우만). 원격 노드 준비 변화는 연결이 유지되면 다시 받지 않는다(남은 한계).

## 4. TalkBack

에뮬레이터에서 TalkBack을 켜고 다음을 확인한다.
- **홈 읽는 순서:** 제목·허브 상태 → (장애 안내) → 제안 또는 첫 루틴(이름·대상·실행) → 나머지 루틴 → 가전 타일(이름·상태·확인 주행 보조 줄) → 가전 추가 → 탭바.
- **설정 탭:** "설정, 읽지 않은 알림 N건"으로 읽히는지. 조회 실패일 때 0건처럼 읽히지 않는지.
- **실행하기 버튼:** 루틴 이름이 포함돼 서로 구별되는지.
- **실행 중:** 정지 버튼에 바로 닿는지. 정지 뒤 단계 문구(보냈어요 / 모션 보드가 확인했어요 / 멈춘 것을 확인했어요)가 읽히는지.
- 결과는 표로 남긴다. 막힌 곳은 고칠 것과 당사자 시험 항목으로 나눈다.
- 위젯 시험의 기록 '시각적 배치 순서'·홈 '가전 목록 아래 배치' 시험은 화면 좌표만 본다 — 낭독 순서는 여기서만 확인된다.

## 6. 보드 날 — RPi5·RPi4 함께 배포와 정지 실물 확인 (미완료)

- RPi5·RPi4를 **같은 커밋으로 함께** 배포한다.
  - 정지 보고 규약이 바뀌었다. 새 RPi5에 옛 RPi4가 붙으면 화면이 늘 "보냈어요"로 나온다.
  - `SIMPLELAY_LINK_KEY`는 두 보드에 이미 있다. 저장소에는 넣지 않는다.
- 폰에서 정지를 누르고 다음을 확인한다.
  - 줄 기록(`SIMPLELAY_MOTION_LOG_PATH`)에 `>> stop`과 `<< {"id":…,"ok":true}`가 둘 다 남는지
  - 화면의 ms가 기록과 맞는지
  - 멈춤 확인(`verified`)이 나오는지
- 기한 값(0.3 s·0.1 s·1.5 s)은 자리표시자다. 실측해서 정하고 [실측 계획](실측-계획-결선.md) G3 두 구간에 기록한다.
- 실물에서 확인하기 전까지 문서·발표에서는 "정지 확인 단계 구현, 실물 미검증"으로 말한다.
