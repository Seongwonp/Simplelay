# 인계 2026-10-06 노트북 → 데스크톱 (3차) — 외부 평가 62/100 수리

2차 인계([인계-2026-10-06-노트북-2](인계-2026-10-06-노트북-2.md))를 끝낸 뒤 진행한다. 단계마다 1커밋, 회귀 테스트는 수정 전 코드에서 실패 확인 뒤 수리. 끝나면 5줄 보고.

평가 기준 커밋 `1727698`, 총점 62/100(완성도 35·독창성 15·활용성 12, 가산점 증거 0/10). 노트북에서 H1·H2·H3·M1 코드 위치를 확인했고 지적이 맞다.

## A. 센서 관측 경로 (HIGH H1·H2 — 가장 먼저)
- **H1** `rpi/verifier/current_sensor.py` `detect_press`는 창(`window_size` 20)이 차기 전까지 늘 False. 생성 시 기준선을 채우지 않고 시도당 1회만 읽어서, 기본 설정 첫 버튼은 3회 재시도 후 `safety_stopped`. 음향만 성공하면 0.45 < 0.50. 기존 테스트(`rpi/tests/test_sensor_verifier.py` 461줄 근처)는 미리 `verify()`를 여러 번 불러 기준선을 채워서 결함을 가렸다 → 그 준비 단계 없이 실제 생성 경로 그대로 시험.
- **H2** `rpi/verifier/audio_sensor.py` 콜백이 큐가 차면 **새 프레임을 버린다**(오래된 것 보존). `closed_loop.py`는 누름이 끝난 뒤에야 센서를 읽는다. → 누름 전 기준선, 누름 중 연속 수집, 누름 후 종료를 하나의 관측 구간으로. 프레임·전류에 시각과 신선도, 오래된 큐는 버리고 최신 유지, 단절은 무음·0과 구분.
- 완료 기준: 기본 설정 첫 실행, 오래된 소리, 누름과 무관한 전류 상승, 센서 단절을 실제 진입점과 같은 배선으로 시험. 임계값은 여전히 실측 필요로 둔다.

## B. 실행 대상 ↔ CT 채널 결속 (HIGH H3)
- `rpi4/act_main.py` 608줄 근처: L3 검증기·정지 대기 전력 판정이 전자레인지 채널(`OUTLET_PRESS_APPLIANCE`)로 고정. `rpi4/models/act_messages.py` `ExecuteMsg`에 필수 대상 ID 없음, `hold`의 대상 ID도 전력 판정기 생성에 안 쓴다.
- 명령에 대상 ID를 필수로 넣고, 대상별로 CT 채널·L2/L3 정책·정지 정책을 고른다. 매핑 없는 대상에 real L3를 켜면 실행 전 거절. RPi5↔RPi4 프레임 호환은 버전 필드나 거절로 명시.
- 완료 기준: 전자레인지 채널 변화로 세탁기·인터폰 실행이나 정지가 확인되는 경우 0.

## C. L2 수신 판정 연결 (MEDIUM M1)
- `act_main.py` 624줄 `ClosedLoopController(...)`에 `acceptance=`가 없어 운영 경로에서 L2 분기를 건너뛴다. 연결하거나, 연결 못 하면 문서·화면에서 "L2는 모의 계약까지"로 낮춘다.

## D. 기타
- **M2** `rpi/verifier/config.py` 18줄: 영전류 2.5 V와 ADC ±2.048 V 기본값이 양립 안 함. 실제 분압 회로는 팀원 확인 전이니, 기동 시 설정 일관성 검사로 거절하고 값은 실측 필요 표시.
- **M3** 첫 연결 실패 시 기동 실패 — 2차 인계 6단계와 같은 일. 거기서 했으면 건너뛴다.
- **L1 문서 상충:** CLAUDE.md "운영 주의"의 "real L3는 센서 드라이버 없어 기동 거절"을 콘센트 모듈 경로 반영으로 고침. `docs/submission/제출-체크리스트.md` 47줄 "이력 재작성 안 함" → 10/6 결정(제거)으로.
