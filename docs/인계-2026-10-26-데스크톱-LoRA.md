# 인계 — 데스크톱 밤샘 LoRA 실험 (2026-10-26 밤)

> 목적: 본체 언어 모델(LG 공개 2.4B 지시형 모델)이 '정해진 동작 목록 중 하나 고르기'를 더 잘하게 미세조정해 본다.
> **실험이다.** 같은 평가에서 나아질 때만 보드에 올린다. 안 나아지면 결과만 기록하고 끝낸다. 시연 문장은 이미 규칙이 처리한다.
> 근거: [언어 모델 평가](발표/언어모델-평가-2026-10-26.md) — 규칙 없이 모델만: 돌려 말하기 약함, 시연 문장 11/20, 서버가 temperature를 적용하지 않음.

## 0. 환경

- 데스크톱 GPU: RTX 3050(메모리 6~8GB) → **4비트 QLoRA**만.
- 저장소 경로에 한글이 있으면 도구가 깨질 수 있다 — 작업 폴더는 ASCII 경로(예: `C:\Temp\lora`)에 둔다.
- 모델 파일·데이터·체크포인트는 **저장소에 넣지 않는다**(크다). 저장소에는 스크립트·데이터 생성 규칙·결과 문서만.
- 원본 모델: 보드가 쓰는 GGUF(Q4_K_M)와 같은 모델의 Hugging Face 원본(이름은 보드 언어 모델 폴더의 파일 이름 참고, 라이선스 확인 — 연구·비상업 용도).

## 1. 학습 데이터 (가장 중요)

- 형식: 지금 `rpi/intent/llm_intent.py`가 모델에 보내는 **프롬프트와 똑같은 모양**(동작 목록 + 문장) → 정답 출력(고른 id 또는 없음).
  프롬프트 문자열은 그 파일의 함수로 만들어 쓴다(손으로 베끼지 말 것).
- 동작 목록은 여러 가지로 섞는다: 공기청정기 11개(평가 스냅숏), 전자레인지 '30초 데우기' 추가판, 목록 일부만 있는 판 — 목록 밖이면 '없음'을 배우게.
- 문장 종류 비율(대략): 돌려 말하기 40%, 직접 명령 15%, 부정·이미 했어 15%, 목록 밖 기기·요청 20%, 애매한 말(없음) 10%.
- 1,500~3,000개. 다양한 말투(반말·존댓말·짧은 말·사투리 조금).
- **평가 문장과 겹치면 안 된다:** `rpi/intent/eval/llm_eval_ko.jsonl`(50)·`llm_eval_ko_holdout.jsonl`(12)과 같은 문장·거의 같은 문장은 빼는 검사 스크립트를 둔다(정규화 후 완전 일치 + 글자 n-gram 유사도 높은 것 제거).
- 데이터 생성 스크립트는 `scripts/lora/make_dataset.py`(저장소), 결과 파일은 저장소 밖.

## 2. 학습

- 도구: `transformers` + `peft` + `bitsandbytes`(4비트), 또는 `unsloth`. LoRA r=16, alpha=32, 학습률 2e-4, 2~3 epoch, 최대 길이는 프롬프트 길이에 맞춤.
- 출력 부분만 손실 계산(프롬프트는 마스크).
- 밤새 돌려도 되지만 **체크포인트를 epoch마다 저장**하고 로그를 남긴다.

## 3. 보드용으로 바꾸기

- LoRA를 원본에 합친 뒤(merge) `llama.cpp`의 `convert_hf_to_gguf.py` → `llama-quantize`로 **Q4_K_M**.
- 보드의 언어 모델 서버 설정 파일이 가리키는 GGUF를 **새 파일로 바꿔 끼우기만** 한다(원래 파일은 지우지 말고 옆에 둔다 — 바로 되돌릴 수 있게).
- 보드에 올리고 바꾸는 일은 **노트북 세션(보드에 붙는 쪽)에서 사람이 있을 때** 한다. 데스크톱은 파일까지만 만든다.

## 4. 평가 (채택 기준)

- 먼저 데스크톱에서 GGUF로 같은 프롬프트를 돌려(`llama.cpp` 실행 파일) 50+12문장 + 시연 문장 20번을 잰다. 규칙을 끈 '모델만' 결과와 규칙을 켠 결과 둘 다.
- 그다음 보드에서 `scripts/llm_eval_hub.py` 방식으로 다시 잰다(**HTTP `/intent/understand`로 재지 말 것 — 키오스크에 진짜 확인 카드가 뜬다**).
- **채택:** 새 12문장(holdout)에서 나빠지지 않고, 목록 밖·부정 잘못 받아들임이 늘지 않고, 보드 응답 중앙값이 12초를 넘지 않을 때만.
- 결과는 `docs/발표/언어모델-평가-2026-10-26.md`에 §11로 추가(전후 표, 데이터 크기, 평가 세트와 겹치지 않게 한 방법). 숫자가 나빠도 그대로 적는다.

## 5. 하지 않는 것

- 평가 문장을 학습에 넣기, 평가 문장을 보고 데이터 고치기.
- 시연 문장을 모델 성과로 말하기(규칙이 고른다).
- 커밋·푸시는 사용자가 시킬 때만, 커밋 메시지에 AI 표기 금지(CLAUDE.md).

## 7. 2차 실험 (2026-10-27 아침 지시)

1차 결과(평가 문서 §11): 모델만 보면 크게 좋아졌지만(오수락 10/16→1/16, 시연 문장 20/20), **규칙+모델 새 12문장이 5/5→4/5**(조용한 바람·수면 요청을 '전원 끄기'로 고름)라 채택하지 않았다. 2차는 그 약점을 고치고, **새 문장 5개뿐이라 생기는 우연**을 줄인다.

순서(지키기):
1. **새 평가 문장을 학습보다 먼저 만들고 얼린다.** `rpi/intent/eval/llm_eval_ko_holdout2.jsonl` — 30문장(맞혀야 할 것 15: 그중 조용히·수면·바람 약하게 5개 이상 / 목록 밖·부정 10 / 애매함 5). 기존 50·12문장과 겹치지 않게 1차 검사기로 확인. **만든 뒤 커밋부터 하고**, 그 뒤로는 고치지 않는다(학습 데이터를 이 문장을 보고 고치지 않는다).
2. 학습 데이터 보강: '조용히/시끄러워/잘 거야/자려고/바람 세다' 류 → 바람 약·수면 모드, **'끄기'와 구분되는 짝 예시**(꺼 줘 vs 조용히 해 줘)를 늘린다. 평가 세 세트(50·12·30)와 겹치지 않게 검사.
3. 1차와 같은 설정으로 학습(필요하면 1에폭만). 체크포인트마다 병합·Q4_K_M.
4. 같은 데스크톱 실행기로 원본·새 체크포인트를 다 잰다: 50 + 12 + **새 30**, 모델만 / 규칙+모델 둘 다, 시연 문장 20회.
5. **채택 기준(미리 고정):** 규칙+모델 경로에서 (12+30 합친) 새 문장 맞힘이 원본보다 낮지 않고, 목록 밖·부정 잘못 받아들임이 원본보다 많지 않을 것. 둘 다 만족할 때만 '보드 올리기 후보'.
6. 결과는 평가 문서 §12로(숫자가 나빠도 그대로). 보드에 올리는 건 노트북 세션에서 사람이 있을 때 — 데스크톱은 GGUF 파일과 해시까지만.

## 8. 2차 2에폭 GGUF를 보드에 올려 보기 (2026-10-27 새벽, 사용자 승인)

판단: §12 합산 기준(새 42문장 32→38, 오수락 1/17→0/17)을 통과했으므로 **보드에서 시험 채택**한다. 보드 결과가 나쁘면 바로 원래 파일로 되돌린다.

1. **공간 먼저:** 보드 데이터 영역 여유가 약 1.2GB라 1.6GB GGUF가 그대로는 안 들어간다. 원래 GGUF를 지우지 말 것. 대신 쓰지 않는 도커 이미지(옛 날짜 태그의 `simplelay-backend:*`, 지금 컨테이너가 쓰는 `latest` 제외)와 `docker image prune -f`로 1.8GB 이상 확보한다. 그래도 모자라면 원래 GGUF를 데스크톱에 해시와 함께 백업한 **뒤에만** 옮긴다.
2. 새 GGUF를 언어 모델 폴더(설정 파일 `config_24.json`과 같은 폴더)에 **다른 이름**으로 복사하고 해시를 맞춘다.
3. 설정 파일을 백업(`config_24.json.bak-20261027`)한 뒤 `model_file`만 새 파일 이름으로 바꾸고 언어 모델 컨테이너(`simplelay-llm`)만 재시작한다. 백엔드·키오스크는 건드리지 않는다.
4. 보드에서 `scripts/llm_eval_hub.py` 방식으로 50 + 12 + 새 30문장과 시연 문장 20회를 잰다(**HTTP `/intent/understand` 금지** — 키오스크에 진짜 카드가 뜬다). 응답 중앙값·p90도.
5. **유지 조건:** 보드에서도 새 42문장 규칙+모델 정답이 원본 보드값보다 낮지 않고, 오수락이 늘지 않고, 중앙값 12초 이하. 아니면 설정 백업으로 되돌리고 컨테이너 재시작.
6. 결과를 평가 문서 §13에 적는다(보드 값, 해시, 유지/되돌림). 발표 문서 숫자는 유지할 때만 바꾼다.
