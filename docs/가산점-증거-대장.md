# 가산점 증거 대장

2026-10-01. 데스크톱 실측 전 빈 양식이다. **아래 행은 성공 증거가 아니다.**
기준은 [본선 실행계획 §6](본선-실행계획-2026-09-30.md#6-결선-배점과-보드-역할-2026-09-30-부문-세부-안내사항-v6)에 정리한 공식 안내다.
완성도 60·독창성 20·활용성 20, 가산점은 각 5점·최대 10점이다.

| 공식 가산점 문구(실행계획 §6 기준) | 대응 증거 | 미결 조건 |
|---|---|---|
| (1) LG 제공 임베디드 SW 플랫폼 기반으로 하드웨어 3종 연동 | 보드별 앱 계정의 API 최소 호출 + 실제 시연 흐름에서 세 보드 연동 | 안내 예시의 “ESP32, RPi4, RPi Zero 필수”에서 Zero를 RPi4로 대체할 수 있는지 사무국 확인 필요 |
| (2) 멀티모달 확장성: 음성·영상·조도 등 다중 센서를 융합해 상황 인지 정확도를 높인다 | 입력별 최소 호출 + 복수 입력이 하나의 상황 판단·제안에 기여하는 시연 | 센서가 존재하거나 API 한 번 성공한 것만으로 융합 효과를 입증하지 않음 |

보드 수를 늘린 것만으로 가산점 인정을 확정하지 않는다. 역할은 RPi5(해석·제안·키오스크),
RPi4(실행 관리·검증), ESP32(CT 전력·릴레이 비상정지), Uno(CoreXY A/B·시간 기반 Z)로 구분한다.
API 최소 호출 성공과 실제 시연 사용은 **별개의 증거**다. root 호출 성공은 앱 계정 권한 증거가 아니다.

원본 대장은 비공개 로컬 사본으로 운영한다. 측정 시각은 UTC와 현지 offset을 함께 남기고,
결과 파일 칸에는 그 PC/보드의 로컬 경로만 쓴다. 원시 응답·설정·서비스 식별자·객체 경로·스크린샷을
이 공개 문서에 붙이지 않는다. 공개 반영 시에도 경로에 내부 식별자가 있으면 일반 자리표시자로 바꾼다.
상태는 미측정/실패/최소 호출 성공/시연 사용 확인으로 구분하고, 모의 결과에는 반드시 “모의”를 붙인다.
기록은 측정 시점의 사실이며 현재 readiness나 실행 허가에 재사용하지 않는다.

## 공감 로직 독립성

습관 학습, 제안 거절 처리, 제안 이유 설명, 사용자의 승인·정지·수정 권한은 플랫폼 추론 없이도 동작해야 한다.
