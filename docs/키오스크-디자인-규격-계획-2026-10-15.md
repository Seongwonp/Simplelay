# 키오스크 시각 디자인 규격 계획 (2026-10-15, 결정 전 초안)

[문구 개선](키오스크-문구-개선-계획-2026-10-15.md) 뒤 새 골든(15.8형 16장 + 큰 글자 참고 7장)으로 **시각 디자인 평가 세 건**을 받았다
(이미지만 본 평가 — 실패널·실거리·실사용자 확인이 아니다): **6/10 · 7.0/10 · 6.5/10**.
세 평가가 같은 곳을 지적했다. 이 문서는 그것을 **화면 하나하나가 아니라 공통 규격(토큰·영역·규칙)** 으로 고치는 계획이다.

## 0. 세 평가의 공통 결론

- **좋은 점(유지):** 어두운 바탕·흰 글자·앰버 1색·빨강 1색의 절제된 팔레트로 한 제품처럼 보인다. 큰 버튼, 정지가 늘 오른쪽 아래·빨강. 결과 아이콘 모양(i·X·?)으로 색에만 기대지 않는다. 비상정지 띠·위험 화면·연습 띠는 즉시 구분된다.
- **공통 문제(세 평가 모두):**
  1. **정지 버튼이 화면마다 다르다** — `executing`(폭 약 550px, 흰 테두리, ■) vs `hold`·`hold_unconfirmed`(폭 약 690px, 테두리 없음, ◉). 같은 자리·같은 모양이 아니다.
  2. **실행 중 버튼판 그림이 진짜 버튼처럼 보인다** — `manual`의 실제 버튼과 같은 테두리·글자색. 안내문에만 기댄다.
  3. **정지 대기·확인 불가가 실행 중과 비슷해 보이고, 주인공이 여럿** — `hold_unconfirmed`는 앰버 제목·앰버 지시문·빨강 버튼이 경쟁하고 시선이 좌상→우하로 갈라진다.
  4. **앰버 과부하** — 주요 행동·연습·불확실·동작 중·쉬는 중·날씨가 한 색.
  5. **글자 크기 단계가 너무 많고(8단계 이상) 줄바꿈이 어색** — "요).", "멈/췄는지", "주세/요", 긴 본문 한 줄 약 40자.
  6. **결과·보조 버튼 규격이 제각각** — '처음 화면으로'가 앰버 채움/회색 채움/테두리, '취소'·'화면으로 조작하기'는 글자만.
  7. **큰 글자(1.22×) 화면이 단순 확대라 잘리고 스크롤** — `hold_large`·`executing_large`·`suggestion_long_large`.
  8. (두 평가) 오버레이·배너가 가장자리 약 140/50px 안쪽에서 끝남, `learning` 갈색 팔레트가 다른 제품 같음, 상단 아이콘이 작고 상태/버튼 구분이 약함.

## 1. 규격 (디자인 토큰 — 시안 출발값, 실패널에서 조정)

수치는 1920×1080 기준 **시안 출발값**이다. 연구가 검증한 값이 아니며 15.8형 실패널 1.5 m·3 m에서 확인해 고친다
(1920×1080 15.8형 전체 면적 기준 96px ≈ 17.5 mm).

### 1-1. 정지 영역 (가장 먼저)

| 항목 | 규격 |
|---|---|
| 위치·크기 | 실행 계열 모든 화면(`executing`·`hold`·`hold_unconfirmed`·누름 진행 중) 오른쪽 아래 **고정 영역** — 예: x 1220·y 830·폭 560·높이 200, 오른쪽·아래 여백 64 이상(세 평가 제안 범위 안에서 하나로 확정) |
| 모양 | 빨강 채움 + 같은 테두리 규칙 + **같은 아이콘 하나**(■) + 글자 크기 고정. 이름만 상황별(`정지` / `다시 정지 시도`) |
| 주변 | 정지 영역 위·옆 48px 안에 다른 조작 없음. 버튼판의 '취소' 강조 테두리는 빨강이 아닌 색으로(정지와 한 묶음처럼 보이지 않게) |
| 결정 필요 | 대기·수동 조작 화면에도 같은 자리에 정지를 둘지 — 평가 하나는 "모든 화면", SimpleLay는 실행이 없을 때 정지를 보이면 오해 소지. **제안:** 실행 중일 때만 정지, 그 밖에는 같은 자리를 비워 둔다 |

### 1-2. 상태 영역

- 실행 계열 화면 **왼쪽 위 같은 기준선**에 `상태 아이콘 + 상태 제목` 한 줄(제목 64~72, 아이콘 96~120). 보냄/응답/확인·확인 불가가 **같은 자리에서 갈아 끼워진다**.
- `hold_unconfirmed`는 **할 일("지금 전자레인지의 '취소' 버튼을 직접 눌러 주세요")을 상태 영역 바로 아래 첫 블록**으로, 상태 설명·작은 팔 복귀는 그 아래 작게.
- (시연용 제안) 화면 맨 위 **상태 색 띠**(48~88px)를 전 흐름에 — 실행=청회색, 정지 보냄=앰버, 완료=중립 회색, 실패=빨강, 연습=별색+아이콘. 지금은 연습·비상정지만 띠가 있다.

### 1-3. 타이포 4단계

| 단계 | 크기(출발값) | 쓰는 곳 |
|---|---|---|
| 핵심 | 80~96 | 결과 제목, 제안 질문, 대기 시계 보조 |
| 상태 | 56~64 | 상태 제목, 할 일 한 줄, 주요 버튼 글자 |
| 본문 | 40~44 | 설명, 근거, 연결 창 본문 |
| 보조 | 32~36 | 캡션, 카운트다운, 작은 팔 위치 |

- 대기 시계(220)는 예외로 유지. 그 밖 크기는 이 4단계로만.
- 본문 최대 폭 1,000~1,320px, 긴 본문은 왼쪽 정렬, **어절 단위 줄바꿈**(조사·문장부호만 다음 줄로 넘어가지 않게).

### 1-4. 색 역할

| 색 | 의미(이것만) |
|---|---|
| 앰버 채움 | **주요 행동 하나**(시작·처음 화면으로) |
| 앰버 아이콘/테두리 | 주의·확인 불가 |
| 빨강 | 정지·비상·실패·위험 |
| 중립 회색 면 | 쉬는 중·동작 중·날씨 같은 일상 상태(아이콘으로 구분) |
| 연습 | 전용 별색(예: 청록) 띠 + 학사모 아이콘 — 앰버 쓰지 않음 |

### 1-5. 버튼 체계

- **주 버튼**(채움, 높이 144~152) · **보조 버튼**(테두리, 높이 96~112) · 글자만 있는 조작은 없앤다(`취소`·`화면으로 조작하기`·`뒤로 가기`를 보조 버튼으로).
- '처음 화면으로'는 결과 종류와 무관하게 **한 모양**. 화면당 채움 버튼은 하나.
- 뒤로 가기 아이콘 1종(‹ 또는 ← 하나로).

### 1-6. 설명 그림(버튼판) vs 실제 버튼

- 실행·정지 대기 화면의 버튼판은 **설명 그림 스타일**: 테두리 제거, 어두운 평면 채움, 글자 50% 회색, **지금 누르는 칸만** 앰버 채움. 카드 테두리 유무·칸 높이를 두 화면에서 같게.
- 실제 조작 버튼(`manual`)은 지금처럼 채움+선명한 경계, '시작'만 앰버 테두리로 구분.

### 1-7. 화면 틀

- 비상정지 띠·덮개 창 어둡게·위험 패널은 **전폭**(지금 좌우 약 140/상하 50 안쪽에서 끝남 — 의도된 베젤 안전영역인지 먼저 확인).
- `learning` 창은 공통 어두운 팔레트·공통 버튼으로.
- 대기 화면: 가전 행을 카드(어두운 채움)로 묶어 누를 수 있음을 보이고 40~60px 올려 중앙 빈 띠를 줄인다. 상단 아이콘은 누름 면 88~120.
- 결과 화면 공통: 아이콘 200, 제목 2줄 허용·폭 ≤1,100~1,400, 다음 행동은 제목 아래 32~40 간격, 하단 버튼 영역 아래 여백 64.

### 1-8. 큰 글자 배치

- 단순 확대 대신 **2열 → 1열 전환**. 상태 영역·할 일·정지 영역은 **스크롤 밖 고정**, 설명만 스크롤.
- 큰 글자에서 버튼판 그림은 줄이거나 접는다(상태가 먼저).

## 3. 순서

1. **작은 수정(먼저):** 정지 영역 고정(1-1), 결과 화면 공통 규격·글자 조작 → 보조 버튼(1-5·1-7 결과), 오버레이 전폭(인셋 의도 확인 뒤), 줄바꿈(1-3).
2. **중간:** 버튼판 설명 그림 스타일(1-6), 상태 영역(1-2), 색 역할(1-4), 타이포 4단계 적용.
3. **큰:** 큰 글자 1열 배치(1-8), (선택) 상태 색 띠 전 흐름.
4. 골든 재생성 → 이미지 열어 확인 → **실패널 1.5 m·3 m 사진**(조명 반사 포함) → 같은 평가 재요청(점수보다 "지금 뭐가 움직여 / 멈춘 건 뭐야 / 이제 뭘 해야 해"와 3초 상태 구분).

## 4. 정해야 할 것

1. 정지 영역을 실행 중일 때만 보일지(제안) / 모든 화면에 같은 자리로 둘지.
2. 연습 별색(청록 등) — 앰버를 연습에서 빼는 데 동의하는지.
3. 상태 색 띠를 전 흐름에 둘지(시연 전달력 ↑, 화면 높이 48~88px 사용).
4. 오버레이 인셋(140/50px)이 의도된 안전영역인지 — 실패널에서 가장자리 터치가 창 관리자 스와이프로 읽힌 기록(9/30)이 있어 일부러 띄웠을 수 있다.
