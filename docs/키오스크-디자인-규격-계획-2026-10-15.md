# 키오스크 시각 디자인 규격 계획 (2026-10-15, 결정 반영 — §4)

[문구 개선](키오스크-문구-개선-계획-2026-10-15.md) 뒤 새 골든(15.8형 16장 + 큰 글자 참고 7장)으로 **시각 디자인 평가 세 건**을 받았다
(이미지만 본 평가 — 실패널·실거리·실사용자 확인이 아니다): **6/10 · 7.0/10 · 6.5/10**.
세 평가가 같은 곳을 지적했다. 이 문서는 그것을 **화면 하나하나가 아니라 공통 규격(토큰·영역·규칙)** 으로 고치는 계획이다.

## 0. 세 평가의 공통 결론

- **좋은 점(유지):** 어두운 바탕·흰 글자·앰버 1색·빨강 1색의 절제된 팔레트로 한 제품처럼 보인다. 큰 버튼, 정지가 늘 오른쪽 아래·빨강. 결과 아이콘 모양(i·X·?)으로 색에만 기대지 않는다. 비상정지 띠·위험 화면·연습 띠는 즉시 구분된다.
- **공통 문제(세 평가 모두):**
  1. **정지 버튼이 화면마다 다르다** — `executing`(폭 약 550px, 흰 테두리, ■) vs `hold`·`hold_unconfirmed`(폭 약 690px, 테두리 없음, ◉). 같은 자리·같은 모양이 아니다.
  2. **실행 중 버튼판 그림이 진짜 버튼처럼 보인다** — `manual`의 실제 버튼과 같은 테두리·글자색. 안내문에만 기댄다.
  3. **정지 대기·확인 불가가 실행 중과 비슷해 보이고, 주인공이 여럿** — `hold_unconfirmed`는 앰버 제목·앰버 지시문·빨강 버튼이 경쟁하고 시선이 좌상→우하로 갈라진다.
  4. **앰버 과부하** — 주요 행동·연습·불확실·동작 중·쉬는 중·날씨가 한 색.
  5. **글자 크기 단계가 너무 많고(8단계 이상) 줄바꿈이 어색** — "요).", "멈/췄는지", "주세/요", 긴 본문 한 줄 약 40자.
  6. **결과·보조 버튼 규격이 제각각** — '처음 화면으로'가 앰버 채움/회색 채움/테두리, '취소'·'화면으로 조작하기'는 글자만.
  7. **큰 글자(1.22×) 화면이 단순 확대라 잘리고 스크롤** — `hold_large`·`executing_large`·`suggestion_long_large`.
  8. (두 평가) 오버레이·배너가 가장자리 약 140/50px 안쪽에서 끝남, `learning` 갈색 팔레트가 다른 제품 같음, 상단 아이콘이 작고 상태/버튼 구분이 약함.

## 1. 규격 (디자인 토큰 — 시안 출발값, 실패널에서 조정)

수치는 1920×1080 기준 **시안 출발값**이다. 연구가 검증한 값이 아니며 15.8형 실패널 1.5 m·3 m에서 확인해 고친다
(1920×1080 15.8형 전체 면적 기준 96px ≈ 17.5 mm).

### 1-1. 정지 영역 (가장 먼저)

| 항목 | 규격 |
|---|---|
| 위치·크기 | 실행 계열 모든 화면(`executing`·`hold`·`hold_unconfirmed`·누름 진행 중) 오른쪽 아래 **고정 영역** — 예: x 1220·y 830·폭 560·높이 200, 오른쪽·아래 여백 64 이상(세 평가 제안 범위 안에서 하나로 확정) |
| 모양 | 빨강 채움 + 같은 테두리 규칙 + **같은 아이콘 하나**(■) + 글자 크기 고정. 이름만 상황별(`정지` / `다시 정지 시도`) |
| 주변 | 정지 영역 위·옆 48px 안에 다른 조작 없음. 버튼판의 '취소' 강조 테두리는 빨강이 아닌 색으로(정지와 한 묶음처럼 보이지 않게) |
| 표시 범위(결정) | **실행·정지 대기·정지 미확인 화면에만**. 세 화면에서 위치·크기·아이콘·테두리 고정. 대기·제안·결과·설정 화면에는 두지 않는다 |

### 1-2. 상태 영역

- 실행 계열 화면 **왼쪽 위 같은 기준선**에 `상태 아이콘 + 상태 제목` 한 줄(제목 64~72, 아이콘 96~120). 보냄/응답/확인·확인 불가가 **같은 자리에서 갈아 끼워진다**.
- `hold_unconfirmed`는 **할 일("지금 전자레인지의 '취소' 버튼을 직접 눌러 주세요")을 상태 영역 바로 아래 첫 블록**으로, 상태 설명·작은 팔 복귀는 그 아래 작게.
- **상태 띠(결정):** **제안 → 실행 → 정지 대기 → 결과** 흐름에 적용, 모든 화면에서 **같은 위치·같은 높이**(48~88px 중 하나로 확정). 색: 일반 상태 = **중립색**, 연습 = **청록**, 확인 필요 = **앰버**, 실패·비상 = **빨강**. 띠에는 아이콘+짧은 글자를 함께 둬 색 없이도 구분. 평소 대기·설정 화면에는 일반 상태 띠를 넣지 않는다. **비상정지 띠는 어느 화면에서도 보인다.**

### 1-3. 타이포 4단계

| 단계 | 크기(출발값) | 쓰는 곳 |
|---|---|---|
| 핵심 | 80~96 | 결과 제목, 제안 질문, 대기 시계 보조 |
| 상태 | 56~64 | 상태 제목, 할 일 한 줄, 주요 버튼 글자 |
| 본문 | 40~44 | 설명, 근거, 연결 창 본문 |
| 보조 | 32~36 | 캡션, 카운트다운, 작은 팔 위치 |

- 대기 시계(220)는 예외로 유지. 그 밖 크기는 이 4단계로만.
- 본문 최대 폭 1,000~1,320px, 긴 본문은 왼쪽 정렬, **어절 단위 줄바꿈**(조사·문장부호만 다음 줄로 넘어가지 않게).

### 1-4. 색 역할

| 색 | 의미(이것만) |
|---|---|
| 앰버 채움 | **주요 행동 하나**(시작·처음 화면으로) |
| 앰버 아이콘/테두리/띠 | 주의·확인 필요 — **채움 버튼처럼 보이지 않게**(채운 면을 쓰지 않거나 버튼과 다른 모양) |
| 빨강 | 정지·비상·실패·위험 |
| 중립 회색 면 | 쉬는 중·동작 중·날씨 같은 일상 상태(아이콘으로 구분) |
| **청록(결정)** | **연습** — 청록 띠 + 연습 아이콘 + '연습 중' 글자(색 없이도 구분). 앰버를 연습에 쓰지 않는다 |

### 1-5. 버튼 체계

- **주 버튼**(채움, 높이 144~152) · **보조 버튼**(테두리, 높이 96~112) · 글자만 있는 조작은 없앤다(`취소`·`화면으로 조작하기`·`뒤로 가기`를 보조 버튼으로).
- '처음 화면으로'는 결과 종류와 무관하게 **한 모양**. 화면당 채움 버튼은 하나.
- 뒤로 가기 아이콘 1종(‹ 또는 ← 하나로).

### 1-6. 설명 그림(버튼판) vs 실제 버튼

- 실행·정지 대기 화면의 버튼판은 **설명 그림 스타일**: 테두리 제거, 어두운 평면 채움, 글자 50% 회색, **지금 누르는 칸만** 앰버 채움. 카드 테두리 유무·칸 높이를 두 화면에서 같게.
- 실제 조작 버튼(`manual`)은 지금처럼 채움+선명한 경계, '시작'만 앰버 테두리로 구분.

### 1-7. 화면 틀

- 덮개 창·패널의 **가장자리 여백 약 140px는 일단 유지(결정)** — 의도된 값인지 모른다. 실패널에서 가장자리 터치가 창 넘기기로 처리되는지 확인한 뒤 조정한다. 여백 때문에 내용이 잘리면 **글자를 줄이기보다 내부 배치와 스크롤을 먼저** 고친다.
- `learning` 창은 공통 어두운 팔레트·공통 버튼으로.
- 대기 화면: 가전 행을 카드(어두운 채움)로 묶어 누를 수 있음을 보이고 40~60px 올려 중앙 빈 띠를 줄인다. 상단 아이콘은 누름 면 88~120.
- 결과 화면 공통: 아이콘 200, 제목 2줄 허용·폭 ≤1,100~1,400, 다음 행동은 제목 아래 32~40 간격, 하단 버튼 영역 아래 여백 64.

### 1-8. 큰 글자 배치

- 단순 확대 대신 **가로 2열 배치를 세로 1열로 바꾼다**(문장을 한 줄에 억지로 넣는 뜻이 아니다 — 글은 자연스럽게 여러 줄로 둔다). 상태 영역·할 일은 스크롤 밖 위쪽에 두고 설명만 스크롤. **정지 버튼은 큰 글자에서도 같은 자리에 고정.**
- 큰 글자에서 버튼판 그림은 줄이거나 접는다(상태가 먼저).

## 3. 순서

1. **작은 수정(먼저):** 정지 영역 고정(1-1), 결과 화면 공통 규격·글자 조작 → 보조 버튼(1-5·1-7 결과), 오버레이 전폭(인셋 의도 확인 뒤), 줄바꿈(1-3).
2. **중간:** 버튼판 설명 그림 스타일(1-6), 상태 영역(1-2), 색 역할(1-4), 타이포 4단계 적용.
3. **큰:** 큰 글자 1열 배치(1-8), (선택) 상태 색 띠 전 흐름.
4. 골든 재생성 → 이미지 열어 확인 → **실패널 1.5 m·3 m 사진**(조명 반사 포함) → 같은 평가 재요청(점수보다 "지금 뭐가 움직여 / 멈춘 건 뭐야 / 이제 뭘 해야 해"와 3초 상태 구분).

## 5. 구현 기록 (2026-10-16, 커밋 전 검토용 — [devlog](devlog/devlog_2026-10-16-kiosk-design.md))

§3 순서 1(작은 수정)·2(중간)와 §4 결정의 상태 띠를 키오스크에 넣었다. **검증 수준: 골든·위젯 시험까지. 실패널(15.8형)에는 아직 설치하지 않았다.**

- **토큰:** `lib/theme/kiosk_tokens.dart` — 글자 4단계(핵심 40·상태 30·본문 21·보조 17, 캔버스 단위 = 1920×1080에서 82·61·43·35px),
  정지 영역(272×96, 오른쪽 20·아래 12 = 실제 화면 약 558×197px, 오른쪽 181·아래 73px), 상태 띠 높이 40(82px), 주/보조 단추 높이 72/52,
  결과 아이콘 88, 결과 제목 폭 660. 색은 `KioskColors.practice`(청록)·`panelText`(50% 회색)를 더했다.
- **정지(1-1):** 실행·정지 대기·정지 미확인 세 화면이 같은 틀(`run_frame.dart`)을 써서 정지 단추가 같은 자리·크기·아이콘(■)·흰 테두리 3.
  이름만 '정지' / '다시 정지 시도'. 대기·제안·결과·설정에는 없다.
- **상태 영역·띠(1-2·§4):** 제안·실행·정지 대기·결과 맨 위 같은 자리·같은 높이의 띠 — 중립(제안·실행 중·정지 대기·결과) / 청록(연습) /
  앰버(확인 필요) / 빨강(실패·장치 문제·비상). 띠 면은 옅게(22%)·왼쪽 줄·아이콘으로 색을 싣고 채운 단추처럼 보이지 않게 했다. 연습 중에
  확인 필요·실패가 겹치면 그 색 띠 안에 청록 연습 칸을 함께 둔다. 실행 계열 세 화면은 왼쪽 위 같은 자리에 상태 아이콘+제목.
  정지 미확인은 제목을 '멈췄는지 확인하지 못했어요'로 줄이고 바로 아래 할 일, 그 아래 작게 '작은 팔이 정지 버튼을 대신 눌렀어요'.
- **글자·줄바꿈(1-3):** 손댄 화면의 글자를 4단계로. 어절 단위 줄바꿈 — 그리는 글에만 보이지 않는 잇기 문자를 넣어 띄어쓰기에서만
  줄을 바꾼다(화면 읽기·글 찾기는 원문). 문단 끝 한 글자 낱말('중')은 앞 낱말과 묶는다.
- **색 역할(1-4):** 연습 = 청록. 평소 화면의 동작 중 가전·제안 쉬는 중 칩·비 예보 아이콘·안내 아이콘은 앰버 → 중립(흰색·회색 면).
- **단추(1-5):** '처음 화면으로'는 결과 종류와 무관하게 앰버 채움 주 단추(높이 72) 하나. '다시 시도'·'화면으로 조작하기'·'근거 전체 보기'는
  테두리 보조 단추(글자만 있는 조작 없음). 뒤로 가기 아이콘은 ← 하나.
- **설명 그림(1-6):** 실행·정지 대기 버튼판을 같은 위젯으로 — 카드·칸 테두리 없음, 어두운 평면, 글자 50% 회색, 지금 누르는(작은 팔이
  기다리는) 칸만 앰버 채움. 정지 대기의 '취소' 칸 빨강 테두리는 없앴다(정지 단추와 한 묶음처럼 보이지 않게).
- **결과 화면(1-7):** 아이콘 88(출발값 200px보다 작게 — 800×480 세로 자리), 제목 2줄 허용·폭 660, 하단 단추 아래 여백 12.
- **그대로 둔 것:** 가장자리 여백(약 140/48px, §4 결정), 실행 동작·서버 규약·문구(정지 미확인 문장 배치만 바꿈).

### 5-1. 큰 글자 1열 배치(§3 순서 3, 2026-10-16 — [devlog](devlog/devlog_2026-10-16-kiosk-large.md))

위 '남은 것' 1을 했다. **검증 수준: 골든·위젯 시험까지(실패널 미설치).** 동작·서버 규약·문구는 바꾸지 않았다.

- **기준:** 설정의 큰 글씨(1.22배)면 `KioskLayout.isLarge`(`kiosk_tokens.dart`, 평소 화면과 같은 기준)로 가로 2열 → 세로 1열.
  글은 줄이지 않고 여러 줄로 둔다.
- **실행·정지 대기·정지 미확인(`run_frame.dart`):** 상태 영역·할 일이 화면 폭을 다 쓰고, 버튼판 그림은 정지 단추 왼쪽 한 줄(정지 단추
  높이)로 줄인다 — 작은 칸 그림 + 옆 안내 글(§1-8 '그림은 줄이거나 접는다'). 정지 단추는 오른쪽·아래에 붙여 재므로 보통 글씨와
  **같은 자리·같은 크기**(시험으로 확인).
- **제안:** 질문 | 순서 2열 → 질문(폭 전체, 여러 줄) 아래 같은 스크롤에 순서. `suggestion_long_large`의 질문이 스크롤 없이 다 보인다.
- **결과:** 결과 원 88 → 56, 보조 단추(다시 시도·화면으로 조작하기)는 할 일 아래 같은 세로 흐름으로, '처음 화면으로'만 아래 고정.
  `done_user_stop_large`의 할 일 줄이 스크롤 없이 보인다.
- **비상 버튼 띠 + 상태 띠:** 비상 띠가 위에 있으면 상태 띠를 얇게(40 → 26, 글자 보조 크기) — 비상 띠는 그대로, 상태 띠의 아이콘·색·글자도
  그대로. 버튼판 그림이 200보다 낮으면 위 안내 글을 접어 칸에 자리를 준다(`hold_estop_confirm` 칸 높이 약 20 → 30 이상).
- **'다시 정지 시도':** 한 줄로 줄여 넣던 것을 어절에서 두 줄로(■ 옆, 가운데). 단추 크기·아이콘 크기·글자 크기 그대로, 테두리에서 떨어진다.
- **남김:** 큰 글씨 `executing_large`는 진행 막대, `suggestion_large`는 '작은 팔이 누를 순서' 제목이 스크롤 경계에 걸려 반쯤 보인다(막대로 더
  있음을 알린다). 큰 글씨 결과 실패에서 글이 길면 보조 단추가 스크롤 아래로 갈 수 있다(위젯 시험 글꼴에서 그랬다 — 맑은 고딕 골든은 다 보임).
