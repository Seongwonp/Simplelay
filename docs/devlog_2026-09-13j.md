## Phase 1 — 연결 전에 보완한 계약 4가지

1. **락 역전 교착 (조회 → 획득).** Phase 0는 개발자 세션이 자기 락 안에서
   `execution_busy()`를, 실행기가 자기 락 안에서 `blocks_execution()`을
   부르는 구조였다 — 그대로 연결하면 두 락을 반대 순서로 잡는다.
   `ControlArbiter`(rpi/services/control_arbiter.py) 하나에서 확인과 점유를
   원자화했다. 중재자 락은 항상 최내곽(leaf)이고 콜백을 밖으로 부르지
   않으므로 역전이 불가능하다. 경합 테스트: 8스레드×200회 동시 보유 0,
   시작 경합 50회 반복 단독 승자.
2. **정지가 명령 처리를 기다리던 구조.** `submit()`이 상태 락을 잡은 채
   어댑터를 불렀다 — 즉시 반환하는 mock에서는 안 드러난다. **블로킹되는
   fake 어댑터**로 재현 테스트를 먼저 쓰고, 어댑터 모션 호출을 락 밖으로
   뺐다. 단순히 밖으로 옮기면 "정지 뒤에 늦은 명령이 나가는" 구멍이
   생기므로 epoch(정지마다 증가)로 감지해 즉시 재정지한다
   (`stop_after_late_command` — 어댑터 명령 흐름에서 그 명령보다 뒤라
   최종 상태는 멈춤). 어댑터 계약에 "stop은 병행 호출 가능"을 명시했다
   (실물 GRBL의 realtime stop 바이트가 이 성질이다).
3. **정지 실패 = 세션 폐기 ≠ 장치 사용 가능.** `adapter.stop()` 실패 시
   세션은 닫되 중재자에 fault(`stop_unconfirmed:*`)를 걸어 새 실행·새
   세션을 전부 409로 거절한다. 복구는 명시적 — **이후 긴급 정지가 실제로
   확인되면**(성공한 stop) 푼다. 세션 없이 실패한 정지는 잠그지 않는다
   (유휴 어댑터 단절로 시스템 전체가 잠기면 안 된다).
4. **만료·감시·배선 완성.** heartbeat 만료를 단조 시계로 판정(벽시계를
   하루 앞뒤로 틀어도 TTL 불변, 테스트로 고정), 자체 watchdog 스레드(외부
   tick 의존 제거), `close()`가 lifespan 종료 절차에서 감시 중지+열린 세션
   정지. `SIMPLELAY_DEV_MODE` 기본 OFF, 어댑터는 **무조건 mock**(실물은
   `allow_real_adapter=True` 명시 필요 — H 주차에 연다), 대상 검증을
   레지스트리에 배선(등록 가전만 세션, 등록 버튼만 press). `/stop`과
   게이트웨이 물리 E-STOP이 개발자 세션도 함께 멈춘다(개발자 쪽 정지
   실패는 fault로 잠근 뒤 삼켜 일반 정지 응답을 막지 않는다).
