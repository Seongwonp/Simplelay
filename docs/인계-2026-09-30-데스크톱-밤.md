## 2. 하드웨어·배포 상태 (집 LAN, 지금은 전원 꺼 둠)

| 보드 | 주소 | 올라간 것 |
|---|---|---|
| RPi5 | 192.168.0.178 | 백엔드 컨테이너(host 네트워크, 기기 env 파일에 API 키·UART 링크·기상청 키·서울 좌표·로컬 가전), 새 키오스크 앱(1.1.0), 키오스크 감시 컨테이너 |
| RPi4 | 192.168.0.81 | 실행기 컨테이너(socat TCP 7000 ↔ 가상 시리얼, 모의 모션) |

- 기기 설정·비밀은 **RPi5의 env 파일에만** 있다(저장소·문서에 없음). 데스크톱에서 SSH로 읽는다.
- RPi5는 전원만 넣으면 백엔드·키오스크가 뜬다(재부팅으로 확인). **RPi4는 재부팅 뒤 `systemctl start docker`가 필요할 수 있다**(루트 읽기 전용).
- 옛 키오스크(8/31)는 읽기 전용 시스템 영역의 내장 앱이라 지울 수 없어 **새 앱 ID(…simplelay_kiosk)** 로 따로 설치했다. 키오스크 빌드는 데스크톱 도커의 플랫폼 빌드 컨테이너에서만 된다.
- 시험용 가전 2개가 RPi5에 등록돼 있다(시험용 전자레인지, Phone-MW). 내장 가전은 개발자 모드가 아니면 목록에 안 보이므로, 시험하려면 폰에서 가전을 추가하고 RPi5 env의 로컬 가전 목록에 id를 넣어야 한다.

**본가에서는 이 보드들에 붙을 수 없다.** 노트북 작업은 시뮬레이터로 한다:
`SIMPLELAY_THINQ_MODE=mock SIMPLELAY_PRESENCE_GATING=true python -m rpi.simulator_main --port 8765` → 폰 앱 주소 `http://10.0.2.2:8765`(안드로이드 에뮬레이터에서 PC) 또는 브라우저 `/kiosk/`(웹 빌드 필요).
시뮬레이터는 내장 가전이 목록에 보이고, API 키가 없으면 루프백만 허용된다(에뮬레이터는 PC 루프백으로 보이지 않을 수 있음 → `SIMPLELAY_ALLOW_UNAUTHENTICATED=1`은 개발용으로만).

## 3. 에뮬레이터에서 본 것 (UI 작업 참고)

- 폰: 새 설치 → 시작하기 → 홈("우리 집") → 설정 → 허브에서 주소·키 입력 → "허브 연결됨". 가전 추가 → "사진 없이 버튼판으로 등록" → 버튼 격자 눌러 이름 → 저장 → "등록했어요 · 기기 연결·버튼 위치 보정이 남았어요" → 홈에 카드 → 가전 상세 → 버튼 → "누를까요?" → 누르기 → 실행 상태 "모의 버튼 조작을 마쳤어요. 실제 조작은 하지 않았어요 · 성공 · 물리 버튼 · 실행기 보고만 받음".

- 키오스크 실기기: 창 관리자가 화면 가장자리에서 시작한 터치를 스와이프로 읽어 앱을 닫는다. 조작 요소는 가장자리에서 떨어뜨린다(테스트가 고정).

## 4. 노트북이 이어서 할 일 — UI·사용 편의 (사용자 결정, 10/5 전후)

사용자가 **앱 UI를 더 손보고 사용 편의성 조사를 더 하겠다**고 했다. 오늘 실제로 써 보며 걸린 곳:

1. **처음 연결이 어렵다.** 새로 설치하면 설정 → 허브에서 주소·API 키를 손으로 쳐야 한다. 조사 후보: 키오스크 화면 QR로 주소·키 전달(키를 화면에 띄우는 보안 고려), mDNS 자동 발견 실패 시 안내.
2. **실행이 끝난 뒤 할 게 뒤로 가기뿐이다.** 제안: 실행 중엔 하단 큰 **정지**, 끝나면 **확인**(시작한 곳으로), 실패·안전 정지면 **다시 시도**. "완료"라는 말은 가전 동작 완료로 읽혀 모의·미확인 원칙과 부딪히니 피한다. 폰 자동 복귀는 비추천(읽는 중 사라짐). **사용자는 오늘 보류했다 — 조사 뒤 결정.**
3. **가전 등록 후 다음 행동이 흐리다.** "기기 연결·버튼 위치 보정이 남았어요"에서 무엇을 어디서 하는지.
4. **어르신 사용성:** [사용자편의 체크리스트](사용자편의-가이드-체크리스트.md)(글자 200%·터치 영역·음성 안내·색만으로 말하지 않기)와 새 화면 대조.
5. 개편 때 에이전트가 남긴 질문: 폰·키오스크 강조색(**2026-10-01 골드로 결정·반영**: 다크 `#D9A356`, 라이트 `#6E4B0A`. 폰·키오스크 골든은 데스크톱에서 다시 만들어야 한다 — 노트북은 테스트 실행이 정책으로 막힘), 서버 주소·API 키를 설정 → 허브에 둘지 개발자 탭으로 옮길지, 키오스크에서 '다시 추천 안 함·30분 쉬기·동작 바꾸기'를 없앤 것, 연결 상태 "모름"에도 "!"를 띄울지.

## 5. 알려진 결함·미결

- **허브 화면이 저장된 설정을 불러오기 전에 열리면 API 키 칸이 비고, 그대로 저장하면 키가 지워질 수 있다**(에이전트 발견, 미수리, 재현 테스트부터).
  - **2026-10-01 노트북에서 수리:** 설정이 늦게 올라오면 손대지 않은 칸만 채우고, 저장은 사용자가 고친 칸만 한다(`hub_screen.dart`, `connection_section.dart`, 키 알림자 `ensureLoaded`). 재현 테스트 `app/test/screens/hub_api_key_preserve_test.dart` 3건을 추가했다. 노트북은 Windows 애플리케이션 제어 정책이 `flutter_tester.exe`를 막아 위젯 테스트를 돌리지 못했다(analyze만 0건 확인). **데스크톱에서 이 테스트와 기존 허브 테스트를 돌리고, 수정 전 코드에서 새 테스트가 실패하는지 확인할 것.**
- 에뮬레이터에서 "앱 정보 → 뒤로 가기 → 앱이 닫힘"을 한 번 봤으나 테스트로는 재현되지 않았다(두 세션이 동시에 에뮬레이터를 조작해 관찰이 오염됐을 수 있음). 다시 보이면 순서를 적어 둔다.
- 폰 설정의 옛 ThinQ 목록과 새 가전 칩이 이중으로 보인다.
- 폰 `pubspec.lock`은 데스크톱 Flutter 3.41.6 기준으로 바뀌었다(`geolocator` 추가). 노트북 Flutter 버전이 다르면 lock이 다시 흔들린다 — 기능과 무관한 lock 변경은 커밋하지 않는다.

## 7. 보드 점검 실행 방법(데스크톱)

2026-10-01 추가. [일반 예제](board-probe-example.json)를 **저장소 밖 로컬 JSON/TOML**로 복사해
각 보드의 대상·읽기 전용 최소 호출과 `app_account`를 채운다. 내부 설정과 원시 결과는 공개 저장소에 넣지 않는다.
데스크톱은 실행을 준비하는 곳이며 보드 기능은 해당 보드의 **실제 앱 계정·동일 실행 환경**에서 측정한다.
root로 얻은 성공은 앱 권한 성공이 아니다.

```powershell
# 데스크톱에서 CLI 동작을 확인할 때의 예시(보드 실측과 구분)
$env:SIMPLELAY_PROBE_CONFIG = "$env:USERPROFILE/simplelay-probe-local/checks.json"
$env:SIMPLELAY_PROBE_OUT = "$env:USERPROFILE/simplelay-probe-local/results"
.venv/Scripts/python.exe -m rpi.tools.board_probe
```

보드에서는 같은 환경 변수를 보드의 로컬 경로로 지정하고 앱의 Python으로
`python -m rpi.tools.board_probe`를 실행한다. 기본은 읽기 전용이며 UART는 DTR 재부팅을 피하려고 존재만 확인한다.
각 호출은 `safe_read_only: true`로 운영자가 부작용을 검토한 것만 넣는다.
결과 JSON은 계정·보드·OS·UTC/현지 시각·실제 서명·오류를 담은 **비공개 원시 기록**이다.
함께 생성되는 `.md`는 일반 명칭만 사용한 공유용 요약이다. [상세 실행법](../rpi/tools/board_probe/README.md).

모터·재시작 실험은 다른 실행 주체를 중지하고 장치 소유를 확보한 정비 시간에만 한다.
로컬 `active` 배열을 작성한 뒤 `--active --i-understand-active`를 함께 붙인다.
실행 관리 서버의 `/status`가 `running=false`여야 하며 조회 불가도 거절한다.
조그는 실측 `SIMPLELAY_MOTION_*` 설정과 이미 원점이 확인된 MCU가 필요하고, 최대 0.5mm 왕복 후 stop을 보낸다.
재연결/복귀 시간은 원시 기록의 `recovery_ms`로 남긴다. [Uno 검토·포팅 계획](arduino-uno-motion-review.md)을 먼저 확인한다.

서버에서 지난 기록을 보려면 `SIMPLELAY_PROBE_HISTORY_DIR`를 결과 디렉터리로 지정한다(미지정 시 비활성).
기존 개발자 모드·개발자 토큰 접근 제한을 통과한 `GET /dev/diagnostics/board-probe`에서
**“이전 점검 기록(측정 시각)”**으로만 반환한다. 기존 개발자 API의 모의 제어 전용 제한도 그대로 적용된다.
오래된 성공은 live readiness나 실행 허가를 바꾸지 않는다. 손상된 최신 파일에서 옛 성공으로 되돌아가지 않는다.
[가산점 증거 대장](가산점-증거-대장.md)의 비공개 로컬 사본에 최소 호출 성공과 실제 시연 사용을 나누어 기록한다.
