## 단계별 기록

**2단계**
- 새 테스트는 `hits.length == 1` → `hits.isNotEmpty` 변형에서 실패하고 원래 코드에서 통과한다.
- 로그 ab의 "이름 매칭을 느슨하게 한 변형에서 실패 확인" 주장은 다음과 같이 정정한다. 당시 변형(`isNotEmpty ? first : 첫 버튼`)은 이름이 없는 경우만 잡았고, 이름이 겹치는 경우는 이번에 처음 고정했다.

**3단계**
- **보호 테스트:** "전자레인지 규칙의 모든 버튼 이름이 내장 전자레인지 버튼판에 있다"(에어컨 규칙 제외). 수정 전 규칙에서 `{'우유 데워줘': ['시간 90초']}`로 실패하는 것을 확인했다.
- **옛 HTML 키오스크(`rpi/touchscreen/index.html`):** `/ui`로 아직 서비스되고 있어 지우지 않았다. 자리표시 문구와 버튼맵만 내장 전자레인지와 맞췄다('우유'·'자동조리' → '즉석밥'·'냉동식품', '라면' 추가).
- **테스트:** 문장은 '즉석밥 데워줘'로 바꿨다. 버튼이 3개에서 2개로 줄며 기대값이 두 곳 바뀌었다(노드 요청 타임아웃 48초 → 42초, 결과 버튼 3개 → 2개). '버튼맵에 없는 라벨'을 일부러 쓰는 케이스 2곳은 유지했다.
- **골든:** 두 앱 모두 규칙과 같은 실제 순서로 바꿨다.
  - 키오스크 실행 입력은 '1분'에서 '시작'·'즉석밥'으로 바꿨다. 로그 ab에서 버튼판이 보이게 하려고 '1분'으로 바꾼 것이 원래 불일치를 가리고 있었다.
  - 폰 골든의 '즉석밥 → 1분 → 시작' 예시도 '즉석밥 → 시작'으로 맞췄다.
  - 갱신한 이미지는 직접 확인했다.
- **문서:** README·아키텍처·폐루프 설계·추론 경계·프로토콜·데모 시나리오·개발현황의 예시를 바꿨다. 규칙·별칭 개수도 실제 값(10종·33종)으로 고쳤다. 원래도 7종·21종으로 오래된 값이었다. 지난 devlog와 결선로드맵의 완료 체크 항목은 당시 기록이라 그대로 뒀다.

**4단계**
- 주소는 불러온 뒤 항상 기본값이 들어가므로, `unconfigured`는 앱 시작 직후에만 나오는 상태다. 설정에서 주소를 지워도 기본값으로 바뀐다(리뷰에서도 확인).
- 확인 중에는 맨 위 경고를 띄우지 않는다. 가전 상태 줄은 '연결을 확인하고 있어요'로 나오고, 예비 연결이 꺼졌으면 아래에 조용히 알린다.
- 테스트 도우미 `FixedRpiConnection`은 `check()`를 막아 상태가 스스로 바뀌지 않게 한다. 새 테스트 3건은 수정 전 코드에서 실패했다.
- 홈 골든은 `unreachable`로 고정해 기존 화면을 그대로 비교한다.

**5단계**
- **호출 상한 0:** 인식 서비스로 보내지 않고 503을 돌려준다. 수정 전 코드와 "0을 기본값으로" 되돌린 변형에서 테스트 실패를 확인했다.
