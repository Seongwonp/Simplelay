## 2. SimpleLay 문구 기준

조사 결과를 SimpleLay에 맞게 고쳐 적용한다. 주 사용자는 고령층과 저시력 사용자다. 실물 증거가 없으면 성공이라고 말하지 않는다는 안전 계약을 지킨다. 다른 회사 문구를 그대로 가져오지 않고 원칙만 따른다.

1. **R1 해요체 하나로.** 화면·소리·화면 읽기 모두 해요체로 쓴다. 합쇼체('~습니다'·'~되었습니다')는 개발자 화면에만 남긴다. 무거운 높임('~시겠어요')은 쓰지 않는다.
2. **R2 상태는 동사로.** '~하는 중', '~중입니다'는 '~하고 있어요'로 쓴다. 명사로 끝내지 않는다('등록됨', '남음', '건너뜀' → '등록했어요', '남았어요', '건너뛰었어요'). 띠나 칩처럼 자리가 좁아 꼭 짧아야 하는 곳만 예외로 둔다. 그때도 같은 화면 안에서는 한 가지 방식만 쓴다. 상태 표시(칩·배지·결과 머리·상태 띠·짧은 상태 이름)는 아래 R12를 따른다.
3. **R3 번역투를 피한다.** '되어지다' 같은 이중 피동, '~의 ~의' 겹침, '것의', '해당', '진행', '수행', '시도', '~에 대해', '~를 통해', '~하게 돼요'를 피하고 그 자리에 무엇을 하는지 동사로 쓴다. 한자어 명사를 잇지 않는다('멈추기 실패', '실행 실패', '연결 확인 필요').
4. **R4 버튼은 짧은 동사.** '~하기'로 쓰고, 누르면 무엇이 일어나는지 이름만 보고 알 수 있어야 한다('허락' → '허락하기', '삭제' → '지우기'). 창을 닫기만 하는 버튼은 '닫기'다. '확인'은 뜻이 두 가지라 버튼 이름으로 쓰지 않는다(아래 R7).
5. **R5 오류 문구는 세 가지를 차례로.** 생긴 일 → 알면 이유 → 지금 할 일([화면 용어와 문구](용어와-화면문구.md)와 같다). '연결을 봐 주세요'만으로 끝내지 말고 무엇을 볼지 말한다(예: '폰과 본체가 같은 와이파이인지 보고 다시 눌러 주세요'). 이유를 모르면 짐작해서 쓰지 않는다.
6. **R6 미확인 결과는 '확인하지 못했어요'.** 눌렸는지, 켜졌는지, 정지가 전달됐는지 확인하지 못한 범위를 구체적으로 쓴다. 사용자 결정(2026-10-22)에 따른다. 반대로 모르는 것을 '했어요'·'실패했어요'로 바꾸지도 않는다. 가전 쪽 끝은 '가열 종료 감지'라고만 말하고 '조리 완료'로 쓰지 않는다. 응답이 온 것만으로 '멈춰요'·'눌렀어요'라고 단정하지 않는다('멈추라고 보내요'). 정지를 요청하는 말은 '정지'와 '멈추기'만 쓰고, 음성 듣기를 끝내는 일처럼 다른 동작에는 쓰지 않는다.
7. **R7 '확인'을 두 뜻으로 쓰지 않는다.** 본체가 확인한 결과는 '~한 걸 봤어요'·'~을 확인했어요'로 쓴다. 사용자가 할 일은 '~을 봐 주세요'로 쓴다. '확인 필요', '켜짐 확인'처럼 명사로 끝난 꼬리표는 결과인지 할 일인지 알 수 없다.
8. **R8 빈 화면은 이유와 다음 행동.** 왜 비었는지와 무엇을 하면 채워지는지를 한 줄씩 쓴다(예: '아직 등록한 가전이 없어요. 아래 \'가전 추가하기\'를 눌러 주세요').
9. **R9 같은 것은 같은 이름.** 폰·키오스크·소리·서버 문구가 같은 말을 쓴다. 이번에 하나로 정할 이름:

   | 정할 이름 | 지금 섞여 쓰이는 말 |
   |---|---|
   | 버튼판 | 조작부 |
   | 버튼 자리 맞추기 | 위치 맞추기 |
   | 새로 보기 | 새로고침·다시 받기·다시 불러오기 |
   | 지우기 | 삭제 |
   | 풀기 | 해제 |
   | 루틴 · 자동 실행 (2026-10-25 사용자 승인으로 바꿈 — 기능 이름은 이 둘만) | 자동으로 하기·자동 규칙·자동 루틴·저장된/저장한 동작 |
   | 와이파이 | Wi-Fi |
   | 말로 하기 | 음성 명령 |
   | 휴대폰(키오스크 쪽) | 폰 |
   | 지금 하기(제안 버튼) | 소리 안내의 '시작' |

   제안을 '알림'이라고 부르지 않는다. '보호자 알림'과 헷갈린다.
10. **R10 쉬운 말.** 모드, 세션, 카드, 탭, 코드, 학습, 경로, 초기화, 반영, 고대비, 파워, ms 같은 말은 풀어 쓴다. 다만 LG 앱이 가전 기능 이름으로 쓰는 말(예: '파워' 바람)은 처음 한 번 괄호에 함께 적어 LG 앱 화면과 맞춰 볼 수 있게 한다.
11. **R11 화면 읽기.** '1/3'은 '3장 중 1장'으로, '$n분 남음'은 '$n분 남았어요'로 소리 내어 자연스럽게 읽히게 쓴다.
12. **R12 줄인 말끝을 쓰지 않는다(사용자 결정 10/19).** '됐어요', '못 써요', '안 돼요'처럼 줄인 반말투 끝은 무례하게 읽힌다. 상태 표시(칩·배지·결과 머리·상태 띠·짧은 상태 이름)는 짧은 명사로 쓴다 — 완료 · 실패 · 멈춤 · 스스로 멈춤 · 확인 못 함 · 보냄 · 연결됨 · 끊김 · 준비 중 · 끝남. 설명 문장은 줄이지 않은 해요체로 쓴다('마쳤어요', '쓸 수 없어요', '준비되지 않았어요', '설정을 바꿨어요', '거절되었어요', '할 수 없어요'). 명사로 줄여도 증거 수준은 그대로다 — 초록 '완료'는 상태를 다시 읽거나 누름을 확인한 것에만 쓰고, '설정을 바꿨어요'도 상태를 확인한 곳에서만 쓴다(전 값을 모르면 '설정을 확인했어요'). '~해도 돼요'처럼 허락을 뜻하는 말은 줄인 끝이 아니라 그대로 둔다. 폰·키오스크·서버 문구가 같은 말을 쓴다.

## 3. 바꿀 문구 표

**표를 만든 방법:** `grep -n`으로 줄 번호를 확인했다(2026-10-19, `84dd837a` 기준).

**미리 알아 둘 것**
- **줄 번호가 밀린다.** 이후 커밋이 쌓이면 줄 번호가 달라지므로 실제로 고칠 때는 지금 문구로 다시 찾는다.
- **시험 기대값도 함께 고친다.** 문구를 바꾸면 시험의 기대 문자열과 골든 이미지도 바꿔야 한다.
- **우선순위:** **안전** = 정지·성공 의미에 닿는다 → **처음** = 처음 쓰는 사람이 보는 화면 → **일반**.
- **점검 범위:** 개발자 화면(`developer_*`)은 범위 밖이다. 남은 합쇼체 6건은 모두 개발자 화면에 있다.

## 4. '잠시 쉬기' → '방해 금지' (사용자 결정 10/19)

### 4-1. 정할 것

- **이름:** **방해 금지.** 갤럭시처럼 띄어 쓴다. iOS는 '방해금지'로 붙여 쓰지만 우리 사용자는 갤럭시가 많다고 보고 갤럭시 표기를 따른다.
- **설명:** 이름 아래에 늘 보이는 부제로 다음 문장을 쓴다.
  - '새 제안과 자동으로 하는 일을 잠시 쉬어요. 직접 누르기와 정지는 그대로 돼요.'
  - 업데이트 전에 켜 둔 방해 금지를 이어받은 경우(`suggestions_only`)에는 '새 제안만 쉬어요. 자동으로 하는 일은 그대로 해요'로 쓴다.
- **바꾸지 않는 것:** **조용한 시간**(매일 정한 시간대)은 이름을 그대로 둔다. 두 기능을 같은 칩이나 같은 문장에 묶지 않는다.
- **켜진 상태:** '쉬는 중' 대신 '방해 금지 켜짐'을 쓴다. 칩처럼 짧아야 하면 '방해 금지 · $n분 남았어요'로 쓴다.
- **끄는 버튼:** '그만 쉬기'·'쉬기 끝내기' 대신 **'방해 금지 끄기'**로 쓴다.
- **이력(주의):** 10/15에 '방해 금지'를 '잠시 쉬기'로 바꾼 적이 있다. 사람들이 '방해 금지'를 "제안만 멈춘다"는 뜻으로 오해했기 때문이다(근거: 키오스크 `dnd_overlay.dart` 머리 주석, `idle_view.dart:1084` 주석). 이번에 이름을 되돌리므로, **범위 문장(부제)을 빼거나 줄임표로 자르지 않는 것**을 조건으로 둔다. 실패널에서 부제가 잘리지 않는지 확인한다.
- **바꾸는 범위:** 서버 키(`suggestion_pause`)와 API 이름(`/dnd`)은 그대로 둔다. 화면에 보이는 말만 바꾼다.
- **다른 기능의 '쉬기'는 바꾸지 않는다:**
  - '집 비우는 날'의 안부 확인 쉬기: `care_events_screen.dart:83`, `notification_section.dart:239`
  - 제안 하나를 30분 미루기: `suggestion_screen.dart:86` — 3-5 표처럼 '30분 동안 묻지 않기'로 바꾼다
  - 서버 주석의 '쉬는 중'(누름 장치가 쉬고 있다는 뜻)
