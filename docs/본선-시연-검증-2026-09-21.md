# 본선 시연 및 검증 — 2026-09-21

## 검증한 범위

백엔드 전체 **1,377 테스트 통과**, 의존성 deprecation 경고 2건. 이번 추가는 피드백 회귀 20건과 API를 연결한 오프라인 리허설 1건이다. 리허설은 합성 사용 이력·가상 시계·테스트 컨트롤러를 사용한다. 테스트 컨트롤러의 REAL 표기는 분기 검사용이며 물리 구동 성공률이나 실제 생활 학습 실험의 증거가 아니다.

RPi5에서 화면을 띄우는 것은 사용자가 이미 성공했다. 이번에는 실제 패널의 터치, 카메라 프로세스, 센서·모터 통합, 앱과 키오스크 동시 조작을 실물로 시험하지 않았다. 이번 변경은 Python과 문서이며 Flutter 검증을 반복하지 않았다.

## 발표 흐름 — 약 3~5분

| 순서 | 보여줄 행동 | 설명과 확인할 증거 |
| --- | --- | --- |
| 1 | 앱 또는 키오스크 설정의 생활 습관 알아가기 | 최근 28일 중 서로 다른 3일의 직접 사용 근거를 설명한다. 실제 기록이 없다면 압축 리플레이임을 밝힌다. |
| 2 | 시간대에 맞는 제안과 이유 | 제안 생성만으로 실행하지 않는다. 왜 이 가전·이 동작을 권했는지 설명한다. |
| 3 | 이번에는 건너뛰기 | 같은 시간대에 재촉하지 않는다. 영구 숨김과 이번 건너뛰기는 다른 선택이다. |
| 4 | 다음 시간대의 제안 승인 | 접수와 완료를 구분한다. 같은 job_id의 실행 상태를 확인하며 중복 승인으로 추가 실행하지 않는다. |
| 5 | 직접 조작을 완료한 뒤 확인 | 같은 일을 다시 권하지 않는다. 이름 없는 버튼 조작은 한 요청의 전체 순서가 알려진 동작과 일치하는 경우만 인정한다. |
| 6 | 부재 또는 환경 변화 | 이유가 사라지면 제안을 철회한다. 사용자 거절로 기록하지 않는다. 부재 시연은 공간 감지 게이트가 연결된 구성에서 한다. |
| 7 | 이벤트 기록으로 설명 | 사용자 선택, 시스템 철회, 시연 출처와 승인 작업 번호를 연결해 보여준다. |

실제 학습 기준은 하루 안에 반복 클릭한다고 채워지지 않는다. 자동 테스트는 시간을 이동시키고 합성 이력을 격리된 fixture에 넣는다. 시연을 위해 운영 DB에 합성 기록을 실제 사용으로 삽입하지 않는다. `/demo/environment`의 값은 화면 이유에 ‘시연 데이터’로 표시하고 이벤트 origin과 승인 사용 출처도 demo로 남긴다. 시연 환경의 건너뛰기 쿨다운은 실제 환경 제안을 억제하지 않는다.

`/demo/suggest`는 명시적인 제안 생성 트리거다. 이 경로 자체가 모터 컨트롤러를 mock으로 바꾸지는 않는다. 오프라인 자동 리허설은 테스트 컨트롤러를 주입하므로 실제 모터를 호출하지 않는다.

## 기록 조회와 해석

기존 API 키 인증으로 `GET /suggestions/events?limit=100`을 조회한다. limit은 1~200이며 최신순으로 반환한다. 읽기만으로 추천을 생성하거나 만료 처리하지 않는다. 화면에 기록 조회 UI를 새로 추가한 것은 아니다.

| action / reason | 의미 |
| --- | --- |
| created / habit_pattern, environment_condition, explicit_demo | 후보 생성 근거. 실제 화면 노출·열람을 보장하는 이벤트는 아니다. 출처는 origin도 함께 확인한다. |
| dismissed / user_skip | 이번 건너뛰기 |
| muted / user_mute | 해당 루틴 숨김 |
| approval_requested / user_approval | 사용자의 승인 요청 |
| submitted / job_accepted | 비동기 실행 접수. 성공 완료가 아니다. job_id로 `/status` 및 실행 이력을 대조한다. |
| execution_returned / controller_returned | 동기 컨트롤러 반환. execution_status를 확인하며 가전 전체 운전 완료로 해석하지 않는다. |
| approval_failed / executor_error 또는 구체적 철회 사유 | 승인 처리 실패. 원시 예외 문자열은 이벤트에 저장하지 않는다. |
| expired / validity_ended | 유효기간 경과. 싫어요나 명시적 거절이 아니다. |
| withdrawn / already_completed | 직접 조작으로 이미 완료 |
| withdrawn / presence_absent | 연결된 공간 게이트에서 명시적 부재 |
| withdrawn / environment_unavailable | 유효한 환경 후보가 없음. 조건 해소·센서 문제·오래된 스냅샷 중 하나로 단정하지 않는다. |
| withdrawn / environment_changed | 목적·대상 가전·시연 출처 변경 |
| withdrawn / routine_muted, appliance_removed | 루틴 숨김 또는 대상 가전 삭제 |

기록은 서버가 상태 변화를 확인한 시점이다. 센서 변화 순간이나 사용자별 화면 응답 시간을 측정한 로그가 아니다. 반복 조회나 같은 카드의 환경 문구 갱신은 새 생성 이벤트를 만들지 않는다.

메모리와 DB 모두 최근 **2,000건**만 유지하므로 평생 누적 통계로 사용하지 않는다. `persistent`는 DB 저장 연결 여부이고, `persistence_ok`는 현재 프로세스에서 저장 실패를 관측하지 않았는지를 나타낸다. 한 번 실패하면 해당 프로세스에서는 false를 유지한다. 저장 실패 시 메모리 기록과 사용자 선택은 유지하되 재시작 후 누락분 복원은 보장하지 않는다. 기록 저장 실패로 이미 접수한 실행을 실패 처리하지 않는다.

이 기록만으로 선호도 자동 학습이나 사용자별 식별을 구현한 것은 아니다. 현재 적응은 사용 패턴, 건너뛰기 쿨다운, 루틴 숨김, 완료·환경 상태에 따른 규칙이다. 승인률을 산출하려면 생성과 노출의 차이, 중도 철회, 시연 데이터 제외 정책부터 정해야 한다.

## 자동 리허설 재실행

테스트 의존성이 설치된 저장소 루트에서:

```sh
python -m pytest -q rpi/tests/test_final_demo_flow.py rpi/tests/test_suggestion_feedback.py
```

현재 Windows 작업 환경은 dbus-fast 소스 경로를 추가해 실행했다:

```powershell
$env:PYTHONPATH=(Resolve-Path '.venv/vendor/dbus_fast-2.46.4/src').Path
.venv\Scripts\python.exe -m pytest -q rpi/tests/test_final_demo_flow.py rpi/tests/test_suggestion_feedback.py
```

실물 리허설에서는 앱·키오스크 동시 승인, 연결 끊김과 재접속, 서버 재시작, 큰 글씨와 터치, 작업 정지·실패를 추가로 확인한다. 기존 계획의 대표 흐름 20회 연속 기준은 아직 달성한 것으로 보고하지 않는다. 실제 센서·모터 시험 결과는 이 소프트웨어 검증과 별도로 기록한다.
