# UI 확정 — 2026-09-30

폰 앱과 키오스크의 제품형 화면 구성을 사용자와 확정한 기준 문서다. 앞으로 Flutter 구현은 이 문서를 따른다.
화면 시안 원본은 [ui-prototype-2026-09-30.html](design/ui-prototype-2026-09-30.html)이다. 브라우저로 열면 폰 탭 이동과 키오스크 상태 전환을 직접 눌러 볼 수 있다.
시안에 나오는 가전 이름과 기록은 예시다.

색·글자 크기 토큰은 기존 [디자인 시스템](design-system.md)을 그대로 쓴다. 기본은 어두운 배경에 골드 강조색이고, 키오스크는 항상 어두운 화면이다.
구현 계획과 우선순위는 [본선 실행 계획](본선-실행계획-2026-09-30.md) §3-6·§3-8을 본다.

## 1. 공통 원칙

1. **메뉴는 사용자가 만든다.** "즉석밥·우유" 같은 고정 명령 버튼은 두지 않는다. 사진 위에서 녹화한 내 루틴과 이력에서 나온 제안만 보여 준다.
2. **제안은 한 번에 하나만 보여 준다.** 홈과 키오스크 모두 제안 카드는 한 장이다.
3. **승인 없이 누르지 않는다.** 가전 카드를 눌러도 상세만 열리고, 실행은 항상 "시작" 또는 "실행하기"를 거친다.
4. **색만으로 상태를 말하지 않는다.**
   - 회색은 쉬는 중이다.
   - 동작 중은 강조색에 남은 시간 숫자를 붙인다(필요하면 진행 링을 더한다).
   - 확인 필요는 노란색에 느린 깜빡임 3번을 준다. 동작 줄이기 설정이면 깜빡이지 않는다.
   - 오류와 정지는 빨간색과 함께 문구로도 적는다.
5. **사용자 말로 쓴다.** 부품 이름("콘센트 모듈", "노드") 대신 사용자가 아는 이름("플러그", "허브")을 쓰고, 무엇을 못 하게 되는지를 함께 적는다.
   - 예: "플러그 연결이 약해요 · 끝났다는 알림이 늦을 수 있어요"
6. **데모 흔적을 숨긴다.** 개발자 기능, 실패 주입, 시연 제안, 코드에 미리 넣은 내장 가전은 개발자 모드에서만 보인다.

## 2. 폰 앱

**탭은 네 개다: 홈 · 루틴 · 기록 · 설정.**
서버 `/status`의 `developer_mode`가 참일 때만 다섯 번째 탭 "개발자"가 설정 옆에 나타난다. 이 값은 `SIMPLELAY_DEV_MODE`로 켠다.

| 화면 | 구성 |
|---|---|
| 홈 | 제목 "우리 집"과 허브 연결 칩, 제안 카드 한 장("실행하기/나중에", 근거 한 줄), 가전 카드 2열, 마지막 칸 "가전 추가" |
| 가전 카드 | 아이콘, 이름, 방. 동작 중이면 강조색 아이콘에 남은 시간과 진행 막대가 붙는다. ThinQ 가전은 작은 배지를 단다. 누르면 가전 상세가 열린다 |
| 가전 상세 | 등록 때 찍은 조작부 사진 위에 버튼 표시(정지 버튼은 빨강, 쉬는 자리는 점선). 사진 속 버튼을 누르면 허브가 대신 누른다(승인 흐름을 거친다). 내 루틴 목록과 "루틴 녹화", 오늘 사용 기록 |
| 루틴 녹화 | 사진 속 버튼을 순서대로 짚으면 번호 핀이 찍히고, 아래에 순서 칩이 쌓인다. 녹화 중에는 실제로 누르지 않는다 |
| 루틴 탭 | 위에 "다음 실행"(시각·루틴 이름·실행 방식), "내 루틴/추천" 구분, 루틴 목록, "새 루틴" 버튼 |
| 루틴 편집 | 문장형 카드 세 줄(언제, 무엇을, 그다음)과 "단계 추가". 실행 방식은 "승인 후 실행/알림만" 중 고른다. 여러 가전을 잇는 시나리오도 같은 편집기로 만든다 |
| 기록 탭 | 날짜별 타임라인. 한 줄에 시각, 결과 점(완료·동작 중·정지), 제목, 경로와 확인 근거 |
| 설정 탭 | 가전 추가, 허브, LG ThinQ 연결, 음성으로 멈추기(동작 중에만 들음), 보호자 알림, 글자 크기 |
| 가전 추가 | 5단계: ① 사진 ② 프레임 모서리 4점 ③ 버튼 짚고 이름 붙이기 ④ 정지 버튼과 쉬는 자리 ⑤ 확인 주행. 위에 단계 막대를 두고 "이전/다음"으로 이동한다 |

## 3. 키오스크 (15.8형 1920×1080, 항상 어두운 화면)

상태는 네 가지다: **평소 → 다가오면 → 동작 중 → 내 가전.**

### 3-1. 평소

- **위 줄:** 왼쪽에 날짜를 둔다. 오른쪽에는 연결 상태 아이콘 세 개(와이파이·누름 장치·플러그)를 둔다.
  - 정상이면 회색 아이콘만 보인다.
  - 문제가 생기면 그 아이콘이 노란색이 되고 오른쪽 위에 "!" 배지가 붙는다.
  - 배지를 누르면 모달이 뜬다. 모달에는 제목, 무엇이 안 되는지, 해결 방법 목록, "다시 연결하기/닫기"가 있다.
- **가운데 왼쪽:** 큰 시계와 실내 온도·습도.
- **가운데 오른쪽:** 인사말("좋은 아침이에요."), 날씨 한 줄 안내 카드(예: "오후 3시부터 비 예보가 있어요. 우산 챙기세요."), 시간대 예보 4칸. 비 오는 칸은 강조색으로 표시한다.
  - 안내는 한 번에 하나만 보여 준다. 우선순위는 확인이 필요한 가전 → 날씨 → 인사말이다.
  - 인터넷이 없거나 예보가 오래됐으면 인사말만 보여 준다.
- **아래:** 앱에서 등록한 가전 아이콘 줄.
  - 한 번에 **4개**만 보이고, 화살표·손가락 밀기로 4개씩 넘긴다.
  - 끝에 닿은 쪽 화살표는 숨긴다(자리는 유지).
  - 순서는 확인 필요 → 동작 중 → 나머지다. 뒤쪽 가전이 동작을 시작하면 맨 앞으로 올라온다. 끝에서 처음으로 돌아가는 반복은 쓰지 않는다.
  - 등록된 가전이 없으면 "앱에서 가전을 추가해 주세요"를 보여 준다.

### 3-2. 다가오면

제안 카드 한 장이 크게 뜬다. **레이더 하드웨어는 없다(2026-10-05 기준).** 지금 이 상태로 넘어가는 계기는 서버가 만든 제안이 키오스크 폴링에 잡힐 때(시연에서는 `POST /demo/suggest`로 강제 생성)와 '내 가전'에서 루틴을 누를 때다. 존재 보고(`POST /presence`)는 `SIMPLELAY_PRESENCE_GATING=true`일 때 부재 중 제안을 보류하는 데만 쓰이고(기본 꺼짐), 화면을 깨우지 않는다.
- 카드에는 가전, 루틴 이름, 근거 한 줄(예시 문구 — 시연 데이터 기준이며 실제 사용 이력은 아직 없다: "최근 2주, 평일 아침 7시대에 5번"), 누를 순서가 들어간다.
- 버튼은 "시작"과 "다음에" 두 개뿐이다.

### 3-3. 동작 중

- **왼쪽:** 가전 이름, 남은 시간(크게, 전력으로 추정), 진행 막대, 확인 근거 세 줄(버튼 눌림 확인, 가열 전력, 정지 버튼 위 대기 중).
- **오른쪽:** 조작부 사진에 정지 버튼 위 대기 위치를 표시하고, 그 아래 화면 폭의 큰 빨간 "정지" 버튼을 둔다.
- 끝나면 "보관 위치로 이동했어요"를 짧게 보여 준 뒤 평소 화면으로 돌아간다.

### 3-4. 내 가전

조작부 사진 위 버튼 표시(홈의 가전 상세와 같은 규칙)와 내 루틴 목록을 둔다. 새 루틴은 폰 앱에서 녹화한다는 안내를 붙인다.
시나리오 진행 화면은 키오스크에 넣지 않고 폰 앱에 둔다.
