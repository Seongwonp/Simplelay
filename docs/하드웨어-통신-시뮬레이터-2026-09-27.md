# 하드웨어 통신 시뮬레이터 — 2026-09-27

하드웨어 수령 전 SW 실행계획 S4의 첫 구현이다. 실제 `ActClient → ActExecutor → ClosedLoopController`를 메모리 스트림으로 연결한다. 모션·L1 검증만 모의 어댑터를 사용하며 기존 실행 코드와 통신 형식은 변경하지 않았다. Claude의 독립 명령 계약 작업과 분리된 범위다.

## 실행

저장소 루트의 PowerShell에서:

```powershell
.venv\Scripts\python.exe -m rpi4.simulator --scenario all
.venv\Scripts\python.exe -m rpi4.simulator --scenario stop
.venv\Scripts\python.exe -m rpi4.simulator --scenario lost_response
```

Python 환경이 준비된 다른 OS에서는 `python -m rpi4.simulator`로 동일하게 실행한다. GPIO·시리얼 장치·센서·계정·네트워크가 필요 없다. API 서버와 사용자 이력 DB를 열지 않는다. 환경변수로 실제 어댑터를 활성화하지 않는다.

표준 출력은 JSON이며 Windows 리다이렉션을 위해 한글을 JSON 유니코드 이스케이프로 출력한다. 경고 로그는 표준 오류로 나간다. 전체 기대 조건 충족 시 종료 코드 0, 조건 불일치 또는 실행 예외 시 비정상 종료한다. `passed`는 **해당 장애 시나리오 검증 통과**이지 가전 동작 성공이 아니다.

## 재현 범위

| 시나리오 | 확인하는 내용 |
| --- | --- |
| success | 두 버튼 실행과 동일 sequence_id 응답 |
| retry | 첫 버튼 검증 두 번 실패 후 성공, 총 네 번 누름 |
| press_failure | L1 재시도 소진 후 로컬 안전 정지, 두 번째 버튼 미실행 |
| stop | 첫 버튼 이후 정지 요청을 실제 실행기가 소비한 뒤 진행, 두 번째 버튼 미실행 |
| lost_response | 실행 완료 응답 폐기 → 허브 시간 초과·abort 송신, execute 자동 재전송 없음 |
| fragmented | 양방향 메시지를 한 바이트씩 다른 이벤트 루프 차례에 전달, 한글 바이트 분할 포함 |
| noise | 잘못된 JSON·알 수 없는 메시지·무관한 sequence_id 응답을 정상 결과로 사용하지 않음 |

시나리오마다 독립 상태를 만든다. `stop`은 임의 sleep 대신 이벤트로 순서를 고정한다. 대기 시간은 테스트 상한이며 실제 통신 지연이나 모터 정지 시간의 측정값이 아니다.

## 결과를 읽는 법과 발견한 한계

- `hub`: 기존 통신으로 허브가 실제 수신한 결과. 응답 유실 시 `timeout_result_unknown`, 결과는 null이다. 시뮬레이터 보고용 이름이며 기존 API 상태를 바꾼 것은 아니다.
- `act_local`: 모의 실행기 내부에서 관측한 결과·누름 목록·안전 정지 사유. 허브가 받은 정보로 간주하면 안 된다.
- `wire`: 송신 프레임 및 의도적으로 버린 응답. 현재 프레임은 success/retry만 전달하므로 상세 정지 사유·L1/L2/L3 근거가 허브까지 보존되지 않는다.
- L2/L3 센서는 연결하지 않았다. `operation_confirmed=false`는 확인하지 않았다는 뜻이며 실제 가전이 동작하지 않았다는 판정이 아니다.

현재 UART 계약에서는 안전 정지와 다른 실패가 동일한 `success=false`로 보인다. 향후 결과 계약과 앱 표시를 연결할 때 해결해야 하며 이번에 프로토콜을 임의 확장하지 않았다. 응답 유실 이후 새 명령 차단·재시작 복구까지 구현됐다고 해석하면 안 된다.

## 검증과 다음 범위

새 테스트: `rpi4/tests/test_simulator.py` 11건. 통신 양쪽·컨트롤러 관련 80건 통과, 이후 최종 코드 기준 백엔드 전체 **1,388건 통과**(기존 의존성 사용 중단 예고 2건). CLI 전체 7개 시나리오도 종료 코드 0으로 확인했다. 앱·키오스크 테스트는 이번에 실행하지 않았다.

아직 포함하지 않은 것: 앱/키오스크에서 시뮬레이터 선택, 독립 프로세스·실제 UART 연결, 물리 정지·모터·센서 검증, L2/L3 장애 주입, 실제 단절·재연결·재시작, 늦은 응답의 다음 요청 경합, 승인 중복 처리와 ThinQ 모의 기기. 기존 앱 내 시연 기능과 이 통신 시뮬레이터도 아직 직접 연결되지 않았다.

다음에는 응답 유실·재연결 후 미해결 명령 정책을 계약 담당과 맞추고, 서버에서 모의 실행기를 명시적으로 선택하는 연결을 추가한다. 합성 결과는 계속 MOCK으로 유지하고 자연 습관 학습에 편입하지 않는다.
