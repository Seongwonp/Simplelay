# 보안 — 장치별 접근표 (2026-10-14)

[NIST IR 8259A](https://csrc.nist.gov/pubs/ir/8259/a/final)의 기기 역량(식별·설정·데이터 보호·인터페이스 접근 제한·업데이트)을 기준으로 **장치마다 한 줄**만 적는다. 표가 있다고 보안 인증을 받은 것은 아니다. 근거와 시험은 [보안 수리 기록](devlog/devlog_2026-10-14-security-fix.md).

| 장치 | 누가 접근하나 | 무엇을 바꾸나 | 키가 없으면 | 업데이트 방법 |
|---|---|---|---|---|
| RPi5 백엔드(HTTP 8000, 호스트 망) | 폰(LAN, `X-API-Key`) · 같은 보드 키오스크(루프백) · 운영 노트북(키) | 가전 실행·정지, 루틴·자동 실행 규칙, 조용한 시간, 가전 등록, 개발자 조작(`/dev/*`, 별도 토큰) | LAN 요청 401(`SIMPLELAY_ALLOW_UNAUTHENTICATED=1`은 개발용). 루프백은 면제하되 다른 사이트 표시(`Origin` 불일치·`null`, `Sec-Fetch-Site` cross-site·same-site)는 403. 공개 `/health`는 생존·버전만. `SIMPLELAY_ACT_MODE=uart`인데 링크 키가 없으면 기동 거절 | 개발 PC에서 이미지 빌드 → 보드에 올려 `deploy/run_backend.sh`. 같은 커밋으로 4종 배포(인계 §8) |
| RPi5 키오스크(15.8형 패널 앱) | 화면 앞 사람 | 백엔드와 같은 조작(정지 포함) — 루프백으로 부른다 | 키를 쓰지 않는다. 네이티브 앱(Dart HTTP)은 `Origin`·`Sec-Fetch-Site`를 보내지 않아 루프백 면제(신뢰 경계: 보드 안 프로세스) | 개발 PC에서 빌드한 앱 패키지를 보드에 설치(빌드 SHA 기록) |
| RPi4 실행기(TCP 7000 → socat 단일 연결) | RPi5 백엔드만(짝 키) | 버튼 누름 실행·정지, 개발자 실물 조작, 콘센트 릴레이 | **시작 거절**(2026-10-14). 서명 없는·MAC 틀린·재전송 프레임은 버린다. 무인증은 `SIMPLELAY_LINK_AUTH=off_for_mock` + 모의 구성에서만. 선점(먼저 붙은 다른 기기)은 `SIMPLELAY_LINK_ALLOW_FROM`으로 완화(실기기 미검증) | 백엔드와 같은 이미지 + `deploy/run_act.sh` |
| 폰 앱 | 사용자 | 위 RPi5 API를 부른다 | 허브 연결 확인(`/status`)이 401 — 키 입력 안내. 통신은 **HTTP 평문**(키가 망에서 보인다 — 전용 망으로 완화, 남은 위험) | APK 설치(빌드 SHA 기록) |
| ESP32 모션(CoreXY) | RPi4 USB 시리얼만 | 축 이동·누름·정지 | 망에 연결되지 않는다(USB 선을 만질 수 있는 사람만) | USB로 펌웨어 올리기(PlatformIO) |
| ESP32 콘센트 모듈 | RPi4 USB 시리얼만 | 릴레이·전력 측정·비상정지 래치 | 망에 연결되지 않는다. 비상정지 래치는 사람이 확인해야 풀린다 | USB로 펌웨어 올리기 |

**이번 범위 밖(다음 점검 목록, [OWASP MASVS](https://mas.owasp.org/MASVS/)):** 폰의 API 키 저장 위치·백업 포함 여부·로그 노출·연결 해제 뒤 자격정보 처리. 비밀정보 전체 이력·의존성 취약점·실제 망 설정 점검도 범위 밖이다.
