# 하드웨어 복귀 날 절차 — ESP32 모션 보드가 돌아오는 날 (2026-10-19 작성)

HW 담당이 모터·레일을 다시 고정하고(잘 움직임) 솔레노이드를 다는 중이다. ESP32 모션 보드가 돌아오면 이 문서를 **위에서 아래로** 따라간다.
지금 RPi4는 모의 모션이다(`SIMPLELAY_MOTION_MODE=mock`, `SIMPLELAY_MOTION_PORT` 줄 주석, 백업 `env.bak-20261016-no-esp32` — [10/16 devlog](devlog/devlog_2026-10-16-desktop-home.md)).

**규칙**

- 각 단계에서 이상하면 **멈추고 기록한 뒤** 다음으로 넘어가지 않는다. 앞 단계를 건너뛰고 뒤 단계(누름·리허설·촬영)를 하지 않는다.
- 사람 둘: 한 사람은 **전원 차단 담당**(모터·솔레노이드 전원 스위치에 손), 한 사람은 기록 담당. 소프트웨어 정지가 안 먹으면 응답을 기다리지 않고 끊는다.
- 실제 가전 대신 **골판지 더미 패널**에서 시작하고, 전자레인지는 5단계 이후 사람 입회로만.
- 이 문서의 수치 칸 중 **실측하지 않은 값은 모두 `측정 필요`** 다. 설계값(펌웨어 `config.h`, 추측 상수)을 측정값으로 옮겨 적지 않는다.
- 원본 기록(시리얼 로그·엔코더·영상)은 저장소 밖에 두고, 문서에는 파일 이름만 적는다. 기기 주소·키·개인 PC 경로를 문서·커밋에 넣지 않는다.
- 기준 문서: [모션 펌웨어 README](../firmware-motion-corexy/README.md) · [솔레노이드 안전 전달표](솔레노이드-안전-전달표-2026-10-16.md) · [PS-1](안전계약-적용-보고-2026-10-15.md) §3 · [실측 기록표](실측-기록표.md) · [운영 런북](결선-운영-런북.md) · [시연 계획 v4](본선-시연-계획-v4.md) · [실물 장면 촬영 대본](촬영-대본-실물-장면.md).

## 1. 펌웨어 올리기 (RPi4에서 esptool)

10/14와 같은 방식이다 — **USB를 옮기지 않고 RPi4에서 올린다.** 빌드는 PC에서 하고([펌웨어 README '빌드'](../firmware-motion-corexy/README.md)), 결과 바이너리만 RPi4로 옮긴다.

| 빌드 | 쓰는 때 | 배너 `fw` |
|---|---|---|
| `esp32dev_bringup` | §0-1·§1-2(방향·부호), 솔레노이드 `T` 단발 | `firmware-motion-corexy-bringup` |
| `esp32dev` | §2부터 전부(시연 보드) | `firmware-motion-corexy` |
| `esp32dev_benchhome` | **쓰지 않는다** — `home`이 움직이지 않는 시험대 전용 | `firmware-motion-corexy-benchhome` |

1. 올리기 전 커밋 SHA를 적는다(`git rev-parse --short HEAD`). 바이너리는 그 커밋에서 빌드한다.
2. RPi4에서 실행기를 멈춘다 — 포트를 실행기가 잡고 있으면 올릴 수 없다: `docker stop simplelay-act`.
   (보드를 끌 때는 컨테이너를 멈추지 않는다는 규칙과 별개다. 이 단계가 끝나면 §2에서 다시 세운다.)
3. 장치 이름을 확인한다: `ls -l /dev/serial/by-id/`.
4. esptool로 올린다(업로드 속도는 `platformio.ini`와 같이 115200 — CH340 보드는 고속에서 실패했다):
   `esptool.py --chip esp32 --port /dev/serial/by-id/<장치> --baud 115200 write_flash <주소> <바이너리>`
   — 앱 영역만 올릴지, 부트로더·파티션까지 올릴지와 각 주소는 10/14에 쓴 명령과 같은지 **확인 필요**(그날 기록은 저장소 밖 작업 기록).
5. 리셋 뒤 배너를 본다. 시리얼 모니터 대신 같은 이미지로 일회용 컨테이너를 띄워 jog 도구를 쓴다
   (`docker run --rm -it --device <장치> simplelay-backend python -m rpi.tools.jog --port <장치> --baud 115200 -c status`; 실행기는 멈춘 상태).

| 날짜 | 커밋 SHA | 빌드 | `fw` | `protocol` | `z_mode` | `z_on_max_ms` | 판정 |
|---|---|---|---|---|---|---|---|
| | | | 기대: 위 표 | 기대: `line-json/v0` | 기대: `solenoid` | 기대: 800 | |

### 1-2. 방향·부호 (bring-up 빌드, 모터를 다시 달았으므로 필수)

[펌웨어 README '처음 켤 때 순서'](../firmware-motion-corexy/README.md) 1~5를 그대로 한다. 요점만:

- `M 0.3 0 500` → A 계수 **증가**, `M 0 0.3 500` → B 계수 증가. 아니면 `ENC_x_INVERT`.
- 벨트를 건 뒤 `M 0.3 0.3 300` → 캐리지 **+X(오른쪽)**, `M 0.3 -0.3 300` → **+Y**. 반대면 `MOTOR_x_INVERT`와 `ENC_x_INVERT`를 **같이** 바꾼다(하나만 바꾸면 폭주).
- 가운데에서 `Z` → `G 20 0` → `G 20 20` → `G 0 0`. 진동하면 `K`로 게인 조정 → 정한 값은 `config.h`에 옮겨 적는다(**펌웨어 변경이 생기면 커밋하고 시연 빌드를 다시 올린다**).
- 끝나면 시연 빌드(`esp32dev`)를 다시 올리고 배너를 다시 확인한다.

## 2. RPi4 env 되돌리기와 재시작

env는 `/mnt/rawdata/simplelay-act/env`(`deploy/run_act.sh`의 `DATA_DIR/env`).

1. **백업 먼저** — 이름 규칙 `env.bak-날짜-이유`: `cp env env.bak-YYYYMMDD-esp32-return`.
2. 두 줄을 되돌린다:
   - `SIMPLELAY_MOTION_MODE=mock` → `SIMPLELAY_MOTION_MODE=serial`
   - `#ESP32없음-20261016#SIMPLELAY_MOTION_PORT=…` → 앞의 주석 표시를 지운다. 값은 `/dev/serial/by-id/…` 경로를 쓴다(USB 재열거 뒤 다시 열기 — `run_act.sh`가 by-id면 `/dev`를 잇는다).
3. 기구 값이 [펌웨어 README 'RPi4 설정과 맞출 값'](../firmware-motion-corexy/README.md) 표와 같은지 본다(`R_OUT`·`DECODING_MULTIPLIER`·`PULLEY_TEETH`·`BELT_PITCH_MM`·`A_SIGN`·`B_SIGN`·`X/Y_MIN/MAX_MM`·`PRESS_MODE=duration`·`PRESS_DRIVE_MS`·`HOME_TIMEOUT_S` > 70·`BAUD=115200`). 다르면 `move`가 `bad_args`로 거절된다.
4. `SIMPLELAY_MOTION_AUTO_HOME` 값을 확인해 적는다(아래 §3 원점 규칙).
5. 다시 세운다: `sh /mnt/rawdata/run_act.sh`. "장치가 없어 실행기를 세우지 않았어요"가 나오면 USB·경로를 고친다. `docker logs simplelay-act`로 시작 거절 이유(링크 키 등)를 본다.
6. RPi5에서 키를 넣어 `GET /health/detail`을 본다:

| 확인 | 기대 | 결과 |
|---|---|---|
| `act_mode` | `uart`(RPi4 실연결) — `local`이면 RPi5가 모의 | |
| `actuator_ready` | **원점 전에는 `false`가 정상**(아래 규칙) → §3 원점 뒤 `true` | |
| 폰·키오스크 화면 | 실물 실행에 '연습' 띠·배지 없음 | |
| 실행기 로그 | 모션 포트 열림, `ready` 수신 | |

**원점 규칙(10/19, 커밋 `d321218c`):** 실행기 시작·모션 포트 재연결 뒤에는 모션 보드가 `homed`라고 보고해도 **믿지 않는다** — 성공한 `home`을 한 번 해야 준비된다.
그사이 손으로 캐리지를 옮겼을 수 있기 때문이다. 그래서 재시작마다 §3의 원점 잡기를 다시 한다.

## 3. 원점과 소프트 리밋

1. 전원 차단 담당이 스위치에 손을 올린다. 캐리지를 가운데쯤에 둔다.
2. 원점 잡기 — 둘 중 하나:
   - 폰 **개발자 도구 '원점'**(`SIMPLELAY_DEV_MODE`·`SIMPLELAY_DEV_REAL_MOTION`이 켜져 있고 RPi4가 실물 링크일 때만 실제 장치. 화면에 '실제 장치'/'모의'가 보인다). 이 경로는 실행기 안에서 `home`을 하므로 위 원점 규칙을 푼다.
   - `SIMPLELAY_MOTION_AUTO_HOME=true`면 새로 승인된 첫 실행이 원점부터 잡는다.
   - (jog CLI의 `home`은 실행기를 멈춘 별도 프로세스라, 실행기를 다시 세우면 원점 규칙 때문에 다시 잡아야 한다.)
3. 원점 방향(좌하단, X-·Y- 벽)으로 가는지 눈으로 본다. 벽을 너무 세게 밀면 멈추고 `HOMING_PWM_LIMIT`·`STALL_ERR_MM`(펌웨어)을 낮춘다.
4. 소프트 리밋: 개발자 조그(한 번 최대 1 mm)로 `X_MIN_MM`·`Y_MIN_MM` 아래, `X_MAX_MM`·`Y_MAX_MM` 위로 보내 `soft_limit`으로 **움직이기 전에** 거절되는지 본다.
   `X_MIN_MM`·`Y_MIN_MM`은 3 이상 권장(0이면 벽을 민다). 실제 이동 가능 범위(자로)는 **측정 필요**.

| 항목 | 값 | 비고 |
|---|---|---|
| 원점 복귀 시간(s) | 측정 필요 | `HOME_MAX_MS` 70 s 설계값 |
| 원점 반복 오차(같은 자리 5회, mm) | 측정 필요 | |
| 실제 X·Y 이동 범위(mm) | 측정 필요 | env `X/Y_MAX_MM`에 반영 |
| 리밋 밖 거절 | 측정 필요 | `soft_limit`, `moved:false` |

## 4. mm 환산(기어비) 재측정

모터를 다시 달았으므로 10/14 이전 값을 쓰지 않는다. 설계 환산은 1400 카운트/회전(28 × 50 × 4 계산), 풀리 20잇 × 2 mm = 40 mm/회전 — **실제 기어비 50이 맞는지부터 측정 필요**.

1. 원점 뒤 캐리지에 바늘이나 펜 끝 같은 기준점을 붙이고, 프레임에 자(또는 모눈종이)를 고정한다.
2. 개발자 조그로 X +10 mm, 그다음 +50 mm(1 mm씩 반복 또는 jog CLI `goto`) → 자로 잰 실제 이동과 `status`의 `a`·`b` 계수를 적는다. Y도 같게. 각 3회.
3. 오차가 크면 `SIMPLELAY_MOTION_R_OUT`(카운트/회전)을 `명령 mm / 실제 mm` 비율로 고치고 **펌웨어 `COUNTS_PER_REV`도 같게** 맞춘다(둘이 다르면 `bad_args`). 고친 뒤 2를 다시 한다.

## 5. 솔레노이드 단발 누름 (안전 먼저)

## 6. 전자레인지 버튼 매핑과 자리 확인

시연 가전은 **기본 가전 `microwave`(전자레인지)**, 시연 작업은 **'30초 → 시작'**(`BT-02` 30초 → `BT-05` 시작).
기본 버튼 목록은 `rpi/services/appliance_registry.py`의 `BUILTIN_MICROWAVE`(=[button-maps/microwave.json](button-maps/microwave.json), 4×3 격자 이름만 — **mm 좌표 없음**).

**지금 좌표가 정해지는 방식**

- 기본 가전에는 mm 좌표가 없다. 좌표 없이 누르려 하면 RPi4가 "좌표가 없어 누르지 않습니다 — 보정 먼저"로 거절한다.
- 폰에서 위치를 맞추면 RPi5가 기본 가전 위에 **보정 덮어쓰기**(DB의 `calibration:microwave`, 버튼 mm·판 번호)와 **정지·기다리는 자리**(`stop_park`)를 저장한다(`apply_calibration`). 기본 목록 자체는 바뀌지 않는다.
- 계산은 RPi5 `rpi/api/mapping_router.py`(`PUT /appliances/microwave/mapping`, 미리보기는 `…/mapping/preview`)와 `rpi/services/panel_mapping.py`. 사진 파일은 보내지 않고 **사진 크기와 짚은 좌표(px)만** 보낸다.
- 판(프레임) 크기는 요청값, 없으면 RPi5 env `SIMPLELAY_FRAME_W_MM`·`_H_MM`. 판 왼쪽 위와 갠트리 원점이 다르면 `SIMPLELAY_FRAME_ORIGIN_X_MM`·`_Y_MM`.
- 누름 장치가 어느 기본 가전 위에 있는지는 RPi5 env **`SIMPLELAY_GANTRY_APPLIANCES`**(기본 `microwave`). 여기 없는 기본 가전(인덕션)은 '설정이 필요해요'로 보이고 실행·자리 확인을 거절한다.
- 개발자 도구에는 지금 기본 가전도 보인다(조그·누르기로 버튼 자리를 직접 찾을 때 쓴다).
- 10/14 이전에 저장된 보정이 있어도 **모터를 다시 달고 §4 환산을 바꿨으면 그대로 믿지 않고 다시 맞춘다.**

**맞추는 순서(폰 '위치 맞추기' 5단계 — `app/lib/screens/add_appliance_wizard_screen.dart`)**

1. **조작부 사진** — 갠트리를 단 상태로 정면에서, 판 네 귀퉁이가 다 들어오게.
2. **버튼판 네 귀퉁이 고르기** — 왼쪽 위 → 오른쪽 위 → 오른쪽 아래 → 왼쪽 아래. 판 안쪽 가로·세로(mm)는 자로 재서 넣는다(**측정 필요**).
3. **버튼 고르고 이름 붙이기** — 최소 `30초`·`시작`·`취소`. 버튼 중심을 짚는다.
4. **정지 버튼과 기다리는 자리** — 정지 버튼은 `취소`(BT-06), 누름 횟수 기본 1. 기다리는 자리는 버튼을 가리지 않고 문 여닫이에 걸리지 않는 곳.
5. **자리 확인** — 누르지 않고 솔레노이드를 올린 채 버튼 위를 한 번씩 지나간다(`POST /appliances/microwave/verify-pass`). 다른 실행 중이면 거절된다.
   '모든 위치에 도착했다고 응답했어요'는 **모션 보드 응답**이지 버튼 위였다는 증거가 아니다 — 사람이 눈으로 본다. 화면이 '연습으로만 자리 확인했어요'면 모의다.

**버튼마다 누름 확인(자리 확인 뒤)**

- 개발자 도구에서 그 버튼 자리로 간 뒤 '누르기' 한 번씩(30초·시작·취소 순서. 전자레인지는 **빈 상태 가열 금지** — 물컵을 넣고, 시작을 누른 뒤에는 바로 취소).
- 나중에 등록 가전에서 '자리 확인'만 다시 할 때는 가전 설정 카드의 **'자리 확인'** 버튼.

| 버튼 | 짚은 사진 px | 저장된 mm (x, y) | 자리 확인(눈) | 단발 누름(사람 판정) | 비고 |
|---|---|---|---|---|---|
| BT-02 30초 | | 측정 필요 | | | |
| BT-05 시작 | | 측정 필요 | | | |
| BT-06 취소(정지) | | 측정 필요 | | | |
| 기다리는 자리 | | 측정 필요 | — | — | |

같은 표의 결과를 [실측 기록표](실측-기록표.md) §4 시도 기록에도 옮긴다.

**버튼을 빗나갔을 때**

1. 몇 mm, 어느 방향인지 자로 잰다. 모든 버튼이 같은 방향으로 밀렸으면 판 원점(`SIMPLELAY_FRAME_ORIGIN_*`)이나 §4 환산 문제다 — 버튼 하나씩 고치지 말고 그쪽을 먼저.
2. 한두 버튼만이면 폰 '위치 맞추기'로 **다시 맞춘다**(사진을 다시 찍거나 같은 사진에서 버튼 점만 다시 짚기) → 자리 확인.
3. 개발자 조그(1 mm씩)로 실제 버튼 중심을 찾아 그 좌표를 기록하고, 위치 맞추기에서 그 자리에 오도록 다시 짚는다. 좌표를 손으로 DB에 넣지 않는다.
4. 가장자리를 스치는 정도면 재시도 오프셋 `SIMPLELAY_MOTION_RETRY_XY_OFFSETS_MM`(RPi4)이 자동 재시도 때 조금 옮겨 누른다 — **처음부터 빗나가는 것을 이것으로 덮지 않는다**. 토글 버튼(시작·취소)의 자동 재누름은 R1 정책 대상이다([안전 보고](안전계약-적용-보고-2026-10-15.md) §2-0).

## 9. CT 콘센트 모듈 (준비됐을 때만)

**10/19 사용자 결정:** 모션 보드가 돌아오면 §5~§8(실제 버튼 누름)을 먼저 하고, 이 단계는 10/28 제출 뒤로 미룬다. 10/28 영상은 CT 없이 찍는다([v4 §0-A](본선-시연-계획-v4.md), [실물 장면 대본](촬영-대본-실물-장면.md) §4-A). 결선(11/6) 전에 끝내는 것이 목표다.
만드는 방법·부품·펌웨어 핀 대응은 [콘센트 모듈 제작 안내](콘센트-모듈-제작-안내.md).

[콘센트 펌웨어](../firmware-outlet/README.md)는 컴파일까지만 확인했고 회로는 제작 중이다. 모듈이 없으면 이 단계를 건너뛰고 시연은 'CT 콘센트 모듈은 설계·펌웨어 완료, 실측 전'으로 말하고 가열 종료 장면은 연습으로 보인다.

0. **전자레인지 전원선은 자르거나 벗기지 않는다.** 전원선 안의 두 가닥을 함께 감싸면 전류가 서로 지워져 0에 가깝게 읽힌다 — CT는 한 가닥만 감싸야 한다. 방법은 둘이다. (가) 콘센트 모듈을 '중간 멀티탭'처럼 만들어 벽 콘센트 → 모듈 상자 → 상자 콘센트에 전자레인지 플러그를 그대로 꽂고, 선 가르기·CT·릴레이는 닫힌 상자 안에서만 한다(퓨즈, 릴레이·단자·선은 10 A 이상 권장 — 전자레인지 소비 전류는 제품 표기로 확인, 220 V 배선은 경험 있는 분 확인을 받는다). (나) 상자가 준비되기 전 측정은 시중 라인 스플리터(클램프 측정용 중간 연장선, 220 V 정격 확인)에 CT를 건다. CT 출력 형식(전압 출력형/전류 출력형 — 전류형은 부하 저항 필요)은 모델명으로 확인해 ESP32 입력 범위에 맞춘다.
1. 모듈 펌웨어의 핀·CT 보정·전압·역률·릴레이 극성은 전부 자리표시자다 — HW 담당과 실측해 채운 뒤 올린다.
2. RPi4 env 백업 → `SIMPLELAY_OUTLET_PORT`(by-id), 채널 설정, `SIMPLELAY_L3_MODE=real`(모듈이 없으면 실행기가 시작을 거절한다). 비상정지 래치가 풀려 있는지 확인.
3. [실측 기록표](실측-기록표.md) §6의 경우 A(정상 30초)·B(출력 감소)·C1(취소)·C2(문 열림)·D(팬만)를 각 3회 이상. 영상에 조작부·표시창·종료음이 같이 들어오게.
4. 종료 감지는 '가열 종료 감지(조리 완료가 아닐 수 있음)'로만 말한다.

## 11. 실물 장면 촬영

[실물 장면 촬영 대본](촬영-대본-실물-장면.md) §0의 선행 조건(§3~§9가 이 문서와 대응)이 모두 통과한 뒤에만 찍는다. 10/28 영상(갈래 A, CT 없음)은 §3~§8까지, 결선 영상(갈래 B)은 §9까지. 측정이 먼저, 촬영이 나중이다.
자막의 숫자는 실측 기록표에서 가져오고 영상에서 따로 세지 않는다. '연습 띠 없음' 대조 컷과 기록 화면 동시 촬영은 대본 §2·§3대로.

## 12. 되돌리기 (언제든)

**모의로 되돌리기(RPi4)**

1. 지금 env를 `env.bak-YYYYMMDD-이유`로 백업.
2. `cp env.bak-20261016-no-esp32 env`(모의 모션: `SIMPLELAY_MOTION_MODE=mock`, 포트 줄 주석) — 또는 두 줄만 손으로 되돌린다. CT를 켰다면 `SIMPLELAY_L3_MODE`도 되돌린다.
3. `sh /mnt/rawdata/run_act.sh` → RPi5 `/health/detail` 확인. 화면에 '연습' 띠가 다시 보이는 것이 정상이다.

**이미지 되돌리기(RPi5·RPi4 둘 다 같은 태그로)**

- 직전 이미지 태그는 그날 배포 직전에 붙인 날짜 태그(10/19 기준 최신 `simplelay-backend:1019d`, 그 전 `1019c`·`1019b`·`1018c`). 새로 배포하기 전에 지금 이미지에 날짜 태그를 붙여 둔다.
- 실행 스크립트는 태그 없는 `simplelay-backend`를 쓴다: `docker tag simplelay-backend:<날짜 태그> simplelay-backend` → RPi5 `deploy/run_backend.sh`, RPi4 `run_act.sh`. 두 보드는 **같은 커밋**이어야 한다.

**펌웨어 되돌리기**

- 시연 빌드에 문제가 있으면 직전에 올렸던 바이너리(SHA 적어 둔 것)를 §1 방법으로 다시 올린다. 시험대 빌드(`benchhome`)는 시연 보드에 올리지 않는다.

**시연 중이면** 다시 시도하지 않고 전부 모의로 내린다([런북](결선-운영-런북.md) §5-4).

**끝낼 때:** 보드는 컨테이너를 멈추지 않고 `sync; poweroff`만. RPi4 재부팅 뒤에는 `systemctl start docker`가 필요하다. 평가 전에는 개발자 실물 조작 env를 끈다.
