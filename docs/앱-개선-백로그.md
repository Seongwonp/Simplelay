## B. High 처리하면서 의도적으로 남긴 것

### ~~B1. 패턴 제안은 대상 가전을 모른다~~ — 완료 (`31ef267`)
`UsageRecord.appliance_id` → SQLite(기존 DB용 ALTER 마이그레이션) → 실행 경로
(동기·비동기 job) → `PatternCandidate` → `ProactiveSuggestion`까지 사슬을 이었다.
목적별 **가장 최근** 실행 가전을 쓴다(최빈값이 아니라 — 다른 가전으로 옮겨 쓰기
시작했다면 사용자가 뜻하는 대상은 최신 쪽이다). 데모 제안도 `appliance_id`로
대상을 못 박을 수 있어, 가전 여러 대를 번갈아 보여주는 연출이 가능해졌다.

남은 것: **실기기에서 가전 2대를 실제로 함께 쓰는 검증**(HW 대기).

### B4. 골든이 환경을 탄다
`app/test/goldens/`, `rpi5-touchscreen-app/test/goldens/`

다른 환경에서 생성된 골든이 이 머신에서 미세하게 어긋났다(테두리 안티에일리어싱·
아이콘 글리프, 0.06~0.31%). 내용 회귀가 아니라 래스터화 차이다. 반복되면 **허용
오차 비교자(tolerance comparator)** 도입을 검토한다.

### B5. 온디바이스 추론 계층이 아직 꺼져 있다
`rpi/api/deps.py`, [inference-boundary](inference-boundary.md)

규칙 → 온디바이스 의미검색 → 온디바이스 LLM의 3계층 중 **1계층(규칙)만 켜져 있다.**
2·3계층은 코드가 준비돼 있고 연결도 확인했지만 실기기 활성화를 확정하지 못했다.
발표에서는 **"경계를 설계하고 연결을 검증했다"** 까지가 정직한 선이다.
켜는 작업은 HW 폐루프가 굳은 뒤에 한다(어려운 것 두 개를 동시에 디버깅하지 않는다).

## 하지 않기로 한 것 (리뷰 안티패턴)

- 실패 화면에 '전체 다시 실행' 버튼 — 일부 버튼은 이미 눌렸을 수 있다
- '되돌리기'로 반대 버튼 자동 누르기 — 물리 조작은 취소 연산이 아니다
- 센서 숫자·신뢰도·차트 늘리기 — 필요한 것은 "눌림을 확인했는가"다
- 모든 동작에 확인창 — 확인은 대상·순서가 불확실한 실행에 집중
- 앱에서 못 받는 데이터를 데모 센서 값으로 보충
- 새 모델·클라우드 추론·복잡한 보호자 플랫폼 신설
