# 한국어 UI 말투 조사와 적용안 (2026-10-22)

상태: **한국어 자료 조사와 수정 후보 정리. 코드·기존 제품 정책은 변경하지 않았다.**

**사용자 결정(2026-10-22):** 사용자에게 결과를 알리는 문구에서 ‘몰라요’를 쓰지 않고 **‘확인하지 못했어요’**로 표현한다. 폰·키오스크·음성 안내·화면 읽기에 동일하게 적용할 작업 기준이다. 기존 문구 기준 R6의 ‘몰라요’ 지시보다 이 결정을 우선한다. 이번에는 문서만 반영했으며 실제 화면 문구는 후속 작업에서 변경한다.

함께 전달할 문서: [UI 마감 수정 계획](UI-마감-수정계획-2026-10-22.md). 기존 말투의 기준 문서는 [UX 문구 기준](UX-문구-기준-2026-10-19.md)이다. 이 문서는 그 기준을 대체하지 않고, 현재 화면의 문제와 한국어 근거 자료를 연결한다.

## 1. 먼저 읽을 것

시간이 적으면 **자료 D1 → D2 → 논문 P1 → 아래 4절 교체표** 순서로 읽는다. 단순히 부드러운 말끝을 붙이는 작업보다, **어떤 사실을 말하는지·어디에서 무엇을 해야 하는지**를 먼저 고친다.

- ‘몰라요’를 무조건 ‘실패’로 바꾸지 않는다. **미확인과 실패는 다르다.**
- ‘봤어요’를 무조건 없애지 않는다. 눈으로 본 것처럼 오해하거나 결과를 흐리는 표현만 현재 데이터에 맞게 고친다.
- 가전의 클라우드 상태 확인을 센서로 물리 동작을 확인한 것처럼 표현하지 않는다.
- 위험 상황에서 친근함을 위해 필요한 행동을 권유형으로 약하게 만들지 않는다. 실제 가전에서 취소해야 한다면 대상과 행동을 직접 안내한다.
- 연구 인용은 SimpleLay의 사용성·고령자 적합성·안전을 검증했다는 뜻이 아니다.

## 2. 한국어 실무·공공 지침

확인일: 2026-10-22. 공식 발행처 자료를 우선했다. 아래 요약과 SimpleLay 적용안은 구분해서 읽는다.

### D1. 토스의 8가지 라이팅 원칙들

- 김자유, 토스 공식 기술 블로그, **2022-11-15**.
- [원문](https://toss.tech/article/21022). **웹 본문 확인.** 기존 조사 문서에 적힌 다른 주소 대신 이번 검색에서 열리는 주소를 사용한다.
- 요점: 다음 동작을 예상하게 하고, 중복·군더더기를 줄이며, 사용자에게 익숙한 말로 작성한다. 글자 수만 줄이는 것이 간결함의 전부는 아니다.
- **적용안:** 루틴의 범례·배지·스위치가 같은 의미를 반복하는지 점검한다. ‘직접 누를 버튼’에는 실제 가전인지 화면인지 장소를 명시한다. 공백을 채우려는 설명은 추가하지 않는다.
- 한계: 금융 서비스의 실무 원칙이며 고령자 대상 가전 제어의 실험 결과가 아니다. 제품의 말투와 안전 조건에 맞춰 적용한다.

### D2. 좋은 에러 메시지를 만드는 6가지 원칙

- 김자유, 토스 공식 기술 블로그, **2022-09-21**.
- [원문](https://toss.tech/article/21021). **웹 본문 확인.**
- 요점: 사용자가 처한 상황과, 알 수 있는 원인, 해결 방법을 안내한다. 오류 자체를 줄일 수 있는 구조인지도 먼저 본다. 사용자가 이해할 말과 적절한 표시 방식이 중요하다.
- **적용안:** ‘눌렸는지 몰라요’만 단독으로 끝내지 말고 가전에서 확인할 대상과 다음 행동을 붙인다. 기록 조회 실패를 빈 기록으로 보여 주지 않는다. 단, 모든 오류에 ‘다시 실행’을 권하면 토글 버튼을 중복 누를 수 있으므로 기존 안전 정책을 우선한다.
- 한계: 여기서 제안하는 친절한 표현을 물리적 위험 안내에 그대로 적용해 지시를 약화하지 않는다.

### D3. 가이드라인을 시스템으로 만드는 법

- 김자유, 토스 공식 기술 블로그, **2022-11-04**.
- [원문](https://toss.tech/article/introducing-toss-error-message-system). **웹 본문 확인.**
- 요점: 팀이 같은 기준을 실제로 적용하도록 사례·표준 표현을 정리하고, 문구의 실제 원인과 해결책을 개발자와 확인한다.
- **적용안:** 폰·키오스크를 따로 일괄 치환하지 않는다. 같은 결과 상태가 두 화면에서 어떤 말로 표시되는지 표로 맞춘다. 이번 마감에는 새 번역 시스템이나 대규모 공통화 대신 기존 결과 매핑과 시험을 활용한다.

### D4. 한눈에 알아보는 공공언어 바로 쓰기(개정판)

- 국립국어원 공공언어과, 게시일 **2022-12-26**(안내 페이지 최종 수정일 2024-06-04).
- [공식 안내·자료 다운로드](https://m.korean.go.kr/front/etcData/etcDataView.do?etc_seq=699&mn_id=46&pageIndex=1).
- **확인 범위: 공식 안내 페이지·목차·서지정보. 첨부 PDF 본문은 이번에 열지 않았다.**
- **읽을 목적:** 어렵거나 모호한 용어와 자연스럽지 않은 문장, 안내문 작성 기준을 검토할 때 참고한다. 이 책이 특정 앱의 해요체나 ‘몰라요/미확인’ 중 하나를 정답으로 지정했다고 인용하지 않는다.
- 한계: 공공 문서 작성 자료다. 모든 앱 문장을 공문서체로 바꾸는 근거로 쓰지 않는다.

## 3. 한국어 논문

**아래 세 편 모두 KCI 공개 서지정보·초록 범위의 조사다. 논문 본문·실험 문항·원자료는 확인하지 않았다.** 연구가 보고한 요지까지만 사용하며, 초록에 없는 표본 수·효과 크기·검증 문구를 만들지 않는다. 금융 앱·음성 에이전트 결과를 가전 제어에 적용하는 부분은 설계자의 해석이다.

### P1. 모바일 뱅킹 앱의 ‘고령자 모드’ 사용자 경험 평가 - 60대 고령자를 중심으로 -

- **김승주·안지선(2025)**, 일러스트레이션 포럼, 26(82), 75–88. DOI: `10.37379/JKSIR.2025.82.07`.
- [KCI 논문·한국어 초록](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003193472).
- 초록에서 확인: **60대 10명**을 대상으로 두 뱅킹 앱을 SUS 설문과 심층 인터뷰로 살폈다. 명확한 용어, 버튼 크기·간격과 화면 전환, 사용자가 이미 이해하고 있는 방식의 중요성을 보고했다.
- **적용안:** ‘내 루틴’에도 자동 실행이 있는데 ‘자동으로 하기’ 탭이 별도로 있는 구조를 사용자가 구별하는지 과업으로 확인한다. 글자를 크게 했다는 이유만으로 고령자에게 편하다고 판정하지 않는다.
- 한계: 60대 소규모 금융 앱 연구다. 더 높은 연령층·시각장애인·가전 정지 상황으로 결과를 일반화하지 않는다.

### P2. 모바일 금융 플랫폼 UX 라이팅 개선 가이드라인 제안 - Grice의 협력 원리를 중심으로 -

- **이유림·최종훈(2023)**, 아시아태평양융합연구교류논문지, 9(9), 675–683. DOI: `10.47116/apjcri.2023.09.49`.
- [KCI 논문·한국어 초록](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003001820), [연구실 공식 소개](https://uxd.ewha.ac.kr/research/?mod=document&pageid=1&uid=35).
- 확인 범위: KCI 검색 결과에 제공된 한국어 초록과 연구실 소개. KCI 본문 페이지 직접 열기는 이번 도구에서 실패했으므로 본문 열람으로 기록하지 않는다.
- 초록에서 확인: 금융 플랫폼 5개와 서비스 4개를 선정해 사용성 평가·설문·심층 인터뷰를 수행하고, 협력 원리를 문구의 문제 원인과 수정 방향을 분석하는 틀로 사용했다.
- **적용안:** 화면마다 ‘필요한 정보가 빠졌는가 / 불필요하게 반복하는가 / 현재 과업과 관련 있는가 / 뜻이 모호한가’를 묻는다. 이 네 질문은 이번 적용을 위한 재구성이며 논문이 SimpleLay에 제공한 검증표는 아니다.
- 한계: 초록만으로 격률별 실험 결과·효과 크기·최적 문장 길이를 판단할 수 없다. 금융 거래와 물리 가전 제어의 위험은 다르다.

### P3. 음성 에이전트와의 대화 오류 상황에서 재응답 메시지 개선 방향

- **김소연·최종훈(2023)**, 아시아태평양융합연구교류논문지, 9(9), 665–674. DOI: `10.47116/apjcri.2023.09.48`.
- [KCI 논문·한국어 초록](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003001813).
- 확인 범위: KCI 검색 결과의 공개 한국어 초록·서지정보. 원문 PDF는 열지 않았다.
- 초록에서 확인: 사용자 조사에서 대표 대화 오류 유형 다섯 가지를 찾고, 심층 인터뷰로 불편과 요구를 분석해 재응답 메시지의 개선 방향을 제안했다.
- **적용안:** 음성에서 ‘알아듣지 못했어요’만 반복하지 않고 사용자가 다음에 할 수 있는 행동을 안내한다. 음성 인식 실패·명령 해석 실패·실행 거절·실행 결과 미확인은 서로 다른 경우로 유지한다.
- 한계: 본문을 보지 않아 다섯 오류 유형의 구체 목록을 이 논문에서 가져왔다고 쓰지 않는다. 음성 기능 확장은 이번 UI 마감 범위 밖이며, 기존 안내 점검용으로 참고한다.

## 5. 폰·키오스크 공통 말투 제안

다음은 적용 제안이다. 다만 **‘몰라요’ 대신 ‘확인하지 못했어요’를 쓰는 것은 사용자 확정 사항**이다. 나머지 항목이 기존 사용자 결정과 충돌하면 기존 기준을 유지한다.

1. **상태와 설명을 나눈다.** 짧은 띠·배지는 ‘완료 / 확인 못 함 / 멈춤’처럼 기존 R12를 따른다. 본문은 ‘공기청정기가 켜졌어요’처럼 대상과 결과를 말한다.
2. **해요체를 기본으로 하되 유아에게 설명하듯 쓰지 않는다.** ‘부탁이 닿다’, ‘가전이 말해 줬다’보다 ‘응답을 받지 못했어요’, ‘설정을 확인했어요’가 상황에 맞을 수 있다. 이것은 설계 판단이며 모든 고령자의 선호로 단정하지 않는다.
3. **모르는 범위를 좁혀 말한다.** ‘상태를 몰라요’보다 ‘버튼이 눌렸는지 확인하지 못했어요’. 단, 확인 못 한 이유를 추측하지 않는다.
4. **결과 한 번, 행동 한 번.** 제목·띠·부제에서 같은 문장을 반복하지 않는다. 실제 확인 수준·연습 표시는 필요한 곳에 유지한다.
5. **행동은 구체적으로 안내한다.** ‘확인해 주세요’만 쓰기보다 ‘실제 전자레인지의 취소 버튼을 눌러 주세요’처럼 현재 상황에 맞는 대상을 밝힌다. 모든 상태에서 취소를 누르게 하라는 뜻은 아니다.
6. **긴급함에 맞춰 말한다.** 일상 제안은 선택을 존중하고, 정지 미확인에서는 우회적인 권유·농담·장황한 사과를 피한다. 문구 변경으로 정지 처리·재시도 정책을 바꾸지 않는다.
7. **단어만 강제 치환하지 않는다.** ‘실행’, ‘확인’, ‘모드’도 실제 사용자에게 익숙하고 정확하면 쓸 수 있다. 쉬운 표현으로 바꾸려다 의미가 흐려지면 원래 표현을 유지한다.

**사용자 정책과 연구 결과의 구분:** ‘확인하지 못했어요’를 쓰는 것은 사용자가 확정한 제품 말투다. 논문으로 표현의 우열을 입증했다는 주장이 필요하지 않다. 기존 R12도 제품 말투 정책으로 유지하며, 한국어 축약형 자체의 무례함을 연구로 입증했다고 쓰지 않는다.

## 6. 적용·검증 순서

1. [마감 계획](UI-마감-수정계획-2026-10-22.md)의 기록 상태 구분과 실제 가전 안내부터 고친다. 문구를 고치기 전에 데이터 분기를 정확하게 만든다.
2. 결과별로 `상태 값 → 현재 문구 → 후보 → 실제 아는 사실 → 다음 행동` 표를 만든다. 폰·키오스크가 같은 사실을 말하는지 본다.
3. 동작이 없는 문구 다듬기에 불필요한 시험을 남발하지 않는다. 반대로 미확인/성공 구분, 조회 실패/빈 기록, 연습/실제, 정지 대상 안내는 상태별 위젯 회귀 시험으로 고정한다. 수정 전 실패·기존 통과를 구분한다.
4. 긴 가전 이름과 글씨 2.0을 확인한다. 긴급 안내·주요 행동·정지가 가려지지 않아야 한다. 화면 읽기 이름과 소리 안내가 이전 문구로 남지 않는지도 점검한다.
5. 팀 밖 사람에게 ‘이 문구가 무슨 뜻인가요? 다음에 어디서 무엇을 해야 하나요?’를 묻는다. ‘어느 말투가 예쁜가요?’만 묻지 않는다. 멈춤·미확인 화면에서는 실제 장치 대신 안전한 화면 과업으로 먼저 시험한다.
6. 한 번 고친 뒤 사용자 과업과 실제 패널에서 확인한다. 참고문헌을 늘리거나 같은 평가자 점수를 올리기 위해 문구만 계속 바꾸지 않는다.

제출 문구 예: **‘국내 UX 라이팅 자료와 고령자 앱 사용성 연구를 참고해 결과·다음 행동 문구를 점검했다.’** 직접 시험하지 않았다면 ‘고령자에게 검증된 문구’, ‘논문으로 입증한 공감지능’, ‘접근성 인증’이라고 쓰지 않는다.
