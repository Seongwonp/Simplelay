### 3. W1 — 비동기 job 모델 전환 (로드맵의 가장 레버리지 큰 수리) ✅

동기 블로킹 실행(실기기 30초+ vs 클라이언트 타임아웃 4~8초)의 구조적 파탄을 해소.

**백엔드** (`feat(rpi): 실행을 비동기 job 모델로 전환`):
- 실행 엔드포인트 4종(execute·execute-buttons·execute-for-appliance·approve)이
  의도 해석만 동기로 끝내고 물리 실행은 백그라운드 스레드로 제출 → `job_id` 즉시 반환
- `/status`에 `job_id`·`last_job_id`·`total_steps` 추가 — job_id 대조로 완료 판정
  (stale-result 레이스 원천 차단), total_steps로 실제 진행률 표시
- 실행 가드 check-and-set을 `threading.Lock`으로 원자화 (TOCTOU 제거)
- 백그라운드 예외는 `ExecutionStatus.FAILED`로 노출, 동기 메서드는 하위호환 유지

**폰 앱** (`feat(app+kiosk): 클라이언트를 job 모델로 전환`):
- `ExecutionStatusNotifier.beginHttpJob`: 1초 주기 /status 폴링 — **HTTP 실행 시
  상태 화면이 '영원히 대기 중'이던 치명 이슈 ⑦ 해소.** 재진입 가드, 30초 무응답 탈출
- 긴급 정지: HTTP 추적 중엔 서버 /stop 호출 후 폴링이 safety_stopped를 받아 표시
- 음성 화면: 접수 후 상태 화면 자동 이동, 에러를 사용자 언어로(422/409/503 구분)
- 디버그 가짜 센서 주입을 BLE 출처로 한정 — HTTP 실경로를 가짜 데이터가 못 덮게

**키오스크**:
- idle에서도 /status 폴링 — **폰이 시작한 실행을 키오스크가 이어받아 표시** (동기화 달성)
- 완료 판정 job_id 대조, 진행바 실데이터(completed/total), 30초 무응답 '서버 응답 없음' 탈출,
  폴링 오버랩 가드, 접수 실패 시 즉시 실패 화면(고착 제거), 정지는 실제 종료 확인 후 표시
