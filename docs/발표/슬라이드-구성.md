# 결선 슬라이드 구성 — 10장 (2026-10-19 초안)

> 팀이 직접 발표 자료를 만들 때 쓰는 장별 내용이다. **발표 자료 파일은 저장소에 넣지 않는다**(저장소 가드가 막는다 — 로컬에서만 만들고 보관).
> 순서와 시간은 [결선 발표 대본](결선-발표-대본.md)과 맞춘다. 세 가지 주장(여러 버튼 개조 · 명령에 묶인 승인 · 따로 확인한 결과) 밖의 화면 둘러보기 슬라이드는 만들지 않는다.
>
> **공통 규칙**
> - 측정하지 않은 숫자는 넣지 않는다. 칸은 **'측정 뒤 기입'**으로 두고, 측정한 날 [실측 기록표](../실측-기록표.md) 값을 그대로 옮긴다(조건·n 함께).
> - 화면 캡처는 그날 빌드의 실제 화면만. 골든 시험 이미지나 `docs/archive/screenshots-2026-08/`(개편 전)는 쓰지 않는다.
> - 화면 말은 앱 글자 그대로: '본체', '누름 장치', 'LG 가전', '가열 종료 감지(조리 완료가 아닐 수 있음)'.
> - 슬라이드에 팀 내부 점검 번호(G…·R…·PS-…)와 커밋 해시를 넣지 않는다.
> - 글자는 뒷줄 심사위원 기준으로 크게 — 한 장에 문장 세 줄 이내, 나머지는 말로.

## 1. 문제와 사용자 (대본 0:00–0:40)

- **제목:** 쓰던 가전을 그대로, 대신 눌러 드립니다
- 사진 한 장: 버튼식 전자레인지 조작부(작은 글씨·여러 버튼).
- 세 줄:
  - 집 가전 대부분은 통신이 없는 버튼식이다.
  - 손이 불편하거나 작은 글씨가 안 보이면 그 버튼판이 장벽이다.
  - 가전을 바꾸지 않고, 쓰던 가전의 버튼을 대신 누른다.
- 아래 띠: 팀 자비스 · SimpleLay. 사용자 시험을 했다고 쓰지 않는다(당사자 시험 전 — [질의응답 대비](../질의응답-대비.md) Q11).

## 2. 세 가지 주장 (0:40–1:20)

세 칸 가로 배치, 칸마다 아이콘 하나 + 한 줄 + 오늘 보일 장면.

| ① 여러 버튼 개조 | ② 명령에 묶인 승인 | ③ 따로 확인한 결과 |
|---|---|---|
| 누름 장치 하나가 조작부의 **여러 버튼**을 순서대로 ('30초 → 시작') | 승인은 카드에 적힌 **그 명령**(대상·경로·동작·인자)에만. 바뀌면 다시 묻는다 | 보낸 길과 **다른 근거**로: 누름 장치 확인 · 콘센트 전력(있을 때) · LG 가전 상태 재조회 |
| 장면: 승인 → 두 버튼 누름 | 장면: 거절하면 그대로 · 허락한 것만 자동 | 장면: '됐어요'는 상태를 본 뒤에만 · 정지도 단계로 |

맨 아래 한 문장 피치: "여러 버튼을 그대로 두고 대신 누르되, 승인한 그 명령만 실행하고, 결과는 따로 확인합니다."

## 3. 함께 쓰는 하드웨어 / 새로 만든 하드웨어 (1:20–2:00 — 갠트리가 움직이기 전)

근거: [재사용 경계](../reuse-boundary.md). 좌우 두 칸 그림, 가운데 세로선. 왼쪽은 회색, 오른쪽은 강조색.

```
┌──────────── 함께 씀 (한이음 Touch Bridge와 같은 기계 1대) ─────────┐ │ ┌────────────── 이번 대회 신규 ──────────────┐
│ CoreXY 갠트리 프레임·벨트·레일                                    │ │ │ 솔레노이드 Z 누름 (켜짐 상한·냉각 추가)       │
│ XY 엔코더 모터 2개 · 모터 드라이버 · 엔코더                       │ │ │ ESP32 콘센트 모듈 (CT 전력 · 릴레이 ·        │
│ 모션 펌웨어 제어 핵심                                             │ │ │   비상정지 래치)  ※ 갈래에 따라 '실측 전'      │
│  (PID · CoreXY 기구학 · 궤적 · 원점 · 솔레노이드 구동)            │ │ │ 안전 계층 (정지 단계 · 생존 신호 · 재누름 차단) │
│                                                                   │ │ │ 승인 결속 (명령 지문)                        │
│                                                                   │ │ │ 결과 확인 (누름 장치 · CT · LG 상태 재조회)   │
│                                                                   │ │ │ 두 앱 (키오스크 전체 · 폰 상태·승인·기록·루틴) │
└───────────────────────────────────────────────────────────────────┘ │ └──────────────────────────────────────────────┘
                                      ESP32 모션 보드는 프로젝트마다 따로
```

- 각주(작게): 폰 앱 **골격**은 이전 작품을 확장. 모션 펌웨어는 원작에 규약·안전 계층(시리얼 규약·워치독·명령 기한·솔레노이드 상한)을 더함.
- 콘센트 모듈 칸 표기는 갈래대로 — 결선 CT 있음: 그대로 / CT 없음·영상: '설계·펌웨어 완료, 실측 전'.
- 쓰면 안 되는 말: "기구도 새로 설계", "펌웨어 독립".

## 4. 시연 안내 (2:00–6:50 — 슬라이드는 거의 비우고 실화면)

- 한 장짜리 길잡이: 장면 다섯 개를 가로 띠로, 지금 장면을 강조. 장면마다 해당 주장 번호(①②③)만 붙인다.
  - 거절 ② → 승인·누름 ①② → 결과 확인 ③ → 같은 조건 다시 ②③ → 정지·일부 실패 ③
- 시연 동안 화면은 **키오스크·폰 미러링 + 기구 카메라**. 이 슬라이드는 장면 사이에만 잠깐.
- 결선 CT 없음 갈래에서 연습 장면을 넣으면 띠에 '연습' 표시를 함께 둔다.

## 5. 증거 한 장 (6:50–7:30)

**모든 칸 '측정 뒤 기입'.** 측정한 날 값·조건·n을 함께 적고, 못 잰 칸은 '측정 전'으로 둔 채 발표한다.

| 무엇 | 값 | 조건 | 근거 |
|---|---|---|---|
| 실제 버튼 누름 성공 | n / N — 측정 뒤 기입 | 무대 기구·솔레노이드, 전자레인지 '30초'·'시작' | [실측 기록표](../실측-기록표.md) §4 |
| CT 가열 시작 판정 | 맞은 n / N, 지연 — 측정 뒤 기입 | 30초 가열 | 실측 기록표 §6 |
| CT 가열 종료 판정 | 맞은 n / N, 지연 — 측정 뒤 기입 · 오판(출력 조절·팬 구간) 횟수 | 30초 가열, 취소·문 열림은 따로 '발생 여부' | 실측 기록표 §6 |
| 정지 — 가장 늦은 값 | 최대 ms — 측정 뒤 기입 (모션 보드 응답 / 엔코더 멈춤 확인 따로) | 무대 기구, 이동 중 정지 n회 | 실측 기록표 §5 |
| 승인 → 결과 확인까지 | 초 — 측정 뒤 기입 (전자레인지 누름 확인 / 공기청정기 상태 확인 따로) | 무대 망 | 측정 뒤 기입 |

- 각주: 벨트 없는 시험대 정지 기록(10/13~14)은 무대 기구 값이 아니다 — 무대 값을 못 쟀을 때만 '시험대'라고 적고 쓴다(실측 기록표 §5-1).
- 화면 가운데에 숫자, 오른쪽 작게 조건. 막대그래프는 쓰지 않는다(n이 작다).

## 6. 상용 버튼 누름 장치와 설계 차이 (7:30–8:05)

**설계 차이만. 성능·가격 우위 주장 없음. 상용품은 시험하지 않았다.** 근거 표는 [실측 기록표](../실측-기록표.md) §3, [개발완료보고서 초안](../submission/개발완료보고서-초안.md) §2-1.

| | 단일 버튼 누름 장치 (공개 사양) | SimpleLay |
|---|---|---|
| 여러 버튼 | 장치 하나가 버튼 하나. 한 장치로 여러 버튼 순서 조작은 공개 사양에서 찾지 못함 | 누름 장치 하나가 한 조작부의 여러 버튼을 순서대로 |
| 결과 확인 | 누름·가전 동작 확인 기능은 공개 사양에서 찾지 못함(SwitchBot 상태 ON/OFF는 스위치 모드에서만 유효) | 누름 장치 확인 + 콘센트 전력 + LG 가전 상태 재조회, 모르면 '몰라요'로 남기고 다시 누르지 않음 |
| 승인 | 앱·음성·타이머로 실행 | 카드의 그 명령에만 묶인 승인 |
| 설치 | 스티커 부착, 공구 없음 · 작다 | 조작부 위 갠트리 — **크고 설치가 더 어렵다** |

- 출처(2026-10-14 확인, 슬라이드 아래 작게): SwitchBot Bot 제품 페이지 <https://www.switch-bot.com/products/switchbot-bot> · SwitchBot API 문서 <https://github.com/OpenWonderLabs/SwitchBotAPI/blob/main/devices/others/bot.md> · Adaprox Fingerbot Plus <https://www.adaprox.io/products/fingerbot-plus>.
- 마지막 줄을 꼭 넣는다: "설치 간편함과 가격은 상용품이 낫다." 발표 전 출처를 다시 열어 바뀐 것이 있으면 확인 날짜를 고친다.

## 7. 구조 (8:05–8:20)

```
 폰 · 키오스크 ──HTTP(API 키)──▶ 본체 RPi5 ──Wi-Fi(페어링 키)──▶ 실행기 RPi4 ──USB 시리얼──▶ ESP32 모션 ─▶ 갠트리 · 솔레노이드
   (승인·기록·루틴)            (판단·승인 결속·기록)          (실행·누름 확인·정지)            └──▶ ESP32 콘센트 모듈 (CT · 릴레이 · 비상정지)
                                      │
                                      └──인터넷──▶ LG ThinQ 클라우드 ─▶ 공기청정기 (명령 → 상태 재조회)
```

- 한 줄: 버튼식 가전 제어·승인·정지는 집 안에서, LG 가전만 클라우드.
- 판단은 규칙 기반(사용 기록을 세는 규칙) — "AI가 학습한다"고 쓰지 않는다([추론 경계](../inference-boundary.md)).

## 8. 안전 — 정지 경로 (8:20–8:35, 시간이 밀리면 질의로)

```
 정지 누름(키오스크·폰) ─▶ 본체: 루틴 먼저 멈춤 ─▶ 실행기: 남은 버튼 보내지 않음 ─▶ 모션 보드: 정지
       화면 단계:   ① 보냈어요   →   ② 모션 보드가 받았어요   →   ③ 엔코더로 멈춤 확인 = '누름 장치가 멈췄어요'
                                                                ③을 못 보면 = '멈췄는지 몰라요' + '다시 멈추기'
 실행 중 생존 신호가 끊기면 → 실행기가 스스로 정지 → '눌렸는지 모름'으로 기록, 다시 누르지 않음
 물리 비상정지 버튼 → 전자레인지 콘센트 릴레이 차단·래치 (누름 장치 모터 전원은 끊지 않음 — 정지 명령으로 멈춤)
```

- 비상정지 범위를 정직하게 적는다: 콘센트 모듈 버튼은 **가전 전원**을 끊는다. 모터 전원 차단은 이 버튼의 범위가 아니다. 손 닿는 모터 전원 스위치를 달았으면 그 사실을, 아니면 '다음 단계'로 적는다.
- 콘센트 모듈이 없는 갈래에서는 비상정지 줄에 '제작 중'을 붙인다.

## 9. 한계와 다음 단계 (8:35–9:15)

| 한계 (지금) | 다음 단계 |
|---|---|
| CT는 정상 종료와 취소·문 열림을 구분하지 못한다 → '가열 종료 감지(조리 완료가 아닐 수 있음)'로만 말하고, 그 신호로는 공기청정기 풍량만 바꾼다 | 종료음·남은 시간 표시·문 스위치 후보를 측정으로 확인 |
| 조작부마다 갠트리 하나 — 크다 | 조작부 크기에 맞춘 소형 프레임·고정 브래킷 |

| 원가·설치 시간·당사자 시험 — 측정 전 | 실제 구매가 BOM, 설치 시간 3회 측정, 팀 밖 사용자 점검 |

- 맨 위 한 줄은 그날 사실대로: 처음부터 끝까지 실물로 한 장면이 있으면 그 장면 이름, 없으면 "처음부터 끝까지 실물로 확인한 장면은 아직 없다."
