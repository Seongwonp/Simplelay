# 결선 슬라이드 구성 — 6장 + 시연 (2026-10-26 개정)

> 팀이 직접 발표 자료를 만들 때 쓰는 장별 내용이다. **발표 자료 파일은 저장소에 넣지 않는다**(저장소 가드가 막는다 — 로컬에서만 만들고 보관).
> 순서와 시간은 [결선 발표 대본](결선-발표-대본.md)과 맞춘다. 뼈대는 세 기둥 — **생활 · 조율 · 책임**. 하드웨어는 수단으로 한 칸만 둔다.
> 2026-10-19 판(여러 버튼·명령 결속·따로 확인, 10장)은 git 기록에 있다.
>
> **공통 규칙**
> - 측정하지 않은 숫자는 넣지 않는다. 넣는 숫자는 조건·표본과 함께(예: "가운데값 약 10초, 고정 50문장").
> - 화면 캡처는 그날 빌드의 실제 화면만. 습관 카드 캡처는 **실제 사용 기록에서 나온 것만** — 없으면 '학습 중' 화면을 쓴다. 연습·모의 화면은 '연습' 표시를 가리지 않는다.
> - 화면 말은 앱 글자 그대로. 슬라이드에 팀 내부 점검 번호와 커밋 해시를 넣지 않는다.
> - 글자는 뒷줄 심사위원 기준으로 크게 — 한 장에 문장 세 줄 이내, 나머지는 말로.

## 1. 문제 (대본 0:00–0:40)

- **제목:** 집이 먼저 알아 두고, 맡긴 만큼만
- 세 줄:
  - 스마트홈은 앱을 열고, 규칙을 짜고, 알림에 답하라고 한다.
  - SimpleLay는 실제로 쓴 기록에서 일상을 알아채고, 사람이 있을 때 묻는다.
  - 사람이 맡긴 것만 알아서 하고, 결과를 알린다.
- 아래 띠: 팀 자비스 · SimpleLay. 사용자 시험을 했다고 쓰지 않는다(팀 밖 시험 전).

## 2. 세 기둥과 맡기기 다섯 단계 (0:40–1:20)

세 칸 가로 배치. 근거는 [공감지능 근거 자료](공감지능-근거-자료-2026-10-25.md).

| 생활 — 알아챈다 | 조율 — 때와 기기를 맞춘다 | 책임 — 맡긴 것만 |
|---|---|---|
| 같은 시간대에 사흘 이상, 세 번 이상 되풀이한 일을 실제 기록에서 알아챔(쓴 날을 보임). 돌려 말하면 본체 안 언어 모델이 동작 하나를 고르고, 사람이 '네'를 눌러야 한다(우리 세트 13/20) | 사람이 있을 때, 평소 시각 10분 전에 묻기. 실내·바깥 공기·날씨·방 밝기를 엮어 제안하거나 조언만 | 사용자가 확인 칸을 보고 맡긴 것만 자동. 열 나는 가전은 매번 '네'. 판단은 집 안 본체, 카메라는 사람 있음/없음만, 끌 수 있음 |

아래 띠(다섯 단계): 직접 사용 기록 → 습관 알아채기 → 사람 있을 때 묻기 → 사용자가 맡기기 → 알아서 하고 알림.

비교 한 줄(작게): "상용 서비스는 앱 알림으로 제안한다. SimpleLay는 실제 기록에서 사흘 이상, 세 번 이상 되풀이한 것만, 집에 사람이 있을 때 묻고, 맡긴 것만 자동으로 한다." 상용 쪽(예: 묻는 것이 기본, 자동 실행은 따로 켬)은 **발표 전 재확인** — [외부 조사](공감지능-외부조사-2026-10-26.md).

## 3. 시연 길잡이 (1:20–7:30 — 슬라이드는 거의 비우고 실화면)

장면 띠, 지금 장면 강조. 장면마다 기둥 표시만.

다가가면 화면이 깸(조율) → "공기가 텁텁하네"(생활) → 습관 카드(생활) → 맡기기 확인 칸(책임) → '알게 된 것'(생활·책임) → '이미 했어요'(조율) → 자동 실행·카메라 끄기(책임)

- 실제 기록이 모자라 연습 카드를 쓰면 띠의 그 장면에 '연습'을 붙인다. 환기 조언·전자레인지는 말로 한 줄씩만(띠에 넣지 않음).
- 화면은 키오스크·폰 미러링 + 기구 카메라.

## 4. 근거 한 장 (질의 대비 — 시간이 나면 7:30에 잠깐)

| 무엇 | 값 | 조건 |
|---|---|---|
| 말 알아듣기 | 규칙 거르기 뒤 맞힘 77%·잘못 고름 6%, 가운데값 약 10초·90%는 14초 안 | 고정 50문장+새 12문장, RPi5, 인터넷 없이, 공개 언어 모델(학습 없음). 규칙을 만든 문장 기준, 새 문장 12개는 4/5·0/7. 실행은 늘 '네' |
| 사람 감지 | 한 장 약 0.8초 | RPi5 CPU, 공개 사전학습 검출 모델 |
| 실제 사용 기록 | 10/25부터 N일 — 발표 날 기입 | 공기청정기, 같은 시간대 |
| 습관 카드 | 실제 기록에서 뜬 수 — 발표 날 기입(없으면 '학습 중') | 같은 시간대 사흘 이상·세 번 이상 |
| 시각 자동 실행 | 22:00 켜기·07:00 끄기, 상태 다시 읽어 확인 | 실제 공기청정기, 각 1회(10/16~17) |

- 거절 규칙(그대로 적는다): "연달아 두 번 거절하거나 답이 없으면 7일 쉬고, '이미 했어요'는 그날 다시 묻지 않는다."

## 5. 한계와 다음 단계 (7:30–8:20)

| 한계 (지금) | 다음 단계 |
|---|---|
| 습관 판단은 학습이 아니라 설명할 수 있는 규칙(시각 묶기·횟수) | 평일/주말을 묻는 때에 쓰고 "평일만인가요?" 한 번 확인 |
| 누구의 습관인지 사람을 구분하지 않는다 | 사람 구분 없이 할 수 있는 범위로 남긴다(얼굴 식별은 하지 않음) |
| 언어 모델이 잘못 고를 수 있다(새 문장 12개로만 따로 잼) | 새 문장을 더 늘려 다시 잰다. 실행은 늘 '네' |
| 열 안 나는 물리 가전 맡기기 미구현, 맡길 수 있는 것은 낮은 위험 LG 가전 동작뿐 | 사용자가 '맡겨도 되는 가전'으로 표시할 때만 |
| 팀 밖 사용자 시험 전 | 1~2명 점검 |
| 콘센트 전류(CT)는 아직 연결하지 않았다 | 다음 단계: 콘센트 전류로 가열 시작·끝 확인 |

- 하드웨어 한 줄(작게): "버튼만 있는 옛 가전은 누름 장치로 같은 흐름에 넣는다. 열 나는 가전은 맡기지 않고 매번 확인한다." 갠트리 기계는 같은 팀 HW 담당의 다른 프로젝트와 함께 쓴다 — [재사용 경계](../reuse-boundary.md). 질의에서 물으면 자세히.
