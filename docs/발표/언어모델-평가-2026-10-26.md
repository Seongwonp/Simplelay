# 기기 안 언어 모델 말 알아듣기 평가(2026-10-26)

"시험 문장 8개" 대신 **고정한 50문장**으로 다시 쟀다. 결론부터: **돌려 말한 말을 맞히는 힘은 약하고, 목록에 없는 말·부정하는 말에도 공기청정기 동작을 고르는 일이 잦다.** 그래서 실행은 지금처럼 **늘 사람이 '네'를 눌러야** 하고, 이 결과로는 그 확인을 줄일 근거가 없다.

> **같은 날 보강 뒤(§7):** 모델 학습 없이 모델 앞뒤에 규칙 거르기를 넣고 같은 50문장을 같은 방법으로 다시 쟀다 — 알아들어야 할 말 맞힘 **53% → 77%**, 골라선 안 될 말에 동작을 고름 **56% → 6%**. 규칙을 이 50문장의 틀린 것을 보고 만들었으므로 같은 묶음 숫자는 좋게 나오는 쪽이다. 새로 쓴 12문장은 §7-3. '네' 확인은 그대로다. 지시문에 예시 문장을 넣어 본 결과(나아지지 않아 넣지 않음)는 §8.

## 1. 무엇을 쟀나

- **문장 묶음:** [`rpi/intent/eval/llm_eval_ko.jsonl`](../../rpi/intent/eval/llm_eval_ko.jsonl) 50문장 — 돌려 말하기 20 · 직접 명령 10 · 부정/이미 함 8("방금 켰어"·"켜지 마") · 목록에 없는 부탁 8("에어컨 켜 줘"·"라면 끓여 줘") · 애매한 말 4("바꿔 줘"). 문장마다 맞다고 볼 동작(여러 개일 수 있음)이나 '고르지 않음'을 미리 적었다.
- **고를 수 있는 동작:** 10/26 허브에 실제로 있던 11개 — 공기청정기 전원 켜기·끄기, 바람 약·중·강·자동, 운전 모드 청정·수면·자동, 저장 루틴 2개(저녁 켜기·아침 끄기). 전자레인지·인덕션은 준비 전이라 목록에 없었다.
- **잰 방법:** RPi5 백엔드 컨테이너 안에서 말 알아듣기 함수(`understand()`)를 직접 불렀다([실행기](../../scripts/llm_eval_hub.py), [채점](../../scripts/llm_eval.py)). 키오스크·폰에 확인 질문을 만들지 않으려고 사용자용 경로는 쓰지 않았다. 규칙으로 바로 알아듣는 말은 규칙이, 나머지는 기기 안 언어 모델 서버의 LG 공개 언어 모델(2.4B, Q4, 학습 없음)이 번호를 고른다. 인터넷 없음, 제한 시간 20초(허브 설정 그대로), 문장마다 한 번.
- 처음에 사용자용 경로로 5문장을 보냈다가 키오스크에 확인 질문이 떠서 멈췄다. 그 5개는 버리고 50문장 전체를 위 방법으로 다시 쟀다(서버는 실행하지 않고, 누르지 않으면 60초 뒤 저절로 사라진다 — 멈춘 뒤 남은 질문 목록이 비어 있음을 확인).

## 3. 틀린 것

- **목록 밖인데 공기청정기를 고름:** "불 꺼 줘"→전원 끄기, "에어컨 켜 줘"→전원 켜기, "텔레비전 틀어 줘"→저녁 공기청정기 켜기, "세탁기 돌려 줘"→아침 공기청정기 끄기, "현관문 잠가 줘"→전원 끄기.
- **이미 했다/필요 없다는 말에 동작을 고름:** "방금 켰어"·"공기청정기는 이미 켜 놨어"·"지금은 켤 필요 없어"→전원 끄기, "아까 내가 껐어"→바람 중.
- **반대 방향:** "바람이 너무 세"→바람 강, "공기청정기 소리가 너무 시끄러워"→바람 강, "집에서 먼지 냄새가 나"→전원 끄기.
- **수면을 못 고름:** "이제 잘 거야"·"아기 재우려고 해"·"수면 모드로 바꿔 줘"→운전 모드 자동.
- **켜기 대신 바람 세기:** "방이 너무 답답해"→강, "숨 쉬기가 좀 답답하다"→중, "기침이 자꾸 나"·"연기가 자욱해"·"꽃가루 때문에 코가 간지러워"→약.
- 맞힌 것: "공기가 텁텁하네"→켜기(시연 문장), "미세먼지가 심하대"·"냄새가 좀 나네"·"청소기 돌렸더니 먼지가 날려"→켜기, "외출할 거야, 공기청정기는 이제 됐어"→끄기 등. 전체 표는 아래 §6.

## 4. 어떻게 말하나(발표·질의응답)

- "본체 안 언어 모델은 50문장 시험에서 돌려 말한 말을 절반 남짓만 맞혔고, 상관없는 말에도 동작을 고르는 일이 절반을 넘었습니다. 그래서 실행 권한을 주지 않습니다 — 고른 동작은 질문으로만 보이고, 사람이 '네'를 눌러야 실행됩니다. 부정하는 말('켜지 마')은 모델에 보내기 전에 규칙이 막습니다."
- 하면 안 되는 말: "알아듣습니다"(조건 없이), "정확합니다", "8개 중 8개".

## 5. 한계

- 한 번씩만 쟀다(같은 문장을 다시 보내면 답이 바뀔 수 있다). 50문장도 작은 표본이고 문장·정답은 우리가 정했다.
- 기기 하나(공기청정기) 동작 11개뿐이라 고를 것이 비슷비슷하다 — 기기가 늘면 결과가 달라진다.
- 정답을 넓게 잡은 문장이 있다("먼지가 많은 것 같아"는 켜기·강풍·청정 모두 맞음).
- 지시문·동작 설명을 손보면 나아질 수 있으나 이번에는 손대지 않았다(잰 그대로를 적음). 다음 단계 후보: 목록 밖·이미 함 말을 규칙에서 먼저 거르기, 모델이 고른 뒤 같은 기기 말이 문장에 있는지 확인하기(→ 같은 날 규칙 거르기로 넣고 다시 잼, §7).
- 시간은 말 알아듣기 함수 안에서 잰 값이다. 폰 음성 인식·네트워크·화면 표시 시간은 빠졌다.

모델은 그대로(학습·지시문 변경 없음) 두고, 말 알아듣기 함수 앞뒤에 규칙 거르기([`rpi/intent/llm_guard.py`](../../rpi/intent/llm_guard.py))를 넣었다. 규칙이 고른 것도 실행이 아니다 — 늘 같은 확인 질문('네')을 거친다.

- **모델 앞 ①목록 밖 대상:** 문장이 가리키는 기기·대상(에어컨·텔레비전·세탁기·불/조명·현관/문·커튼·보일러·냉장고·선풍기·가습기·음악 …)이 고를 동작 어디에도 없으면 '고르지 않음'. 덮인 대상은 동작 설명의 가전 종류와 이름에서 뽑는다(에어컨을 등록하면 "에어컨 켜 줘"는 막지 않는다).
- **모델 앞 ②이미 함·필요 없음:** "방금 켰어"·"이미 켜 놨어"·"아까 껐어"·"켤 필요 없어"·"괜찮아, 그냥 둬"는 '고르지 않음'(제안 카드의 '이미 했어요'와 같은 뜻).
- **모델 앞 ③뻔한 값:** "너무 세다·시끄럽다·조용히" → 바람 약, "너무 약하다" → 바람 강, "약하게·세게·중간" → 그 값, "수면·잘 거야·재우려고" → 수면 모드. 그 동작이 목록에 하나만 있을 때만(공기청정기가 둘이면 모델에 맡김).
- **모델 뒤 확인:** 고른 동작이 문장과 어긋나면 버린다 — 켜기 ↔ 끄는 말, 공기 불평(먼지·냄새·연기·답답·텁텁) ↔ 끄기·약풍, "너무 세다" ↔ 강풍, 문장이 말한 모드와 다른 모드.
- 지시문은 손대지 않았다(모델이 작고 한 번에 10초 남짓이라, 길게 늘리는 대신 규칙으로 거름).

### 7-1. 다시 잰 방법

§1과 같다 — RPi5 백엔드 컨테이너 안에서 같은 실행기·같은 11개 동작 사본으로 `understand()`만 직접 불렀다. 돌고 있는 서버는 건드리지 않으려고 바뀐 코드를 컨테이너 임시 폴더에 복사해 그 경로를 먼저 읽게 했고(컨테이너 재시작 없음), 끝나고 지웠다. 문장마다 한 번, 제한 시간 20초.

### 7-3. 새로 쓴 12문장(규칙을 만든 뒤 쓰고 손대지 않음)

### 7-4. 어떻게 말하나(보강 뒤)

- "본체 안 언어 모델만으로는 50문장 중 돌려 말한 말을 절반 남짓 맞혔고 상관없는 말에도 절반 넘게 동작을 골랐습니다. 그래서 모델 앞뒤에 규칙을 두었습니다 — 목록에 없는 기기·이미 한 일은 모델에 보내기 전에 거르고, 모델이 고른 것이 말과 반대면 버립니다. 같은 문장으로 다시 재 보니 맞힘 77%, 잘못 고름 6%였습니다. 그래도 실행은 늘 사람이 '네'를 눌러야 합니다."

## 8. 예시 문장 넣은 뒤(2026-10-26 같은 날 — 넣지 않기로 함)

모델 학습 없이 지시문에 예시 문장 몇 개("이런 말엔 이 번호")를 붙이면 돌려 말한 말을 더 맞히는지 쟀다. 예시 문장은 평가 문장(50개·새 12개)과 겹치지 않게 따로 썼다. 번호는 그때 목록에서 그 동작을 찾아 붙이고, 그 동작이 없거나 둘 이상이면 그 예시는 뺀다.

- **ㄱ안(7개, 한 줄에 하나):** "창문 열었더니 황사가 들어왔어"→켜기, "환기를 못 해서 꿉꿉해"→켜기, "페인트 냄새가 심해"→강풍, "이제 눈 좀 붙여야겠다"→수면, "윙윙거려서 집중이 안 돼"→약풍, "회사 다녀올게"→끄기, "배고프다"→고르지 않음.
- **ㄴ안(4개, 한 줄로 짧게):** 꿉꿉해→켜기, 눈 좀 붙여야겠다→수면, 회사 다녀올게→끄기, 배고프다→고르지 않음(강풍·약풍 예시 뺌).
- 잰 방법은 §7-1과 같다(컨테이너 임시 폴더, `understand()`만 직접, 같은 11개 동작, 문장마다 한 번, 재시작 없음, 끝나고 지움). 규칙 거르기는 그대로다.

| 항목 | 예시 없음(§7) | ㄱ안 7개 | ㄴ안 4개 |
|---|---|---|---|
| 돌려 말하기 맞힘(20개) | **13개** | 10개 | 12개 |
| 직접 명령(10개) | 10개 | 10개 | 10개 |
| 골라선 안 될 말에 동작을 고름(16개) | 1개 | 1개("라면 끓여 줘") | **0개** |
| 애매한 말에 동작을 고름(4개) | 1개 | 2개 | 2개 |
| 언어 모델 시간 가운데값 / 90% | 9.9초 / 14.0초 | **13.8초** / 14.1초 | 11.7초 / 12.9초 |
| 시연 문장 "공기가 텁텁하네" | 켜기 | 강풍(틀림) | 고르지 않음 |
| 새 12문장: 알아들을 말 5개 / 잘못 고름 7개 | 4개 / 0개 | 4개 / 0개 | 4개 / 0개 |

- **결론: 넣지 않는다.** 두 안 모두 돌려 말하기 맞힘이 늘지 않았고(13 → 10·12), 시간은 지시문이 길어진 만큼 늘었다(가운데값 +1.8초·+3.9초). ㄱ안은 강풍 예시를 따라 공기 불평 대부분에 강풍을 골랐다(켜기가 기대인 문장에서 틀림). ㄴ안은 잘못 고름이 1 → 0이었지만, 한 번씩 잰 차이라 우연일 수 있고 시연 문장을 놓쳤다. 코드는 예시 없는 지시문 그대로다.
- 한 번씩 쟀으므로 1~2개 차이는 실행마다 바뀌는 범위 안이다(§7-2 끝: 같은 문장도 답이 바뀐다). "예시를 넣으면 나빠진다"가 아니라 "이 크기 모델에서 예시 몇 개로는 나아지는 것을 확인하지 못했다"로 말한다.
- 다음 후보: 예시보다 동작 설명 한 줄을 손보기(켜기 줄에 "공기가 나쁠 때"를 붙이는 식), 또는 결선 뒤 평가 세트와 분리한 학습(고도화 계획의 미세조정 단계).
