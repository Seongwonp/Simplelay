# 정지 버튼 대기·보관 모의 동작

> 하드웨어 개발 기준(사용자 정정): FIT0482 ×3(A/B/Z), JMOD-MOTOR-1 ×2. Z 기구·거리 환산·채널 배선은 미확정이며 아래 모션은 이 모터의 실제 동역학을 재현하지 않는다.

## CoreXY 예상 모션 추가

현재 확인 서버: http://127.0.0.1:8767/simulator/parking (`python -m rpi.simulator_main --port 8767`). 기존 실행 중 서버를 중단하지 않고 새 코드 확인용으로 포트를 분리했다.

- 노란 캐리지·가로 레일 이동, A/B 모터 회전, 벨트 표시, Z 측면 누름/복귀를 SVG 애니메이션으로 표현한다. 벨트의 도면상 경로와 모터 회전 각도는 **개념도**이며 제작된 CoreXY의 실제 벨트 배선·풀리 반경·엔코더 부호·RPM을 반영한 디지털 트윈은 아니다.
- 같은 정규화 좌표 단위에서 ΔA=ΔX+ΔY, ΔB=ΔX−ΔY로 상대 벨트 변위를 계산한다. 1·3·6초는 미리보기 재생 시간이다. 실제 장치 속도나 정지 지연이 아니다.
- **버튼 입력 종료 위치**를 X/Y로 명시적으로 주입하면 정지 위치로 가는 모의 출발점이 생긴다. API에서 이를 생략한 기존 호출은 위치 미확인으로 남고 XY 애니메이션을 만들지 않는다.
- 흰 원은 마지막 모의 확인 위치, 노란 캐리지는 예상 위치다. 애니메이션 종료는 ACK·가전 종료 관측을 생성하지 않는다. 성공 응답은 사용자가 별도 주입해야 한다.
- 반복 상태 조회는 모션을 재시작하지 않는다. 통신 오류·잠금은 모션을 취소하고 예상 캐리지를 숨긴다. 화면을 떠나면 모션만 일시 중지하며, 다시 재생은 서버 상태에 영향을 주지 않는다. OS의 동작 줄이기 설정과 화면의 체크박스를 지원한다.
- Z는 가상의 전체 스트로크로 표현한다. 실제 초기 깊이가 관측됐다는 뜻이 아니다.

검증: CoreXY 계산·역변환·완료 시 ACK 미생성·반복 조회·고장 중단 JS 테스트 4건(`node --test rpi/tests/corexy_preview.test.cjs`), 관련 Python 테스트 27건 통과. 브라우저에서 예상 XY 이동과 모터 변위, 모션 종료 후에도 확인 위치가 출발점에 남는 것을 확인했다. 이번 변경은 아직 커밋·푸시하지 않았다. 실제 매핑 저장 계약은 다음 단계다.

## 브라우저 조작 추가

`python -m rpi.simulator_main --port 8766` 실행 후 http://127.0.0.1:8766/simulator/parking 에서 확인한다. 기존 서버가 8765에서 실행 중이어서 이번 확인에는 별도 포트를 사용했다.

1. 정지 X/Y와 보관 X·상단/하단을 입력하고 **새 모의 세션**을 만든다.
2. **초기 보관 위치·Z 확인 주입 → 버튼 시퀀스 시작 → 버튼 입력 완료 주입**을 누른다.
3. **현재 동작 성공 응답 주입**을 두 번 눌러 Z 복귀와 정지 좌표 이동을 각각 확인한다.
4. **가전 정지 요청** 후 성공 응답을 두 번 주입한다. 누름·Z 복귀가 확인돼도 가전 종료는 미확인으로 남는다.
5. **가전 종료 관측 주입** 후 성공 응답을 두 번 주입하면 보관 위치로 간다.

실패 응답·통신 유실·구동부 비상정지도 모의로 주입할 수 있다. 흰 원은 마지막 확인 위치, 점선 원은 이동 목표다. 실제 위치 추적이나 이동 애니메이션이 아니다. 현재 API는 독립 모델을 조작하며 기존 실행기·`/stop`과 연결되지 않는다.

서버별로 하나의 모의 상태를 공유한다. 세션 ID·상태 판 번호·동작 ID를 대조해 다른 창의 변경, 중복 클릭, 초기화 전 응답을 거절한다. 새 세션은 모의 기록 초기화이며 실제 장치 복구 명령이 아니다. 실제 SimulatorController인 서버에서만 페이지/API가 열린다.

브라우저용 API·독립 상태 모델·기존 시뮬레이터 관련 테스트 30건 통과. 브라우저에서 초기 위치부터 정지 대기, 정지 누름 후 종료 미확인, 별도 종료 관측 후 보관까지 직접 조작해 확인했다.

브라우저 연결 후 최종 백엔드 전체 **1,541건 통과**(기존 의존성 경고 2건). 커밋·푸시는 수행하지 않았다.

## 구현 범위

`rpi4/parking_simulator.py`는 실제 모터·API·기존 Act 통신과 연결되지 않은 독립 상태 모델이다. `python -m rpi4.parking_simulator`로 대기 → 정지 버튼 입력 확인 → 가전 종료 확인 → 보관의 JSON 기록을 확인한다. 모든 위치 확인·누름 확인·가전 종료 관측은 테스트가 주입하는 **모의 근거**다.

- 정지 버튼 좌표와 상단/하단 보관 좌표를 명시적으로 분리한다. 좌표는 0~1 시뮬레이션 좌표이며 mm·모터 스텝이 아니다. 실제 이동 경로의 충돌·접근 가능성을 보장하지 않는다.
- 초기 보관 위치·Z 복귀를 모의로 확인한 뒤 버튼 시퀀스를 시작한다.
- 버튼 입력 완료 → Z 복귀 응답 → 정지 좌표 이동 응답 → 누르지 않고 대기한다. 버튼 입력 완료는 가전 운전 종료가 아니다.
- 대기 중 가전 정지 요청 → 정지 버튼 누름 응답 → Z 복귀 → 가전 정지 확인 대기. 중복 요청으로 다시 누르지 않는다.
- 정지 좌표 접근 중 요청은 현재 이동 확인 뒤 처리한다. 이 모델은 실행 중인 이동을 선점하거나 물리적 즉시 정지를 보장하지 않는다.
- 자연 종료 또는 가전 정지를 별도로 확인한 뒤 Z 복귀 응답 → 보관 이동 응답 순서로 진행한다.
- 구동부 비상정지, 통신 유실, 이동/복귀 실패는 잠금 상태로 전환한다. 자동 재가동·자동 파킹하지 않고 늦은 응답도 거절한다. 새 세션 초기화는 모의 수동 복구를 뜻하며 실제 복구 절차가 구현된 것은 아니다.

## 남은 연결 작업

1. 버튼 시퀀스 도중 중단 요청: 기존 시퀀스 취소의 확정 결과와 위치·Z 상태를 받은 뒤 가전 정지 절차로 넘어가는 연결이 필요하다. 현재 모델에서는 해당 요청을 거절한다.
2. 이동 중 가전 종료 관측: 현재 동작이 정리된 뒤 관측을 입력하는 방식이다. 실제 비동기 관측의 순서·유효기간·작업 ID는 후속 통합에서 다룬다.
3. 실제 매핑 저장/API/앱 편집 화면, 정지 동작 종류(짧게·길게·일시정지·취소), 좌표 보정 판 번호는 미연결이다.
4. 기존 `/stop`, Act 통신, 브라우저 시뮬레이터는 변경하지 않았다. 이 모듈이 그 경로의 정지 기능을 강화했다고 해석하지 않는다.
5. Z 복귀 센서·누름 피드백, 이동 한계·충돌 방지, 전력/음향 기반 종료 관측, 독립 비상정지 회로는 하드웨어 확인이 필요하다.

## 검증

독립 테스트 `rpi4/tests/test_parking_simulator.py` **17건 통과**. 상단/하단 보관, 정지 누름과 가전 종료의 분리, 중복 정지 요청, 접근 중 요청, 고장 잠금·늦은 응답 거절, Z 복귀 실패 시 XY 이동 금지, 좌표 검증을 확인했다. 이번 단계에서 백엔드 전체·실기기·UI 테스트는 실행하지 않았다.
