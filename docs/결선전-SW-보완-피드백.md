# 결선 전 SW 보완 피드백

작성일: 2026-10-17

이 문서는 결선 직전 소프트웨어의 우선순위를 정리한다. 새 기능을 늘리기보다
실물 통합 흐름을 안전하게 실행하고, 실패했을 때 무엇이 일어났는지 설명할 수
있는 상태를 만드는 것을 목표로 한다.

## 현재 판단

- 승인 지문, 정지 단계, 비상정지 래치, 자동 실행 중복 방지, 조용한 시간,
  ThinQ 대상 검증 등 핵심 안전 계약은 이미 코드와 시험으로 상당 부분 고정되어 있다.
- RPi5에서 ThinQ 실가전 연계를 확인했다. 공기청정기가 22:00에 켜지고
  다음 날 07:00에 꺼지는 시각 자동 루틴과 자동 실행 결과를 실제로 확인했다.
- 남은 가장 큰 위험은 기능의 부재가 아니라 `CoreXY 실제 버튼 누름 → CT
  가열 시작·종료 감지 → 자동 실행 → ThinQ 상태 확인`을 같은 설치 환경에서
  반복했을 때의 관측성·복구성이다.

## 우선순위

### 1. 실물 통합 실행 기록

하나의 실행을 `run_id` 또는 이에 준하는 식별자로 묶어 다음 단계가 같은
기록으로 이어지게 한다.

1. 버튼 누름 요청·실제 누름 확인
2. CT 가열 시작 감지
3. CT 가열 종료 감지
4. 자동 실행 판단과 방해금지(조용한 시간) 판정
5. ThinQ 명령 전송과 상태 재조회
6. 최종 결과와 실패 이유

각 단계에는 허브 시각, 결과, 근거, 실패 원인을 남긴다. 앱·키오스크·서버
로그가 서로 다른 실행을 섞어 보여 주지 않아야 한다.

### 2. 예외 처리의 완성

예외 처리는 `try/catch`의 개수가 아니라 다음 네 가지가 모든 실패 경로에
있는지를 기준으로 확인한다.

1. 안전한 상태로 멈추는가
2. 성공으로 잘못 표시하지 않는가
3. 원인과 확인 수준이 기록되는가
4. 사용자가 다음에 할 일을 알 수 있는가

결선에서 반드시 재현할 경로:

| 상황 | 기대 결과 |
|---|---|
| CoreXY가 버튼을 누르지 못함 | 성공 표시 금지, 누름 확인 불가 기록, 재시도 여부를 명확히 안내 |
| CT 가열 시작 미감지 | 가열 종료 자동화로 진행하지 않음 |
| CT 가열 종료 미감지 | 자동 실행하지 않음, 가열 종료 미확인 기록 |
| ThinQ 응답 지연·연결 끊김 | 결과 확인 불가로 기록, 근거 없는 재전송 금지 |
| 조용한 시간과 실행 시각이 겹침 | 실행하지 않고 조용한 시간으로 건너뜀 기록 |
| 자동 실행 중 정지·비상정지 | 아직 보내지 않은 동작 차단, 정지 수준을 실제 확인 단계까지만 표시 |
| RPi5 재시작 뒤 오래된 사건 수신 | 이전 사건을 새 사건으로 오인하거나 중복 실행하지 않음 |
| 키오스크가 이전 실행 결과를 표시 | 새 실행의 `job_id`·이벤트 순번을 기준으로 화면 전환 |

### 3. CT 결과 문구와 근거

현재 CT만으로 정상 종료, 취소, 문 열림 종료를 구분하지 못한다. 따라서
코드·앱·키오스크·발표 문구에서 `조리 완료`라고 단정하지 않고 다음 표현을
사용한다.

> 가열 종료를 감지했어요. 조리 완료인지는 확인하지 못했어요.

CT 이벤트에는 가능하면 감지 종류, 관측 구간, 감지 시각, 입력 근거를 함께
남긴다. 정상 종료와 취소·문 열림을 구분할 수 있게 되기 전까지는 자동
실행 정책의 한계도 기록에 남긴다.

### 4. 자동 실행 상태 설명

자동 실행 규칙 카드와 기록에는 다음 상태를 구분해 보여 준다.

- 켜짐
- 이번 실행은 조용한 시간이라 건너뜀
- 연결 불가 또는 결과 확인 불가
- 대상 가전이 바뀌어 다시 허용 필요
- 마지막 실행 결과와 다음 실행 시각

특히 조용한 시간에 건너뛴 사건은 시간이 지난 뒤 자동으로 재실행하지 않는다는
점을 화면과 기록에서 일관되게 말한다.

### 5. 루틴 저장과 자동화 허용의 분리

사용 기록에서 만든 루틴 초안은 저장만 하며, 저장했다고 자동 실행되지 않는다.
사용자가 별도로 자동 실행 내용을 확인하고 허용해야 규칙이 켜진다. 화면 문구도
다음 두 단계를 분명히 구분한다.

- `루틴으로 저장`: 저장만 하며 아직 자동 실행하지 않음
- `다음부터도 자동으로`: 조건·대상·동작을 확인한 뒤 승인 없이 실행

CoreXY 물리 버튼 누름은 자동 실행 대상이 아니며, 매번 사용자 승인이 필요하다.
자동 실행은 허용된 낮은 위험도의 ThinQ 동작에 한정한다.

## 결선 전 검증 묶음

### 정상 흐름

- 실제 설치 환경에서 버튼 누름 확인
- CT 가열 시작·종료 감지
- 허용된 자동 실행 규칙 실행
- ThinQ 상태 재조회로 결과 확인
- 앱·키오스크·기록에서 같은 실행이 같은 결과로 보이는지 확인

### 실패 흐름

- 버튼 누름 실패
- CT 시작·종료 미감지
- ThinQ 응답 지연·상태 재조회 실패
- 조용한 시간과 겹치는 시각 실행
- 실행 중 정지와 비상정지
- RPi5 재시작 뒤 중복 사건
- `실행 → 정지 → 다음 실행` 연속 동작

각 항목은 영상만 남기지 말고 다음 표로 함께 기록한다.

`시각 | run/job 식별자 | 입력 | 기대 결과 | 실제 결과 | 화면 문구 | 복구 방법`

## 우선순위가 낮은 작업

새로운 AI 기능, 새로운 루틴 종류, 장식적인 UI 변경은 위 통합 흐름과 실패
복구 검증이 끝난 뒤로 미룬다. 결선 직전에는 “더 많이 한다”보다 “실패해도
안전하고, 무엇이 확인됐는지 증명한다”가 중요하다.
