# 코드 구조

SimpleLay 코드가 **어느 보드에서 어떤 파일로 돌고**, 안전 약속이 **어느 함수에 있고 어느 시험이 지키는지**, 요청이 **어떤 순서로 지나가는지**를 한 장에 모은 문서다.
심사위원·팀원이 코드를 처음 열 때 읽는다.

## 0. 읽는 법

- **기준 커밋:** `55d2a06`(2026-10-15). 아래 `파일:줄`은 이 커밋 기준이다. 코드가 바뀌면 줄 번호는 어긋난다 — 함수 이름으로 다시 찾는다.
- **검증 수준:** 이 문서는 코드가 **어떻게 짜여 있는지**만 말한다. 무엇이 실물로 확인됐는지는 저장소 [README](../README.md)의 검증 수준 표가 기준이다.
  여기서 "실물"은 실제 보드·기기에서 본 것, "모의"는 가짜 장치·모의 클라우드·시험 코드로만 본 것이다.
- **폴더 이름의 역사:** `rpi/`는 보드 하나로 설계하던 시절의 이름이다. 지금 `rpi/`의 대부분은 **RPi5 허브**에서 돌지만,
  `rpi/controller`·`rpi/verifier`·`rpi/tools/fake_*`는 **RPi4 실행기도 import하는 공용 라이브러리**다 —
  `rpi4/` 운영 코드(시험 제외)가 `rpi.controller`를 25번, `rpi.verifier`를 29번 import한다(시험 포함 86·55번).
  그 밖에 `rpi.services.link_auth`·`demo_failure`·`act_client`, `rpi.tools.jog`·`fake_outlet`도 RPi4가 쓴다.
  모션 보드 어댑터(`rpi/controller/serial_motion.py`)와 센서 판정(`rpi/verifier/`)은 이름과 달리 **RPi4에서 돈다.**
- 환경 변수는 [환경 변수](환경변수.md), 시험 지도는 [rpi/tests/README](../rpi/tests/README.md), 배포는 [deploy/README](../deploy/README.md).

### '확인됨'의 수준이 두 곳에서 다르다 — 의도한 차이

| 어디 | '확인'으로 치는 단계 | 근거 |
| --- | --- | --- |
| 서버 `stop_level_confirmed`(`rpi/services/stop_confirm.py:31`) → `/stop` 응답 `stop_confirmed`(`rpi/api/router.py:1000`) | `mcu_ack` 이상 | 안전 계약 ①의 '확인' = **제어기(모션 보드) 응답**. 가전이 멈췄다는 뜻이 아니다 |
| 폰 `stopLevelConfirmed`(`app/lib/models/command_result.dart:204`) — 개발자 콘솔(`developer_console_screen.dart:394-405`)이 문제 표시에 씀 | `mcu_ack` 이상 | 개발자가 링크·보드 응답을 보는 화면이라 서버 정의를 따른다. 일반 화면은 단계별 문장만 쓴다 |
| 키오스크 `stopLevelConfirmed`(`rpi5-touchscreen-app/lib/models/command_result.dart:164`) → 완료 화면 ✓(`done_view.dart:210`) | **`verified`만** | [키오스크 문구 개선 계획](키오스크-문구-개선-계획-2026-10-15.md) §2-1 — 매일 쓰는 사람에게 ✓와 "작은 팔이 멈췄어요"는 **엔코더로 멈춤을 확인했을 때만** 보인다. `mcu_ack`는 "정지 신호를 받았어요 — 멈췄는지는 확인 못 했어요"와 ? 아이콘 |

서버가 `stop_confirmed=true`를 줘도 키오스크는 `stop_level`을 다시 읽어 ✓를 정한다. 셋을 하나로 맞추지 않는 것은 **보는 사람이 다르기 때문**이다(개발자: 보드가 받았나 / 당사자: 멈췄나).
단, `verified`도 "값이 안 변함"으로 판정하므로 엔코더가 죽어 있으면 거짓 확인이 될 수 있다(G11, 아래).

### 열린 빈칸

[안전 계약 적용 보고](안전계약-적용-보고-2026-10-15.md) §2가 기준이다 — G1~G11과 키오스크 두 번 누름 **R1**.
**수리(시험 조건만, 보드 미배포):** **G1** 승인·루틴 경로 링크 끊김 → '눌렸는지 모름' 기록, **G2** 접수 뒤·보내기 전 정지, **G11** 죽은 엔코더의 '멈춤 확인'
([10/15 devlog](devlog/devlog_2026-10-15-safety-g2-g1-g11.md)), **G3** 루틴 구간 사이 정지(`/stop` 맨 앞 루틴 정지 표시·기다림 뒤 재확인·다음 구간 실행 시작 게이트),
**G7** 텍스트·홈 음성 "멈춰"가 '취소' 버튼 누름 → 해석 맨 앞 정지어 판정(`rpi/intent/stop_words.py`)으로 `/stop`의 뜻, 폰 홈 음성도 정지어면 정지를 보냄
([10/16 devlog](devlog/devlog_2026-10-16-safety-g3-g7.md)), **G5** 조용한 Wi-Fi 끊김 → 실행 중 RPi5→RPi4 생존 신호(`rpi/services/link_heartbeat.py`, 주기 1 s·제한 3 s 추측값),
끊기면 RPi4가 받은 정지와 같은 길로 스스로 멈추고(`ActExecutor.check_link_watchdog`) RPi5는 '눌렸는지 모름'으로 남김([G5 devlog](devlog/devlog_2026-10-16-safety-g5.md) — RPi4·RPi5 같은 커밋 배포 필수).
**10/16 추가 수리(시험 조건만·보드 미배포):** G4 실제 쓰기 잠금 안의 정지 재확인, G9 hold 해제 대기를 수신 루프 밖 실행 task로 옮김. G10은 정지 대상별 의미를 문서화하고 기존 동작 시험만 추가했다([기록](devlog/devlog_2026-10-16-safety-g4-g9-g10.md)). RPi4 실행 코드 변경이므로 RPi5·RPi4 같은 커밋 배포 필요.
**R1 자동 재누름 수리(10/16, 시험 조건만·보드 미배포):** 버튼 정의 `behavior` → 서비스 실행 스냅샷 → `execute.button_behaviors` → RPi4 공유 폐루프. toggle·unknown의 L1/L2 재누름을 막고 미확인으로 기록한다. idempotent만 기존 재시도를 유지한다([기록](devlog/devlog_2026-10-16-r1-docs.md), [규약](protocol.md)).
**남음:** G6·G8, R1 사람의 전체 재실행·버튼 분류 실측. G5 socat 재접속 지연·실물 PS-1도 별도 확인이 필요하다.
이 문서의 흐름 설명 일부는 수리 전 코드 기준이다.

## 4. 보드 사이 규약

- **RPi5 ↔ RPi4:** [protocol.md](protocol.md)의 'UART 프로토콜 (RPi5 ↔ RPi4)' 절 — 링크 인증(10/12), RPi5 → RPi4(execute·abort·estop_ack·dev_motion 등), RPi4 → RPi5(result·stop_report·estop_state·appliance_done 등)와 '추가 프레임' 절.
  선은 Wi-Fi 위 TCP 7000이고 RPi4 컨테이너 안에서 가상 시리얼로 바뀐다([deploy/README](../deploy/README.md)).
- **RPi4 ↔ 모션 보드:** protocol.md '모션 MCU 링크' 절. **기준표는 미채택 폴더에 있는 [`firmware-motion/protocol_table.json`](../firmware-motion/protocol_table.json)이다** —
  어댑터·가짜 모션 보드·현행 펌웨어가 이 표를 따르는지 `test_motion_protocol_table.py`가 본다. 폴더를 옮기거나 지울 때 이 표를 먼저 옮긴다.
- **RPi4 ↔ 콘센트 모듈:** protocol.md '콘센트 모듈 링크' 절(컴파일·가짜 출력 수준).
- **가짜 장치:** `rpi/tools/fake_mcu.py`(모션 보드)·`rpi/tools/fake_outlet.py`(콘센트 모듈)·`rpi/tools/fake_thinq_cloud.py` — 하드웨어 없이 같은 규약으로 시험한다.
- **HTTP:** 폰·키오스크 ↔ RPi5. `/status`의 마지막 칸 필드·ThinQ 결과 네 경우는 protocol.md 뒤쪽 절.

**10/28 제출 전에는 하지 않는다.** 이유:

1. **시험이 조용히 약해진다.** 시험 다수가 모듈 속성을 직접 바꿔 끼운다(`monkeypatch.setattr(모듈, …)` 약 180곳). 코드를 다른 모듈로 옮기면 바꿔 끼운 자리가 실제 코드에서 쓰이지 않게 되는데도
   시험은 실패하지 않고 통과할 수 있다 — 안전 시험이 아무것도 지키지 않는 상태가 된다. 옮길 때마다 수정 전 실패 확인을 다시 해야 한다.
2. **열린 수리와 겹친다.** G1·G2·G11 수리가 `service.py`·`service_commands.py`·`act_client*`·`act_executor.py`·`serial_motion.py`를 고치는 중이다. 같은 파일을 동시에 나누면 충돌하고 수리 검증이 흐려진다.
3. **보드 배포와 맞물린다.** RPi5·RPi4는 같은 커밋으로 배포해야 한다. 구조 변경은 보드 날 검증을 한 번 더 요구한다.

그 대신 지금은 이 문서·패키지 README·[환경 변수](환경변수.md)·[시험 지도](../rpi/tests/README.md)로 구조를 드러내고, 새 경로의 인증 누락은 `test_route_auth_coverage.py`로 막는다.
