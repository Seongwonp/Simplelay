# 온디바이스 vs 클라우드 추론 경계

> SimpleLay 안에서 "추론"이 필요한 작업마다 어디서 돌릴지, 왜 그런지, 언제 다른 쪽으로
> 넘어가는지를 정의한다. 이 문서는 판단 기준과 결론만 다루고, 특정 모델·API·SDK 이름은
> 적지 않는다(구현 시점에 팀이 선택).

---

## 판단 기준 4가지

| 축 | 왜 중요한가 |
| --- | --- |
| **지연시간** | 사용자가 그 자리에서 기다리는 폐루프 흐름이라, 왕복 지연이 곧 체감 반응성이다 |
| **신뢰성 / 네트워크 의존성** | 결선 시연장·실제 가정 Wi-Fi는 우리가 통제할 수 없다. 핵심 기능이 외부망에 의존하면 그 자체가 새로운 실패 지점이 된다 |
| **개인정보** | 음성 명령·사용 패턴은 가정 내 루틴 데이터다. 꼭 필요한 최소한만 기기 밖으로 내보낸다 |
| **처리 능력 한계** | 자유발화 이해도나 복잡한 추론은 소형 온디바이스 모델이 못 따라갈 수 있다 — 무조건 온디바이스가 답은 아니다 |

**우선순위**: 앞의 세 축(지연시간·신뢰성·개인정보)이 네 번째 축(처리 능력)보다 먼저다.
"더 똑똑한 답"보다 "그 자리에서, 인터넷 없이도, 확실하게 나오는 답"을 우선한다 — 이게
SimpleLay의 핵심 차별점인 "자가 검증 + 선제 제어"(문서 없이도 스스로 확인하고 재시도하는
구조)와 같은 방향이기 때문이다. 폐루프의 신뢰성을 외부 API 가용성에 걸어서는 안 된다.

---

## 태스크별 결정

### 1. 의도 해석 (목적 텍스트 → 버튼 시퀀스·가전 동작) — `rpi/intent/`

가장 중요한 결정. **실제 경로는 본체(RPi5) 안의 결정론적 규칙 계층 하나다**(2026-10-19 기준). 결과는 언제나
그 가전에 등록된 닫힌 동작 목록 중 하나 또는 '모름'이고, 어느 경우든 실행 전에 사람이 확인한다.

**지금 실제로 도는 것(본체 안, 인터넷 불필요):**

1. **정지어 먼저** — 발화 전체가 "멈춰"·"그만"·"정지" 같은 정지어면 해석하지 않고 `POST /stop`과 같은 뜻으로
   보낸다(`rpi/intent/stop_words.py`, 안전 보고 G7). 아래 다듬기보다 앞이며 원래 문장으로 판정한다.
2. **말 다듬기 + 같은 뜻 사전** — `rpi/intent/normalize.py`가 공백·문장부호·군말('좀'·'한번' 등)을 빼고 끝
   어미('해 줘'·'해 주세요'·'줄래'·'할래')를 표준형으로, 가전 이름('공청기'·'공기정화기' → 공기청정기)과 끝 동작
   ('틀어' → 켜, '바람 세게'·'강하게' → 강풍 등)을 표준 낱말로 바꾼다. 표는 `rpi/intent/voice_lexicon.py` **한 곳**이고,
   전자레인지 규칙 표(`rpi/intent/rules.py`)·LG 가전 동작 비교(`rpi/services/thinq/bindings.py`)·사용자 등록 기능
   이름이 같은 다듬기를 쓴다. 표에 없는 말은 짐작하지 않는다. 부정('켜지 마'·'안 켜')과 다듬은 결과가 정지어인 말은
   일치시키지 않는다.
3. **'혹시 이것인가요?' 후보** — 2로도 못 찾았을 때만, 한글 자모로 풀어 편집 거리로 그 가전의 등록 동작과 비교해
   후보 **하나**를 고른다. 점수 하한 미만·1·2위 차이가 작음·반대 뜻(켜/꺼, 강/약, 시작/일시정지 — 동사 글자는 퍼지로
   고치지 않는다)·부정이면 후보가 없다. 후보는 **실행하지 않는다** — `POST /execute`의 422 응답 본문에
   `suggestion: {purpose, label}`로, 그 가전이 할 수 있는 동작 목록은 `choices: [{purpose, label}]`로 싣는다.
   사람이 고르면 그 목적 문장으로 기존 경로(확인 → 실행)를 다시 탄다. 하한값(점수 0.8·차이 0.1)은 시험 세트로 정한
   값이며 본체 실발화로는 아직 재지 않았다(추측/측정 필요).

   **화면(폰 음성 화면, `app/lib/screens/voice_screen.dart`, 10/19 커밋 `60747343`):** 422 본문에 `suggestion`이나
   `choices`가 있으면 본체가 준 이유 한 줄 아래에 **'혹시 이것인가요? {label}'** 버튼 하나, **'{가전 이름}이/가 할 수 있는
   일이에요'** 아래 동작 버튼 목록, '이렇게 말해 보세요: …' 예시를 화면에 남긴다(곧 사라지는 알림이 아니다). 어느 버튼을
   눌러도 **실행하지 않고** 그 `purpose` 문장을 입력 칸에 올려 기존 확인('이대로 실행할까요?')을 다시 묻는다 — 사람이 그
   확인을 눌러야 `POST /execute`가 다시 간다. 본문에 두 필드가 모두 없는 옛 서버면 종전 안내('무슨 말인지 몰랐어요. 다시
   말해 주세요.')를 쓴다. 시험: `app/test/screens/voice_screen_test.dart`의 '못 알아들은 말(422) — 후보·할 수 있는 일' 묶음
   4건(화면에 남김·후보를 눌러도 확인부터·동작 목록도 확인부터·옛 서버 종전 안내). 키오스크는 음성 입력·`/execute`가 없어
   이 화면이 없다. 실폰·실발화로는 아직 확인하지 않았다(위젯 시험 수준).

시험: `rpi/tests/test_voice_normalize_1019.py` — 한국어 변형 58문장(반대 뜻·부정·목록 밖·한 글자 인식 오류 포함)에서
**다른 동작으로 잘못 매칭 0건**을 단정한다. 같은 시험이 '모름' 비율과 문장당 지연을 개발 PC에서 재서 출력한다(RPi5 값은
측정 필요). 조사·근거는 [음성 의도 해석 조사](음성-의도-해석-조사-2026-10-19.md).

**본체 안 언어 모델(10/26부터 결선 경로에서 씀):** `SIMPLELAY_LLM_URL`(루프백 전용 기기 안 서버, `rpi/intent/llm_intent.py`)을
켜 두면, 규칙으로 못 알아들은 말("공기가 텁텁하네" 같은 간접 표현)을 **허용된 동작 목록 중 하나로 고르는 데만** 쓴다. 목록에 없는
말은 '잘 모르겠어요'로 끝나고, 결과는 늘 사용자가 '네'로 확인해야 실행된다. 인터넷 없이 고정 50문장+새 12문장으로 쟀다 — 모델까지 가면 가운데값 약 10초·90%는 14초 안,
규칙 거르기 뒤 맞힘 77%·잘못 고름 6%(규칙을 만든 문장 기준, 새 문장 12개는 4/5·0/7), 돌려 말하기 13/20
([언어 모델 평가](발표/언어모델-평가-2026-10-26.md)).

**배선은 있으나 결선 경로에서 쓰지 않는 것:**

- **기기 내장 대화형 에이전트**(`rpi/intent/dbus_agent.py`, `SIMPLELAY_LLM_MODE=dbus`일 때만) — 처음에는 기기 안에서
  끝나는 계층으로 기대했으나, 10/19 실기기 확인에서 **클라우드에 의존하고 응답이 오지 않았다**. 인터넷이 끊기면 쓸 수
  없고 응답을 기다리는 동안 사용자가 멈춰 있게 되므로 결선 경로에서 켜지 않는다(기본 꺼짐).
- **기기 벡터 검색 유사도 계층**(`rpi/intent/dbus_vectordb.py`, 같은 환경 변수로만 켜짐) — 우리 보드에는 그 서비스와
  임베딩 모델이 없어 **꺼져 있다**. 켜도 빈 검색이라 다음 계층으로 넘어갈 뿐이다.
- **외부 언어모델**(`SIMPLELAY_LLM_BASE_URL`, 기본 꺼짐) — 운영자가 명시적으로 켤 때만. 결선 경로에서 쓰지 않는다(위 본체 안 언어 모델과 다른 설정이다).

조립은 `rpi/api/deps.py`의 `_build_intent_resolver()`가 `TieredIntentResolver`로 한다 — 규칙 계층이 항상 맨 앞이고,
위 선택 계층은 환경 변수로 켤 때만 뒤에 붙는다. **기본 상태(아무 설정 없음)에서 오프라인으로 완결된다.**

> 한동안 코드가 유사도를 규칙보다 **앞에** 두고 있었다(8/26 수리). 먼저 성공한 계층이 이기므로 유사도가 임계값만 넘기면
> 정확한 규칙을 덮어쓸 수 있었다. 순서는 테스트로 고정해 뒀다.

> 순서에 대한 주의: `rpi/intent/llm.py`의 `LlmIntentResolver(client, fallback)`는 그 자체로는 "모델 먼저, 실패하면 폴백"
> 구조다. 이 문서의 원칙(싼 것·확실한 것 먼저)은 그 클래스를 고쳐서가 아니라 바깥에서 `TieredIntentResolver`로 순서를
> 강제해 달성한다.

### 2. 사용 패턴 학습 · 선제 제안 — `rpi/intent/patterns.py`

모델이 아니라 **본체 안의 통계**다. 최근 28일(`window_days`) 사용 기록에서 같은 가전·같은 목적을 시간대별로 세어,
정한 횟수 이상·여러 날에 걸쳐(`minimum_days`) 반복된 것만 제안 후보로 올린다. 기록과 계산이 모두 본체 안에 있고
기기 밖으로 나가지 않는다.

### 3. 음성 인식(STT) — 앱(`app/lib/services/voice_service.dart`)

`speech_to_text` 패키지가 폰 OS의 음성 인식 API에 위임한다. 온디바이스로 처리할지 OS가
자체적으로 클라우드를 쓸지는 폰 운영체제가 결정하는 영역이라 SimpleLay 코드가 관여하지
않는다. 현재 상태 그대로 둔다.

### 4. 카메라로 가전 버튼 배치 인식 — `rpi/vision/`, `POST /panel-scan`

기기 설정 시 1회만 실행하는 작업이라 지연시간 축이 거의 안 걸린다. 반복 실행되는 폐루프
경로가 아니므로 온디바이스를 기본으로 권장하되(개인정보·비용), 인식 정확도가 부족하면
설정 단계에 한해 외부 경로를 선택 옵션으로 열어둘 수 있다 — 이 기능은 실시간 사용자 대기
흐름 밖에 있으므로 1번 항목만큼 엄격하게 온디바이스를 강제할 이유는 없다.

**현재 배선(2026-09-15)**: 외부 경로를 **선택 기능, 기본 꺼짐**으로 구현했다.

- 운영자가 인식 서비스 주소·키·모델 환경변수 셋을 모두 줘야 켜진다. 하나라도 없으면 503.
- 사진은 조작부 한 장만 보내고, 서버는 사진을 저장하거나 로그에 남기지 않는다. 키는 서버
  환경에만 두고 앱에 넣지 않는다.
- 응답은 믿지 않는 입력으로 검증해 **초안**만 돌려준다. 저장은 사람이 확인한 뒤 기존 등록
  API가 한다. 누를 mm 좌표는 기준점 보정을 통과했을 때만 채운다.
- 실행 경로(목적 → 누름 → 판정)는 이 기능을 부르지 않는다. 인터넷이 끊겨도 폐루프는 그대로다.
- 실제 서비스 응답(사진 입력 지원, 좌표 축 순서, 정확도)은 **아직 확인 전**이다 —
  `scripts/vision_gateway_probe.py`로 서버와 같은 요청·변환을 돌려 확인한다.

### 5. 제안 음성 안내(TTS)

가벼운 작업이라 온디바이스가 자연스러운 기본값이다. 키오스크·폰 양쪽 다 기기 내장
음성 합성으로 구현돼 있고, 외부로 나가는 경로가 없다.

### 6. (검토 중) 기기가 제공하는 맥락 정보 활용

기기 쪽에 시간대·날씨·일정·재실 인원 같은 **맥락 정보**가 이미 관리되고 있고, 조회할 수
있다. 이걸 쓰면 우리 제안의 근거가 "이 시간대에 3번 반복했다"에서 "더운 오후이고, 사람이
있다"까지 넓어진다 — 공감지능·초개인화 축의 실제 데이터 출처가 된다.

방향이 한쪽만은 아니라는 점이 중요하다. 재실 정보는 **우리가 기기 쪽에 공급하는** 것도
가능해서, `/presence`로 들어온 감지 결과를 올려보내면 SimpleLay가 공간 지능을 **소비만
하는 게 아니라 기여하는** 구성이 된다.

추론 경계 관점에서 이 항목은 전부 **기기 안에서 오가는 조회**라 외부망을 새로 끌어들이지
않는다. 즉 위 결론(핵심 경로는 오프라인 완결)을 흔들지 않으면서 맥락만 풍부해진다.
아직 배선 전이며, 실기기에서 실제 가용성을 확인한 뒤 붙인다.

## 결론 한 줄

**폐루프의 핵심 경로(목적 → 버튼 시퀀스 → 실행 → 검증)는 인터넷이 완전히 끊겨도
100% 동작해야 한다.** 외부 추론 경로는 있으면 좋은 확장이지, 기본 경로가 되어서는 안 된다.
결선 시연장 네트워크는 우리가 통제할 수 없고, SimpleLay의 정체성 자체가 "스스로 확인하고
재시도하는" 자기완결적 시스템이기 때문이다.
