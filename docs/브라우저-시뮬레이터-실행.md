# 브라우저 시뮬레이터 실행

2026-09-27. 하드웨어 없이 기존 API와 Flutter 키오스크를 리허설한다.

## 실행

저장소 루트에서:

```powershell
.venv\Scripts\python.exe -m rpi.simulator_main --port 8765
```

- 조작 패널: http://127.0.0.1:8765/simulator
- 기존 Flutter 키오스크: http://127.0.0.1:8765/kiosk/
- 종료: 서버 터미널에서 Ctrl+C. 시연 이력은 메모리이므로 종료하면 사라진다.

키오스크 웹 산출물은 Git에 포함하지 않는다. 처음 실행하거나 Dart 코드를 변경했으면 `rpi5-touchscreen-app`에서 `flutter build web --base-href /kiosk/ --output <저장소의 절대 경로>/kiosk-web`으로 빌드한 후 서버를 시작한다. 이 PC는 Windows 셰이더 경로 문제를 피하려고 다음 ASCII 경로를 사용했다.

```powershell
$env:PUB_CACHE='C:\Temp\simplelay-0921\.venv\pub-cache'
$env:TEMP='C:\Temp\simplelay-0921\.venv\flutter-temp'
$env:TMP=$env:TEMP
Set-Location C:\Temp\simplelay-0921\rpi5-touchscreen-app
& C:\Temp\simplelay-0921\.venv\flutter\bin\flutter.bat build web --base-href /kiosk/ --output C:/Temp/simplelay-0921/kiosk-web --no-pub --no-wasm-dry-run
```

`C:\Temp\simplelay-0921`은 이 PC에 이미 존재하는 저장소 연결 경로다. 다른 PC에서는 해당 PC의 SDK와 저장소 경로를 사용한다.

## 확인 순서

1. 패널에서 전자레인지 → 즉석밥 시퀀스 실행. 아래 통신 프레임의 execute/result와 모의 실행 표시를 확인한다.
2. 2회 실패 또는 3회 실패를 주입하고 다시 실행한다. 모의 실행기 내부 입력 기록과 허브의 집계 응답을 따로 확인한다.
3. 정상으로 해제하고 시퀀스 실행 직후 중단 요청을 누른다. 협조 중단은 버튼 사이 경계에서 처리된다.
4. 패널의 '키오스크에 시연 제안 띄우기'를 누른다. 키오스크의 '[시연 데이터]' 제안을 승인하고 모의 실행 화면을 확인한다. 승인하지 않으면 실행하지 않는다.

## 범위와 한계

- ActClient, ActExecutor, ClosedLoopController는 기존 코드를 사용한다. 전송은 메모리 스트림, 모터와 검증기는 mock이다. `execution_mode=mock`이며 실제 가전 동작을 검증하지 않는다.
- 전용 런처는 실사용 DB 설정, 외부 LLM/비전 주소, 로컬 대상 설정을 제거하고 GPIO·개발자 제어·벡터DB 시드를 끈다. 원격 노드 컨트롤러 연결도 거부한다. 이 격리는 `python -m rpi.simulator_main`을 쓸 때 적용된다. 일반 서버에 ACT_MODE만 바꾸는 것과 다르다.
- `/simulator`는 기본 컨트롤러가 SimulatorController일 때만 열린다. 인증 정책은 기존 서버와 같다. 기본 바인딩은 이 PC 전용이다.
- 웹 키오스크는 같은 origin의 API를 사용한다. 설정은 브라우저 저장소에 보관한다. 네이티브 RPi 설정 파일 경로는 유지한다. 웹에서는 espeak 대신 브라우저 음성 합성(speechSynthesis, ko-KR)을 쓴다(9/29). 실제로 소리가 나는지는 브라우저·OS 음성 엔진에 달렸다.
- 폰 앱 실기기 연결은 아직 검증하지 않았다. LAN 테스트 시 서버를 `--host 0.0.0.0`으로 실행하고 앱에서 PC 주소를 사용해야 한다. 앱의 내장 가전 노출/사용자 가전 동기화 정책 정리가 먼저 필요하다. 앱 자체 데모 모드는 서버 통신 검증을 대신하지 않는다.
- 가전 정지 버튼 누르기, Z축 복귀/정지 위치 대기/보관 위치 이동, 물리 비상정지, 응답 유실 UI는 미구현이다. 응답 유실 등 7개 통신 시나리오는 별도 `python -m rpi4.simulator --scenario all`에서 확인한다.
- (9/29 갱신) 결과 프레임에 `outcome`(success·failed·stopped·safety_stop)이 추가돼 서버 `/status`·SSE의 `last_outcome`, `/history`의 `outcome`으로 정지와 실패를 가른다([protocol.md](protocol.md)). 폰 앱·키오스크 화면은 아직 이 값을 읽지 않는다. 9/29 인증 변경으로 `SIMPLELAY_API_KEY` 없이 LAN(폰)에서 접속하면 401이다 — 키를 설정하거나 개발 PC에서만 `SIMPLELAY_ALLOW_UNAUTHENTICATED=1`.
- 9/28까지의 통신은 실패와 정지를 `success=false` 하나로 전했다. 패널의 허브 문구는 실패 보고라고만 표시한다. 키오스크의 기존 안전 중단 화면은 후속 계약 통합 때 근거에 맞춰 정리해야 한다.

## 검증

- 백엔드 전체 1,514건 통과. 이후 추가한 API/라우트 제한 2건을 포함해 새 시뮬레이터 테스트 5건 통과.
- 키오스크 비골든·비스크린샷 테스트 138건 통과, 웹 빌드 성공. 정적 분석은 기존 activeColor 사용 중단 안내 1건만 남았다.
- 실제 브라우저에서 패널 실행의 execute/result, 키오스크 렌더링, 시연 제안 수신과 승인 요청을 확인했다.

## Claude 후속 작업 경계

먼저 위 문서와 `docs/devlog/devlog_2026-09-27-integration.md`를 읽는다. 독립 명령 계약은 이 작업 폴더에 복사됐지만 서비스에 아직 연결하지 않았다.

다음 우선순위는 폰의 서버 내장 가전 조회/선택 정책이다. 서버 내장 가전을 사용자 편집 목록으로 저장하거나 PUT/DELETE 동기화에 넣지 말고, 서버 출처 목록으로 분리해야 한다. 서버 주소 변경 시 이전 목록을 비우고 선택값도 다시 대조한다. 기존 빈 설치 상태와 명시적 앱 데모 동작은 유지한다. `app/lib/providers/appliance_provider.dart`, `appliance_sync_provider.dart`, `app/lib/services/rpi_api_service.dart`부터 검토한다.

시뮬레이터 통신/런처와 Flutter 키오스크 웹 저장소 변경은 현재 Codex 작업 범위다. 같은 파일의 동시 수정은 피한다. 커밋·푸시는 아직 하지 않았다.
