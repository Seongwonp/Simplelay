# 하드웨어 연결 설계 (H0~H1 준비)

작성 2026-09-13. 하드웨어 도착(약 2주 뒤) 전에 **무엇을 어디서 책임지는지**와
**도착 직후 무엇을 어떤 순서로 재는지**를 정한다. 구현 문서가 아니다 —
여기 적힌 인터페이스 변경은 대부분 아직 코드에 없다.

## 표기

| 표기 | 뜻 |
|---|---|
| **확인** | 현재 코드에서 직접 확인한 사실(파일 경로 병기) |
| **설계안** | 이 문서가 제안하는 책임·계약. 팀 확인 전 |
| **결정 필요** | 선택지가 둘 이상이고 팀이 골라야 한다 |
| **추측/측정 필요** | 계산이나 문서 근거는 있지만 실측 전이라 사실로 쓰지 않는다 |

## 1. 버튼 ID → 보정 좌표 변환의 책임 위치

### 지금 코드

- 버튼 맵의 `x`, `y`는 **격자 칸 번호(정수)**다. mm 좌표가 아니다
  (`docs/button-maps/microwave.json`, `rpi/services/appliance_registry.py`) — **확인**.
- 보정은 **버전 문자열만** 준비 판정에 있다(`calibration_profile_version`).
  보정값 자체를 저장하는 곳은 없다 — **확인**.
- 누름 명령은 버튼 ID와 정성적 보정 요청(좌표 보정 필요·깊이 증가)만 싣는다.
  거리 값은 없다(`rpi/controller/models.py`) — **확인**.

### 설계안

상위 계층은 **버튼 ID만** 다루고, 좌표 변환은 **모션 어댑터가 보정 프로필로**
한다. 폰·키오스크·RPi5 서비스는 mm를 모른다.

```
RPi5 서비스 ── 버튼 ID + 정성 보정 ──▶ RPi4 폐루프 ──▶ 모션 어댑터
                                                    │ 보정 프로필(가전별)
                                                    ▼
                                         X·Y mm, Z 깊이, 유지 시간
```

이유:

- 좌표는 기구·설치 위치에 묶인다. 같은 가전도 설치할 때마다 달라진다.
- 정성 보정("조금 옆으로")을 안전한 거리로 바꾸는 상한도 기구를 아는 쪽이
  정해야 한다(`rpi/controller/retry.py` 주석의 기존 의도와 같다).

보정 프로필(가전 1대 = 파일 1개, RPi4 로컬) — **설계안**:

| 항목 | 뜻 | 값 |
|---|---|---|
| `profile_version` | 내용 해시. RPi5 준비 판정의 버전과 일치해야 실행 허용 | 자동 |
| `origin_mm` | 홈 기준 가전 패널 원점 | 설치 시 측정 |
| `buttons[id].x_mm, y_mm` | 버튼 중심 | 설치 시 측정 |
| `press_depth_mm`, `press_depth_max_mm` | 기본 깊이, 재시도 포함 상한 | **측정 필요** |
| `dwell_ms` | 누름 유지 시간 | **측정 필요** |
| `xy_retry_step_mm`, `xy_retry_max_mm` | 재시도 좌표 보정 한 번의 폭, 누적 상한 | **측정 필요** |
| `workspace_mm` | 소프트 리밋 작업 영역 | 기구 치수 |

- RPi4가 시작할 때 프로필 버전을 RPi5에 보고한다. 버전이 다르거나 없으면
  **조작 가능이 아니다**. 이 보고 메시지는 아직 프로토콜에 없다 — **설계안**.
- 격자 칸 번호(`x`, `y`)는 화면 배치용으로 남긴다. 좌표로 재해석하지 않는다.

## 2. 실제 모션 어댑터 계약

### 결정 필요: 제어 펌웨어

`docs/actuator-design.md`는 엔코더 모터 + 별도 MCU의 PID를 적고 있다. 코드의
포트 이름은 G-code 계열을 가정한다.

- **(가) G-code 계열 펌웨어 사용:** 홈·리밋·이동 중 일시정지·소프트 리셋·
  상태 조회가 이미 있다. 엔코더 모터 구동과 맞는지 확인이 필요하다.
- **(나) 자체 MCU 시리얼 프로토콜:** 기구에 맞추기 쉽지만 아래 계약을 전부
  직접 구현해야 한다.

어느 쪽이든 아래 계약은 같다. 계약을 먼저 테스트로 고정하고 전송만 갈아 끼운다.

### 계약 — **설계안**

| 항목 | 요구 |
|---|---|
| 연결 | 시작 시 버전·상태 조회. 알람 상태면 준비 안 됨 |
| 홈 | 전원 인가 뒤 첫 이동 전 홈 필수. 홈 완료 표시가 없으면 누름 거절 |
| 하드 리밋 | 리밋 스위치가 걸리면 **MCU/드라이버 수준에서** 즉시 정지. 소프트웨어 판단을 기다리지 않는다 |
| 소프트 리밋 | 프로필 작업 영역 밖 목표는 **이동 전에** 어댑터가 거절 |
| 속도·가속 | 상한을 프로필이 아니라 어댑터 상수로 고정(설치자가 못 올림). 값은 **측정 필요** |
| Z 깊이·유지 | 프로필 상한 초과 요청 거절. 재시도의 깊이 증가도 상한 안에서만 |
| 누름 기한 | 한 번의 누름(이동+누름+복귀)에 기한. 넘으면 정지 후 오류 |
| 워치독 | MCU는 호스트 신호가 일정 시간 끊기면 스스로 정지. 주기는 **측정 필요** |
| 이동 중 정지 | 아래 절 |
| 오류 분류 | 알람 / 리밋 / 기한 초과 / 스톨(엔코더 진행 없음) → 안전 정지 + 재홈 전까지 준비 안 됨 |

### 이동 중 정지 — 지금 없는 계약

지금 정지 요청은 **버튼 사이와 재시도 경계에서만** 반영된다
(`rpi/controller/closed_loop.py`) — **확인**. 블로킹 누름·검증·재시도 대기·
시연용 페이싱 대기 중에는 끼어들지 못한다.

설계안:

1. 어댑터에 `request_stop()`을 둔다. **다른 스레드에서 즉시** 모션 컨트롤러에
   정지 명령을 보낸다. 진행 중인 누름 호출이 반환되기를 기다리지 않는다.
2. 진행 중이던 누름 호출은 "정지로 중단" 예외로 끝난다. 폐루프는 재시도하지 않는다.
3. 재시도 대기와 페이싱 대기는 정지 이벤트를 기다리는 대기로 바꿔 즉시 깬다.
4. 정지 뒤 위치를 신뢰할 수 없으면 재홈 전까지 준비 안 됨.

정지 결과는 세 단계로 나눠 기록한다(§5 명칭과 같다):
**명령 전송** → **컨트롤러가 정지 상태 보고** → **물리 정지 확인**(엔코더 속도 0).

### 지금 코드에서 같이 고칠 것 (H1 착수 시)

- 홈 스위치 상태가 GPIO 오류일 때 **준비됨(True)을 돌려준다**
  (`rpi/services/actuator.py`) — **확인**. 개발 PC용 폴백이 실기기에서
  위험 쪽으로 열린다. 실기기 게이트가 켜진 구성에서는 오류 = 준비 안 됨이어야 한다.
- `docs/protocol.md`의 단계별 `ack`는 RPi4가 보내지도 RPi5가 받지도 않는다.
  구현하거나 문서에서 지운다(**결정 필요**).

## 3. 누름 전후 타임스탬프 기반 센서 캡처

### 지금 코드 — **확인**

- 폐루프는 누름 호출이 **반환된 뒤** 검증을 한 번 부른다.
- 전류는 호출당 **1샘플**, 음향은 큐에서 **1프레임**을 읽는다. 타임스탬프가 없다.
- 음향 큐(4칸)가 차면 **새 프레임을 버린다**. 누른 순간이 아니라 과거 소리를
  판정할 수 있다.
- 전류 기준값은 방금 읽은 샘플까지 포함한 이동 평균이다.

개별 임계값보다 **측정 시점 구조**가 더 큰 문제다. 반환 뒤 한 점을 보면
누름 순간을 놓친다.

### 설계안

```
시간 ──────────────────────────────────────────────────────▶
      [사전 창]   press_start      press_end   [사후 창]
  ADC ▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪   (링 버퍼, 단조 시각)
  음향 ▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫▫   (링 버퍼, 단조 시각)
      └─ 기준값 ─┘└──────── 판정 구간 ────────┘
```

1. 센서는 **모션 시작 전부터** 백그라운드에서 링 버퍼로 계속 모은다.
   샘플마다 호스트 단조 시각을 붙인다.
2. 어댑터가 `press_start`(Z 하강 시작)·`press_end`(Z 복귀 완료) 시각을 보고한다.
3. 검증은 `[press_start − 사전 창, press_end + 사후 창]`을 잘라 판정한다.
   기준값은 **사전 창**에서, 반응은 판정 구간에서 본다.
4. 인터페이스: 검증 호출이 버튼 ID와 함께 **누름 구간**을 받는다. 가짜 검증기는
   구간을 무시해도 된다.

- 창 길이, MCU 이벤트가 시리얼로 오는 지연(호스트 시각 보정값)은 **측정 필요**.
- 음향 콜백의 장치 시각과 호스트 단조 시각의 차이도 **측정 필요**.

## 4. ADC 입력 범위 검증 · 초기 기준값 · 음향 stale 프레임

### ADC 입력 범위

- 설정은 ADS1115 gain 2(전체 범위 ±2.048 V)인데 ACS712의 무전류 출력은
  2.5 V로 적혀 있다(`rpi/verifier/config.py`) — **확인**. 분압 설계는 문서에 없다.
  코드 그대로면 **포화 위험**이 있다.

| gain | 전체 범위 | 1 LSB | 185 mV/A 기준 1 LSB |
|---|---|---|---|
| 2/3 | ±6.144 V | 187.5 µV | 약 1.01 mA |
| 1 | ±4.096 V | 125 µV | 약 0.68 mA |
| 2 | ±2.048 V | 62.5 µV | 약 0.34 mA |

(데이터시트 수치. 입력 전압은 어느 gain에서도 ADC 전원 전압을 넘으면 안 된다.
실제 ADC 전원·센서 전원 전압은 **측정 필요**.)

설계안 — **시작 시 즉시 거절**:

- `영점 전압 × 분압비 ± 예상 최대 변화`가 gain의 전체 범위와 ADC 전원 전압
  안에 들지 않으면 센서 검증기를 만들지 않고 오류로 끝낸다. 분압비는 설정 항목으로 둔다.
- 운용 중 샘플이 범위 끝에 붙으면 "안 눌림"이 아니라 **센서 이상**으로 보고한다.

### 초기 기준값

- 기준값 창을 채우는 함수가 있지만 운영 경로에서 부르지 않는다.
  그래서 처음 19번의 전류 판정은 무조건 실패한다 — **확인**.
- 설계안: 검증기 시작 시 창을 채운다. 채우지 못하면 준비 판정의 보정 항목을
  통과시키지 않는다. §3의 사전 창 기준값으로 옮기면 이 문제는 구조적으로 사라진다.

### 음향 stale 프레임

- 설계안: 가득 차면 **가장 오래된 프레임을 버리는** 링 버퍼로 바꾼다.
  타임아웃 시 무음(0) 배열을 돌려주는 대신 "데이터 없음"을 명시한다.
- 위험소리 감시가 같은 마이크에 두 번째 입력 스트림을 연다. 공존 가능 여부는
  **측정 필요**. 안 되면 한 스트림을 나눠 쓴다.

### 판정 수치 — 전부 **추측/측정 필요**

- 전류 임계 12 mA는 185 mV/A에서 약 2.2 mV다(계산). 실제 배선·필터·샘플링에서
  잡음보다 큰지는 **측정 전에는 모른다**.
- 음향 단독 점수는 코드상 0.45로 기준 0.50에 못 미쳐 **절대 성공하지 않는다** —
  **확인**. `docs/sensor-spec.md`와 판정 모듈 주석의 표(음향 단독 = 눌림)와
  다르다. 어느 쪽이 맞는지는 실측 뒤 **결정 필요**. 그전까지 문서가 코드와
  다르다는 사실을 숨기지 않는다.
- 전류 센서를 가전 내부 전원선에 다는 방식은 "가전 개조 없이"와 충돌할 수
  있다. 설치 방식은 **결정 필요**.

## 5. 물리 비상정지와 소프트웨어 정지 — 명칭과 보장 범위

같은 "정지"라는 말로 서로 다른 보장을 부르지 않는다.

| 명칭 | 지금 있는가 | 무엇을 보장하는가 | 보장하지 않는 것 |
|---|---|---|---|
| **전원 차단 비상정지** | 없음 | 모터 전원·드라이버 enable을 회로가 직접 끊는다. 소프트웨어 상태와 무관 | — |
| **비상정지 버튼 신호** | 있음(ESP32 GPIO33) — **확인** | 정지 **요청 메시지**를 RPi5로 보낸다 | 전력 차단. 디바운스 없음, 알림 LED가 약 1.2초 루프를 막는다 |
| **긴급 정지 요청** (`POST /stop`, 폰·키오스크 버튼) | 있음 | 요청 접수, 로컬 정지 플래그, 노드별 전달 결과(받음/미확인) | 모터가 멈췄다는 확인 |
| **실행 루프 정지** | 있음 | 폐루프가 버튼·재시도 경계에서 더 누르지 않는다 | 진행 중인 이동·누름 중단 |
| **모션 정지 명령** | 없음(§2 설계안) | 이동 중에도 컨트롤러에 즉시 정지 명령 | 물리 정지 확인 |
| **물리 정지 확인** | 없음(§2 설계안) | 엔코더 속도 0 또는 컨트롤러 정지 상태 보고 | — |

- 화면·음성 문구는 **물리 정지 확인이 생기기 전까지** "멈췄어요"가 아니라
  "정지를 요청했어요" 계열로 맞춘다. 문구 변경은 H1 이후 별도 작업이다
  (지금은 UI 동결).
- 비상정지 버튼은 **전원 차단 회로를 1차, 소프트웨어 메시지를 2차**로 둔다 —
  **설계안**. 전원 차단 회로 구성은 HW 담당과 **결정 필요**.
- 정지 지연은 `실기기-배포-체크리스트.md` §5와 같이 ① 요청 접수 ② 루프 종료
  ③ 물리 정지로 나눠 잰다. ③은 지금 기록 수단이 없다.

## 6. 하드웨어 수령 직후 검증 순서

한 단계가 통과해야 다음으로 간다. **처음부터 여러 가전을 붙이지 않는다** —
원인 분석이 불가능해진다. 두 번째 가전은 "같은 구조가 다른 가전에도 적용된다"를
보이는 마지막 단계다.

| 단계 | 내용 | 통과 기준 |
|---|---|---|
| H0 전원 | 무부하·스톨·동시 기동 전류, 5 V 레일 강하 측정 → `전력버짓.md` 표 채움. 모터 전압 문제 결정 | 측정표 완성, 퓨즈·어댑터 정격 결정 |
| H0 부팅·화면 | RPi5·RPi4 부팅, **전용 7인치 터치 패널** 표시·터치 좌표·자동실행 | 전원만 꽂으면 키오스크가 뜨고 터치가 맞는다 |
| H0 링크 | RPi5↔RPi4 UART 왕복, 비상정지 버튼 → RPi5 정지 로그 | 메시지 왕복 로그 |
| H1a 모션 단독 | 가전 없이 홈, 리밋 스위치 트리거, 소량 조그, 이동 중 정지 지연 3단계 측정 | 리밋에서 멈춤, 정지 지연 수치 기록 |
| H1b 센서 단독 | 모션 없이 ADC 무전류 전압 실측 → gain·분압 결정. 사람이 버튼 N회 누르며 원시 기록 | 누름/비누름이 원시 데이터에서 구분되는지 판단 |
| H1c 폐루프 1버튼 | 전자레인지 버튼 1개: 누름 → 누름 구간 판정 → 실패 주입 → 보정 재시도 → 정지 | 한 흐름 완주 로그 |
| H1d 반복 | 버튼 3개 × 50회: 첫 시도 성공률, 최종 성공률, 버튼당 p95 시간 → 타임아웃 설정 조정 | 실측 표 |
| H2 두 번째 가전 | 같은 코드, 보정 프로필만 교체 | 코드 변경 없이 동작 |

### 원시 데이터 수집

- 지금은 ADC·음향 원시값과 검증 상세를 **저장하지 않는다**. 실행 이력 CSV에는
  작업·가전·결과·정지 지연·보정 버전·버튼별 시도 수가 있다 — **확인**.
- 벤치 기록 도구(아직 없음) — **설계안**:
  - 한 번의 측정 = 한 폴더. 연속 샘플(ADC 값, 음향 프레임)을 단조 시각과 함께
    저장하고, 모션 이벤트(`press_start`, `press_end`, 정지 3단계)를 같은 시각축에 남긴다.
  - 사람 판정(실제로 눌렸는가)을 별도 열로 기록한다. 센서 판정과 비교할 기준이다.
  - 실행 이력 CSV와는 작업 ID·시각으로 잇는다.
  - 원시 데이터는 저장소에 올리지 않는다. 요약 수치만 문서에 옮긴다.

실험 기록표 양식:

| 날짜 | 단계 | 가전 | 버튼 | 시도 | 사람 판정 | 센서 판정 | 정지 지연 ①②③ | 원시 폴더 | 메모 |
|---|---|---|---|---|---|---|---|---|---|
