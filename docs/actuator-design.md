# 액추에이터(구동부) 설계 확정 사항

> 하드웨어 설명이 여러 문서에 흩어져 있고 옛 구조(피니언/렉 레일) 설명도 섞여 있어서,
> 최종 확정된 구동부 방식만 이 문서에 모아 정리한다. 다른 문서의 구동부 관련 내용과
> 충돌하면 **이 문서가 최신**이다.

---

## 1. 기구 방식 — CoreXY

기존 피니언/렉 레일 구조를 버리고 CoreXY 갠트리 방식으로 확정.

**버린 이유** (피니언/렉 레일의 문제):
- 레일 작동에 필요한 공간이 실제 제어 공간의 4배 이상
- Y축 모터가 Z축 모터+레일 무게까지 부담해서 속도가 점점 느려짐
- Z축 터치 시 모터가 튕기는 현상

**CoreXY 구성 요소**:
- 리니어 가이드 레일 × 3 (3D 자체 제작)
- 베어링(또는 아이들러 풀리) × 8 — 베어링 내장형 풀리를 구하지 못해, 베어링 겉에 고정하는 방식으로 대체
- 하단 구동 모터 2개 (역구조형 마이크로 DC 기어드 모터)
- 타이밍 벨트 (2GT 6mm)

**운동 방정식** (모터 A, B의 이동량으로 X/Y를 유도):
```
ΔX = ½(ΔA + ΔB)
ΔY = ½(ΔA - ΔB)
ΔA = ΔX + ΔY
ΔB = ΔX - ΔY
```
두 모터가 항상 함께 구동되는 구조라, 한쪽만 움직여서 대각선 이동을 만든다. 모터 PID
제어는 RPi4가 아니라 별도 마이크로컨트롤러(Arduino, 커스텀 펌웨어)가 담당한다 — RPi4는
일반 리눅스라 실시간성이 부족해서, 두 모터의 타이밍이 어긋나면 대각선 이동이 틀어질
위험이 있기 때문. (자세한 보드 역할 분담은 `개발현황.md` 참고.)

## 2. 프레임 설계 — 가운데 개방형 + 홈 파킹 (신규 확정)

**문제 제기**: 액추에이터 프레임이 가전 조작 패널 전체를 덮으면, 자동 조작이 필요 없을 때
사용자가 손으로 직접 버튼을 누르고 싶어도 프레임에 가로막힌다.

**확정한 해결 방식**:
1. **가운데 개방형 프레임** — 프레임 중앙을 비워서, 사용자가 손을 넣어 패널에 직접 접근할
   수 있게 만든다.
2. **동작 완료 후 홈 포지션 복귀** — 버튼 조작이 끝나면 캐리지(+ Z축 누름 장치)가 자동으로
   홈 포지션(레일 맨 위 또는 맨 아래, 버튼이 적은 쪽 가장자리)으로 돌아가서, 평소에는
   패널 가운데를 가리지 않는다.

**아직 확인 필요한 것 (예솔님 검토 필요)**:
- [ ] 홈 포지션을 상단/하단 중 어느 쪽으로 할지 — 실제 버튼맵 배치를 보고 버튼이 적게
      몰린 가장자리로 정한다 (시작/취소 같은 자주 쓰는 버튼이 몰린 쪽은 피한다).
- [ ] 프레임 강성 — 가운데를 개방하면 벨트 구동 캐리지를 지지하는 뼈대가 줄어들어서
      진동/휨에 더 취약해질 수 있다. 폐루프 재시도(검증 실패 시 좌표 보정 후 재시도)가
      어느 정도 오차를 흡수하긴 하지만, 어느 수준까지 흔들려도 되는지는 실측 필요.
- [ ] Z축(현재 SwitchBot 사용 — 상용 BLE 버튼 누름 장치) 몸체도 홈 복귀 시 패널 위에서
      완전히 비켜나는지 확인 — X/Y 캐리지만 파킹되고 Z축 몸체가 남아있으면 여전히 손이
      안 들어갈 수 있다.
