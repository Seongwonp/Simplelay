## §0. 한 장 요약

**시연 목표.** 9/30 지도교수 의견 "여러 가전에 적용되는 모습"을 한 사람의 하루로 보인다.

1. **버튼식 가전 3종에 같은 흐름** — 사진으로 등록한 조작부 위에서 만든 루틴이 카드가 되고, 승인한 뒤에만 누른다(①②③).
2. **눌렸는지 확인하고, 안 되면 고쳐 다시 누른다** — 폐루프 재시도(②, 실패는 일부러 넣는다).
3. **가전의 끝이 다음 행동으로 이어진다** — 세탁 완료 알림 → 빨래 안내(④, 오늘은 모의 이벤트).
4. **화면과 별개인 비상정지** — 콘센트 모듈 버튼이 가전 전원을 끊고, 사람이 확인해야 풀린다(⑤).
5. **사용자가 통제한다** — 다음에(넘기기), 부재 중 제안 보류(⑥).

**총 시간: 6분 00초**(도입 20초 + 장면 6개 5분 20초 + 마무리 20초). 남는 약 4분은 발표(집 전체 그림 → 가격 비교 → 기기 사진, 실행계획 §1-4).
줄여야 하면 §1 끝 "줄이는 순서".

> **위험 하나(사용자 판단 필요).** 9/29 전문가 의견의 "소프트웨어 가전 제어 포함"은 v3 본 장면에서 빠진다. ThinQ 경로는

## §1. 장면 대본 (6분)

표기: 화면 **K**=키오스크, **P**=폰(미러링), **T**=디지털 트윈(`/simulator/twin`, 전부 모의 등급에서만). "말할 문장"은 §7 안에서만 고른다.
모든 장면의 카드는 **사용자 루틴**이 만든다. 루틴은 셋업 때 폰 루틴 탭에서 미리 저장한다(§3-3의 네 개).

### 도입 (0:00–0:20)

- 화면: K 평소 화면(시계·날씨·가전 아이콘 세 개).
- 말할 문장: *"가전은 그대로 두고, 사진으로 등록한 버튼을 손가락 로봇이 대신 누릅니다. 한 사람의 하루를 따라가 보겠습니다. 화면의 '모의' 표시는 실제 장치가 아닌 부분입니다."*

### ① 아침 — '아침 데우기' 루틴 → 즉석밥 → 복약 안내 (0:20–1:30, 70초)

| 항목 | 내용 |
|---|---|
| 화면 | P 루틴 탭 '아침 데우기'(평일 07:30, 승인 후 실행) → K 카드 "'아침 데우기' 루틴을 실행할까요?"(누를 순서 "전자레인지 즉석밥 → 시작") → K 동작 중 → P 보호자 알림함 "약 드실 시간이에요…" |
| 사용자 행동 | 발표자가 "7시 30분이라고 하겠습니다" 하고 폰에서 **지금 실행**, 키오스크에서 **시작** 한 번 |
| 시스템 동작 | `POST /routines/{id}/trigger` → 카드(실행 아님) → `POST /suggestions/{id}/approve` → 갠트리가 `즉석밥 → 시작` → `wait_until_done`(실물: L3 `operation_confirmed` 필요, 모의: "시연 통과") → `announce` → 보호자 알림함 `routine_announce` |
| 말할 문장 | *"사용자가 만든 아침 루틴이 시간이 되면 먼저 여쭙고, '시작'을 누르셔야만 움직입니다. 데우기가 시작된 게 확인되면 약 드실 시간을 알려 드립니다 — 시간 알림까지이고 약을 판단하지는 않습니다."* |
| 심사 포인트 | 사용자 루틴(고정 메뉴 없음), 승인 게이트, 루틴의 다음 단계가 앞 단계 확인에 묶임 |

주의: 시각 트리거(07:30)는 시연장에서 기다릴 수 없어 **지금 실행**으로 띄운다 — 그렇게 말한다. 안내는 폰 알림함 기록이며 **키오스크 음성 안내는 없다**(갭 S5).
가열 여부는 결정 D3(빈 전자레인지 가열 금지 vs L3 실물 확인)가 정해질 때까지 "가열하지 않음"이 기본이다.

### ② 외출 전 — '외출 전 세탁' + 일부러 넣은 실패 → 보정 재시도 (1:30–2:40, 70초)

| 항목 | 내용 |
|---|---|
| 화면 | K 카드 "'외출 전 세탁' 루틴을 실행할까요?"("세탁기 전원 → 표준 → 시작") → (실물) 갠트리가 '전원'을 두 번 누름 / (모의) T "재시도 1회째"·보정 표시 → K 완료 → P 기록 "재시도 1회 후 성공"(화면 미확인) |
| 사용자 행동 | 발표자 "첫 버튼 확인을 일부러 실패시키겠습니다" → 운영자 주입 → 폰 지금 실행 → 키오스크 시작 |
| 시스템 동작 | `POST /demo/inject-failure {"button_index":0,"attempts":1}`(1회용) → 루틴 카드 승인 → 첫 버튼 검증 실패 → 보정 요청(`xy_adjustment_required`, `increase_press_depth`)을 실은 재누름 → 성공. `/status.last_retry_count 1`, `/history.csv` `전원:ok:2` |
| 말할 문장 | *"눌렸는지를 확인하는 구조라, 확인이 안 되면 위치와 깊이를 고쳐 다시 누르고 세 번 안 되면 멈춥니다. 지금 실패는 일부러 넣었고, 센서 판정은 [모의입니다/실측 중입니다]."* |
| 심사 포인트 | 예선 P4(누름 오차 보정), 폐루프, 같은 흐름이 두 번째 가전에도 적용 |

주의: 세탁기에는 콘센트 모듈이 없어(모듈 1개, 전자레인지용) 확인 근거는 `reported`다. 세탁기 실물 모델·버튼 이름은 미정(갭 H2) — 등록한 이름을 그대로 쓴다.

### ③ 낮 — 인터폰 방문자 → 승인 → 문열림 (2:40–3:30, 50초)

| 항목 | 내용 |
|---|---|
| 화면 | (인터폰 호출음 또는 말로 "방문자가 왔다고 하겠습니다") → K 카드 "'방문자 문 열기' 루틴을 실행할까요?"("인터폰 문열림") → K 완료 |
| 사용자 행동 | 발표자가 폰에서 '방문자 문 열기' **지금 실행** → 키오스크 **시작** |
| 시스템 동작 | `POST /routines/{id}/trigger` → `POST /suggestions/{id}/approve` → `문열림` 한 번 누름 → `last_outcome success`, 확인 근거 `reported` |
| 말할 문장 | *"문 열기처럼 민감한 동작은 언제나 사람이 보고 승인해야 누릅니다. 인터폰이 울린 걸 스스로 알아채는 기능은 아직 없어서 지금은 직접 띄웁니다."* |
| 심사 포인트 | 세 번째 가전(조작부 모양이 달라도 같은 등록·승인 흐름), 안전한 기본값 |

주의: 인터폰 호출 감지는 **없다**(템플릿 주의 문구 그대로, 결정 D4·갭 L3). 인터폰은 소비 전력이 작아 30A CT로 판정할 수 없다(실행계획 §3-7) — 문이 열렸는지는 확인하지 않는다.

### ④ 귀가 — 세탁 완료 알림 → 빨래 안내 (3:30–4:10, 40초)

| 항목 | 내용 |
|---|---|
| 화면 | P 보호자 알림함 "루틴 '세탁 끝 알림' · 가전 알림 'wash_complete'이 왔어요 (시연: 모의 이벤트예요) — 세탁이 끝났어요. 빨래를 꺼내 널어 주세요" |
| 사용자 행동 | 없음(운영자 주입) |
| 시스템 동작 | `POST /demo/thinq/event {"event":"wash_complete"}`(ThinQ 모의 모드 필수) → 루틴 엔진 `event` 트리거 → '세탁 끝 알림'(알림만) → `routine_notice` |
| 말할 문장 | *"세탁기가 끝났다는 신호를 받으면 다음에 할 일을 알려 드립니다. 오늘 완료 신호는 모의로 넣었고, 버튼식 세탁기의 완료는 콘센트 전력으로 판정하도록 [계획/구현 중]입니다."* |

주의: 같은 이벤트가 옛 시나리오 `wash_then_dry`의 **제습기 카드**도 만든다(10/6 확인) — 지우기 전까지는 운영자가 곧바로 넘기거나(§3-4) 카탈로그에서 빼야 한다(갭 S1).
알림은 폰 알림함에만 뜬다. 키오스크에 한 줄로 보이는지는 확인 전이다(갭 S5).

### ⑤ 비상 — 콘센트 모듈 버튼 → 래치 → 확인 후 해제 (4:10–5:10, 60초)

| 항목 | 내용 |
|---|---|
| 화면 | 전자레인지 동작 중(① 루틴 재실행 또는 '정지 버튼 위 대기' 중) → 발표자가 콘센트 모듈 **비상 버튼** → K 위쪽 비상 띠·P 배너 "비상정지가 걸려 있어요" → 다음 실행이 막힘 → 버튼을 풀고 폰/키오스크에서 확인 → 띠 사라짐 |
| 사용자 행동 | 비상 버튼 누름 → 버튼 해제 → 화면에서 확인 |
| 시스템 동작 | ESP32가 **호스트와 무관하게** 릴레이를 열어 가전 전원 차단 → `estop` 이벤트 → RPi4가 실행 중이면 협조 정지 + 모션 정지, 래치(재부팅에도 유지) → RPi5 `/status.estop_latched true`, 실행 412 "비상정지가 걸려 있어요" → `POST /stop/ack` → `ok true, latched false`(버튼이 눌린 채면 `ok false`) |
| 말할 문장 | *"이 버튼은 화면·네트워크와 상관없이 가전 전원을 끊고, 사람이 확인하기 전에는 다시 움직이지 않습니다. 화면의 정지 버튼은 같은 정지를 요청하지만, 실제로 멈췄는지는 장치를 확인해 달라고 말씀드립니다."* |
| 심사 포인트 | 9/22 C4(먹통 시 정지), 자동 해제 없음, "정지됨/실패" 구분 |

주의: **콘센트 모듈은 펌웨어 컴파일까지만 확인했다.** 릴레이가 끊는 것은 **가전 전원**이지 모터 전원이 아니다. 부분 실물(가짜 모듈)에서는 버튼을 누를 외부 수단이 없고(갭 S3),

## §3. 리허설 실행 절차 (전부 모의 등급, 오늘 실행 가능)

### 3-1. 서버 띄우기 — `rpi.simulator_main`이 아니라 `uvicorn`으로

`python -m rpi.simulator_main`은 `SIMPLELAY_LOCAL_APPLIANCES`를 **지운다**. 그러면 폰에서 등록한 가전(전자레인지·세탁기·인터폰)은
등록 응답이 "operable"인데도 승인 때 **412 "아직 기기와 연결되지 않았어요"** 가 난다(10/6 `--port 8781`에서 확인, 갭 S2).
그래서 같은 환경 변수를 손으로 주고 앱을 직접 띄운다.

```powershell
# 저장소 루트. 폰을 붙일 때만 --host 0.0.0.0 과 SIMPLELAY_API_KEY.
$env:SIMPLELAY_ACT_MODE = "simulator"
$env:SIMPLELAY_GPIO_ENABLED = "false"
$env:SIMPLELAY_SENSORS_ENABLED = "false"
$env:SIMPLELAY_LLM_MODE = "mock"
$env:SIMPLELAY_VECTORDB_SEED = "false"
$env:SIMPLELAY_DEV_MODE = "false"
$env:SIMPLELAY_THINQ_MODE = "mock"              # ④ 세탁 완료 이벤트에 필요
$env:SIMPLELAY_PRESENCE_GATING = "true"         # ⑥ 부재 보류에 필요
$env:SIMPLELAY_LOCAL_APPLIANCES = "home_mw,washer_panel,intercom"
Remove-Item Env:SIMPLELAY_DB_PATH -ErrorAction SilentlyContinue   # 운영 이력과 섞지 않는다(재시작하면 초기화)
.\.venv\Scripts\python.exe -m uvicorn rpi.main:app --host 127.0.0.1 --port 8782
```

Git Bash: `SIMPLELAY_ACT_MODE=simulator SIMPLELAY_GPIO_ENABLED=false SIMPLELAY_SENSORS_ENABLED=false SIMPLELAY_LLM_MODE=mock SIMPLELAY_VECTORDB_SEED=false SIMPLELAY_DEV_MODE=false SIMPLELAY_THINQ_MODE=mock SIMPLELAY_PRESENCE_GATING=true SIMPLELAY_LOCAL_APPLIANCES=home_mw,washer_panel,intercom PYTHONUTF8=1 .venv/Scripts/python.exe -m uvicorn rpi.main:app --port 8782`.

### 3-5. 부분 실물(RPi5 + RPi4) 리허설에서 더 볼 것

- RPi4 `SIMPLELAY_OUTLET_PORT=fake`로 띄우면 L3·래치 경로가 생긴다. 정지 버튼 대기(`/status.hold_state`)는 **정지 버튼 mm·보관 위치·UART가 모두 있어야** 열린다 — 전부 모의에서는 `hold_state null`이었다(10/6 확인).
- `/status.estop_latched`가 `false`(보고함)인지 `null`(보고 안 함)인지 본다. `null`이면 실행기가 걸림을 보고하지 않는 것이다 — RPi4가 10/5 밤 커밋 이전 코드일 수 있다(재배포 필요).

## §4. "조용히 실패하는 것" 점검표

화면은 정상처럼 보이는데 장면이 무너지는 것들이다. 셋업 때 위에서부터 확인한다.

| # | 항목 | 증상 | 확인·해결 |
|---|---|---|---|
| 1 | **RPi4 도커 미기동** | RPi4 재부팅 뒤 실행기 없음 → RPi5 실행이 시간 초과·연결 경고 | 루트가 읽기 전용이라 자동 기동 불가. SSH `systemctl start docker` → `docker ps`에 `simplelay-act` Up. RPi5를 먼저 띄웠으면 `docker restart simplelay-backend` 한 번 더(런북 §3) |
| 2 | **비상정지 래치가 남음** | 앞 리허설에서 누른 버튼의 래치가 ESP32(NVS)·RPi4에 남아 모든 실행이 412 "비상정지가 걸려 있어요" | `GET /status`의 `estop_latched false` 확인. 걸려 있으면 버튼을 풀고 `POST /stop/ack` → `ok true`. 버튼이 눌린 채면 `ok false`가 정상 |
| 3 | 콘센트 릴레이 부팅 기본 꺼짐 | 모듈 재부팅 뒤 전자레인지 전원이 꺼져 있음 → 표시창 꺼짐, L3 실패 | `SIMPLELAY_OUTLET_RELAY_ON_START=1`이거나 사람이 켠다. 셋업 때 가전 표시창이 켜졌는지 눈으로 본다 |
| 4 | **`SIMPLELAY_DEMO_PACING`** | `deploy/run_backend.sh`가 `SIMPLELAY_DEMO_PACING=1`을 **항상** 켠다 → 실물에서 누름 사이가 이중으로 느려져 장면 시간이 넘침 | 실물·부분 실물은 끈다(런북 §8 결정 대기 2). 리허설 때 ①의 걸린 시간을 재서 확인 |
| 5 | **내장 전자레인지 사용** | 개발자 모드가 꺼진 제품 화면에서는 내장 `microwave`가 목록에 **안 보인다**(키오스크 '내 가전'·폰 홈). 게다가 내장 `microwave` 성공은 ThinQ 모의에서 공기청정기 카드(`cook_then_air`)를 띄운다 | **등록 가전(`home_mw` 등)만 쓴다.** `/demo/suggest`(기본 대상 `microwave`)도 쓰지 않는다 |
| 6 | **`SIMPLELAY_LOCAL_APPLIANCES` 누락** | 등록 응답은 `readiness operable, can_execute true`인데 승인하면 412 "아직 기기와 연결되지 않았어요" | RPi5 백엔드에 등록 가전 ID 세 개를 쉼표로. 모의는 §3-1 명령 |
| 7 | `rpi.simulator_main`으로 리허설 | 위 6과 같은 412(런처가 변수를 지움) | §3-1 `uvicorn` 명령을 쓴다(갭 S2) |
| 8 | **`washer` ID 충돌** | ThinQ 모의가 켜지면 `washer`는 서버 구성 가전 → 같은 ID로 등록 409, 템플릿 '외출 전 세탁'(`washer` 버튼 누름)은 저장 422 | 버튼식 세탁기는 `washer_panel` 같은 다른 ID로 등록하고 루틴도 그 ID로 |
| 9 | **`SIMPLELAY_THINQ_MODE`** | 기본 off면 ④의 `/demo/thinq/event`가 404 "ThinQ 연동이 꺼져 있어요" → 세탁 완료 장면이 사라짐 | ④를 하려면 `mock`. `GET /thinq/devices` 200 |
| 10 | 제습기 카드 끼어듦 | ④ 이벤트가 '세탁 끝 알림'과 함께 `wash_then_dry` 제습기 카드를 만든다 → K에 v3에 없는 가전 카드 | 이벤트 직후 그 카드를 넘긴다(`reject`), 카탈로그에서 빼면 해결(갭 S1) |
| 11 | `SIMPLELAY_PRESENCE_GATING` | 없으면 `POST /presence`가 200인데 아무 일 없음(⑥ 무반응) | `true`로 기동 |
| 12 | 부재가 켜진 채 남음 | 다음 루틴 지금 실행이 409, 카드 즉시 철회 | ⑥ 끝에 `present:true`. 60초 TTL로도 '모름'이 된다 |
| 13 | 잔여 실패 주입 | 앞 리허설의 주입이 남아 ①이 재시도·안전 정지 | 셋업 첫 줄 `DELETE /demo/inject-failure` |
| 14 | API 키 / LAN 401 | 키 미설정이면 폰·외부 단말 전부 401 | `SIMPLELAY_API_KEY` + 앱에 같은 키. `SIMPLELAY_ALLOW_UNAUTHENTICATED=1`은 쓰지 않는다 |

## §5. 백업 플랜

| 상황 | 바뀌는 장면 | 어떻게 |
|---|---|---|
| **누름 장치가 한 가전에만 붙음**(갭 H1 미해결) | ②③ | 전자레인지만 실물, 세탁기·인터폰은 같은 서버에서 모의 등급으로 — "이 두 가전은 오늘 모의로 보입니다"라고 먼저 말한다. 무대에는 조작부를 두되 움직인다고 말하지 않는다 |
| 하드웨어 고장(당일) | ①②③⑤ | 노트북 서버(§3-1)로 1분 안에 전환, 트윈을 보조 화면에. 사전 영상이 있으면 ②만 영상 |
| 콘센트 모듈 미완성 | ⑤ | 키오스크 정지 → "정지됨". "콘센트 버튼은 펌웨어까지 만들었고 회로는 조립 중"이라고 말한다 |
| 래치가 안 풀림(버튼 고착 등) | ⑤ 이후 | 실행 412가 계속되면 ⑥으로 넘어가 화면 장면만 한다. 해제는 버튼을 푼 뒤 `POST /stop/ack` |
| ThinQ 모의 꺼짐 | ④ | 말로만: "세탁기가 끝났다는 알림이 오면 이런 안내를 드립니다" + 알림함 캡처 |
| 전자레인지 가열 | ① | 결정 전까지 **가열하지 않는다**(결정 D3). L3 확인 없이 "시작 버튼 누름까지"만 말한다 |
| 폰·키오스크 연결 불안정 | 전체 | 키오스크 단독(지금 실행은 운영 노트북 curl로). 키오스크도 안 되면 트윈 + 운영 노트북 |
| 시간 초과 | — | §1 "줄이는 순서" |
