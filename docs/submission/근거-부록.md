# 근거 부록 — 날짜·빌드·작업 기록 (GitHub 전용)

[개발완료보고서](개발완료보고서-초안.md)와 [작품소개서](작품소개서-초안.md) 본문은 **무엇을 어떤 수준으로 확인했는지**만 적는다.
팀 내부 점검 번호·커밋 해시·작업 기록 링크는 이 문서로 모았다. 제출 PDF·책자에는 넣지 않고 공개 저장소에서만 본다.

실물 결과는 각 날짜 작업 기록(devlog)의 개발자 보고를 인용한다. 이 문서를 고치며 실물을 다시 시험하지 않았다.
커밋은 그 날짜에 보드에 올린 빌드 또는 기록 커밋이다. 기록에 실측 실행 빌드가 따로 없으면 기록 커밋을 실측 빌드라고 단정하지 않는다.

## 1. 내부 용어 대응

본문은 쉬운 말을 쓰고, 팀 문서·코드는 아래 내부 이름을 쓴다.

| 본문 표현 | 내부 이름 | 뜻 |
|---|---|---|
| 누름 확인(전류) | L1 | 누름 장치 쪽 전류로 버튼이 눌렸는지 판정 |
| 가전 소리 확인 | L2 | 가전 소리로 입력을 받았는지 판정 — 실행 경로에 연결하지 않음 |
| 전력 확인(CT) | L3 | 콘센트 CT 전력 상승·유지로 가전이 동작했는지 판정 |
| 정지 세 단계: 보냄 / 모션 보드 확인 / 멈춤 확인 | `sent` / `mcu_ack` / `verified` | 정지 보고 단계. 멈춤 확인은 엔코더 움직임을 본 실행에서만 |
| 상태를 다시 읽어 바뀐 것을 확인 | `state_confirmed` | ThinQ 명령 뒤 상태 재조회로 목표값을 본 결과 |
| 정지 경계 보강 여덟 가지 | G1·G2·G3·G4·G5·G7·G9·G11 | 아래 §3 표 |
| 남은 정지 경계 두 가지 | G6·G8 | 정지 결과를 화면에 돌려주는 것, 실행기 재시작 뒤 원점 재확인 — [안전 계약 적용 보고](../안전계약-적용-보고-2026-10-15.md) §2 |
| 같은 버튼 두 번 누름(재누름 금지) | R1 | 토글·성질 모르는 버튼은 자동 재누름 금지 |
| 정지 경계 실물 시험 | PS-1 | ESP32 모션 보드 복귀 뒤 실제 보드로 정지 상황을 만드는 시험 — 같은 보고 §3 |
