## 1쪽 — 누구를, 왜, 무엇이 다른가

### 쓰던 가전을 바꾸지 않고, 제안·승인·확인으로 대신 조작한다

작은 버튼을 정확히 누르고 여러 단계 메뉴를 기억하는 일은 고령자와 저시력 사용자에게 부담이다. 그렇다고 멀쩡한 가전을 스마트 가전으로 바꾸기는 어렵다.
SimpleLay는 버튼식 가전의 조작부 위에 누름 장치를 얹는다. 장치가 할 일을 **제안**하고, 사용자가 **승인**한 것만 누르며, 콘센트 전력으로 가전이 실제로 동작했는지 **확인**해 알려 준다.
처음 등록(조작부 사진·버튼 위치)은 보호자나 설치자가 폰으로 하고, 매일 쓰는 승인·거절·정지는 당사자가 큰 글씨 키오스크와 폰으로 한다.

### 단일 버튼 푸셔 방식과 다른 점

| | 단일 버튼 푸셔(공개 사양: SwitchBot Bot·Fingerbot Plus) | SimpleLay |
|---|---|---|
| 버튼 등록 | 누를 버튼 옆에 장치를 붙임(스티커 부착) | 조작부 사진에서 버튼 위치·이름을 등록 |
| 여러 버튼 | 장치 하나가 버튼 하나를 누르는 구조. 한 장치로 여러 버튼 순서 조작은 확인하지 못함 | 갠트리 하나가 한 조작부의 여러 버튼을 순서대로(즉석밥 → 시작) |
| 동작 확인 | 누름·가전 동작 확인 기능은 확인하지 못함(SwitchBot 상태값 ON/OFF는 스위치 모드에서만 유효) | 콘센트 CT 전력으로 가열 시작·종료 확인, 확인 못 하면 그대로 보고·안전 정지 |
| 스마트 가전 | 앱·허브 경유 원격·음성 비서 연동. ThinQ 가전과 한 흐름은 확인하지 못함 | LG ThinQ 가전도 같은 승인·결과 흐름 |
| 제안 | 앱 타이머·일정 실행. 사용 기록 기반 제안은 확인하지 못함 | 사용 기록으로 습관 제안, 사용자가 허용한 조건에서만 낮은 위험 동작 자동 실행 |

이 표는 설계 차이이며 상용 제품과의 성능 비교가 아니다(상용 제품을 시험하지 않았다). 공개 사양 출처(2026-10-14 확인): SwitchBot Bot 제품 페이지 https://www.switch-bot.com/products/switchbot-bot · SwitchBot 공식 API 문서 https://github.com/OpenWonderLabs/SwitchBotAPI/blob/main/devices/others/bot.md · Fingerbot Plus 제품 페이지 https://www.adaprox.io/products/fingerbot-plus. '확인하지 못함'은 공개 사양에서 찾지 못했다는 뜻이지 기능이 없다는 뜻이 아니다.
같은 장치에서 **동작 확인 기능을 끈 비교 조건**과 SimpleLay를 비교한 결과는 2쪽에 적는다.

### 구성

| 보드 | 역할 |
|---|---|
| RPi5 허브 | 제안·승인·기록, 15.8형 터치 키오스크, ThinQ 연동 |
| RPi4 실행기 | 버튼 순서 실행·결과 확인·정지 보고(계획서 RPi Zero 자리) |
| ESP32 모션 | CoreXY 갠트리(엔코더 모터 2개) + 솔레노이드 누름 |
| ESP32 콘센트 모듈 | CT 전력으로 가전 동작 확인, 릴레이·비상정지 래치 |

갠트리와 모션 펌웨어의 제어 핵심은 팀원의 이전 작품과 공유하고, 승인·확인·제안·콘센트 모듈·화면은 이 대회를 위해 새로 만들었다.

## 2쪽 — 시연과 검증

### 결선 시연 (v4, 시연 약 6분)

1. **제안 거절** — "안 할래요"를 누르면 장치는 움직이지 않는다.
2. **첫 조리 승인** — 갠트리가 전자레인지 버튼을 누르고, CT로 가열 시작과 가열 종료를 감지한다(조리 완료가 아닐 수 있음). 이어 공기청정기 강풍 제안에서 "다음부터도 자동으로"를 고르면 조건·대상·동작을 확인한 뒤 ThinQ로 바꾸고, 상태를 다시 조회해 바뀐 것을 확인한다.
3. **같은 조건에서 다시** — 조리는 다시 승인하고, 가열 종료 뒤 공기청정기는 추가 승인 없이 강풍을 요청한다. 이미 강풍이면 변경 명령 없이 현재 상태만 확인한다.
4. **기록 확인 → 자동 실행 끄기.**
5. **일부 실패** — 명령은 보냈지만 확인하지 못하면 "결과 확인 불가"로 남기고 다시 보내지 않는다.

버튼 누름은 매번 승인한다. 가열 종료 감지는 취소·문 열림과 아직 구분하지 못하므로 화면은 '조리 완료가 아닐 수 있음'을 함께 말한다.

### 비교 조건 실험 · 초기 사용성 점검 · 원가

- **비교 조건 실험:** 전자레인지 "즉석밥 → 시작"을 ① 사람이 직접 ② 같은 장치에서 동작 확인 기능을 끈 비교 조건 ③ SimpleLay로 수행. 일부러 넣은 실패 조건에서 잘못된 상태로 끝난 횟수 ② 【기입】 / ③ 【기입】, 실패를 알아챈 시간 ② 【기입】 / ③ 【기입】. 상용 제품 시험이 아니다.
- **초기 사용성 점검:** 팀 밖 【기입: N】명이 모의 화면 과업 5개(제안 이해·승인·거절·정지·방해 금지) 중 【기입: k】개를 도움 없이 끝냈고, 도움을 요청한 지점 【기입: j】곳 중 【기입: i】곳을 고쳤다. 접근성 검증이나 당사자 평가가 아니며 일반화하지 않는다.
- **원가·설치:** 시연 1대 실제 구매가 【기입】원, 처음 해 보는 사람의 설치 시간 【기입】분(1회).
