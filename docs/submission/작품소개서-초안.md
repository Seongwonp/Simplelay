## 1쪽 — 누구를, 왜, 무엇이 다른가

### 쓰던 가전을 바꾸지 않고, 제안·승인·확인으로 대신 조작한다

작은 버튼을 정확히 누르고 여러 단계 메뉴를 기억하는 일은 고령자와 저시력 사용자에게 부담이다. 그렇다고 멀쩡한 가전을 스마트 가전으로 바꾸기는 어렵다.
SimpleLay는 버튼식 가전의 조작부 위에 버튼 누름 장치(CoreXY 갠트리 + 솔레노이드)를 얹는다. 장치가 할 일을 **제안**하고, 사용자가 **승인**한 것만 누르며, 콘센트 전력으로 가전이 실제로 동작했는지 **확인**해 알려 준다.
처음 등록(조작부 사진·버튼 위치)은 보호자나 설치자가 폰으로 하고, 매일 쓰는 승인·거절·정지는 당사자가 큰 글씨 키오스크와 폰으로 한다.

### 단일 버튼 푸셔 방식과 다른 점

| | 단일 버튼 푸셔(공개 사양: SwitchBot Bot·Fingerbot Plus) | SimpleLay |
|---|---|---|
| 버튼 등록 | 누를 버튼 옆에 장치를 붙임(스티커 부착) | 조작부 사진에서 버튼 위치·이름을 등록 |
| 여러 버튼 | 장치 하나가 버튼 하나를 누르는 구조. 한 장치로 여러 버튼 순서 조작은 확인하지 못함 | 갠트리 하나가 한 조작부의 여러 버튼을 순서대로(예: 30초 → 시작) |
| 동작 확인 | 누름·가전 동작 확인 기능은 확인하지 못함(SwitchBot 상태값 ON/OFF는 스위치 모드에서만 유효) | 콘센트 CT 전력으로 가열 시작·종료 확인, 확인 못 하면 그대로 보고·안전 정지 |
| 스마트 가전 | 앱·허브 경유 원격·음성 비서 연동. ThinQ 가전과 한 흐름은 확인하지 못함 | LG ThinQ 가전도 같은 승인·결과 흐름 |
| 제안 | 앱 타이머·일정 실행. 사용 기록 기반 제안은 확인하지 못함 | 사용 기록으로 습관 제안, 사용자가 허용한 조건에서만 낮은 위험 동작 자동 실행 |

이 표는 설계 차이이며 상용 제품과의 성능 비교가 아니다(상용 제품을 시험하지 않았다). 공개 사양 출처(2026-10-14 확인): SwitchBot Bot 제품 페이지 https://www.switch-bot.com/products/switchbot-bot · SwitchBot 공식 API 문서 https://github.com/OpenWonderLabs/SwitchBotAPI/blob/main/devices/others/bot.md · Fingerbot Plus 제품 페이지 https://www.adaprox.io/products/fingerbot-plus. '확인하지 못함'은 공개 사양에서 찾지 못했다는 뜻이지 기능이 없다는 뜻이 아니다.
같은 장치에서 **동작 확인 기능을 끈 비교 조건**과 SimpleLay를 비교한 결과는 2쪽에 적는다.

### 구성

| 보드 | 역할 |
|---|---|
| RPi5 허브 | 제안·승인·기록, 15.8형 터치 키오스크, ThinQ 연동 |
| RPi4 실행기 | 버튼 순서 실행·결과 확인·정지 보고(계획서 RPi Zero 자리) |
| ESP32 모션 | CoreXY 갠트리(엔코더 모터 2개) + 솔레노이드 누름 |
| ESP32 콘센트 모듈 | CT 전력으로 가전 동작 확인, 릴레이·비상정지 래치 |

갠트리와 모션 펌웨어의 제어 핵심은 팀원의 이전 작품과 공유하고, 승인·확인·제안·콘센트 모듈·화면은 이 대회를 위해 새로 만들었다.

## 2쪽 — 시연과 검증

### 결선 시연 (v4, 시연 약 6분)

1. **제안 거절** — '이번엔 안 할게요'를 누르면 장치는 움직이지 않는다.
2. **첫 조리 승인** — 갠트리가 전자레인지 버튼을 누르고, CT로 가열 시작과 가열 종료를 감지한다(조리 완료가 아닐 수 있음). 이어 카드 '공기청정기 바람을 세게 할까요?'에서 '다음부터도 자동으로' → '허락하고 이번에도 하기'를 고르면 ThinQ로 바꾸고, 상태를 다시 조회해 바뀐 것을 확인한다.
3. **같은 조건에서 다시** — 조리는 다시 승인하고, 가열 종료 뒤 공기청정기는 추가 승인 없이 바람을 세게 한다. 이미 그 설정이면 변경 명령 없이 현재 상태만 확인한다.
4. **기록 확인 → 자동 실행 끄기**(루틴 탭 '자동 규칙').
5. **일부 실패** — 명령은 보냈지만 확인하지 못하면 '보냈지만 설정이 바뀌었는지 몰라요'로 남기고 다시 보내지 않는다.

버튼 누름은 매번 승인한다. 가열 종료 감지는 취소·문 열림과 아직 구분하지 못하므로 화면은 '조리 완료가 아닐 수 있어요'를 함께 말한다.
**지금 다섯 장면 중 실물로 끝까지 성공한 장면은 없다**(실제 누름·CT 판정 미측정). 준비되지 않은 장면은 '연습'으로 밝히고 녹화·모의로 대신한다.
화면 말은 처음 쓰는 사람 기준으로 정했다 — 기기는 '본체', 버튼 누름 장치는 '누름 장치', ThinQ 가전은 'LG 가전'.

### 검증 수준

| 수준 | 내용 |
|---|---|
| 실물 확인 | 모터 축 구동·엔코더 계수, 누름 제어 신호, 정지 세 단계(보냄 → 모션 보드 확인 → 멈춤 확인, 10회), 걸림 뒤 재시도 없이 정지, USB 재연결(벨트·솔레노이드 없이, 10/12~14). 실제 공기청정기 ThinQ 제어·상태 재조회(노트북 허브 10/15, **RPi5 허브 10/16**). 시각 규칙으로 카드 없이 22:00 켜기·다음 날 07:00 끄기, 상태 재조회로 확인(10/16~17). 새 키오스크 실패널 설치와 LG 가전 실행 화면, 다음 한 번 건너뛰기(10/16~18) |
| 실물 확인(제한된 흐름) | 공기청정기 꺼짐 + 공기질 나쁨 → 켜기 제안 → API 승인 → 실제 켜짐(10/15, 노트북 허브). 폰·키오스크 승인은 미확인, 클라우드 반영 수 분 지연으로 주 시연에서 뺌 |
| 시험 조건 통과·보드 배포됨 | 정지 경계 보강(보내기 전·루틴 사이 정지, 링크 끊김 '눌렸는지 모름', 실행 중 생존 신호, 엔코더 근거 있는 멈춤 확인)과 토글 버튼 자동 재누름 금지. RPi4·RPi5에 배포(10/16 밤부터), 실물 시험은 모션 보드 복귀 뒤 — 지금 RPi4는 모의 모션 |
| 모의까지 | CT 가열 판정과 실제 CT에서 공기청정기 자동 실행으로 잇는 흐름, 습관 제안(합성 이력), 콘센트 모듈(컴파일·가짜 모듈) |
| 미측정 | 캐리지 이동·실제 버튼 누름 성공률, CT 시작·종료 판정 지연, 캐리지 정지 거리·시간, 대회장 인터넷 조건의 ThinQ 지연 |

실물 결과는 개발 기록의 개발자 보고를 인용했다(날짜별 근거는 개발완료보고서 부록). 자동 시험(10/18, 골든 제외): 백엔드+RPi4 3,565 · 폰 1,177 · 키오스크 1,046 — 제출 직전 다시 돌려 적는다.

### 비교 조건 실험 · 초기 사용성 점검 · 원가

- **비교 조건 실험:** 전자레인지 '30초 → 시작'(시연과 같은 과업)을 ① 사람이 직접 ② 같은 장치에서 동작 확인 기능을 끈 비교 조건 ③ SimpleLay로 수행해, 일부러 넣은 실패 조건에서 잘못된 상태로 끝난 횟수와 알아챈 시간을 ②·③으로 비교한다. 상용 제품 시험이 아니다.
- **초기 사용성 점검:** 팀 밖 1~2명이 화면 과업 5개(제안 이해·승인·거절·정지·잠시 쉬기)를 도움 없이 끝내는지 본다. 접근성 검증이나 당사자 평가가 아니며 일반화하지 않는다.
- **원가·설치:** 시연 1대 실제 구매가, 처음 해 보는 사람의 설치 시간(1회).
