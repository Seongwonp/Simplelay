# 공개 저장소 점검

기준: 2026-10-28, `72e7adbc` 위 작업 트리. 현재 파일의 문서 정리이며 전체 보안 감사나 공개 승인 완료 보고가 아니다.

## 정리 결정

- 기존 main 압축·이력 재작성·강제 push는 사용자와 논의 후 보류했다. 커밋과 실측 근거의 연결을 보존한다.
- 개발로그의 실패·시험·실측·재사용 경계와 AI 도구 사용 사실을 보존한다. 당시 결과를 소급해 바꾸지 않는다.
- 삭제 대상은 비공개 제공 자료·내부 인터페이스·비밀값·개인 경로다. 공개 기술·제품명과 공식 출처를 일괄 삭제하지 않는다.
- 저장소 공개/비공개 설정, 원격 브랜치·PR·태그·백업을 변경하지 않는다.

## 과거 이력과 바이너리

- `git log --all`의 추가 파일명 메타데이터에서 민감 확장자 이력 이름 1종이 잡혔다. 파일 내용·바이너리는 열지 않았다. 기존 [공개 문서 정리 기록](devlog/devlog_2026-10-14-public-docs.md)과 함께 검토할 항목이다.
- 과거 이력 전체의 텍스트·비밀값·모든 원격 PR 사본·GitHub 캐시는 이번에 감사하지 않았다. 현재 HEAD 정리는 과거 노출 제거가 아니다.
- 화면 캡처·사진·SVG의 시각 내용, 모델·외부 코드의 라이선스와 제공 조건을 전수 검토하지 않았다.
- 실제 비공개 정보가 확인되면 필요한 이력만 제거하는 방법과 저장소·외부 사본 처리 방법을 먼저 정한다. 자격증명이면 삭제만 하지 않고 폐기·교체를 별도로 판단한다.

## 남은 결정

1. 고정 빌드 이름과 패키지 메타데이터를 공개해도 되는지 제공 조건 확인. 필요하면 로컬 생성·분리 방식을 빌드 시험과 함께 검토.
2. 파일명 이력 1종과 기존 PR 사본의 실제 민감성 확인. 내용 확인은 사용자가 범위를 따로 지정한 경우에만 진행.
3. 제출 서류의 상황 제안 실물/모의 불일치와 최신 보드 배포 SHA를 결선 근거로 정리.
4. 실폰·패널·기구 검증, HTTP 평문, 이미지·외부 라이선스 검토는 별도 과제로 유지.

공개 준비의 첫 점검이지 저장소 전체 공개 가능성에 대한 보증은 아니다. 코드·HW 동작, 펌웨어·키·배포 설정은 바꾸지 않았다.
