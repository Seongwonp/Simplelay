# 결선 실측 계획 — 그래프 4종

작성 2026-10-10. 근거: [인계 2026-10-09 노트북 6차](archive/인계-2026-10-09-노트북-6.md) §1.
**지금은 도구와 절차만 있다. 실측값은 하나도 없다.** 측정은 최종 하드웨어(갠트리·누름 장치·콘센트 모듈)가
조립된 뒤에 한다. 이 문서의 숫자 중 계획 표본 수 말고는 전부 "실측 후 정함"이다.

기록 원칙은 [실측 기록표](실측-기록표.md) 공통 규칙을 그대로 따른다 — 빈칸은 '모름', 추정과 실측을 섞지 않음,
원시 파일은 저장소 밖(`data/bench/`, git 무시 경로). 그림에 쓴 원시 파일 이름과 요약 수치만 기록표에 옮긴다.

## 0. 도구

`scripts/plots/` — 기록을 그림으로 옮길 뿐 판정하지 않는다.

| 그래프 | 스크립트 | 입력 |
|---|---|---|

| 2. 누름 성공률 | `python -m scripts.plots.success_rate success.csv --out g2.png` | 표 CSV(§2) |

- 필요 패키지: `matplotlib`(pyproject `test` 추가 의존성에 넣었다 — `.venv/Scripts/python.exe -m pip install -e ".[test]"`).
  기기 실행 경로에는 필요 없다. 한글 글꼴은 맑은 고딕·나눔고딕 순으로 쓰고 없으면 기본 글꼴(한글이 네모로 보일 수 있음).
- 시험: `rpi/tests/test_plots.py`.

### 실측/합성 구분 — 추측하지 않는다

| 입력 | 판정 근거 | 정해지지 않을 때 |
|---|---|---|
| 표 CSV(그래프 1~3) | `data_kind` 열(`measured`·`synthetic`, 모든 행이 같아야 함) 또는 `--data-kind` | 거절. 열과 옵션이 둘 다 있으면 같아야 하고, 행마다 섞여 있으면 거절 |
| 기록기 출력(그래프 4) | 파형 행의 `source` — `power`면 실측, `mock_power`면 합성(기록기가 합성 입력을 `mock_*`로 적는 규칙) | 둘이 섞이면 거절. `--data-kind`는 확인용(어긋나면 거절) |

합성으로 판정된 그림에만 가운데에 **"예시(합성 데이터)"** 워터마크와 아래쪽에 "합성 데이터 — 실측 아님"이 들어간다.
실측 그림에는 넣지 않는다. 합성 그림은 발표·보고서의 근거로 쓰지 않는다(형식 견본으로만).

### 거절하는 입력

파일 없음 · 0바이트 · 머리행만 · 필수 열 없음 · 필수 칸 빈칸(행 번호를 알려 준다) · 숫자 아님 · 0/1이 아닌 판정 ·
기록 모순(첫 시도 성공인데 최종 실패 등) · 시각 순서 역전 · 전력 표본 2개 미만 · 판정 시각 없음/여럿/파형 밖.
거절하면 그림 파일을 만들지 않고 종료 코드 2로 끝난다.

## 1. 목표 좌표 vs 실제 누른 위치 오차

- **목적:** 좌표 보정 뒤 누름 장치가 버튼 중심에서 얼마나 벗어나는지 보인다. 재시도 보정(오프셋 이동)이 필요한 이유의 근거.
- **방법:** 조작부 위에 얇은 기록지(눈금 1 mm, 기준점 2개)를 붙이고 누름 끝에 잉크·먹지를 묻혀 누른 자국을 남긴다.
  목표 좌표는 보정 프로필의 버튼 좌표(mm), 실제 위치는 자국 중심을 기록지 눈금으로 읽는다(사진 + 자로 재확인).
  재시도 보정이 들어간 누름은 첫 누름만 적는다(보정 효과는 그래프 2에서 본다).
- **횟수:** 버튼 3개(즉석밥·시작·취소 — 실제 가전 버튼판 기준으로 시작 전에 확정) × 30회 이상.
- **합격선:** 실측 후 정함. 지금 코드의 보정 허용 오차(RMS 1.0 mm·한 점 2.0 mm)는 추측값이다([기록표 §4-1](실측-기록표.md)).
  정하면 `--tolerance-mm`으로 원을 그린다. 정하기 전에는 그림에 "합격선: 실측 후 정함"이 찍힌다.
- **기록 형식** `offset.csv` (UTF-8, 한 행 = 한 누름):

| 열 | 뜻 |
|---|---|
| `button` | 버튼 이름 |
| `trial` | 시도 번호 |
| `target_x_mm`, `target_y_mm` | 보정 프로필 목표 좌표 |
| `actual_x_mm`, `actual_y_mm` | 자국 중심(같은 좌표계) |
| `data_kind` | `measured` (없으면 `--data-kind` 필수) |
| `note` | 선택 — 측정일·측정자·조건 |

## 2. 버튼별 누름 성공률

- **목적:** 첫 시도 성공률과 재시도 포함 최종 성공률의 차이로 폐루프(확인·재시도)의 효과를 보인다.
- **방법:** 판정 기준은 **사람**(표시창 변화·버튼음, 영상 보관). 센서 판정은 비교 대상이며 이 그림에 넣지 않는다.
  실패 주입 시도는 `fault_injected=1`로 적고 자연 성공률에서 뺀다(그림에 제외 수 표시). 모의 실행은 기록하지 않는다
  (실행 이력의 실행 모드가 `real`인 것만).
- **횟수:** 버튼 3개 × 자연 시도 30회 이상. 30회 미만이면 그림에 "표본 부족"이 찍힌다.
- **합격선:** 실측 후 정함.
- **기록 형식** `success.csv` (한 행 = 한 버튼 누름, [기록표 §4](실측-기록표.md) 시도 기록과 같은 행):

| 열 | 뜻 |
|---|---|
| `button`, `trial` | 버튼·시도 번호 |
| `fault_injected` | 0/1 |
| `first_press_ok` | 0/1 — 재시도 없이 눌림(사람) |
| `final_press_ok` | 0/1 — 재시도 포함 최종 눌림(사람) |
| `retries` | 재시도 수(0 이상, 첫 시도 성공이면 0) |
| `data_kind`, `note` | 위와 같음 |

## 3. 정지 요청 → 모터 정지 지연 분포

- **목적:** 비상정지가 실제로 얼마나 빨리 멈추는지 구간별로 보인다. 어느 구간이 긴지(네트워크·루프 경계·기구)를 가른다.
- **방법:** [기록표 §5](실측-기록표.md)의 네 시각. t0(사람이 정지를 누름)과 ③(모터 실제 정지)은 영상 프레임으로,
  ①(서버 정지 접수 `stop_requested_at`)과 ②(루프 종료)는 실행 이력으로 읽는다. 촬영 시작 때 화면에 서버 시각을 띄우거나
  기록기 marker를 찍어 시각축을 맞추고, 맞춤 오차를 `note`에 적는다. 엔코더가 있으면 ③은 속도 0 시각으로 대신한다.
  ACK(정지 접수 응답)는 ①에 해당한다.
- **횟수:** 정지 경로 3개(키오스크·폰·물리 버튼) × 정지 시점 2개(이동 중·누름 중) × 10회 이상(합계 60회 이상).
- **합격선:** 실측 후 정함.
- **기록 형식** `stop.csv` (한 행 = 정지 한 번, 단위 ms, 같은 시각축):

| 열 | 뜻 |
|---|---|
| `trial` | 시도 번호 |
| `path` | 키오스크 / 폰 / 물리 버튼 |
| `stop_phase` | 이동 중 / 누름 중 / 재시도 대기 중 |
| `t0_press_ms` | 사람이 정지를 누름(영상) |
| `t1_accepted_ms` | 서버 정지 접수(① ACK) |
| `t2_loop_end_ms` | 실행 루프 종료(②) |
| `t3_physical_stop_ms` | 모터 실제 정지(③ 영상·엔코더) |
| `data_kind`, `note` | 위와 같음 |

t0 ≤ ① ≤ ② ≤ ③이 아니면 시각 맞춤 오류로 보고 거절한다.

**모션 MCU 구간 두 개(2026-10-13 추가 — 정지 확인 단계, [계획](계획-정지-확인-2026-10-12.md)·
[devlog](devlog/devlog_2026-10-13-stop-confirm.md)).** RPi4가 정지 줄을 쓴 시각(`sent`)부터 두 구간을 따로 잰다.
코드는 들어갔고 가짜 MCU로만 시험했다 — **실측값 없음, 두 보드 함께 배포 뒤 첫 측정.**

| 구간 | 근거(같은 단조 시각축) | 어디서 읽나 |
|---|---|---|
| A. `sent → mcu_ack` | RPi4가 `{"cmd":"stop"}`를 쓴 시각 → MCU의 같은 `id` `{"ok":true}`를 읽은 시각 | `SIMPLELAY_MOTION_LOG_PATH` 줄 기록의 `>>`·`<<` 두 줄(`mono_ns`), 또는 `stop_report`·`dev_motion_result`의 `ack_ms` |
| B. `sent → verified` | 위 `sent` → 정지 뒤 `status` 두 번(약 100 ms 간격)의 엔코더 a·b가 같다고 본 두 번째 응답 시각 | 줄 기록의 두 번째 `status` 응답 `<<`(원시 기록기를 켰으면 `mcu_stop_verified` 행) |

- A는 MCU가 정지 명령을 받은 지연이다(물리 정지가 아니다). B는 엔코더 기준 멈춤 확인까지다 — 엔코더가 모터 축에
  있어 벨트 미끄럼은 보이지 않고, 확인 간격(100 ms) 자체가 B에 더해진다. B는 영상 ③과 나란히 적어 차이를 본다.
- 응답 기한(RPi4 0.3 s)·확인 간격(0.1 s)·RPi5 보고 기한(1.5 s)은 호스트 박자 자리표시자다. A·B 분포를 본 뒤 정한다.
- `stop.csv`에 선택 열 `t_sent_ms`·`t_mcu_ack_ms`·`t_verified_ms`(같은 시각축)를 더해 적는다. **그림 도구
  (`scripts/plots/stop_latency.py`)는 아직 이 열을 그리지 않는다** — 첫 측정 뒤 도구를 넓힌다.
- 같은 정지 시도에서 화면이 말한 단계(보냄·모션 보드 확인 n ms·멈춤 확인)가 기록과 맞는지도 `note`에 적는다.

## 4. CT 전력 파형 위 "시작 확인" 판정 시점

- **목적:** 버튼을 누른 뒤 가전이 실제로 돌기 시작했는지(L3)를 무엇을 보고 언제 판단했는지 한 장으로 보인다.
- **방법:** RPi4에서 `SIMPLELAY_RECORDER_PATH`로 원시 기록기를 켜고(콘센트 모듈 CT 전력 → `power` 행,
  누름 호출 → `press_start`/`press_end` 행) 전자레인지 즉석밥 → 시작 1회를 돌린다.
  **판정 시각:** 지금 기록기는 L3 판정 이벤트를 스스로 찍지 않는다. 실행 이력·로그의 L3 판정 시각을 같은 단조 시각축(ns)으로
  옮겨 `--decision-t-ns`로 주거나, 판정 이벤트가 기록 파일에 들어오면 `--decision-event <이름>`(기본 `l3_start_confirmed`)을 쓴다.
  어느 쪽인지는 하드웨어 연결 때 정하고 이 줄을 고친다.
  CT 2채널(전자레인지 ch0·세탁기 ch1)을 따로 기록하게 되면 source 이름을 확인해 스크립트의 `POWER_SOURCES`를 맞춘다.
- **횟수:** 사이클 5회 기록. 그림은 "첫 누름 끝 → 판정" 지연이 중앙값인 회차 1장을 쓰고(고르는 규칙을 미리 정해 골라 쓰기 방지),
  5회 지연값은 표로 함께 적는다.
- **합격선:** 실측 후 정함(현재 L3 상승 판정 값은 추측 — [기록표 §4-1](실측-기록표.md)).
- **기록 형식:** `rpi/verifier/recorder.py`의 CSV(머리행 `COLUMNS` 고정) 또는 JSONL을 그대로 쓴다. 쓰는 열은
  `t_monotonic_ns`, `source`(`power`/`mock_power`), `power_watts`, `event`(`press_start`·`press_end`·판정 이벤트).
  1회 사이클만 들어 있게 자른 파일을 넣는다(판정 이벤트가 2개 이상이면 거절).

## 5. 측정 뒤 할 일

1. 원시 파일을 `data/bench/`에 두고 파일 이름·측정일·조건을 [기록표](실측-기록표.md)에 적는다.
2. 각 그래프를 `data_kind=measured`(그래프 4는 실측 source)로 만든다. 워터마크가 없는지 눈으로도 확인한다.
3. 합격선을 정했으면 이 문서의 "실측 후 정함"을 값과 근거로 바꾼다. 그림은 보고서용 경로로 복사할 때만 커밋을 검토한다.
