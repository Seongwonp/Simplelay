# 개발 로그 — 2026-09-01

## 가전 정의의 단일 진실원천 — "폰에서 추가하면 키오스크에 뜬다"

출발점은 사용자 관찰 두 가지였다: "키오스크 설정에 전자레인지·인덕션이 왜 떠
있는지 모르겠다", "폰에서 기기를 추가하면 키오스크에도 연동돼야 하는데 방법이
없다". 파보니 둘은 같은 구조 문제였다 — **가전 정의가 다섯 곳**(백엔드
button-maps JSON·폰 하드코딩·폰 로컬 저장·키오스크 하드코딩·자연어 규칙)에
흩어져 있고 `GET /appliances` 자체가 없었다. 폰의 커스텀 가전은 폰 밖으로
나갈 길이 없었고, 설정의 가전 칩은 하드코딩 2종 중에서 고르는 맥락 없는
UI였다.

### 사전 서칭 조사 (요지)
- **NN/g 스마트 기기 온보딩**: 기기 추가·연결은 드문 작업이라 사용자가 절차를
  기억하지 못한다 — 설정 항목이 아니라 단계별 흐름으로, 실패 시 원인+다음
  행동을 말해줄 것. 모든 기기는 단일 인터페이스에서 중앙 관리.
- **고령자 키오스크 국내 연구·표준 공통 결론**: 최소 텍스트, 생소한 단어 금지,
  사용 단계 축소, 익숙함(familiarity) 디자인. 관리·구성 기능은 고령 사용자
  화면에 두지 않는다 — 일상 조작만 남기고 설정·등록은 보호자의 폰으로.
- 출처: NN/g smart-device onboarding/best-practices, 서울시 고령층 친화 디지털
  접근성 표준(키오스크), KCI 고령층 키오스크 UX 연구 다수 — 링크는 8/23
  체크리스트 문서와 함께 관리.

### 구현 (커밋 3개)
1. **백엔드 — 가전 레지스트리** (59289af): `GET /appliances`(내장+커스텀),
   `PUT /appliances/{id}`(upsert, 그리드 밖 좌표·중복 위치 422, 내장 id 409),
   `DELETE`(커스텀만). SQLite 영속. 내장 정의와 docs/button-maps 매니페스트의
   일치를 테스트로 고정 — 8/31 코스 교체처럼 한쪽만 고치면 이제 테스트가 잡는다.
2. **폰 — 저장·삭제 동기화** (cf49626): 가전 편집기 저장 시 서버에도 등록,
   설정에서 삭제 시 서버에서도 제거. best-effort — 서버가 죽어 있어도 폰 로컬
   동작은 그대로, 실패는 안내만.
3. **키오스크 — 선택 화면 + 목록 연동** (053f206): 대기 화면 터치 → 가전이
   여럿이면 큰 카드 선택 화면("어느 가전을 조작할까요?", 지난번 배지), 하나면
   바로 조작판. 목록은 1분 주기 GET /appliances, 실패 시 내장 폴백. 설정의
   가전 칩은 "노드를 등록할 가전" 선택으로만 축소.

이로써 **폰에서 가전 등록 → 1분 안에 키오스크 선택 화면에 카드로 등장 → 그
버튼맵이 그대로 조작판** 경로가 성립한다. 데모에서 "우리 집 가전을 그 자리에서
편입시키는" 장면으로 쓸 수 있다.

### 남은 것 / 실기기 확인
- 실기기에서: 폰 등록 → 키오스크 반영 왕복 확인 (컨테이너 재배포 필요)
- 커스텀 가전의 음성 명령은 기존 제약 그대로(LLM 경유) — 레지스트리와 별개
- 향후: 커스텀 가전에도 자연어 별칭을 등록하는 UI(레지스트리에 필드는 추가
  가능한 구조)

검증: 백엔드 **608** · 폰 **142(+11 골든)** · 키오스크 **40(+7 골든)** 통과.
골든(픽셀) 테스트는 기준 이미지를 만든 기계에서만 안정 — 다른 기계에서는
`flutter test --exclude-tags screenshot`(파일 머리 주석 참고).

또한 노트북 환경 정비: dbus-fast 설치(테스트 1건이 extra 미설치로 실패했었음).

## 보호자 알림함 + 안부 신호 — "가족을 잇는 돌봄 레이어"

추천 기능 1·2번 구현. 실패·위험소리·긴급정지는 그동안 키오스크(가전 옆)에만
표시됐다 — 정작 걱정하는 보호자는 밖에 있다.

### 백엔드 (fc4bd48, 데모 트리거 별도 커밋)
- **CareEventStore**: 보호자 알림 이력(SQLite 영속). 실행 실패 / 긴급정지
  (사용자 중단과 스스로 실패를 구분 — 같은 SAFETY_STOPPED라도 보호자에겐
  전혀 다른 소식) / 위험소리 rising edge / 안부 신호. `GET /care-events`.
- **안부 신호(quiet_routine)**: "평소 그 시간대에 3일 이상 쓰던 가전이 오늘
  시간대 종료까지 조용하면 하루 1회 알림". 서울시 스마트플러그·한전
  안부든든 등 실제 고독사 예방 서비스와 같은 원리를 usage_log로 구현 —
  스마트플러그 추가 설치 불필요, 판단은 전부 설명 가능한 임계값(AI 아님).
  - 자정 걸침 시간대(야간)는 제외: 새벽 안부 알림은 불안 유발
  - 실패한 시도도 활동으로 취급(조용함 아님 — 실패는 별도 이벤트가 알림)
  - 하루 1회 dedupe, 60초 주기 체크(제안 루프에 편승)
- `POST /demo/care-event`: 리허설 트리거 (자연 발생 조건이 까다로움)

### 폰 (74fdcf9)
- 알림함 화면(/care): 종류별 아이콘+라벨(색만으로 구분 안 함), 당겨서
  새로고침, Semantics. 홈 AppBar 종 아이콘 + 안 읽은 개수 배지(45초 폴링).
- 읽음 기준(마지막 본 이벤트 id)은 기기 저장 — 재시작에도 유지.
- 테스트가 실제 결함을 잡음: cascade(..)로 refresh·markAllSeen을 이어
  부르면 목록이 비어 있을 때 읽음 처리가 돌아 아무것도 읽음이 안 됐다.

### 심사 스토리
공감지능에 '거절 학습(다시 추천 안 함)'에 이어 '안부 감지'까지 —
"버튼 눌러주는 장치"가 "가족을 잇는 돌봄 레이어"로. 데모: 시연 중
`POST /demo/care-event` → 심사위원 앞에서 보호자 폰 배지가 뜨는 장면.

쌓인 뒤 자연 발생 1회 관찰(또는 데모 트리거).
