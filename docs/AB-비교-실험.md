# A/B 비교 실험 설계 — 사람 / 확인 없는 누름 / SimpleLay

작성 2026-10-10. 근거: [인계 2026-10-09 노트북 6차](archive/인계-2026-10-09-노트북-6.md) §2.
**설계만 있다. 실험은 하지 않았고, 비교 실험 모드(비교군 ②)는 구현하지 않았다.**
결과 칸은 비어 있으며, 채울 때는 행마다 `모의`/`실측`을 반드시 적는다(§6).

## 1. 질문

같은 갠트리로 누르기만 하는 장치(확인 없음)와 SimpleLay(누름 확인 L1 · 동작 확인 L3 · 재시도)는
**실패 조건에서** 무엇이 다른가 — 잘못된 상태로 끝나는 횟수와, 사용자가 그 사실을 알게 되는 시점.
정상 조건에서 둘이 비슷한 것은 예상 범위다. 차이는 일부러 넣은 실패 조건에서 본다.

## 2. 비교군

| 군 | 이름 | 누르는 주체 | 누름 확인(L1) | 동작 확인(L3) | 재시도 | 사용자 알림 |
|---|---|---|---|---|---|---|
| ① | 사람 직접 | 사람 손 | 사람 눈·귀 | 사람 | 사람 판단 | — |
| ② | 동작 확인 기능을 끈 비교 조건 | 같은 갠트리 | **끔** | **끔** | **없음**(1회) | 명령 보냈음만 표시 |
| ③ | SimpleLay | 같은 갠트리 | 켬 | 켬(콘센트 모듈 CT) | 켬(기본 정책) | 확인 결과·실패 알림 |

- ②는 **동작 확인 기능을 끈 비교 조건**이다(2026-10-14 표현 확정). 상용 제품을 시험한 것이 아니므로 결과로 상용 제품보다 낫다고 말하지 않는다. 기구·좌표·누름 시간은 ③과 **똑같이** 두고 판정과 재시도만 끈다.
- 제출 전에 실제로 할 최소 횟수·하드웨어 전제·담당은 [제출 전 검증 과업](제출전-검증-과업.md) §1이 기준이다(설정만으로 ②를 만드는 방법 포함).
- L2(가전 수락 확인)는 지금 RPi4 운영 경로에 연결되지 않았다(계약·모의까지). 따라서 ③도 L1·L3만으로 비교한다.
- ①은 기준선이다. 비교 대상 사람은 처음엔 팀원, 사용자 의견 계획(인계 6차 §4, `docs/사용자-의견-계획.md` 작성 예정)이 서면 그 참여자로 넓힌다.

## 3. 과업

**전자레인지 "30초 → 시작"** (30초 버튼 다음 시작 버튼. 10/18 결정으로 [시연 v4](본선-시연-계획-v4.md) '30초 데우기'와 같은 과업으로 맞췄다 — 처음 설계(10/10)는 [시연 v3](archive/본선-시연-시나리오-v3.md)의 '즉석밥 → 시작').
성공 정의: 과업 뒤 가전이 **30초 설정으로 실제 가열 중**이다(표시창·회전판·소리, 사람 판정, 영상 보관).
과업 한 번 = 명령 한 번(①은 사람이 버튼 두 개를 누르는 것까지).

## 4. 실패 조건(일부러 넣는 것)

| 기호 | 조건 | 넣는 방법 | ①에 적용 |
|---|---|---|---|
| C0 | 정상 | 없음 | 적용 |
| C1 | 좌표 2 mm 어긋남 | "시작" 버튼 목표 좌표를 X로 +2 mm(버튼 가장자리에 걸리게). 실제로 안 눌리는 거리인지 C0 보정 뒤 먼저 확인하고, 안 눌리면 어긋남 거리를 기록하고 바꾼다 | 해당 없음 |
| C2 | 누름 시간 부족 | 누름 유지 시간을 가전이 인식 못 하는 값으로 줄임(값은 실측 후 정함) | 해당 없음 |
| C3 | 가전이 시작을 거부 | 전자레인지 문을 살짝 열어 둠(버튼은 눌리지만 가열 안 됨) | 적용 |

- C1·C2는 L1(누름 확인)이, C3은 L3(전력 상승 확인)가 잡아야 하는 실패다. ③이 못 잡으면 그대로 기록한다(유리한 결과만 고르지 않는다).
- 조건 순서는 무작위로 섞고 순서를 기록한다. 조건마다 시작 전에 가전을 대기 상태로 되돌린다.

## 6. 결과 표시 — 모의와 실측을 섞지 않는다

- 먼저 **모의**로 한 번 돌려 표 형식만 확인한다. 모의에서는 판정 결과가 주입값(`MockVerifier`)이라 성공률·차이가
  설계대로 나올 뿐 증거가 아니다. 그 행은 표시 칸에 `모의`를 적고 요약표·발표에 숫자로 쓰지 않는다.
- **실측**은 실제 갠트리·누름 장치·콘센트 모듈로, 실행 이력의 실행 모드가 `real`인 것만이다. 표시 칸에 `실측`.
- 한 요약 행에 모의와 실측을 합치지 않는다. 그림을 만들면 [실측 계획](실측-계획-결선.md)의 `data_kind` 규칙을 따른다
  (모의 = `synthetic`, 워터마크).
- 발표 문장은 실측 행이 생긴 뒤에만 만든다. 그 전에는 "비교 실험을 설계했다"까지만 말한다.

## 7. 비교 실험 모드(군 ②) — 구현하지 않음, 연결 지점만

군 ②는 판정과 재시도를 끄는 실행 경로가 필요하다. 시연·평소 실행에 새어 들어가면 안전 장치를 끄는 셈이므로
아래 조건을 모두 지킬 때만 연다(팀 결정 뒤 별도 커밋).

**게이트**
- env `SIMPLELAY_COMPARE_PRESS_ONLY=1`(가칭, 기본 꺼짐) **그리고** `SIMPLELAY_DEV_MODE=1`일 때만 켜진다.
  둘 중 하나라도 없으면 평소 경로. 모르는 값이면 기동 거절.
- 켜진 동안 폰·키오스크 화면에 항상 **"비교 실험 모드"** 배지를 띄운다(숨길 수 없음).
- 비상정지·래치·정지 대기 경로는 그대로 둔다 — 끄는 것은 L1·L3 판정과 재시도뿐이다.
- 실행 이력에 비교 모드 표시를 남겨 성공률 통계(실측 기록표 §4)에 섞이지 않게 한다.

**연결 지점**(2026-10-10 기준 코드 위치, 구현 때 다시 확인)

| 할 일 | 위치 |
|---|---|
| L1 끔: 판독 없이 통과하는 검증기로 교체 | `rpi4/act_main.py` `_build_verifier()` |
| 재시도 끔: `max_attempts=1` 정책 주입 | `rpi4/act_main.py`의 `ClosedLoopController(...)` 생성(현재 `retry_policy` 미지정 → `rpi/controller/retry.py` `DocumentedRetryPolicy` 기본 3회) |
| L3 끔: 실행 대상 판정기를 꽂지 않음 | `rpi4/services/act_executor.py`의 `self._controller.use_operation(binding.operation)` |
| L2 | 운영 경로에 판정기가 없어(`operation=None`, act_main) 할 일 없음 |
| 모의(로컬) 경로에서 표 형식 확인 | `rpi/services/controller_factory.py` `build_controller()`의 mock `ClosedLoopController` |
| 상태에 모드 노출 | `rpi/api/schemas.py` `StatusResponse`(`developer_mode` 옆 필드) · `rpi/api/router.py` `status()` |
| 배지 | 키오스크 `rpi5-touchscreen-app/lib/services/kiosk_api_service.dart`(상태 파싱) + 상단 띠 · 폰 `app/lib/models/hub.dart`(허브 상태) + 홈·실행 화면 |
| 이력 표시 | `rpi/services/history.py`(실행 모드와 별개의 비교 모드 열, CSV 내보내기 허용 목록) |
| C1 좌표 어긋남 주입(③·② 공통) | `rpi4/act_main.py`에서 `RecordingGrblClient`로 감싸는 자리와 같은 곳에 `PressCommand.x_mm`에 고정 오프셋을 더하는 래퍼(같은 dev 게이트, 기본 0) |

시험으로 고정할 것(구현 때): 게이트 둘 중 하나만 켜면 평소 경로 · 비교 모드에서도 비상정지 래치 동작 ·
상태 응답에 모드가 나오고 배지가 뜸 · 비교 모드 실행이 성공률 집계에서 빠짐.
