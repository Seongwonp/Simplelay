# 2026-10-06~07 데스크톱 — 노트북 인계 2차 실행

[인계 2차](인계-2026-10-06-노트북-2.md)를 실행했다. 사용자 결정에 따라 4·5·6단계를 먼저 했고, 0단계(이력 정리)는 원격 반영만 남았다. 모든 실행은 **모의 모션**이다. 실물 버튼 누름은 여전히 0건이다.

## 0. git 이력에서 발표 자료 제거 — 완료(10/7 강제 푸시)

- 이력에 남은 문서 파일은 발표 자료 1개뿐이었다.
- 백업: 저장소 밖에 미러 백업을 만들었다.
- 다시 쓰기: 별도 미러 클론에서 `git filter-repo`로 이력을 다시 썼다.
  - 다시 쓴 이력에서 문서 파일 0건
  - 최신 트리가 원래와 동일
  - 백엔드 시험 2,435 통과
- **원격 강제 푸시는 자동 권한 판정에서 막혔다.** 사용자가 "4·5·6 먼저"를 골랐다.
  - 그 사이에 main에 커밋이 쌓였으므로, 강제 푸시 직전에 최신 원격에서 다시 쓰기를 한 번 더 돌린다. 2초 걸린다.
- GitHub의 PR 참조에는 강제 푸시 뒤에도 원본이 남는다. 공개 전에 GitHub 지원 요청을 검토한다.
- 강제 푸시 뒤 다른 클론(노트북, RPi 배포본)은 `git fetch && git reset --hard origin/main`이 필요하다.

- **10/7 반영:** 사용자 지시로 최신 원격(`7a12ca5`)을 새로 미러해 다시 쓰고 `main`을 강제 푸시했다(`7a12ca5`, 트리 동일, 원격 브랜치 이력의 문서 파일 0건). `agent/simplelay-flutter-app`은 원래 해당 파일이 없어 그대로다. 데스크톱 로컬은 `reset --hard origin/main`으로 맞췄다. 원래 이력 백업은 저장소 밖에 있다.

## 5. 보드 점검 앱 권한 (`f2d8402`)

- 백엔드와 실행기 컨테이너는 실제로 root로 돈다. 그래서 그 결과는 앱 권한 증거가 아니다.
- 키오스크 앱 계정과 같은 UID로 다시 돌렸다.
  - 모듈과 로컬 웹 호출은 앱 권한까지 성공했다.
  - 시스템 서비스 호출은 접근 거절이었다. 보안 레이블이 없는 조건이었으므로 **미검증**으로 둔다.
- 로컬 설정의 Ping 인터페이스 지정을 고쳤다.
- 원본 결과와 설정은 저장소 밖에만 둔다. 증거 대장은 일반 문장으로 갱신했다.

## 6. UART 첫 연결 실패에도 기동 (`b20758b`)

- 첫 연결도 끊김 뒤 재연결과 같은 백오프로 백그라운드에서 다시 시도한다.
- 연결 전 상태:
  - 실행은 412 "누름 장치 연결 안 됨"으로 거절한다.
  - `/health actuator_ready=false`, `/status actuator_link_up`, `/connections`에 그 상태가 보인다.
- 시험 3건은 수정 전 코드에서 실패했다. 상세는 [devlog](devlog_2026-10-06-uart-first-connect.md)에 있다.
- **보드 확인:**
  - RPi4 실행기를 끈 채로 RPi5 백엔드를 띄웠다. 백엔드는 기동했고, 실행은 412로 거절됐다.
  - 실행기를 켜자 백엔드 재시작 없이 자동으로 붙었고, 모의 실행이 성공했다.
