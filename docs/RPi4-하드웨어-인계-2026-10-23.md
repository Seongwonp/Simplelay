# RPi4·Touch Bridge 하드웨어 인계

작성 2026-10-23. **모터·엔코더·SwitchBot을 담당자의 기준 코드로 확인하는 도구**다. RPi5·SimpleLay 앱·에뮬레이터 없이 사용할 수 있다.

## 담당자에게 먼저 전달할 내용

- 함께 전달하는 장비: **RPi4 + ESP32 + 모터·기구 + USB 케이블**. RPi4 전원도 준비한다.
- 목표: 담당자의 기존 펌웨어로 두 모터의 이동과 좌표, SwitchBot 누름을 확인하고, SW 담당자가 그 규약에 맞춰 앱을 연결한다.
- **인계용 콘솔은 RPi4에 설치했고 실제 상태 조회까지 확인했다. 실제 이동·누름 성공을 확인한 것은 아니다.**
- 새 SimpleLay 통신 어댑터는 구현·관련 테스트까지 마쳤지만, **운영 실행기에 배포하지 않았다.** 이번에는 아래 독립 콘솔로 확인한다.
- 기존 실행기 `simplelay-act`는 정지했고 자동 재시작도 꺼 두었다. USB를 점유하지 않도록 시험 중에는 켜지 않는다.
- 설치 폴더는 `/mnt/rawdata/simplelay-handoff-20261023`이다. 접속 주소·계정 안내는 별도로 전달한다. 다른 장소에서는 네트워크 주소가 달라질 수 있다.

접속 후 시작:

```sh
systemctl start docker
cd /mnt/rawdata/simplelay-handoff-20261023
sh start.sh
```

콘솔에서 먼저 `?`, `P`로 응답을 확인한다. 이동 명령은 담당자가 기구·전원 상태를 확인한 뒤 직접 입력한다. 끝나면 `:quit`으로 닫고, RPi4는 `sync` 후 `shutdown -h now`로 정상 종료한다.

**돌려줄 것:** 실제 사용한 전체 소스 묶음(스케치·모든 헤더·라이브러리 버전), 네 방향 명령과 실제 방향, A/B 엔코더 변화, 좌표와 실제 이동량, Bot 응답, `logs/console.log`. 이전 압축본과 최신 개별 파일을 임의로 섞지 않는다.

**HW 코드는 HW 담당자만 수정한다.** SW 담당은 ESP32 스케치·헤더·핀·PID·모터 제어식을 변경하지 않고 앱·RPi5·RPi4의 통신 어댑터를 기존 규약에 맞춘다. 이번 인계 도구 설치에서는 펌웨어를 수정하거나 재업로드하지 않았다.

## 기기에 준비할 것

- `touchbridge_console.py`, `touchbridge-console.sh`, 로컬 접속 안내와 파일 해시 표.
- RPi4의 기존 `simplelay-backend` Docker 이미지에 있는 Python·pyserial을 사용한다. 호스트에 Python이 없어도 된다.
- 받은 최신 스케치 3개와 예전 전체 압축본은 별도 폴더에 보관한다. 서로 버전이 달라 임의로 합친 묶음을 담당자의 확정 원본으로 부르지 않는다.
- 실제 주소·USB 식별값·접속 정보·원본 파일·바이너리는 로컬 전용 인계 폴더에 둔다. 공개 저장소에는 넣지 않는다.

## 사용하는 순서

1. RPi4에 접속하고 Docker를 시작한다: `systemctl start docker`.
2. 기존 실행기가 켜져 있으면 `docker stop simplelay-act`로 USB 점유를 해제한다.
3. 인계 폴더에서 `sh start.sh`를 실행한다. 로컬 `start.sh`는 USB 경로를 지정하고 아래 도구를 연다.
4. 처음에는 `?`, `P`를 입력해 원문 도움말·상태를 본다. 도구를 여는 것만으로 모터 명령은 나가지 않는다.
5. HW 담당자가 준비한 상태에서 원본 명령을 입력한다. 예를 들어 `M 0.5 0.5 300`은 A/B에 PWM 0.5를 300 ms 동안 주는 명령이다. mm 이동량이 아니다.
6. `Z`는 현재 자리를 기준으로 지정하고, `G x y`는 그 기준의 절대 좌표 이동이다. 자동 원점 복귀 `H`와 구분한다.
7. `T`·`GT`는 실제 Bot 누름을 요청한다. 이동 시험과 누름 시험을 구분해 기록한다.
8. `S`는 원본 중단 명령이다. `:quit`으로 콘솔을 닫는다. Ctrl+C는 `S`를 한 번 보내고 닫는다.

도구의 `OK`는 접수 결과다. 뒤의 `DONE`, `FAULT`, `PRESSED`, 상태·엔코더 변화와 눈으로 본 이동을 함께 남긴다. 비동기 응답은 계속 화면에 나오며 `logs/console.log`에 시각·단조 시각·송수신 방향이 기록된다.

PC/리포에서 직접 실행할 때는 `python -m rpi.tools.touchbridge_console --port <USB 경로>`를 사용한다. Docker 런처를 리포 위치에서 쓸 때는 `TOUCHBRIDGE_TOOL`에 Python 파일의 전체 경로를 지정한다. `--command P --wait 2`는 상태 한 번을 읽는 방식이다.

## 담당자가 돌려줄 결과

| 항목 | 기록 |
| --- | --- |
| 실제 사용하는 전체 펌웨어 | ino·config·모션/모터/엔코더·Bot 헤더와 라이브러리 버전 |
| 네 방향 | 명령과 실제 캐리지 이동 방향 |
| 모터·엔코더 | A/B 각각의 계수 변화, 실제 두 모터 회전 여부 |
| 좌표 환산 | 원본 계산 좌표와 실제 이동량, 사용하는 기구 설정 |
| Bot | 장착·한 번 누름·응답 원문 |
| 증상 | 안 움직인 명령, 오류 원문, 해당 영상 |

모터 방향·PID·기구 조정은 이 도구가 자동으로 바꾸지 않는다. 앱 연결·사진 매핑은 이 결과를 받은 뒤 [통합 계획](통합-재설계-실행계획-2026-10-23.md)에 따라 진행한다.

인계 중 실행기의 자동 재시작을 꺼 두었다면 그 상태를 기록한다. 기존 실행기를 다시 켜는 것은 원본 규약을 지원하는 어댑터 배포 후 별도로 한다.
