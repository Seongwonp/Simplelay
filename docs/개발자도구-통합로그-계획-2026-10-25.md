# 개발자 도구 통합 로그 계획 — 2026-10-25

상태: 사용자 요청으로 계획만 등록. 앱·서버·펌웨어 코드는 변경하지 않음.

## 목적

폰 에뮬레이터에서 누른 명령이 RPi5 → RPi4 → ESP32를 거쳐 어떤 응답으로 끝났는지 개발자 도구의 ‘기록’에서 한 흐름으로 확인한다. 로그 조회 때문에 시리얼 포트를 별도로 열거나 모터를 움직이지 않는다.

## 현재 확인

- RPi5: 172.20.10.6, 컨테이너 simplelay-backend. HTTP 접근 로그는 경로·상태 코드를 보여주지만 요청 JSON 전체를 기록하지 않는다.
- RPi4: 172.20.10.7, 컨테이너 simplelay-act. SIMPLELAY_MOTION_LOG_PATH=/data/motion-lines.log가 활성화되어 있다.
- 원시 모션 기록: `>>` 전송, `<<` 수신, `##` 실행 표식. 벽시각과 mono_ns를 함께 기록한다.
- 기존 /dev/log는 개발자 세션 관리자 기록이며, 전체 HTTP·보드 링크·ESP32 원시 송수신을 합친 로그가 아니다.
- 현재 확보한 로그에서 x=1,y=0 및 x=0,y=1 이동 뒤 MOVING → 약 1.11초 뒤 ERROR_POSITION → 호스트 stop → STOPPED를 확인했다. PID 과대 여부는 이 로그만으로 확정하지 않는다.

## 구현 순서

1. **관측 이벤트 형식 정의**: event_id, origin, direction, wall_time_utc, monotonic_ns, boot_id, request_id, run_ref, command_id, kind, level, payload. 다른 보드의 monotonic 값을 직접 비교하지 않는다. 인과 식별자를 우선하고 시계 오차를 표시한다.
2. **앱 명령 기록**: 전송 시각·명령 종류·좌표·응답·실패를 기록한다. 앱 요청과 RPi5 접수에는 같은 request_id를 사용한다. heartbeat/상태 조회는 기본 접고 필요할 때 펼친다.
3. **RPi5 및 RPi4 연결**: 허브 접수·검증 거절·보드 전송·보드 응답과 ESP32 TX/RX에 상관 식별자를 연결한다. 연결할 수 없는 줄은 ‘연결되지 않은 원시 로그’로 남긴다. 실행 중 재시작 시 세션을 구분한다.
4. **안전한 수집**: 기존 LoggingTransport/LineLog를 재사용한다. 별도 프로세스가 ESP32 포트를 열지 않는다. 제한된 큐·파일 순환·드롭 개수 표시로 로그 지연이 제어와 정지를 막지 않도록 한다. 로그 전송 경로는 정지 명령을 지연시키지 않게 분리하거나 우선순위를 보장한다.
5. **조회 API**: 기존 개발자 인증 아래 cursor 기반 증분 조회, origin/level/request 필터, 제한된 페이지 크기. 끊김·재연결·수집 시작 전 기록 없음·유실을 명시한다. 임의 파일 경로 조회는 제공하지 않는다.
6. **개발자 도구 기록 화면**: 기본은 명령별 타임라인, ‘전체/앱/허브/실행기/ESP32’, ‘오류만’, 자동 스크롤 멈춤, JSON 펼치기, 복사, 로그 파일 내보내기. 정지 버튼은 로그 화면에서도 접근 가능하게 유지한다.

## 비밀정보와 보존

인증 헤더·개발자 세션 secret·링크 서명·누름 승인 토큰·ThinQ PAT는 수집 단계에서 제거한다. 영상·음성 원본은 기록하지 않는다. 명령 JSON은 허용 필드만 남긴다. 최대 파일 크기·보존 기간·지우기 기능을 명시한다.

## 완료 기준

- 개발자 이동 한 번의 앱 요청부터 ESP32 응답까지 대응 관계를 볼 수 있다.
- 허브에서 거절되어 ESP32에 전달되지 않은 명령은 ‘미전송’으로 구별된다.
- ERROR_POSITION 이후 stop/STOPPED를 같은 흐름으로 확인한다.
- 로그 폭주·디스크 오류·조회 끊김에도 모터 제어/정지 경로를 막지 않는다.
- 저장/내보내기에 토큰이 없고, 서로 다른 보드의 시각을 무조건 같은 시간축으로 단정하지 않는다.
- 실행기 재시작·로그 회전·새 보드 세션에서 중복/누락을 표시한다.

추정 규모: 원시 ESP32 로그 조회·표시부터 S~M, 전 구간 상관관계 및 장애 검증까지 M~L. 이번 요청에서는 구현하거나 보드를 재시작하지 않는다.
