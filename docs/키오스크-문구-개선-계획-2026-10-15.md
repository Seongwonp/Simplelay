# 키오스크 문구·화면 개선 계획 (2026-10-15, 결정 반영본)

근거: 처음 쓰는 사람 관점의 화면 평가 두 건(둘 다 **6/10**, 키오스크 골든 이미지만 보고 평가 — 실사용자 시험이 아니다)과
코드 인벤토리(HEAD `3997427`). UI 동결은 10/15 사용자 결정으로 해제됐다.

두 평가의 공통 결론: **빨간 정지는 1초 만에 찾는다. 그러나 "지금 무엇이 움직이는지 · 진짜 끝났는지 · 멈췄는지"를 모르겠다.
허브·콘센트 모듈·연습 모드·보정 같은 말에서 막힌다.**

## 0. 원칙 (모든 변경에 적용)

1. **확인한 것만 말한다.** 큰 제목이 작은 글씨보다 더 많이 말하지 않는다. 확인 못 했으면 제목부터 그렇게 말한다.
2. **주어를 밝힌다.** 정지 단계(`sent`·`mcu_ack`·`verified`)는 **작은 팔(누름 장치)** 기준이다 — "작은 팔이 멈췄어요"까지만.
   "전자레인지가 멈췄어요"는 RPi4가 **전력 하강으로** 정지를 확인한 때(`hold_stop_outcome == "stopped"`)만.
3. **다음 행동을 한 가지** 적는다. "확인하지 못했어요"로 끝내지 않고 "가전을 직접 봐 주세요 / 취소 버튼을 직접 눌러 주세요"까지.
4. **정지 버튼은 위치·크기·색을 바꾸지 않는다.** 이름만 상황에 맞게(예: "다시 정지 시도").
5. **화면에 보이는 물건 이름으로** 말한다(내부 부품 이름·영문·단위 숫자 대신).
6. 거짓이 될 문장은 쓰지 않는다 — 확인된 근거:
   - 비상정지 해제(`POST /stop/ack`)는 걸림만 푼다 — 서버에 작업 큐가 없고, 실행 중이던 루틴은 해제 뒤에도 이어서 하지 않으며(`rpi/routines/runner.py:72`),
     비상 버튼으로 꺼진 콘센트 전원은 켜지 않는다(`rpi/verifier/outlet.py:581`). → "해제해도 멈췄던 작업은 다시 시작하지 않아요" **쓸 수 있음**.
     단, **콘센트 비상 버튼으로 걸린 경우 자동 실행 규칙은 꺼지지 않는다** — 해제 뒤 새 가열 종료 사건에는 허용한 자동 실행이 다시 동작한다
     (`rpi/api/deps.py:684`, `auto_rules.py:731`). → "자동 실행도 꺼져요"는 **쓰지 않음**. 재부팅으로 꺼진 콘센트 전원은 해제 확인 뒤 다시 켠다(`outlet.py:577-595`).
   - 자동 재시도(버튼마다 최대 3회)는 전류 변화(L1)만 보고 판정한다. 실제로 눌렸는데 전류 변화를 놓치면 다시 누른다 — 전원 버튼이면 토글 위험
     (`rpi/controller/closed_loop.py:406-417`). 재누름 전에 가전 전력을 다시 보지 않는다. → "두 번 누르지 않아요" **쓰지 않음**.
     사용자가 누르는 `다시 시도`도 상태 확인 없이 같은 순서를 다시 보낸다 → 실패 화면 문구에 "가전이 이미 켜졌다면 다시 시도하지 마세요"를 넣는다.
   - 제안 카드 20초는 키오스크 화면에서만 닫히는 시간이다. 거절·실행을 보내지 않고, 서버 카드는 남는다(습관 제안은 시간대 끝, 그 밖은 15분 뒤 만료).
     → "20초 뒤 이 화면에서 닫혀요"는 참.
   - 방해 금지 칩 시간은 **남은 시간**이다. → "1시간 30분 남음"은 참.
   - "다시 연결하기"는 재연결 명령이 아니라 연결 상태를 다시 묻는 것이다. → "다시 확인하기"로.

### 3-2. 연습 화면 공통 (`provenance_*`, 연습 실행·완료·대기)

- 연습 표시를 **화면 맨 위 고정 띠**로: "연습 중 · 실제 가전은 누르지 않아요". 큰 글자(1.6배)에서도 줄지 않게.
- 연습에서 "동작 중", "눌렀어요", "눌림 확인" 같은 실물 동사를 쓰지 않는다 → "짚었어요", "연습 결과".
- 골든 `provenance_running`의 '모의 검증'은 시험이 넣은 값 — 시험 입력을 실제 화면에 나올 연습 문장으로 바꾼다.

| 5b | B11 콘센트 전원 재켜짐 의심 — 시험으로 재현 → 재현되면 수리(문구와 별도 커밋) | 40분 |
| 6 | 골든 재생성·눈으로 확인·devlog·재평가 | 1시간 |

잘림은 따로 미루지 않고 **그 화면을 고칠 때 같이** 고친다(정지·연결 안내가 잘리면 쉬운 말로 바꿔도 읽을 수 없다 — 검토 의견).
키오스크(1~3·6)와 서버(5)는 동시에 진행할 수 있다. 커밋은 단계마다 하나.
