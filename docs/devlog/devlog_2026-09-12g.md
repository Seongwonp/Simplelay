## 화면을 가로지르는 규칙

세 번 이상 반복된 것들. 구조화(계획서 D6) 때 공용 위젯으로 뽑는다.

- **대상이 먼저.** 제안·실행 상태·음성·수동 조작 모두 "어느 가전에게"를
  질문·버튼보다 위에 둔다. 여러 가전을 다루므로 엉뚱한 가전에 대고 한 뒤
  아는 일이 없어야 한다.
- **카드가 아니라 행.** 단계·기록·설정 항목을 둥근 카드로 감싸면 모든 것의
  깊이가 같아져서 지금 봐야 할 것이 눈에 띄지 않는다. 제목·여백·구분선.
- **주 행동은 아래 고정.** 제안·실행 상태·가전 추가. 6단계짜리 제안에서
  실행 버튼이 스크롤 밖으로 밀리면 확인한 뒤 다시 찾아 내려가야 한다.
- **큰 글씨에서는 주/부 행동을 세로로.** '이번만 넘기기'·'다시 말하기'가
  단어 중간에서 꺾였다. `textScaler >= 1.5`면 쌓는다.
- **색을 빼도 구분되게.** 완료=체크, 지금=채운 원+'지금', 대기=빈 원.
  긴급 정지는 정지 기호·3px 외곽선·64px. 흑백 변환본으로 매번 확인했다.
- **모르는 것을 아는 척하지 않는다.** 서버가 '이동 중'과 '누르는 중'을
  나눠 주지 않으니 화면도 나누지 않는다. 사용자 정지와 안전 정지는 종료
  사유가 있는 기록에서만 나눈다. 대상 가전은 설치 목록에서 찾을 때만 말한다.
- **내부 이름을 사용자에게 말하지 않는다.** RPi·URL·ESP32 노드·BLE·미등록은
  고급 설정과 편집 시트에서만. 일반 화면은 "버튼을 대신 눌러 줄 기기",
  "예비 연결(블루투스)", "아직 장치가 없어요".

## 화면별로 한 일

- **D1 제안 확인**: 대상 가전 → 질문 → 누를 순서(번호+라벨만) → 버튼 지도.
  준비 안 된 가전은 실행을 내걸지 않고 이유를 버튼 위에서 말한다. 순서
  목록이 전역 표('1분 추가')를, 지도가 가전 라벨('1분')을 써서 같은 버튼을
  두 이름으로 부르던 것을 대상 가전 라벨로 통일.
- **D2 실행 상태**: 현재 버튼 이름 가장 크게 + 상태 구절(누르는 중 / 눌림
  확인 중 / 보정 후 다시 시도 중). 연속 진행 바 대신 `총 N단계 중 K단계`
  구간형. 재시도를 실패로 말하지 않는다. BLE 경로에서 실행 중인데 부제가
  idle 문구였던 결함을 골든에서 잡아 고쳤다.
- **음성**: `○○에게`, 음성 인식을 쓸 수 없는 기기(권한·엔진)를 인식 실패와
  분리, `5초 동안 조용하면 듣기를 멈추고 확인을 물어요`(숫자는
  `VoiceService.silenceTimeout` 하나에서).
- **수동 조작**: 가전 머리, 결과 문장(`'켜기' 눌림을 확인했어요`), 버튼판은
  카드 없이 최소 72px 셀, 준비 안 됨은 안내 + 흐림.
- **이력**: 날짜는 구획 제목(오늘·어제·M월 D일), 결과는 모양+문장, 서버의
  `appliance_id`·`termination`을 받는다. `nowProvider`로 시각을 읽는다.
- **설정**: 가전 → 연결 → 알림 → 제안 → 화면·소리 → (접힌) 고급.
  `_SettingCard`는 이름만 남고 행+구분선이 됐다.
- **가전 추가**: 1 종류 → 2 이름·위치 → 3 사진(선택) → 4 버튼 배치,
  저장은 아래 고정에 "지금까지 적은 것 + 저장 뒤 남는 일".
