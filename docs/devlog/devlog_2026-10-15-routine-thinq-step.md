# 2026-10-15 — 루틴에 'ThinQ 가전 조작' 단계 넣기 (폰, 사용자 요청 동결 예외)

루틴 편집기의 '단계 추가'는 버튼 누르기·끝날 때까지 기다리기·안내하기만 있었다. 폰 모델(`RoutineStepKind.thinqCommand`)과
서버(`thinq_command` 단계)는 이미 ThinQ 단계를 알고 있었지만 폰에서 넣을 방법이 없었고, 예전에 저장된 단계는 편집기에
'ThinQ 명령 set_wind_strength'처럼 동작 이름 그대로 보였다. 사용자 요청으로 폰에서 넣을 수 있게 했다. 서버(`rpi/`) 코드는 바꾸지 않았다.

> **검증 수준: 위젯·단위 시험과 모의 ThinQ 공기청정기(서버 시험)까지.** 실폰·실제 클라우드·실가전으로는 확인하지 않았다.

## 1. 동작

- '단계 추가'에 **'ThinQ 가전 조작'**(부제 '공기청정기 전원·풍량·운전 모드를 바꿔요')이 생긴다. 설치된 가전 중 ThinQ 가전이 **한 대라도 있을 때만** 보인다.
- 흐름: ThinQ 가전 고르기(한 대면 건너뜀, 버튼 가전은 목록에 없음) → 무엇을 어떤 값으로(한 화면에 9개):
  전원 켜기/끄기 · 풍량 약풍/중풍/강풍/자동 · 운전 모드 청정/수면/자동.
- 고르면 단계만 생긴다 — **아무것도 보내지 않는다.** 저장은 종전대로 `POST /routines`·`PUT /routines/{id}`이고, 실행은 종전대로
  '실행하기'/'지금 실행' → 승인 카드 → 승인 뒤에만 일어난다. 새 자동 실행 경로는 없다.
- 단계 모양(서버 `RoutineStep.from_dict`와 같은 이름):
  `{"kind": "thinq_command", "appliance_id": <가전 ID>, "action": "set_wind_strength", "args": {"wind_strength": "HIGH"}}`.
- 편집기 문장: `[공기청정기] 풍량 강풍으로 바꾸기`, `[공기청정기] 전원 켜기`(가전 이름은 칩). 동작 이름은 내지 않는다.
  고르는 표에 없는 값은 상태 표의 말로(파워·조용), 그래도 모르면 원래 값 그대로 적는다(지어내지 않는다). 모르는 동작은 'ThinQ 명령(이 앱이 모르는 조작)'.
- 고르는 표는 가전 상세 '지금 상태' 카드의 조작 줄과 **같은 표**다. `thinq_state_card.dart`에 지금 값 없는 목록 `kAirPurifierControls`를 두고,
  `thinqControlsFor(state)`는 그 목록에 지금 값만 채워 돌려준다(종전 동작·시험 그대로).
- 다른 곳: 루틴 목록 줄은 단계 내용을 적지 않는다(대상 가전 이름 · 단계 수). 승인 카드·실행 상태 화면은 서버가 만든 문장(`summary`)을 쓴다 —
  모의로 확인한 문장은 '공기청정기(모의) 풍량 강', '… 전원 켜기', '… 운전 모드 수면'이다(풍량 값은 서버 표의 '약·중·강'이라 편집기의 '강풍'과 말이 조금 다르다).

## 2. 서버 호환 확인 (코드 변경 없음)

- 저장 검증: 구조 검증(`action` 이름 형식·`args`가 객체)과 가전 검증(등록부의 가전이 ThinQ 경로이고 대응표에 그 동작·값이 있는가)을 통과한다.
- 실행: 승인 카드의 명령 경로가 `thinq`이고, 승인 뒤 루틴 실행이 `succeeded`로 끝난다(모의 시작 값과 같으면 보내지 않고 `already_at_target`, 다르면 1회 보내 `state_confirmed`).
- 폰은 가전 종류(공기청정기·세탁기·제습기)를 구분하지 못한다(폰 종류 표에 공기청정기가 없어 '기타'로 읽힌다). 그래서 ThinQ 가전이면 모두 고를 수 있게 했고,
  세탁기처럼 그 동작이 없는 가전을 고르면 **저장할 때 서버가 422로 거절**하고 편집기가 그 문장을 보인다(서버 문장에는 동작 이름이 들어간다).
  제습기는 전원만 대응표에 있어 풍량·운전 모드는 같은 이유로 저장 때 거절된다.

## 4. 확인하지 않은 것

- 실폰·실제 클라우드·실가전에서 이 단계로 만든 루틴을 승인·실행한 적 없다(모의 공기청정기만).
- 실제 공기청정기 모델 프로필이 중풍(`MID`)·운전 모드 자동(`AUTO`)을 허용하는지는 모른다 — 허용하지 않으면 허브가 보내기 전에 거절한다(대응표는 추측/확인 필요 상태).
- 골든(스크린샷) 시험은 돌리지 않았다. 편집기 화면의 새 시트·문장은 골든에 없다.
- 이미 저장된 ThinQ 단계의 값을 편집기에서 바꾸는 기능은 없다 — 빼고 다시 넣는다.
