# 2026-10-19 — 실행기 다시 시작·포트 재연결 뒤 원점 다시 잡기

## 빈칸

RPi4 실행기가 시작할 때(`rpi4/act_main.py` 시작 연결·배경 재시도)와 모션 포트를 잃었다가 다시 붙을 때
`SerialMotionClient.connect()`가 모션 보드의 `homed` 보고를 그대로 믿고 READY로 두었다. 모션 보드 전원은 그대로인 채
실행기만 다시 시작했거나(이동 도중 죽은 경우 포함) 포트만 다시 붙었으면, 그사이 손으로 캐리지를 옮겼어도 원점 확인 없이
저장된 좌표로 이동·누름을 할 수 있었다.

## 수리

- `rpi/controller/serial_motion.py`: 이 프로세스가 원점을 잡았는지 따로 기억한다(`_origin_unverified`). 처음 만들 때·
  `connect()` 성공 때·`note_link_down` 때 켜고, 성공한 `home()`만 끈다. 켜져 있으면 상태 조회가 `homed: true`여도
  UNHOMED로 둔다(뒤이은 `status()`도 되살리지 않는다).
- 자동 원점이 켜져 있으면 새로 승인된 다음 실행의 첫 누름이 원점부터 잡는다. 꺼져 있으면 준비 안 됨 —
  "실행기가 다시 시작했거나 누름 장치와 다시 연결돼 위치를 믿을 수 없어요. 원점을 다시 잡아야 해요."
- 포트를 잃었던 그 실행 안에서는 여전히 원점을 다시 잡지 않는다(`_reset_mid_run` 그대로).
- 개발자 원점 잡기는 연결 확인만 보므로 그대로 된다.

## 시험

- 새 회귀 시험 `rpi/tests/test_motion_restart_rehome.py` 5건 — 수정 전 코드에서 5건 모두 실패, 수정 뒤 통과.
- 가짜 MCU를 `homed=True`로 두고 연결만으로 READY를 기대하던 시험은 연결 뒤 `home()`을 한 번 하도록 고쳤다
  (명령 순서를 보는 시험은 기대값에 `home`을 넣음).
- 백엔드+rpi4 전체: 3,607 통과·77 건너뜀(골든 없음).

## 남은 것

- 실물 미검증(가짜 MCU만). 배포 뒤 첫 실행은 자동 원점이 꺼져 있으면 개발자 원점 잡기를 먼저 해야 한다 —
  RPi4·RPi5 같은 커밋 배포 규칙 그대로.
