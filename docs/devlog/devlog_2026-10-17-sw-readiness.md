# 2026-10-17 — 결선 전 SW 보완 기준 정리

결선 준비를 위해 UI가 아닌 소프트웨어 운영 완성도를 다시 점검했다.
핵심 기능을 더 늘리기보다 실제 설치 환경에서 실패를 안전하게 처리하고,
무엇이 확인됐는지 설명할 수 있는지를 우선하기로 했다.

## 확인된 상태

- RPi5에서 실제 ThinQ 공기청정기 시각 자동 루틴을 확인했다.
  22:00 켜기와 다음 날 07:00 끄기, 자동 실행 결과를 실제로 확인했다.
- 승인 지문, 정지 단계, 비상정지 래치, 자동 실행 중복 방지, 조용한 시간
  판정 등 기존 안전 계약은 코드와 시험으로 상당 부분 고정되어 있다.
- 다음 통합 검증의 중심은 `CoreXY 실제 버튼 누름 → CT 가열 시작·종료
  감지 → 자동 실행 → ThinQ 상태 확인`이다.

## 정리한 기준

- 실패마다 안전한 정지, 거짓 성공 방지, 원인 기록, 다음 행동 안내가 있어야 한다.
- CT가 정상 종료·취소·문 열림을 구분하기 전까지 모든 화면과 발표 문구는
  `가열 종료 감지`로만 표현한다.
- 사용 기록으로 만든 루틴 초안의 저장과 자동 실행 허용은 별도 단계다.
- 조용한 시간에 건너뛴 사건은 시간이 지난 뒤 자동으로 재실행하지 않는다.
- 물리 버튼 누름은 자동 실행 대상이 아니며 매번 사용자 승인이 필요하다.

세부 우선순위와 결선 전 정상·실패 검증 묶음은
[결선 전 SW 보완 피드백](../결선전-SW-보완-피드백.md)에 정리했다.
