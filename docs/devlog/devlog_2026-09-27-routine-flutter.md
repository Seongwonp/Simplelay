# 다가전 모의 시나리오 — 앱·키오스크 연결

## 구현 범위

공용 Flutter 패키지 `packages/routine_rehearsal`을 두 클라이언트에 연결했다. 기존 단일 가전 제안 흐름과 별도로 열리는 모의 리허설 화면이다. 자연 사용 이력 학습이나 실제 다가전 실행기가 구현된 것은 아니다.

- 가전 선택·제외 → 새 미리보기 → 별도 승인. 선택 변경 후에는 승인 버튼이 잠긴다.
- 서버 세션·판 번호를 승인에 함께 보낸다. 다른 단말이 먼저 변경하면 서버가 오래된 승인을 거절한다.
- 2초마다 조회만 한다. 조회는 실행·재시도·승인을 일으키지 않는다.
- 이미 진행한 요청보다 늦게 도착한 과거 조회 응답은 무시한다. 통신 실패 시 조작을 잠그고 최신 상태를 다시 조회한다. 변경 요청은 자동 재전송하지 않는다.
- 성공·실패·확인 불가·후속 취소·제외·정지 확인을 가전별로 표시한다. 정지 요청은 정지 확인과 다르며 이미 성공한 기기를 되돌리지 않는다.
- 모의 서버 전용 API만 사용한다. 일반 서버에서는 404이며 실행 우회 경로는 없다. 응답의 `execution_mode`가 mock이 아니면 화면 조작을 잠근다.
- 앱은 현재 설정된 서버와 API 키를 사용한다. 서버 서비스 객체가 바뀌면 화면 상태를 새로 만들고 과거 응답을 폐기한다.

## 실행

서버: 저장소 루트에서 `python -m rpi.simulator_main --port 8768`.

모의 화면 진입 버튼은 빌드 옵션을 켰을 때만 보인다. 기본 빌드는 기존 화면을 유지한다.

```powershell
# app 또는 rpi5-touchscreen-app 폴더
flutter pub get
flutter run --dart-define=SIMPLELAY_ROUTINE_MOCK=true
```

- 앱: 홈 상단의 '다가전 모의' 아이콘. 앱 설정의 서버 주소를 모의 서버로 지정한다. 휴대폰에서 PC에 연결하려면 같은 LAN과 서버 `--host 0.0.0.0`이 필요하며 localhost는 휴대폰 자신을 뜻한다.
- 키오스크: 대기 화면 오른쪽 아래 '다가전 모의'. 웹은 같은 origin을 사용하고 네이티브는 기존 localhost:8000 설정을 사용하므로 네이티브 리허설은 서버 포트를 맞춘다.
- 키오스크 웹 빌드:

```powershell
flutter build web --base-href /kiosk/ --output ../kiosk-web --dart-define=SIMPLELAY_ROUTINE_MOCK=true
```

현재 PC에서는 http://127.0.0.1:8768/kiosk/ 에 빌드를 제공한다. 웹 산출물은 커밋하지 않는다.

## 검증

- 공용 화면 5건: 제외 후 재승인, 늦은 조회와 승인 응답 경합, 요청 실패 후 자동 재전송 방지, 가전별 성공/확인 불가 유지, 비모의 응답 차단.
- 앱 홈·API 관련 27건 통과. 인증 헤더·모의 경로·409 전달을 포함한다.
- 키오스크 제안·단계 전환·API 관련 57건 통과. 일반 서버의 404 전달을 포함한다.
- 정적 분석: 공용 패키지 문제 없음, 앱·키오스크 오류/경고 없음. 기존 info는 각각 5개·1개.
- 키오스크 웹 빌드 성공. 실제 브라우저에서 진입 → 선풍기 제외 → 새 미리보기 → 별도 승인 → 공기청정기 모의 성공 및 선풍기 제외 유지 확인.
- 이 PC의 Flutter 분석과 테스트는 한글 프로젝트/임시 경로에서 도구가 종료됐다. 저장소를 가리키는 영문 junction 및 TEMP/TMP 영문 경로를 사용해 위 결과를 얻었다. 소스나 테스트 검증을 생략하지 않았다.

휴대폰 실기기, RPi 터치, TalkBack, 실제 가전·모터·센서는 이번 검증에 포함하지 않았다. 브라우저에서 기존 키오스크 아이콘 글리프 일부가 네모로 표시되는 현상도 남아 있으며 폰트 로딩은 별도 확인이 필요하다.

## 다음 범위

두 클라이언트를 같은 서버에 붙여 한쪽의 구성 변경·승인·응답 유실이 다른 화면에 반영되는 리허설을 확장한다. 이후 실제 준비 상태·제어 경로·기기별 정지 능력을 공용 계약에 연결한다. 하드웨어를 받기 전에는 모의 검증으로만 표시한다.

구현·검증 후 사용자 요청으로 다가전 모의 화면과 서버 계약을 함께 커밋·푸시한다. 실물 검증 완료를 뜻하지 않는다.
