## 고친 것 2건

1. **fault 세대 비교·해제의 원자화.** `fault_reason` 읽기 → `fault_seq`
   읽기 → `clear_fault()`가 세 번의 별도 락이라, 비교 통과 직후 걸린 새
   fault를 오래된 정지의 성공 응답이 지울 수 있었다. 중재자에
   `fault_snapshot()`(reason+seq 동시 캡처)과
   `clear_fault_if_matches(seq)`(같은 락에서 대조+해제)를 두고 정지 확인
   경로가 그것만 쓴다. 무조건 `clear_fault()`는 수동 개입·테스트 정리용.
2. **정지 예약을 세션 무효화와 같은 임계구역으로.** 무효화(락 안)와 정지
   카운터 등록(_send_stop 진입에서 다시 락)이 떨어져 있어, 그 빈틈에
   이전 명령의 settle이 재정지를 확인하면 4조건이 전부 충족돼 **아직
   전송도 안 된 긴급 정지를 모른 채** 제어권이 나갔다.
   `_reserve_stop_locked()`가 전송 예정인 정지를 무효화와 같은 락에서
   올린다(정지 진입점 5곳 전부). 어댑터 호출은 계속 락 밖이다.

## 이 세션의 테스트가 확인한 범위 (그 이상을 주장하지 않는다)

- 중재자 세대 해제: "비교 직후 새 fault" 조합에서 오래된 확인이 새 fault를
  지우지 못하고, 현재 세대로만 풀린다 — 단위 계약.
- detach 직후·전송 전(_send_stop 이음새)에 멈춘 상태에서, 이전 명령의
  settle이 재정지 확인까지 끝나도 반납되지 않고, 예약된 정지의 전송·확인
  뒤에야 제어권이 나간다 — 이전 구조에서 뚫리던 창.

**전체 안전성 검증 완료가 아니다.** 여기까지의 1.1~1.4 테스트는 각 리뷰가
지목했거나 우리가 재현한 인터리빙 조합을 mock 어댑터 기준으로 덮는다.
검증 안 된 것: 재현하지 않은 스레드 인터리빙 전반(모델 체킹 없음), 실물
어댑터의 병행 stop·명령 스트림 순서(H 주차), 프로세스 경계(fault는 메모리
전용 — 재시작이 곧 해제).
