## 1. B11 — 재부팅 걸림 뒤 비상 버튼이 이어지면 해제 확인이 콘센트 전원을 다시 켰다 (커밋 `2ab4360`)

- 의심(계획 §5): 콘센트 모듈 재부팅으로 `power_lost`(해제 확인 뒤 릴레이 다시 켜기)가 선 뒤 비상 버튼이 눌리면 `power_lost`가 남아,
  사람이 비상 버튼을 풀고 해제하면 릴레이가 다시 켜진다. 비상 버튼으로 꺼진 전원은 켜지 않는 규칙(protocol.md)과 어긋난다.
- **재현됨.** 가짜 콘센트 모듈로 릴레이 켬 → `reboot()`(재부팅 걸림, `outlet_reboot`) → `press_estop()` → 버튼 풂 → `estop_ack`:
  수정 전 코드에서 `fake.relay_on`이 **True**(다시 켜짐). estop 이벤트를 잃고 주기 `status`로만 걸림을 안 경우는 실행기 걸림 원인이
  `outlet_reboot`로 남아 화면 문장도 '다시 켜져'(해제하면 켜짐)로 남았다.
- 수리(최소):
  - `rpi/verifier/outlet.py` — `estop` 이벤트, 또는 `ready`·`status`가 걸림(`estop:true`)을 보고하면 `power_lost`와 `relay_expected_on`을 지운다.
  - `rpi4/services/act_executor.py` — `handle_outlet_estop`: 재부팅 걸림 위에 온 모듈 보고(ready·status)는 '같은 걸림 재확인'으로 버리지 않고
    새 비상 버튼 걸림으로 원인(`estop_source`)을 바꾼다. 그 밖의 재확인 무시 규칙은 그대로.
- 시험 `rpi4/tests/test_eval_fixes_outlet.py` +3: 이벤트 경로·status 보고 경로(둘 다 해제 뒤 릴레이 꺼짐·`power_lost` 지워짐·'다시 켜져' 문장 없음),
  재부팅 걸림 단독은 종전대로 해제 뒤 다시 켬(회귀). 수정 전 코드: **2 실패**(릴레이 켜짐 / 원인 그대로), 실행기 수정만 빼면 status 경로 1 실패.
- 미검증: 실물 콘센트 모듈(회로 미제작) — 가짜 모듈로만 확인.

  RPi4가 만든다. RPi5만 새 판이면 정지 대기·비상 버튼 문장이 옛 말로 남고 B11 수리도 들어가지 않는다 — 학교 배포 때 RPi4·RPi5를 이 커밋으로 함께.
- 키오스크와 맞출 것: 연결 창 해결 방법이 이제 '다시 확인하기'를 말한다(키오스크 단추 이름 변경과 함께 나가야 한다. 키오스크 쪽 대체 문장
  `lib/models/ambient.dart`의 '다시 연결하기'도 같이). 재부팅 걸림 구분은 여전히 `estop_detail`의 '다시 켜져'.
- 작업 중 사고(기록): 실패 확인에 `git stash`를 썼다가 다른 작업 트리의 stash와 엇갈려(stash는 작업 트리끼리 공유) 서로의 변경이 바뀌어 들어갔다.
  조정자가 복구했고, 문장 소스는 같은 편집 스크립트로 다시 만든 뒤 원래 차이와 줄 단위로 같음을 확인했다. 앞으로 실패 확인은 파일 복사로만 한다.
