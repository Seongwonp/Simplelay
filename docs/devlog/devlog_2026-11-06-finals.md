# 2026-11-06 — 결선 당일: 엔코더 끊김, 누름 시연을 실제 영상으로 대체

## 1. 전날 밤 상태

- 보드 배포: RPi5 `9bc872ab`, RPi4 `699a9bf9` 이미지. 모션 펌웨어는 HW 담당 동의 범위에서 도착 허용 오차를 3 → 40 카운트(모터 한 축 기준 약 1.1 mm)로 넓힌 판이다(원본 전체 백업은 RPi4에 보관).
- 11/5 밤에 실제 경로 한 번을 확인했다: '네' → 시작 버튼 누름 → 콘센트 모듈이 소비전력으로 작동 확인 → 정지 버튼 위 대기 → 앱 정지 → 정지 버튼 누름 → 전자레인지 멈춤.
- 레일을 손본 뒤 모터 A 쪽이 레일 부하에서 약했고, 새 전원으로 바꿔도 전력 문제가 이어졌다.

## 2. 당일 오전 모터 진단 (노트북에 ESP32 직결)

모션 보드에 직접 명령을 보내 엔코더 카운트를 읽었다. 출력 0.5, 0.3초 기준.

| 시험 | A 엔코더 | B 엔코더 |
|---|---|---|
| 처음 | 0과 1 사이만 오감 | 0 (엔코더 표시등 꺼짐) |
| B 커넥터·납땜 손본 뒤 | 0과 1 사이만 오감 | +594, -662 (양방향 계수) |
| A 출력 0.8, 0.5초 | 0과 1 사이만 오감 | A가 돌 때 벨트를 따라 약 50 움직임 |

- A 모터는 실제로 돈다(눈으로 확인, 벨트로 이어진 B 카운트도 함께 변함). A 엔코더는 두 신호(A상, B상) 중 한 줄만 들어오는 모양이라 카운트가 한 방향으로 늘지 않는다. 신호선(GPIO16·17 쪽) 끊김으로 본다 — 납땜 필요, 미수리.
- 이 상태에서 느린 이동(`G 5 0 10`)도 1초 안에 추종 오차(`FOLLOW_ERROR`)로 멈췄다. 펌웨어가 엔코더로 움직임을 판단하므로 출력을 올려도 해결되지 않는다.
- SwitchBot 누름(`T`)은 정상(`PRESSED`).

## 3. 결정: 누름 시연은 실제 영상으로

- 현장에서 납땜할 시간과 장소가 없어, 11/4에 같은 장치로 찍은 실제 누름 영상 두 개(누름 → 30초 데우기 → 가열 종료 감지 → 공기청정기 강풍)를 발표 자료의 '시연 ② 대신 누르기' 장에 넣었다. 원래 부록 대체 영상 장에 있던 것을 본편으로 옮겼다.
- 누름 장치는 전자레인지에 붙인 채 책상에 전시했다.
- 발표 자료에서 '이동 오차 0.1 mm 이내' 문구를 뺐다. 위 허용 오차 변경 뒤로는 사실이 아니어서 '도착 위치 확인 뒤에만 누름', '도착 허용 오차 약 1 mm'로 바꿨다.
- 발표 자료는 저장소 밖에 두는 규칙이라 이 변경은 커밋 기록이 없다.

## 4. 설치와 평가 직전

- RPi5 env에서 개발자 실물 조작을 껐다: `SIMPLELAY_DEV_MODE=0`, `SIMPLELAY_DEV_REAL_MOTION=0`(백업 `env.bak-20261106-before-eval`). 허브 재시작 뒤 `/status.developer_mode=false`, 실행기 연결 정상 확인.
- FastAPI 기본 API 문서 페이지(`/docs` 등)는 끄는 설정이 코드에 없어 그대로 열어 두었다. 당일 코드 변경은 하지 않았다.
- 폰 앱: 허브가 꺼져 있을 때 홈에 '해야 할 일 — 버튼 자리를 다시 맞춰 주세요'가 떴다. 확인 주행 조회에 답을 못 받아 '모름'으로 본 것이고, 허브에 붙자 사라졌다.
- 시연 ① 리허설: 본체 인사, 집 모형 조명, LG 공기청정기 켜기(클라우드 명령 성공), 공기청정기가 켜진 뒤 모형 표시등까지 끝까지 동작했다.
- 평가 직전 핫스팟 휴대폰을 들고 이동하면서 RPi5·RPi4가 핫스팟에서 떨어졌다. 노트북과 집 모형은 다시 붙었지만 두 보드는 스스로 다시 붙지 않았다. 허브(RPi5)는 다시 연결해 시연 ①을 했고, RPi4는 도커를 켜지 못한 채 발표했다(누름은 영상이라 영향 없음).
