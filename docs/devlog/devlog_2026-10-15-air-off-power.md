# 2026-10-15 저녁 — 공기청정기가 꺼져 있어도 공기질 값이 오면 '켤까요?' 제안 (서버·폰)

사용자가 ThinQ 앱의 공기청정기 **공기질 센서 설정을 '운전 중에만' → '항상'**으로 바꿨다. 그 뒤 읽기 전용 조회에서 공기청정기가
**꺼진 채로** 센서 값이 왔다(전원 `POWER_OFF`·풍량 `AUTO`, `PM2` 8 · `GOOD`, `PM10` 10). 지금까지 서버는 꺼짐을 '값 없음'으로 쳐서
제안하지 않았고, 폰 상태 카드는 꺼져 있으면 '값을 받을 수 없어요'라고만 했다. 사용자 결정(안 '가')으로 꺼져 있을 때 나쁨이면
**'공기청정기를 켤까요?'**(전원 켜기 한 단계)를 묻게 했다. 켜져 있을 때의 강풍 제안은 그대로다.

> **검증 수준: 서버는 실물 확인(허브는 노트북), 폰 화면은 위젯 시험까지.** 같은 날 밤 실제 공기청정기로 끝까지 했다(아래 §0).
> 폰·키오스크 화면에서 이 카드를 보고 승인하는 것은 아직이다(에뮬레이터가 이날 밤 부팅 중 멈춰 API로 승인). RPi5 허브도 아직이다.

## 0. 실물 확인 (10/15 21시, 노트북 허브 real 모드)

공기청정기를 끈 채 센서 가까이에서 청소기 필터를 털었다(냄새 강함). 판독은 읽기 전용 감시(20초 간격)와 허브 판독(2분 간격).

| 시각 | 일어난 일 |
| --- | --- |
| 21:03~21:18 | 꺼짐, 초미세먼지 8 · 좋음 — 필터를 턴 뒤에도 클라우드 값은 한동안 그대로였다(본체 표시는 먼저 주황으로 바뀜) |
| 21:18:22 | 꺼진 채 **종합 공기질 `totalPollutionLevel` = BAD**가 클라우드에 올라옴(초미세먼지는 8 · 좋음 그대로) |
| 21:20:19 | 허브가 켜기 카드 생성 — 질문 "공기청정기를 켤까요?", 근거 "공기청정기 센서: 종합 공기질 · 나쁨", 명령 `set_power POWER_ON` 하나, 모의 표시 없음 |
| 21:21:09 | 승인(API) |
| 21:21:12 | 실행 기록 `confirmation=state_confirmed`, "전원 켜기로 바꿨어요.", 약 2.0초 |
| 21:21:28 | 다음 조회에서 전원 켜짐, 카드 내려감 |

알게 된 것: 본체가 나쁨을 보인 뒤 클라우드 값이 바뀌기까지 수 분이 걸릴 수 있고, 허브 판독 간격(기본 120초)이 더해진다 — 시연에서 '나빠지면 바로 카드'를 기대하면 안 된다.
이번 나쁨은 냄새가 올린 **종합 등급**이었고 PM 등급은 좋음이었다. 허브를 다시 띄우면 메모리 속 가전 등록이 사라져 공기청정기를 다시 추가해야 판독한다(노트북 허브 기준).

## 1. 바뀐 동작

| 판독 | 전 | 후 |
|---|---|---|
| 켜짐 + 나쁨 | 강풍 카드(`air_quality_high`) | 그대로 |
| 켜짐 + 나쁨 + 이미 강풍 | 제안 없음 | 그대로 |
| **꺼짐 + 센서 값 + 나쁨** | 값 없음 → 제안 없음 | **켜기 카드(`air_quality_power_on`)** |
| 꺼짐 + 센서 값 + 좋음·보통 | 값 없음 | 좋음(다시 준비) — 제안 없음 |
| 꺼짐 + 센서 칸 없음('운전 중에만') | 값 없음 | 그대로 값 없음 |

- **켜기 카드:** 시나리오 이름 '공기가 나빠요', 질문 '공기청정기를 켤까요?', 근거는 강풍 카드와 같은 모양
  ('공기청정기 센서: 초미세먼지 42 · 나쁨', 모의면 끝에 '(시연: 모의 센서 값이에요)'). 할 일은 **정확히 한 단계**
  `air_purifier` `set_power` `{power: POWER_ON}` — 풍량은 넣지 않는다. 꺼진 공기청정기는 전원 밖의 명령을 클라우드가 거절(2304)하기 때문이다.
- 꺼져 있을 때 풍량 칸은 마지막 설정일 뿐이라 '이미 강풍'의 근거로 쓰지 않는다(꺼짐 + 풍량 HIGH + 나쁨 → 켜기 카드).
- 두 카드 모두 `auto_allowed=False`('다음부터도 자동으로' 없음, `approve-and-allow` 422), 시연 트리거 409, 조용한 시간·잠시 쉬기·다시 받지 않기·
  부재·비상정지(승인 412) 규칙은 다른 카드와 같다. `set_power`는 원래 공기청정기 대응표(`rpi/services/thinq/bindings.py`)에 있는 동작이라
  허용 목록을 고치지 않았다.

## 2. 설계 — 카드 둘, 재알림 기억 하나

- **시나리오를 따로 둔다**(`air_quality_high`·`air_quality_power_on`). 기록·마지막 실행·'다시 받지 않기'(질문 문장으로 억제)가 섞이지 않는다.
  트리거는 둘 다 `air_quality`이고 트리거 이벤트로 가른다 — 켜짐 `purifier_on`, 꺼짐 `purifier_off`(엔진 `on_air_quality(..., power_off=)`).
  `GET /scenarios`의 `air_quality_high` 트리거 `event`가 `null`에서 `purifier_on`으로 바뀌었다(폰·키오스크는 이 값을 쓰지 않는다).
- **재알림 기억은 함께 쓴다**(`AirQualityMonitor` 하나). 나쁜 공기 한 번에 카드 하나다. 켜기를 승인해 켜졌는데 여전히 나쁘면 강풍 카드는
  곧바로 뒤따르지 않는다 — 좋음·보통을 한 번 본 뒤 + 카드 뒤 45분(종전 규칙)이 지나야 강풍을 묻는다. 연달아 두 번 묻지 않으려는 선택이다.
  같은 이유로 두 카드가 동시에 떠 있는 일도 없다(리허설 `forget_recent` 제외).

## 3. 모의·모의 클라우드: 센서 '항상' 흉내

- 모의 클라이언트 `MockThinqClient(air_sensor_always=...)`, 허브에서는 환경 변수 `SIMPLELAY_THINQ_MOCK_AIR_SENSOR_ALWAYS`(`1`·`true`·`yes`·`on`, mock 모드만 —
  [환경 변수](../환경변수.md)). **기본은 예전 설정('운전 중에만')** 그대로 — 다른 시험이 기대는 모의 기본(꺼짐 → 센서 칸 없음)을 바꾸지 않았다.
- 모의 클라우드 `FakeThinqCloud(air_sensor_always=...)`, 실행 때 `--air-sensor-always`. 모의 클라우드는 지금까지 꺼져 있어도 센서 칸을 그대로 돌려줬는데
  (서버가 꺼짐을 걸러서 드러나지 않았다), 이제 기본은 모의 클라이언트와 같게 **켜져 있을 때만** 싣는다.
- 리허설(모의): `SIMPLELAY_THINQ_MOCK_AIR_SENSOR_ALWAYS=1`로 허브를 띄운 뒤, 공기청정기를 켜지 않은 채 `POST /demo/thinq/air-quality {"level": "BAD"}` →
  '공기가 나빠요 · 공기청정기를 켤까요?' 카드.

## 4. 폰 '지금 상태' 카드

- 미세먼지 값 줄은 원래도 전원과 상관없이 값이 있으면 보였다(이번에 확인 — 바꾼 것 없음). 꺼짐 + 값이면 값 줄이 보이고 이유 줄은 없다.
- 꺼짐 + 값 없음 문장: '전원이 꺼져 있어 미세먼지 값을 받을 수 없어요' →
  **"전원이 꺼져 있어 미세먼지 값이 오지 않아요. 꺼져 있을 때도 보려면 ThinQ 앱에서 공기질 센서를 '항상'으로 바꿔 주세요."**
- 켜짐 + 값 없음 문장('미세먼지 값을 아직 받지 못했어요(켠 직후에는 잠시 걸려요)')과 조작 줄 아래 '전원이 꺼져 있어요. 켠 뒤 풍량·운전 모드를 바꿀 수 있어요.'는 그대로.
- 이 카드에는 골든이 없다 — 골든은 바꾸지도 돌리지도 않았다.

## 6. 수정 전 실패 확인

시험을 먼저 쓰고 **수정 전 코드**(이 작업의 기준 커밋 그대로)에서 돌렸다.

- 백엔드 새 시험 `test_air_quality_power_on.py` **35개 중 30개 실패.** 통과한 5개는 바뀌지 않아야 하는 동작을 지키는 시험이다
  (꺼짐 + 센서 칸 없음 → 값 없음 2개(단위·서버), 예전 설정 모의에서 꺼짐 → 제안 없음, 켜짐 + 나쁨 → 강풍 그대로, 켜짐 + 강풍 → 제안 없음).
  기본 카탈로그 목록 시험 2개(`test_cook_done_card`·`test_demo_v3_gaps`)도 실패.
- 결함을 되살린 변형(수정 뒤 코드에 적용 → 실행 → 되돌림): '꺼져 있어도 풍량 HIGH면 이미 강풍'과 '엔진이 이벤트로 카드를 고르지 않음(둘 다 냄)'을
  함께 넣었을 때 두 공기질 시험 파일에서 **10개 실패**. 앞의 것은 단위 시험 `test_off_bad_offers_power_on_even_if_the_stored_wind_is_high`가 따로 잡는다.
- 폰 `thinq_state_card_test.dart` **24개 중 1개 실패**(꺼짐 + 값 없음 문장). 새 '꺼짐 + 값 → 값 줄' 시험은 수정 전에도 통과했다 —
  값 줄은 원래 전원을 보지 않았다(회귀 방지 시험으로 둔다).

## 8. 남은 것·위험

- **실물 미확인:** 폰·키오스크 화면에서 켜기 카드 보고 승인, 켠 직후 센서 칸이 잠시 비는지('항상' 설정에서도), PM 등급이 나쁨일 때.
  RPi5 허브 real 모드도 아직이다. (꺼진 채 나쁨 → 켜기 카드 → 승인 → 실제 켜짐 `state_confirmed`는 §0에서 확인.)
- 공기질 센서 설정이 '운전 중에만'으로 돌아가면 꺼져 있을 때 제안이 다시 없어진다(폰 카드가 바꾸는 방법을 알려 준다). 결선 장소에서 설정을 확인한다.
- 켜기 승인 뒤에도 나쁘면 강풍 카드는 최소 45분 + 좋음·보통 확인 뒤에야 온다 — 시연 순서에서 '켜기 → 바로 강풍'을 기대하면 안 된다.
- 보드 배포 전이다(서버·폰 모두 이 커밋 미배포).
