# 2026-10-15 ThinQ 실물 첫 연동 · 폰 '지금 상태' 카드와 직접 조작

공기청정기(AS186HWWA)가 도착해 [ThinQ 실물 확인 절차](../ThinQ-실물-확인-절차.md)를 처음 실제 클라우드로 밟았다.
같은 날 사용자 요청으로 폰 앱에 상태 카드와 직접 조작을 넣었다 — **UI 동결(10/14) 뒤 사용자 요청 예외**다.

## 1. 실제 클라우드 확인 (절차 §4, 노트북 + 인터넷)

| 기준 | 결과 | 증거(저장소 밖) |
|---|---|---|
| A 인증·기기 목록 | 성공 — 공기청정기 1대(클라우드 모델 코드 `AIR_0B5001_WW`) | `devices.json` |
| B 프로필 | 성공 — 전원 `POWER_ON/OFF`, 풍량 `windStrengthDetail` `LOW/MID/HIGH/AUTO`, 운전 모드 `CLEAN/SLEEP/AUTO`(`SILENT` 없음 → 실행 전 거절) | `*_profile.json`, `summary.txt` |
| C 상태 | 성공 — 전원 켜짐·청정·풍량 자동·PM 좋음·필터 100% | `*_state.json` |
| D 승인 후 제어 1회 | `succeeded / accepted / state_confirmed (real)` — 풍량 자동 → 강, 본체 변화 사용자 육안 확인 | `control.json` |
| E 서버 real 모드 | 앱 'ThinQ에서 찾은 가전'에 '제어할 수 있어요 — 전원 · 풍량 · 운전 모드' → 추가 → 홈 ThinQ 타일 → 상세에서 강풍 → `success · sent · state_confirmed` "강풍으로 바꿨어요." | 앱 화면 녹화, `/history` |

- 풍량은 이 모델에서 `windStrengthDetail`로 쓴다. 대응표(`rpi/services/thinq/bindings.py`)가 이미 그 칸을 먼저 고르므로 고치지 않았다.
- 첫 제어 시도 한 번은 확인 입력 전달 문제(셸 파이프)로 **보내지 않고** 끝났다 — 전송 0회.
- 앱 경유 제어 3회(09:25 강풍 시험, 09:26 자동 사용자 시험, 09:36 강풍 녹화) 모두 `POST /thinq/command` 1회씩, 각각 `state_confirmed`. 중복 전송 없음.
- 서버는 노트북(시뮬레이터 서버 + `SIMPLELAY_THINQ_MODE=real`)에서 돌렸다. RPi5는 인터넷이 없어 ThinQ에 닿지 않는다 — **RPi5 real 모드는 미확인**.
- §5-1 '이미 목표값'(제어 0회) 실물 확인은 아직 하지 않았다.
- ThinQ 계정 연결은 설치 때 허브에 한 번(PAT) 하는 방식을 유지한다. 앱에 토큰 붙여넣기 화면은 두지 않는다(사용자 결정 — 일반 사용자에게 개발자 절차를 요구하지 않는다).

## 2. 폰: '지금 상태' 카드 + 직접 조작

- `GET /thinq/status/{id}`(서버에 이미 있음)를 상세 화면에 들어올 때와 '다시 읽기'에서만 읽는다(클라우드 호출 상한 보호).
  전원·운전 모드·풍량·초미세먼지(PM2.5)·미세먼지(PM10)·필터 남은 양, 읽은 시각, 모의면 '(모의)'.
- 못 읽으면 이유를 말하고 값을 지어내지 않는다. 그때는 지금 값을 모르므로 조작 줄도 내걸지 않는다.
- 공기청정기 조작: 전원(켜기·끄기), 풍량(약풍·중풍·강풍·자동), 운전 모드(청정·수면·자동).
  누르면 **한 번 묻고**('풍량을 강풍으로 바꿀까요?'), '바꾸기'에서만 `POST /thinq/command` 1회 → 실행 상태 화면 → 돌아오면 다시 읽는다.
  지금 값은 눌러도 묻지도 보내지도 않는다. 허브가 거절하면(프로필에 없는 값 등) 이유를 말한다.
- 실행 상태 화면: ThinQ 가전이면 '버튼판'을 그리지 않고 단계 제목을 '할 일'로.

시험(골든 제외): 폰 **844** 통과, analyze error·warning 0. 새 시험 `app/test/screens/thinq_state_card_test.dart` 10개, `thinq_appliance_test.dart` +1.
수정 전 실패 확인: 카드를 뺀 화면 → 5개 실패, 조작 줄을 뺀 카드 → 6개 실패, 상태 화면 수정 전 → 1개 실패.
