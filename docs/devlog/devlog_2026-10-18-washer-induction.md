# 2026-10-18 — 인덕션 '설정이 필요해요' · 연습용 LG 세탁기

사용자 요청 두 가지. 시험 조건(모의·저장소 안 모의 클라우드)에서만 확인했다 — 보드 배포·실물 확인은 아직이다.

## 1. 작은 팔이 누를 수 있는 기본 가전을 정한다

- 예전: 서버가 기본 가전(전자레인지·인덕션)을 모두 작은 팔(로컬 갠트리) 대상으로 보아 인덕션도 '준비됐어요'(operable)였다.
  실물 갠트리는 1대이고 전자레인지 위에만 있다.
- 지금: `SIMPLELAY_GANTRY_APPLIANCES`(쉼표 목록, **기본 `microwave`**)에 든 기본 가전만 작은 팔로 실행한다. 나머지 기본 가전은
  `needs_setup`('설정이 필요해요') + 사유 '작은 팔이 이 가전 위에 없어서 누를 수 없어요', 실행 요청은 412로 같은 사유를 준다.
  가전 목록·`GET /readiness`·실행 거절이 같은 판정(`SimpleLayService.gantry_absent`, `readiness_view`)을 쓴다.
- 바꾸지 않은 것: 사용자 등록 가전(is_custom)의 판정, `SIMPLELAY_LOCAL_APPLIANCES`로 로컬에 물린 가전, 노드로 가는 가전.
  서버를 직접 조립하는 단위 시험(인자 없음)은 종전처럼 기본 가전 전부를 작은 팔 대상으로 본다.
- 인덕션을 작은 팔에 다시 올리려면 `SIMPLELAY_GANTRY_APPLIANCES=microwave,induction`.
- 시험: `rpi/tests/test_gantry_appliances.py`(고치기 전 코드에서 인덕션 operable·실행 200·전자레인지 빼기 무시로 실패 확인).

## 2. 연습용 LG 세탁기

- `SIMPLELAY_THINQ_PRACTICE_DEVICES=washer`면 LG 가전 실제(real)·모의 클라우드(fake_cloud) 모드에서도 모의 세탁기 한 대를
  'LG 세탁기(연습)'(가전 ID `thinq_washer`, 종류 세탁기)로 더한다. env가 없으면 지금과 같다(실제 기기만). mock 모드는 이미 모의
  세탁기가 있어 쓰지 않는다. 모르는 값은 기동을 막지 않고 건너뛴다(기록에 남김).
- 기기 ID로 가르는 클라이언트(`rpi/services/thinq/practice.py`): 연습 세탁기만 기존 모의 클라이언트로, 나머지는 실제 클라이언트로.
  연습 세탁기 호출은 실제 클라우드에 닿지 않는다(시험에서 모의 클라우드 제어 0건 확인). 계정 기기 목록(발견)에는 섞지 않는다.
- 실행 환경은 **가전마다**: 실행 결과·기록·`/status` 마지막 실행·`/thinq/status/{id}`·`/thinq/devices`의 가전 항목이 연습 세탁기는
  `mock`, 실제 공기청정기는 `real`. 서버 전체 실행 환경(자동 실행 규칙·공기질 판정이 보는 값)은 실제 그대로다.
- 세탁기 동작은 기존 모의 구현 재사용: 시작·일시정지(`set_operation`), 상태(운전 상태·남은 시간·원격 시작). 연습 세탁기는 원격 시작
  켜짐·대기 상태·남은 시간 45분(모의 값)으로 시작한다. 전원 켜기/끄기는 세탁기 대응표에 없어 넣지 않았다.
- 세탁기 자리가 이미 있으면(실제 세탁기를 환경 변수·추가로 넣은 설치) 연습 세탁기를 더하지 않는다(실제가 먼저).
- 화면: 폰 LG 가전 상세·키오스크 LG 가전 화면에 세탁기 상태 줄('빨래 빨래하는 중'·'남은 시간 45분'·'휴대폰으로 시작 켜져 있어요')과
  '빨래 시작·잠시 멈춤' 조작(한 번 묻고 보냄). 연습 표시는 기존 체계(execution_mode mock → '지금 상태 (연습)'·'연습이에요. 실제
  가전은 그대로예요'). 키오스크 처음 화면 타일은 이름이 '(연…'으로 잘려 '(연습)'을 이름에서 빼고 'LG 가전' 배지 자리에 '연습' 배지를
  둔다(이름 표기 '(연습)'만 — 모의 모드 '(모의)' 이름은 종전 그대로). 폰 홈 가전 칸은 'LG 세탁기(연습)'가 그대로 들어간다.
- 시험: `rpi/tests/test_thinq_practice_washer.py`(real 조립 경로 + 저장소 안 모의 클라우드), `app/test/screens/thinq_washer_practice_test.dart`,
  `rpi5-touchscreen-app/test/kiosk_thinq_washer_practice_test.dart` — 고치기 전 코드에서 실패 확인.
- 골든: 키오스크 `kiosk15_idle_practice_washer`·`kiosk15_thinq_washer_practice`, 폰 `lt_thinq_washer_practice`·`lt_home_practice_washer`.
  키오스크 처음 화면 골든의 인덕션은 서버가 실제로 주는 '설정이 필요해요'로 갱신했다.

## 보드에 켜는 법(조정자가 env를 고친다)

RPi5 env에 한 줄: `SIMPLELAY_THINQ_PRACTICE_DEVICES=washer`. 인덕션 판정은 env 없이 기본(`microwave`)으로 바뀐다.
RPi5 백엔드·폰·키오스크를 같은 커밋으로 배포해야 화면이 맞는다(옛 키오스크는 세탁기 조작 칸 대신 '휴대폰 앱에서 바꿀 수 있어요',
타일 이름이 잘린다).

## 남은 것

- 보드 실물 확인 전(RPi5 실제 모드에서 연습 세탁기 목록·실행·키오스크 결과 '연습', 실제 공기청정기 22:00/07:00 자동 실행이 그대로인지).
- 연습 세탁기 상태는 서버 재시작 때 처음 값으로 돌아간다(메모리). 남은 시간은 고정 예시 값이다.
- 연습 세탁기를 대상으로 한 자동 실행 규칙은 서버 전체 실행 환경(real)으로 판정한다 — 규칙을 만들지 않는 것을 전제로 했다.
