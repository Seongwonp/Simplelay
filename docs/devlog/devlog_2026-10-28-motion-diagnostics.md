# 모션 진단과 단독 누름

날짜: 2026-10-28. 시작 기준: `6a5c0a63`. [수리 계획](../결선전-복귀결함과-첫연결-수리계획-2026-10-28.md)에 따른 노트북 작업이다.

## 구현

- 모션 어댑터에 최근 100건의 메모리 기록을 두고, 인증된 개발자 화면에서는 최근 32건을 읽는다.
  전송 시도·응답·시간 초과·재시작·연결 끊김, 명령 번호·보고 좌표·목표 좌표를 구분한다.
  일반 실행은 실행 번호, 개발자 조작은 RPi4 요청 번호를 문맥으로 붙이고, 모션 응답은 해당 명령 번호에 결속한다.
  시각은 같은 모션 객체의 경과 시간이며 장치 사이 절대 시각 비교에 쓰지 않는다.
- RPi4의 `trace`는 메모리만 읽는다. 실행 중에도 읽을 수 있고 MCU 조회나 이동을 보내지 않는다.
  원문·위치 토큰·인증정보는 허용 목록에서 제외한다. 수집 과정에 디스크 쓰기·화면 응답 대기를 넣지 않았다.
- 개발자 화면에 **스위치봇 한 번 누르기**를 분리했다. 현재 위치를 재조회하고 직전 이동에서 받은 일회용 토큰으로만 누른다.
  XY 이동·원점 설정은 보내지 않으며 자동 재전송하지 않는다. 사용 후에는 새 조그가 필요하다.
  기존 등록 버튼 누름과 구별되는 `press_here` 명령이며, 버튼 선택·사진 매핑을 단독 시험의 선행 조건으로 삼지 않는다.
  개발자 세션·실물 모드·연결·비상정지·일반 실행과의 배타 제한은 유지한다.
- 앱은 단독 누름의 중복 탭을 막고, 통신 조회 실패를 빈 기록과 구별한다. 옛 본체의 미지원도 별도 안내한다.
- 개발자 조작 규약은 3이다. RPi5·RPi4·폰을 같은 커밋으로 배포해야 새 기능을 쓸 수 있다.
  모션 펌웨어는 수정하지 않았으며 기존 v2 명령만 사용한다. [규약](../protocol.md)의 개발자 조작 절 참고.

## 재현한 결함과 수리

1. 재부팅 전에 시작한 상태 조회가 뒤늦게 도착하면 연결·원점 상태를 되살릴 수 있었다.
   조회 시작 때의 연결 세대와 반환 때의 세대를 비교해 옛 응답을 거절한다.
2. 위치 응답 순서는 비교하면서 원점 여부는 항상 덮고 있었다. 원점 여부도 같은 응답 순서로 갱신한다.
3. 재시작을 감지한 뒤 새 상태 조회가 `homed:true`를 보내면 사용자의 원점 재확인 없이 준비 상태가 될 수 있었다.
   재확인 필요 상태를 별도로 유지하고 명시적인 원점 동작 뒤에만 해제한다.
4. 개발자 이동에서 보고 위치가 없으면 목표 위치를 대신 넣어 오차 0으로 기록할 수 있었다.
   대체값을 제거하고 좌표를 null로 보존한다. 폰도 이 경우 도착 대신 위치 미확인으로 읽는다.
5. 명시적 원점 동작도 좌표 기준의 새 세대로 구분한다. 원점 동작 이전에 시작한 상태 응답이 나중에 도착해도 옛 좌표로 되돌리지 않는다.
6. 단독 누름은 이미 도착한 정지 표시를 해제하지 않는다. 정지 뒤에는 기존 위치 토큰이 폐기되므로 새 위치 확인이 필요하다.
7. 진단 수집이 비정상적으로 큰 정수 좌표를 받아도 수신 스레드를 중단하지 않도록 유한 숫자 판독을 보강했다.

이 항목들은 합성 응답·주입 조건으로 확인한 호스트 결함이다. 촬영 때 관찰한 좌표 초기화와 같은 원인이라는 증거는 아직 없다.
단독 누름 전후에 임의의 `Z`나 `home`을 넣지 않았고, 복귀를 위해 가짜 좌표를 만들지도 않았다.

  별도의 실제 보드·기구 시험으로 계산하지 않는다.

## 다음 장치 점검

1. RPi5·RPi4·폰·키오스크 SHA와 펌웨어 식별 정보를 기록한다. 환경 설정·버튼 매핑은 로컬에 백업한다.
2. 원점 동작이 현재 자리 설정인지 실제 홈 이동인지 설정과 로그로 확인한다. 화면의 명칭만 믿고 누르지 않는다.
3. 조그로 자리를 맞춘 뒤 단독 누름 한 번: 보드 전송은 상태 조회와 누름만 있어야 한다.
   누름 뒤에는 ‘센서 읽기’로 좌표를 재조회해 누름 전후 좌표·재시작 사건·원점 설정 명령 유무를 남긴다.
   두 번째 누름은 새 조그 전까지 하지 않는다.
4. X·Y 각 방향의 요청 거리·보고 거리·자 측정 거리와 왕복 오차를 비교한다.
   현재 기본/상한을 늘리지 않았다(RPi5 기본 1 mm, 설정 상한 5 mm, RPi4 상한 10 mm).
   거리 환산이 틀렸으면 환산부터, 맞으면 측정한 가동 범위에 따라 큰 이동 선택지를 정한다.
5. 일반 승인 실행에서 누름 전후와 복귀 요청·거절 이유를 기록한다. 실제 관찰 원인을 확정한 뒤 복귀 호출부만 수리한다.
   원점 상실·정지·비상정지 뒤 자동 복귀는 추가하지 않는다.
6. 누름 결과와 복귀 결과를 분리할 서버 필드가 필요한지는 실제 실패 응답으로 결정한다.
   현재 작업에서 정상 실행의 새 파킹 동작이나 폰·키오스크 일반 결과 계약은 추가하지 않았다.
7. CT는 별도 단독 계측부터 확인한다. 이번 변경과 동시에 통합하지 않는다.

펌웨어·거리 환산·이동 범위·자동 파킹은 이번에 변경하지 않았다. 실제 기구와 스위치봇 동작은 다음 장치 점검 범위다.
