## 3. 정책(L1, 사용자 확정)

**가열 종료가 감지되면 취소·문 열림이어도 제안·자동 실행이 일어날 수 있다 — 공기청정기 풍량 변경은 낮은 위험 동작이라 허용하고,
화면·문서에 '조리 완료가 아닐 수 있음'을 명시한다.** 코드 동작은 이미 이랬고(취소 판별 없음), 이번에 바꾼 것은 주석·문서·합격 기준이다.
실측 기록표 §6의 C1(취소 버튼)·C2(문 열림)는 실패가 아니라 **발생 여부·지연 기록**이고, 실패는 B(가열 중 전력 감소)·D(종료 후 팬)다.
문구를 바꿨다고 취소 판별이 생긴 것은 아니다.

## 4. M1 신선도 설계

- **서로 다른 장치의 monotonic을 그대로 비교하지 않는다.** RPi4 프레임의 `at_s`·`t_monotonic_ns`는 RPi4 프로세스 시계이고 `clock_id`가 그 시계를 가리킨다.
- 링크 세션마다 RPi5가 `clock_probe {probe}`를 보내기 **직전** 자기 단조 시각 L0을 적고, RPi4가 `clock_ref {probe, clock_id, t_monotonic_ns: R}`로 곧바로 답한다.
  RPi4 시각 x는 RPi5 시각 `L0 + (x − R)`로 옮긴다. R을 읽은 실제 순간은 L0 이후이므로 옮긴 값은 실제보다 이르거나 같다 → 나이는 최대 왕복 시간만큼 **길게** 잡힌다(보수적).
- RPi5는 프레임을 **받는 순간** 끝 시각을 옮겨 `event_end_mono_s`로 둔다. 나이 = 지금 − 그 값 — RPi4가 낸 뒤 링크·버퍼에서 늦어진 시간까지 센다.
  허용 전 사건 판정도 이 나이로 한다. 판단 때와 **ThinQ 전송 직전**(H1 재판정 안) 두 번 본다(상한 `SIMPLELAY_AUTO_RULE_MAX_EVENT_AGE_S`, 기본 120초, 측정 필요).
- **근거가 없으면 보류가 기본:** 기준점 없음(옛 RPi4·아직 답 없음), 프레임 `clock_id`가 지금 세션 것이 아님(RPi4 재시작), 링크 끊김(기준점 버림), 1초 넘게 미래.
  RPi5 모의 주입은 RPi5 자기 시계 식별자를 실어 같은 시계로 본다.
- 드리프트(수 ppm)는 120초 상한에 비해 무시했다 — 측정한 값이 아니다. 두 보드 사이 실제 왕복·지연은 재지 않았다.

## 6. 남은 것

- **배포:** M1 규약(`clock_protocol`)·H2 응답(`auto_allow`)·M3 응답 모양 때문에 RPi4·RPi5·폰·키오스크를 같은 커밋으로. 옛 RPi4면 자동 실행이 늘 '근거가 없어' 보류다.
- **`/stop` HTTP 응답은 규칙 끄기의 DB 저장을 기다린다.** 물리 정지와 메모리 판정(세대)은 기다리지 않지만, DB 쓰기가 멈추면 응답이 늦는다 — 응답과 저장을 떼는 것은 이번 범위 밖.
- 실측: 두 보드 사이 `clock_probe` 왕복 시간, 가열 종료 → 자동 실행 지연(실측 기록표 §6), C1·C2 발생 기록, 사건 나이 상한 120초.
- M4의 근거 문장은 '이 제안을 승인한 횟수'(제안 기록 최근 200건, DB 있으면 영속)다 — 자연 습관 학습(28일·3일 반복)과는 다른 집계이고, 카드도 그렇게만 말한다.
- 골든 10장 눈 검토 뒤 갱신, 실폰 TalkBack·200%, CoreXY 실제 누름·CT·AS186HWWA 실물 — [인계](../인계-2026-10-13-데스크톱.md) §8.
