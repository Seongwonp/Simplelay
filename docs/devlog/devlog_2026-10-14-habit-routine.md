# 2026-10-14 데스크톱 — 습관 제안 → 루틴 초안 저장 (UI 동결 예외, 범위 제한)

사용자 승인(10/14) 4번. 가전 사용 기록 분석이 찾은 반복 순서를 **가전·버튼 순서가 채워진 루틴 초안**으로 보여 주고, 사용자가 이름과 '직접 실행 / 정해진 때 물어보기'만 고른 뒤 확인하면 저장한다.

## 0. 시작 전 일정 판단(착수 전 기록)

- 범위: 서버(후보 목록·저장·거절 3개 API, 판단 저장 1개 설정 키) + 폰 루틴 탭 카드 1개와 확인 시트 1개. 기존 편집기·팔레트·탭 구조는 그대로 둔다. 키오스크는 바꾸지 않는다(초안 저장은 폰에서만).
- 근거 계산은 기존 `PatternDetector`의 근거(성공·실제 실행·직접 사용만)를 그대로 쓴다. 새 분석 방법은 만들지 않는다.
- 예상: 서버 2~3시간(시험 포함), 폰 2~3시간(위젯 시험 포함), 전체 시험·문서 1~2시간. **검증 포함 하루 안에 가능하다고 판단했다.** 하드웨어 검증·제출 서류 일정과 겹치는 작업(보드·배포)은 없다.
- 5번(조용한 시간)은 4번을 끝낸 뒤 다시 판단한다.

## 1. 흐름

1. 서버 `GET /routines/candidates`가 패턴 감지기의 근거(성공·실제 실행·직접 사용 기록만, 기본 28일 창·3일·3회)로 성립한 반복을 찾고, 그 목적을 그 가전의 **결정적인 버튼 순서**(등록 기능 또는 내장 규칙, 제안 '동작 바꾸기'와 같은 표)로 바꿔 초안을 만든다. 버튼 순서를 모르면 초안을 만들지 않는다(빈 폼 금지). 버튼 누름 가전만 — ThinQ 가전은 이번 범위 밖.
2. 폰 루틴 탭 '내 루틴' 맨 위에 카드 한 장씩: '사용 기록으로 만든 루틴 초안' · "전자레인지 · 즉석밥 → 시작" · "최근 28일 중 아침에 4일 사용했어요" · [루틴으로 저장] [괜찮아요]. 팝업·소리·알림 없이 이 탭에만 있고, **실행 중(대기·실행·재시도)에는 감춘다** — 작업 도중 끼어들지 않고, 다음에 앱(루틴 탭)을 열었을 때 조용히 보인다.
3. [루틴으로 저장] → 아래에서 올라오는 확인 시트(새 화면 아님): 가전·버튼 순서(고치지 않음)·근거, 이름(채워져 있음), '직접 실행할 때만'(기본) / '매일 07:30에 물어보기'(기록 시각 중앙값), "저장만으로는 실행하지 않아요. 실행은 매번 승인을 받아요. 자동 실행은 켜지지 않아요." → [저장] [취소]. 저장하면 "'이름' 루틴을 저장했어요. 실행하지는 않았어요."
4. 저장한 루틴은 승인 루틴(`mode=approve`). '정해진 때 물어보기'는 그 시각에 **카드만** 만든다(종전 루틴 규칙). 고치려면 기존 편집기(그대로 둠).

세 동의를 나눈다: 루틴 저장(이 시트) · 정해진 때 제안(시트의 두 번째 선택, 그때도 카드 승인 필요) · 자동 실행 허용(이 흐름에는 없음 — 버튼 누름 루틴은 자동 실행 규칙 대상이 아니다).

## 3. 지키는 것과 강제 자리

| 조건 | 강제 |
|---|---|
| 저장만으로 실행하지 않음 | `candidates.py`·라우터에 실행 진입점 호출 없음(기존 `test_routine_package_and_router_have_no_direct_execution_calls`가 새 모듈도 검사). 시험이 서비스·루틴 러너의 실행 진입점 10개를 세어 **0회**, 카드 0장, 루틴 트리거 기록 0건 |
| 자동 실행 허용 안 생김 | 저장 뒤 `/routines/auto-rules` 빈 목록, 그 루틴의 카드에 `auto_rule_offer` 없음, `approve-and-allow` 422(물리 버튼 규칙 유지) |
| 중복 저장 방지 | 같은 가전·같은 버튼 순서(장치 명령 열 비교 — 편집기로 버튼 ID로 적은 루틴도 같다)가 있으면 목록에서 빠지고 저장 409(그 루틴 이름). 저장은 판단 저장소 잠금 안에서 확인·저장(연타해도 1개) |
| 저장 후보 재추천 없음 | 판단 `saved`는 만료 없음 — 루틴을 지워도 다시 안 보인다 |
| 거절 후보 반복 독촉 없음 | `declined`는 14일 동안 안 보인다(그사이 계속 써도) |
| 문구 | 가전 사용 기록 문장("최근 28일 중 아침에 4일 사용했어요" — 실제 창·날 수), '하셨'·개인 단정 없음, '추천'이라 부르지 않음(예시 루틴과 구분) |
| 근거 제외 | 모의·시연·제안 승인 실행·실패 기록은 세지 않음(패턴 감지기 기존 규칙 그대로) |
| 조용히 | 제안을 쉬는 동안(방해 금지) 빈 목록, '다시 받지 않기'로 내린 목적 제외, 폰은 실행 중 감춤 |
| 영속 | 판단은 DB 설정 `routine_candidate_decisions`(재시작 뒤 유지, 시험) |

## 4. 시험

- 수정 전 실패 확인: 서버 새 시험 15건 중 14건이 HEAD 코드에서 실패(없는 초안 404 1건은 원래 통과 — 회귀 방지), 폰 새 위젯 시험 6건 중 5건이 HEAD `lib`에서 실패('실행 중 감춤'은 HEAD에 카드가 없어 원래 통과 — 회귀 방지, 같은 묶음의 첫 시험이 카드가 보이는 쪽을 고정).
- 변형 확인: 저장 직후 버튼 실행을 부르게 바꾸면 '실행 0회' 시험 3건이 실패하는 것을 확인하고 되돌렸다.
- 전체(ASCII 임시 worktree, 이 변경만 얹음): 백엔드+rpi4 **2,987 통과·13 건너뜀**(전체 실행에서 부하 때문에 실패한 `test_sensor_verifier`·`test_serial_motion` 각 1건은 단독 재실행 통과, 문서 링크는 이 기록이 추적되면 통과), 폰 **807**(`--exclude-tags screenshot`, 801에서 +6), 폰 `analyze` error·warning 0(기존 info 4). 키오스크는 바꾸지 않았다.
- 루틴 탭은 골든 장면이 없다(새 카드·시트는 위젯 시험으로만 확인).

## 5. 미검증·남은 것

- 실폰·실서버에서 보지 않았다. 실제 사용 기록(실물 실행 성공)이 아직 없어 실기기에서는 초안이 나오지 않는 것이 정상이다 — 모의 실행·시연 기록은 근거가 아니다.
- ThinQ 가전의 반복(공기청정기 풍량 등)은 초안을 만들지 않는다. 필요하면 별도 승인 뒤.
- 편집기로 직접 만드는 루틴(`POST /routines`)에는 중복 검사를 넣지 않았다(종전 동작 유지). 초안 저장 경로만 막는다.
- 키오스크에는 초안을 보이지 않는다(저장은 폰에서만).
