# 개발 로그 — 2026-09-13 (하드웨어 경계 결함 수정 · 작업 축 전환)

기준 HEAD: `3f3492d` → 코드 `9311ac5`.
결선 대비 냉정 평가를 받고 팀 검토로 과장·오류를 걸러냈다. 결론은 하나다:
**앱·백엔드는 충분히 성숙했지만, 대회 차별점인 실제 모션과 폐루프 검증은
아직 증명되지 않았다.** 그래서 UI·일반 기능·개발자 모드 신규 기능을 여기서
동결하고, 하드웨어 도착(약 2주 뒤)까지는 하드웨어 연결을 돕는 작업만 한다.

## 평가 정정 — 기록할 정확한 표현

- "임베디드 작품이 아니다"는 과장이다. **임베디드 구조는 만들었지만 핵심
  하드웨어 가설이 미검증**인 상태다.
- 키오스크는 RPi5 + HDMI 화면·마우스로 구동한 기록이 있다. 미검증은 **전용
  7인치 터치 패널**이다. 로드맵 W2 ⑤를 이렇게 고쳤다.
- 모터 PID 코드가 없다는 사실 자체는 치명이 아니다. G-code 계열 펌웨어를 쓰면
  별도 PID가 필요 없을 수 있다. 문제는 실제 모션 어댑터와 보정 좌표 연결이 없다는 것이다.
- 누름 명령에 좌표가 없는 것도 잘못이 아니다. 버튼 ID만 넘기고 어댑터가 보정
  프로필로 바꾸는 구조가 더 맞다.
- 전류 임계 12 mA가 약 2.2 mV라는 계산은 맞다. 그것이 잡음보다 작다는 것은
  **실측 전 추측**이다.
- Android 음성 인식의 네트워크 의존은 기기·언어팩에 따라 다르다. 오프라인이라고
  말하려면 실기기 확인이 필요하다.
- 개발자 모드는 낭비가 아니다. 하드웨어 도착 뒤 조그·로그·명령 전송에 쓴다.
  다만 Phase 2.1이면 충분하다.

코드로 확정된 결함 중 이번 범위는 아래 두 개다. 나머지(모션 mock 고정, 경계에서만
반영되는 정지, ADC 설정, 기준값, 음향 큐, 전원 차단 없는 비상정지)는 구현하지 않고
[하드웨어 연결 설계](../하드웨어-연결-설계.md)에 계약으로 옮겼다.

## 1. 실행 상한을 비동기 실행 합류점에서 (`54f094d`)

- 동기 실행만 해석 결과의 버튼 개수·바이트 상한을 다시 검사했다. 실제 HTTP
  경로인 `/execute`와 제안 승인은 `submit_purpose → _submit`으로 내려가 검사를
  지나쳤다. LLM 해석을 켠 구성에서 모델이 폭주하면 상한 없는 물리 실행이 된다.
- 검사를 `_submit`으로 옮겼다. 네 비동기 진입점(`/execute`·`/execute-buttons`·
  `/execute-for-appliance`·제안 승인)이 모두 지난다. 대상 확정·제어권 획득보다
  먼저 거절하므로 제어권이 남지 않는다. 동기 `execute_buttons`도 같은 검사를 받는다.
- 제안 승인 라우터가 해석 거절(`ValueError` 계열)을 잡지 않아 500이 됐다 → 422.
- 회귀 11건. 수정 전 코드에서 8건이 실패하는 것을 확인했다.
- 처음 쓴 바이트 초과 사례(40자 한글 20개)는 예산 안이었다. 예산이 그 크기를
  받도록 설계돼 있어서다. 스키마의 라벨 길이 검사를 거치지 않는 **해석 결과의
  긴 라벨**로 바꿨다.

## 2. `/stop` — 이벤트 루프 분리, 전달 결과 노출 (`9311ac5`)

- async 핸들러가 동기 정지 브로드캐스트를 직접 불렀다. 응답 없는 노드를 전체
  상한(2.5초)까지 기다리는 동안 `/status`·SSE·다른 API가 전부 멈췄다.
- 서비스 정지를 스레드로 넘겼다. 개발자 세션 정지는 노드 브로드캐스트를 기다리지
  않고 동시에 보낸다(두 경로는 서로의 락을 잡지 않는다).
- 응답에 `nodes_requested`·`nodes_acknowledged`·`nodes_unconfirmed`를 더했다.
  기존 필드는 그대로라 폰·키오스크는 영향이 없다. 화면 문구는 동결이라 바꾸지 않았다.

**요청 접수와 물리 정지 확인을 같은 뜻으로 쓰지 않는다.**

| 응답 | 뜻 | 뜻하지 않는 것 |
|---|---|---|
| `ok` | 서버가 정지 요청을 받았다 | 모터 정지 |
| `nodes_acknowledged` | 노드가 요청을 받았다고 2xx로 응답했다 | 노드의 모터 정지 |
| `nodes_unconfirmed` | 전송 실패·오류 응답·기한 초과, 또는 수신 확인 수단 없음 | 요청을 안 보냈다는 뜻 아님 |

- HTTP 노드만 수신 여부를 돌려준다. ESP-NOW 노드는 게이트웨이로 보냈다는 사실만
  알 수 있어 **항상 미확인**으로 분류된다. UART로 붙은 RPi4(로컬 컨트롤러)는
  노드 목록이 아니라 응답에 나타나지 않는다 — 이 경로의 확인은 설계 문서 §2의 몫이다.
- **과정에서 잡은 테스트 결함:** 첫 비차단 테스트는 `/status`를 보낸 시점부터
  시간을 쟀다. 루프가 막히면 테스트 쪽 대기와 요청 시작도 함께 밀려, 스레드 이관을
  동기 호출로 되돌린 변형에서도 통과했다. 게이트 체인이 이 실패 확인을 조건에 넣지
  않아 커밋까지 진행됐다. 푸시 전에 발견해 `/stop`을 보낸 시점부터 재도록 고쳤고,
  변형에서 0.62초 대기로 실패하는 것을 확인한 뒤 커밋을 amend했다.
  **실패 확인은 커밋 게이트 조건에 넣는다.**
