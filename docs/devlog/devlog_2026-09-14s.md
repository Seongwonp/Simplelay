## 1. 홈 스위치 fail-closed (`9490680`)

설계 문서 작성 중 찾은 결함을 H1까지 미루지 않고 고쳤다. GPIO를 켠 구성에서
초기화 실패·읽기 오류 때 준비 판정이 `True`였다 — 스위치를 못 읽었는데 `/health`가
갠트리가 홈에 있다고 말했다.

- 초기화 실패·읽기 오류·기한(0.2초) 초과·bool이 아닌 값 → 모두 준비 안 됨.
  `None`이 `not None`으로 홈으로 읽히던 경로도 닫았다.
- 판독은 데몬 스레드에서 기한을 두고 기다린다. 이전 읽기가 안 끝났으면 새로 띄우지
  않고 닫는다. 일시 오류 뒤 정상 판독이면 다시 판정한다.
- `/health`는 판독을 이벤트 루프 밖에서 한다.
- 그대로 둔 것: 정상 입력 판정(NC 스위치, 홈에서 `is_pressed=False`), GPIO를 끈 개발
  구성의 `True`.
- 회귀 17건. gpiozero를 가짜 모듈로 끼워 **수정 전 코드에서도 같은 테스트를 돌렸고**
  10건이 실패하는 것을 확인했다.
- 이 판정은 지금 `/health` 표시에만 쓰인다. 실행 게이트는 아니다(설계 문서 §2의 홈 계약 몫).

## 2. 원시 센서 기록기 (`2214550`)

`python -m rpi.bench.raw_recorder`. 하드웨어 수령 직후 임계값을 믿기 전에 값부터 본다.

| 기록 | 내용 |
|---|---|
| ADC | 라이브러리 정수 판독값, 전압(V, 반올림 없음) |
| 음향 | 콜백 블록마다 RMS·피크·샘플 수 |
| 이벤트 | `press_start` · `press_end` · `marker` · `error` |
| 시각 | 모든 행 호스트 `monotonic_ns` |

- **판정 없음.** 임계값·눌림·성공 판정이 없고 `rpi.verifier`를 import하지 않는다(테스트로 고정).
- ADC gain은 기본값이 없다. 영점 전압과 범위가 맞지 않으면 포화된다(설계 문서 §4).
- 판독 오류는 `error` 이벤트로 남기고 기록을 계속한다.
- 누름 이벤트는 지금 키보드(s/e)로 찍는다 — 사람 입력 지연이 포함된다. 모션 어댑터가
  생기면 어댑터가 `mark()`를 부른다.
- 기본 출력 `data/bench/`는 git 무시 경로임을 커밋 전에 확인했다.
- **검증 경계:** ADS1115·sounddevice 입력부는 라이브러리가 없는 개발 PC라 실행하지
  못했다. 기록 코어·루프·키 명령·CLI 인자 검증 19건만 통과했다.

## 3. README 정리 (`542868d`)

테스트 21개 표기 제거(최신 수치는 CLAUDE.md), 솔레노이드·Z축 확정 표현 → 방식 결정
필요·코드 mock, RPi5→RPi4 UART와 ESP32 노드 경로, 디렉토리 구조 갱신, 옛 마일스톤 표 →
실제 상태 표. 실제 모터·센서 검증이 아직 실기기에서 증명되지 않았다는 사실을 앞쪽에 적었다.

## 4. 실측 기록표 (`c5004d6`)

[docs/실측-기록표.md](../실측-기록표.md) — 원가·설치 시간·대안 비교·성공률·정지 지연.
빈 표와 측정 방법만 두고 숫자는 채우지 않았다. 성공률은 사람 판정이 기준이고,
정지 지연은 t0 누름 → ① 요청 접수 → ② 루프 종료 → ③ 물리 정지로 나눈다.
