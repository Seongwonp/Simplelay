# 2026-10-14 데스크톱 — 보안 1차 점검 수리

외부 보안 1차 점검(로컬 `f2ae2c0` 기준) 4건과 배포 점검 항목을 사용자 승인(10/14)에 따라 고쳤다. UI 기능 동결은 그대로다 — 보안 수리에 필요한 최소만 바꿨다. 기준 자료는 [참고 자료와 설계 근거](../참고자료-설계근거-2026-10-14.md) 1·2·6번, 장치별 한 장 표는 [보안 장치별 접근표](../보안-장치별-접근표.md).

> **검증 수준: 시험까지, 미배포.** 실제 RPi5·RPi4·패널·폰에 올리지 않았다. 실제 브라우저 공격(Private Network Access 포함)이 성립하는지는 시험하지 않았다.

## 3. 키오스크가 실제로 보내는 헤더

같은 기기의 키오스크가 깨지지 않게, 고치기 전에 실제 헤더를 로컬 에코 서버(저장소 밖)로 받아 봤다.

- **네이티브 키오스크와 같은 Dart HTTP 클라이언트**(Flutter SDK의 dart, `dart:io`): `user-agent: Dart/3.11 (dart:io)`, `host`, `content-type`, `accept-encoding`만. **`Origin`·`Sec-Fetch-*` 없음** → 면제 그대로.
- **Chromium(앱 내 브라우저, 같은 출처 페이지)**: GET은 `Origin` 없이 `Sec-Fetch-Site: same-origin`, POST는 `Origin: http://localhost:<포트>` + `Sec-Fetch-Site: same-origin`, 주소창 이동은 `Sec-Fetch-Site: none` → `/kiosk/` 웹 빌드도 통과.
- 실제 15.8형 패널 앱에서 잡은 헤더는 아니다(미검증). 앱 코드는 `Content-Type`만 직접 붙인다.

**신뢰 경계(헤더 없는 루프백 요청을 면제하는 이유):** 보드의 루프백에 직접 연결을 여는 프로세스는 이미 그 보드에서 코드를 실행할 수 있는 위치다(백엔드 env·DB를 읽을 수 있다). 최신 브라우저는 다른 출처 요청에 `Sec-Fetch-Site`(모든 요청)·`Origin`(POST)을 붙이므로 이 경로로 들어오지 못한다. 이 헤더를 보내지 않는 옛 브라우저는 경계 밖이며 키오스크 기기에 쓰지 않는다.

## 4. HTTP 평문(④) — 배포 방안

지금 폰 → RPi5는 `http://<허브>:8000` + `X-API-Key` 헤더다. 같은 망에서 트래픽을 볼 수 있는 사람(같은 Wi-Fi 비밀번호를 아는 사람 포함)은 키를 읽어 그대로 쓸 수 있고, 폰은 상대가 진짜 허브인지 확인하지 않는다.

| 선택 | 무엇을 막나 | 남는 위험 | 결선 전 |
|---|---|---|---|
| 전용 망: 여행용 공유기, WPA2-AES 이상(가능하면 WPA3-SAE), 긴 비밀번호, 행사장 공용 Wi-Fi에 붙이지 않음, 우리 기기(RPi5·RPi4·폰·노트북)만, 공유기 관리자 비밀번호 변경 | 망 밖 사람의 접근·도청 | 망 안 참가자는 평문을 본다. 비밀번호가 새면 키도 샌다. 가짜 허브 확인 없음 | **지금 선택(완화)** |
| 접근 제한: DHCP 예약, RPi4 7000은 RPi5만(`SIMPLELAY_LINK_ALLOW_FROM` 또는 호스트 방화벽 `DOCKER-USER` 사슬), 개발자 API 끔 | 망 안 다른 기기의 링크 선점·개발자 조작 | 위와 같다 | 인계 §8-12 |
| TLS(자체서명 인증서 + 폰 앱에 그 인증서를 신뢰 루트로 넣어 핀 고정, uvicorn `--ssl-*`) | 도청·가짜 허브 | 인증서 배포·교체 절차, 키오스크 루프백은 HTTP 유지 | 미적용 — 앱 변경·시험 시간이 필요해 사용자 결정 사항. **적용한다면 인증서 검증을 끄는 방식(모든 인증서 허용 콜백 등)은 쓰지 않는다.** 시험: 잘못된 인증서 → 연결 거절 |

기본 주소는 `http`로 둔다(TLS를 적용하지 않았으므로). 이 항목은 **"전용 망·접근 제한으로 완화, 평문 통신 위험 잔존"**으로 기록한다.

## 6. 남은 것

- **미배포.** RPi5·RPi4·폰·키오스크를 같은 커밋으로 올려야 한다 — 새 RPi4는 키 없으면 시작하지 않고, 옛 키오스크는 새 서버의 `/health`에서 조용한 시간을 꺼짐으로 본다.
- HTTP 평문(④)은 남은 위험이다. TLS 적용 여부는 사용자 결정.
- `scripts/setup_rpi.sh`의 안내 문구("`/health` → `act_mode`")는 이번 수정 권한 밖이라 고치지 않았다 — 지금은 `/health/detail`.
