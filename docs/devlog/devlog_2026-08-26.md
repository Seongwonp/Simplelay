# 개발 로그 — 2026-08-26

## 플랫폼 인터페이스 대조 → 온디바이스 해석 계층 결함 3건 수리

지금까지 온디바이스 연동 코드(`rpi/intent/dbus_vectordb.py`, `rpi/intent/dbus_agent.py`)는
실기기 없이 인터페이스 추정만으로 작성돼 있었다. 인터페이스 문서와 한 줄씩 대조해
**실기기 없이도 확정 가능한 결함**을 골라 수리했다. 백엔드 테스트 **464 → 475**.

먼저 대조 결과의 절반은 좋은 소식이다 — 호출 시그니처, 인자 구성, 스트리밍 응답의
필드 구성과 상태 코드 해석은 전부 실제 인터페이스와 일치했다. 설계 자체는 맞았고,
틀린 곳은 전부 **응답을 읽는 쪽**이었다.

### 치명 1 — 유사도 계층이 구조적으로 항상 실패

검색 결과 파서가 `metadata`를 버리고 빈 딕셔너리로 채우고 있었는데, 정작 리졸버는
그 `metadata`에서 버튼 시퀀스를 읽는다. 즉 **실기기를 붙여도 이 계층은 100% 다음
단계로 폴스루**했다. 기능이 꺼져 있던 게 아니라, 켜도 절대 동작할 수 없는 상태였다.

동작이 안전한 방향으로 실패해서(다음 계층이 받아줌) 겉으로 드러나지 않았다는 점이
오히려 위험했다. "벡터DB 계층 배선 완료"로 기록돼 있었고, 심사 질의에서 그렇게
답했다면 사실과 달랐을 것이다.

### 치명 2 — 결과 필드 순서를 잘못 읽음

결과 한 건은 `id, metadata, originalData, score` 순인데, 파서는 "id 다음 첫 문자열이
originalData"라고 가정했다. `metadata`가 그 사이에 있으므로, 비어 있지 않으면
metadata 조각이 originalData 자리에 들어온다. 수리 전 정규식으로 실제 확인해보니
originalData에 metadata의 **키 이름**이 잡혔다.

점수가 항상 결과 한 건의 마지막이라는 점을 이용해 블록으로 자른 뒤,
`첫 문자열=id / 마지막=originalData / 그 사이=metadata 키·값 쌍`으로 분해하도록 교체했다.
metadata가 없는 경우에도 같은 규칙이 그대로 성립해서 기존 케이스가 깨지지 않는다.

### 왜 464개 테스트가 이걸 못 잡았나 — 이음매 구멍

이게 이번 건에서 제일 배울 점이다. 두 테스트가 **서로 모순된 가정** 위에서 각각 통과하고
있었다.

- 파서 테스트: metadata가 아예 없는 가짜 원문을 넣고, 결과의 `metadata == {}`를 **정답으로
  단언**했다 — 결함을 명세로 굳혀놓은 셈
- 리졸버 테스트: `SearchResult`를 손으로 만들어 metadata를 채워 넣었다 — 파서를 안 탄다

각 계층은 완벽히 테스트돼 있었는데 **둘을 잇는 경로를 지나가는 테스트가 하나도 없었다.**
테스트 파일 docstring에 "리졸버 로직을 파싱 계층과 독립적으로 검증한다"고 의도까지 적혀
있었는데, 그 독립성이 정확히 구멍이 됐다.

CLI 출력 → 파서 → 리졸버를 한 번에 통과시키는 이음매 테스트를 추가했다. 수리 전 코드로
돌리면 실패하는 것을 확인했다.

### 중요 3 — 도구 호출 알림이 답변에 섞임

스트리밍 응답의 상태 코드 중 하나는 "도구를 호출하는 중"이라는 진행 알림인데, 이걸
답변 본문과 함께 이어붙이고 있었다. 우리는 JSON만 돌려달라고 요청하므로 이 텍스트가
섞이면 파싱이 깨진다. 본문 조립에서 제외했다.

### 중요 4 — 포기할 때 상대에게 안 알림

응답 대기가 타임아웃되면 모니터 프로세스만 죽이고 예외를 던졌다. 상대는 요청이 취소된
줄 모르고 계속 처리한다 — **우리만 실패로 처리하고 기기는 계속 도는 상태**다.

8/24에 ESP 노드 경로에서 고쳤던 치명 1과 정확히 같은 종류다. 그때 세운 원칙("포기할 땐
반드시 상대에게 중단을 알린다")을 이 경로에만 적용하지 않은 누락이었다. 취소를 전송하되,
취소 실패는 로그만 남기고 원래 오류를 가리지 않게 했다.

### 문서

- `docs/inference-boundary.md`가 "온디바이스 추론 미구현 / 규칙 단독 배선" 시점에 멈춰
  있었다. 실제 배선(3계층)과 맞췄고, 기기가 관리하는 맥락 정보(시간대·날씨·일정·재실)를
  제안 근거로 쓰는 검토 항목을 신설했다. 재실은 우리가 **공급하는** 방향도 가능해서,
  공간 지능을 소비만 하는 게 아니라 기여하는 구성이 된다
- `.gitignore`에 pptx/pdf를 확장자 단위로 추가 — 커밋할 이유가 없는 형식이고 실수로
  스테이징되는 경로를 없애는 쪽이 안전하다

### 아직 실기기가 필요한 것

- **응답 출력 텍스트 포맷** — 이번 수리는 인터페이스의 필드 구성에 근거했고, CLI가
  그걸 어떤 텍스트로 찍는지는 여전히 미확인이다. 파싱은 교체 가능한 순수 함수로 분리해뒀다
- **유사도 계층 예시 시드** — 조회 쪽만 배선돼 있고 예시를 채우는 호출부가 없다.
  비어 있으면 이 계층은 계속 다음 단계로 넘어간다(안전하지만 계층이 논다).
  저장소가 재부팅 후에도 유지되는지 확인한 뒤 시드 시점을 정한다
- **Python 런타임** — 여전히 1순위 리스크. 다만 확인해야 할 질문이 하나 더 있다:
  우리 백엔드가 도는 기기와, 온디바이스 서비스를 호출할 수 있는 기기가 같은 기기인가.
  다르면 배선 방식을 바꿔야 한다(대안은 별도로 정리해뒀고, 어느 쪽이든 백엔드와 테스트
  자산은 유지되는 방향이다)

## 공개 저장소에서 벤더 고유 명칭 제거 (3단계)

우리 코드가 기기 쪽 서비스 이름·CLI 이름·제품명을 소스와 문서 곳곳에 그대로 담고
있었다. 공개 저장소라 검색 한 번이면 연결되는 흔적이다. 세 단계로 나눠 처리했다.

### 1단계 — 재유입을 막는 가드부터

청소를 먼저 하면 시간이 지나며 다시 스며든다. 그래서 **가드를 먼저 만들고**, 그때
남아 있던 16개 파일을 부채 목록에 적은 뒤, 정리하면서 목록을 줄여나가는 순서로 갔다.
진행 상황이 테스트로 보이고 작업 중 새 유출이 끼어드는 것도 막힌다.

가드에 넣은 장치 둘:
- 금지어를 소스에 그대로 적으면 가드 파일 자체가 유출이 되므로 **조각으로 조립**한다.
  허용 목록의 경로도 마찬가지 — 자기 자신을 검사에서 빼버리면 정작 거기 들어온 유출을
  못 잡는다
- **이미 정리된 파일이 부채 목록에 남아 있어도 실패**시킨다. 이게 없으면 목록이 한 번
  부풀고 영영 줄지 않아서, 나중에 들어온 진짜 유출까지 조용히 덮어버린다

가드가 실제로 실패하는지 임시 파일로 확인했다(파일명까지 지목).

### 2단계 — 서비스 주소를 소스 밖으로 (핵심)

서비스 이름·오브젝트 경로·호출 CLI는 **우리 코드의 일부가 아니라 배포되는 기기의
성질**이다. 소스에 박혀 있으면 저장소가 특정 기기 빌드에 묶이고, 빌드가 바뀔 때마다
코드를 고쳐야 한다. 환경변수로 옮겼다 — 값은 systemd의 EnvironmentFile(기기에만 있고
저장소에는 없는 파일)이 주입한다. API 키가 이미 쓰던 경로 그대로다.

> 저장소는 연동의 *모양*만, 기기는 *신원*을 갖는다.

컴플라이언스만이 아니라 설계로도 낫다. 부수적으로 얻은 것:
- 오브젝트 경로를 서비스 이름에서 D-Bus 관례로 파생시켜 설정 항목이 절반으로 줄었다
- GPIO 어댑터의 클래스 상수 4개가 서비스 이름 하나에서 파생되도록 정리됐다
- **기본값을 두지 않았다.** 켜놓고 조용히 아무 일도 안 일어나는 상태가 가장 진단하기
  어렵다. 모드만 켜고 주소를 안 주면 어떤 변수가 비었는지 짚으며 기동 시 실패한다
  (이 동작도 테스트로 고정)

### 3단계 — 우리 식별자 개명

파일 2개와 대응 테스트 2개를 `git mv`로 옮기고(이력 보존), 클래스 5종을 기능 기준
이름으로 바꿨다. 15개 파일에 걸친 기계적 변경이고 동작은 그대로다.

### 정리 중에 가드가 두 번 잡았다

가드를 먼저 만든 값어치가 여기서 나왔다.

1. **슬래시 형태를 놓치고 있었다.** 벤더 네임스페이스는 점 형태(버스 이름)와 슬래시
   형태(오브젝트 경로) 둘 다 쓰이는데 점 형태만 검사했다. 테스트 단언 하나가 그대로
   빠져나갔다
2. **플랫폼 이름 자체를 일부러 뺐던 게 구멍이었다.** 무관한 오픈소스 선형대수
   라이브러리와 철자가 겹쳐서 제외했는데, 그 사이 테스트 docstring에 플랫폼 이름이
   들어간 문장이 남아 있었다. 이제는 검사하되 그 라이브러리 이름만 먼저 지우고 본다

### 결과

추적 중인 파일에 벤더 고유 명칭이 남은 곳은 **없다**. 부채 목록은 비었다.

허용으로 남긴 곳은 **이름을 부르는 것 자체가 목적**인 위치뿐이다 — 크로스빌드 툴이
만드는 플랫폼 디렉터리(안드로이드의 `android/`와 같은 자리라 이름이 고정이고 기기
설치용 앱 ID도 여기서 나온다), 그 ID로 결정되는 산출물 경로를 적은 빌드 안내,
무시할 로컬 전용 폴더 이름을 적어야 하는 `.gitignore`, 그리고 작업 규칙 문서.

발표자료(pptx/pdf)도 확장자 단위로 무시 처리했다. 이미 추적 중인 파일 하나는 추적
해제 시 다른 기기의 작업 트리에서 삭제되는 영향이 있어 팀 판단으로 그대로 뒀다.
