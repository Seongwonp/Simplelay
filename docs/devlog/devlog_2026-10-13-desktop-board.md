# 2026-10-13 데스크톱 — 같은 커밋 배포, 정지 확인 실측(G3), 폰 골든·큰 글꼴·접근성

[10/13 데스크톱 인계](../인계-2026-10-13-데스크톱.md)를 사용자가 정한 순서대로 진행했다.
보드: RPi5·RPi4(Wi-Fi)·ESP32(RPi4 USB, 시험대 펌웨어 `esp32dev_benchhome`)·모터 전원. **벨트가 없어 모터 축만 돌고 캐리지는 움직이지 않는다. 캐리지 이동과 버튼 누름은 여전히 미검증이다.**

## 2. 정지 확인 실측 (인계 §6)

### 확인한 것 (실물, 모터 축)

| 장면 | 줄 기록 | 폰 화면 |
|---|---|---|
| 대기 중 정지(폰) | `>> stop` → `<< ok` 5.9 ms, status 두 번 같음 | "멈춘 것을 확인했어요 (모션 보드 응답 6 ms)" |

| 이동 중 정지(폰) | `move` 34 ms 뒤 stop, MCU 이동 `error: stopped`, 응답 10.1 ms, 엔코더 a=1 | "… (12 ms)" |

- 줄 기록에 `>> stop`과 `<< {"id":…,"ok":true}`가 **모두 남는다**(10/12 발견 2 해소).
- 화면의 ms는 기록 간격보다 0~1.3 ms 크다. 측정 지점이 다르기 때문이다.
- 일반 실행 정지 행에서 "멈춘 것을 확인"이 나온 이유: 그때 엔코더가 0을 읽어 값이 변하지 않았다(아래 발견 6). 그 행을 물리 멈춤의 근거로 쓰지 않는다.

### G3 두 구간 (스크립트, 같은 개발자 경로, n=10씩)

- 조건: 5 mm 조그를 시작하고 약 88 ms 뒤 `/dev/stop`.
- 결과와 정한 기한은 [실측 계획](../실측-계획-결선.md) §3 '첫 실측'에 있다.
  - A. sent→mcu_ack: 중앙 10.95 ms
  - B. sent→verified: 중앙 160 ms
  - 기한: 0.3 s 유지, 멈춤 확인은 0.05 s·두 번 연속·0.5 s로 변경, 1.5 s 유지

## 4. 발견 (고칠 것, 우선순위 순)

1. **[높음] RPi4 실행기가 USB 재열거 뒤 죽은 포트를 붙잡는다.**
   - 모터 배터리를 꽂는 순간 RPi4에 `Undervoltage detected`가 떴다. ESP32가 `ttyACM0`에서 `ttyACM1`로 다시 잡혔다.
   - 실행기는 사라진 포트에 쓰다 EIO가 났다. 폰은 잠금으로 정직하게 보였다.
   - 임시 조치: RPi4 env `SIMPLELAY_MOTION_PORT`를 `/dev/serial/by-id/usb-1a86_…-if00`로 바꾸고 실행기를 다시 띄웠다.
   - 남은 일: 실행기가 포트를 다시 열지 못한다. 런북에 by-id 경로를 적는다. RPi4 전원(5 V 3 A)과 모터 전원 분리를 확인한다.
2. **[높음] 모션 걸림 알람이 "눌림 확인 실패"로 보고된다.**
   - 일반 실행 첫 이동에서 MCU `stall` 알람이 났다. 이동은 한 번뿐이었다.
   - 그런데 결과는 `safety_stop`, 즉석밥 `attempts 3`, `last_detail` 없음이었다.
   - 폰 기록은 "다시 눌러도 확인하지 못해 안전 정지", 키오스크는 "눌림을 확인하지 못해 안전하게 멈췄어요"라고 보였다. **원인이 바뀌어 보인다.**
   - 원인: `ClosedLoopController`가 어댑터 오류를 재시도할 수 있는 오류로 보고 `continue`한다. 알람 상태에서 뒤의 두 시도는 움직이지 않고 바로 실패한다.
   - 수리 계획(RPi4·RPi5·폰·키오스크를 함께 배포):
     - 모션 알람·재시작·기한 초과·준비 안 됨은 재시도하지 않고 바로 끝낸다.
     - 실제 시도 수와 원인(`motion_alarm: stall`)을 결과에 싣는다.
     - 화면은 "모터가 걸려 멈췄어요" 계열 문장으로 나눈다.
3. **[중간] 키오스크가 이전 실행의 결과 화면에 머문다.** 그다음 실행과 정지가 화면에 나오지 않아, **키오스크 정지 줄 문구는 실패널에서 확인하지 못했다.**
4. **[중간] 글꼴 2.0, 360×780 dp에서 승인 화면 아래 고정 영역이 화면 절반을 차지한다.** 할 일 줄이 첫 화면에 보이지 않는다.
5. **[중간] 접근성 트리:**
   - 홈 루틴 세 줄의 글이 한 노드로 묶여 있다. 실행 버튼은 뒤에 따로 있다.
   - 제안 카드 버튼은 이름 없이 "실행하기"다.
   - 실제 TalkBack 제스처 낭독은 미확인이다. adb 스와이프가 다음 항목 제스처로 인식되지 않았다.
6. **[HW] 모터는 도는데 엔코더 A가 0을 읽었다**(사용자 관찰 "조금 움직였다"). 그 결과 `stall` 알람이 났다. 09:25 시험까지는 정상으로 셌다. **선을 다시 꽂아 해결**(4-1).
7. [낮음] 줄바꿈 두 곳:
   - 홈 루틴 줄의 "1단 / 계"(루틴 탭은 바름)
   - 가전 타일의 "연결을 확인해 주 / 세요"
8. [낮음] 개발자 조그 중 정지하면 MCU 정지가 두 번 나간다. 사용자 정지 한 번, 조그 실패 뒤 어댑터 정지 한 번이다. 둘 다 확인돼서 해는 없다.

## 4-1. 엔코더 다시 꽂은 뒤 (같은 날 저녁)

- 사용자가 엔코더 선을 다시 꽂았다. x+5 → (175, 176), y+5 → (352, 0)으로 **엔코더가 다시 정상**이다. 발견 6은 접촉 불량이었다.
- **일반 실행 전 과정이 처음으로 실물에서 돌았다**(모터 축, 시험용 좌표). 순서는 이렇다.
  - 즉석밥 위치로 `move`
  - `press` → `press_start`/`press_end` 0.2 s(솔레노이드가 없어 신호만 나감)
  - 시작 버튼으로 `move`, 62 ms 뒤 사용자 정지 → 이동 `stopped`, 정지 `ok` 14.3 ms, 결과 `stopped`
  - 폰은 "실행을 멈췄어요. 멈춘 것을 확인했어요 (모션 보드 응답 16 ms)"를 보였다.
- **키오스크는 이 실행과 정지를 보이지 않았다**(k02). 0.3 s 간격으로 6장을 찍었다. 첫 장은 승인 카드였고 나머지는 평소 화면이다. 실행이 약 0.45 s라 '동작 중'을 놓쳤고, 사용자 정지 결과도 띄우지 않았다. **키오스크 정지 줄 문구는 실패널에서 확인하지 못했다**(발견 3과 함께 남은 일).
- 최종 배포: RPi5·RPi4 모두 `1bba354` 이미지 `c7d4b111`(코드는 `af7e2df`와 같음). 서버 정지 문장 "(모션 보드 응답 7 ms)"를 실물에서 확인했다.

## 5. 시험용으로 바꾼 서버·보드 상태

- RPi5 `home_mw` 버튼 좌표: 즉석밥 (5,5)·시작 (10,5)·취소 (5,10) mm, 1:1 기준점. **시험용 좌표이며 실제 조작부가 아니다.** 실제 보정 때 덮어쓴다.
- RPi4 env `SIMPLELAY_MOTION_PORT`는 by-id 경로다.
- 폰 에뮬레이터: TalkBack은 끄고, 화면 크기와 글꼴 배율을 원래대로 돌렸다.

## 6. 하지 않은 것

- 데이터 정리(전자레인지 4개를 시연용 3개로): 서버 가전을 지우는 일이라 사용자 결정을 기다린다.
- 키오스크 정지 줄 실패널 확인: 발견 3 때문에 못 했다.
- 200%에서 실행 중 정지 줄(RunningStopStrip) 확인: 엔코더 문제로 실행을 다시 못 했다.
- 실제 TalkBack 낭독 확인.
- 실기기(실폰) 확인.
