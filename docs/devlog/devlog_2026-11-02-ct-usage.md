# 2026-11-02 — CT로 손 사용을 안다: 사용 기록·'가열이 끝났어요'

앱·키오스크 없이 전자레인지를 손으로 돌려도 CT 전력으로 언제 켜졌고 얼마나 돌았는지 허브가 알게 했다.
**시험 조건만 확인했다** — 합성 전력 곡선·모의 저장소. 실제 콘센트 모듈로 끝까지 돌린 것은 아니고 보드에 배포하지 않았다.

## 실측 근거(실제 전자레인지 1대, 100 ms 창, 220 V 가정 추정치)

대기 0 W. 1분 가동: 시작 순간 짧게 약 3,550 W, 가열 중 약 1,000 W, 종료 뒤 약 5초 안에 0 W.
문을 여닫을 때 약 1초 안팎의 튐(최고 약 1,950 W 상당)이 있고 지속되지 않는다.

## 전자레인지 판정값

| 항목 | 이전 | 지금 | 이유 |
|---|---|---|---|
| `run_min_w` | 100 | 100 | 대기 0 W·가열 1,000 W 사이 |
| `min_run_s` | 10 | **5** | 100 W 이상 5초 유지면 가동. 문 튐(약 1초)보다 충분히 길다 |
| `hold_run` | 없음 | **켬** | 5초가 끊기지 않고 이어져야 한다. 튐이 3초 안쪽 간격으로 이어져도 쌓이지 않는다 |
| `standby_max_w` | 15 | 15 | |
| `settle_s` | 10 | **3** | 대기로 3초 유지면 끝 |
| `max_gap_s` | 5 | **1** | `settle_s`보다 길면 보지 못한 시간이 대기로 세어진다. 전력 끊김 판정 1초와 맞춤 |
| 끝 쿨다운(`cooldown_s`) | 60 | **6** | 가장 짧은 사이클(5+3초)보다 짧게 — 곧바로 다시 돌린 두 번째 끝을 버리지 않는다 |

세탁기 값은 그대로다(`hold_run` 끔). 값은 실측 1대 기준이라 다른 모델은 측정이 필요하다. 출력 조절로 마그네트론이 쉬는 동안
전력이 대기 띠까지 내려가면 끝이 두 번으로 나뉠 수 있다 — 낮은 출력 가동은 아직 재지 않았다([실측 기록표](../실측-기록표.md) §6).

## 흐름

1. RPi4 `ApplianceDoneWatch`가 `heat_complete` 프레임을 낸다. 시작·끝 시각과 가동 시간은 **이미 `evidence.power`에 있어**
   (`started_at_s`·`done_at_s`·`run_s`) 규약을 늘리지 않았다. 선택 필드 `evidence.power.gaps`(운전 중 끊김 횟수)만 더했다.
2. RPi5 `receive_appliance_done` → `ObservedUses.on_done`(`rpi/services/observed_use.py`) → 사용 기록·알림 → 기존 루틴·규칙 경로(그대로).
3. 사용 기록은 `source=observed_power`, 목적 문장 `전자레인지 사용`, `occurred_at`은 가동 시작 시각, 새 칸 `duration_s`.
   두 보드 단조 시계를 맞추지 않고 프레임 안의 RPi4 시각끼리 뺀 나이를 허브 현재 시각에서 뺀다.

## 기록하지 않는 것

- `source`가 `real`이 아닌 프레임(모의·리허설 주입) — 알림도 없다.
- 전력 근거가 없는 끝, 운전 중 끊김(`gaps`)이 있던 끝 — 시작·길이를 다 보지 못했다. 알림도 없다. 전력 끊김을 0 W로 보지 않는다.
- 같은 사건을 다시 받은 경우.
- 같은 가전의 실행과 겹치는 경우 — 사용 기록만 뺀다. 알림은 낸다. 앞뒤 15초 여유(추측/측정 필요)는 누름이 끝난 뒤 가열이 이어지기 때문이다.
  겹친 손 사용까지 빠지지만 두 번 세는 것보다 낫다.

## 안전 불변 조건

관찰 습관은 **아는 것까지만**이다. `PatternDetector`의 `candidates`·`established`는 지금처럼 `direct`만 보고, 관찰 기록은 별도
`observed_uses`로만 나온다. 그래서 습관 카드·루틴 초안·자동 실행·맡기기로 이어지지 않는다(`test_safety_observed_habit_never_reaches_cards_drafts_or_routines_list`,
이 조건을 풀면 실패함을 확인). 안부 신호(`RoutineQuietChecker`)도 관찰 기록을 보지 않는다. 실행 승인 코드는 건드리지 않았다.

## 화면

- 끝 알림: 알림 종류 `heat_done`, 문구 "가열이 끝났어요". 폰은 기존 알림함(표시 이름 '가열 끝', 경고색 아님), 키오스크는 기존 안내 한 줄
  (`/ambient`의 `tip`, 10분). 소리·승인 카드는 만들지 않았다. 키오스크 안내 한 줄은 평소 화면에만 보인다.
- '알게 된 것': `GET /learning`의 새 목록 `observed` — 같은 3일·3번 규칙을 지난 것만. 예: "평일 오후 7시쯤, 1분쯤 사용".
  어떤 버튼을 눌렀는지 모른다는 말과 먼저 묻지 않는다는 말을 함께 보인다. 숨기기·맡기기 단추는 없다.

## 가전 ID

RPi4는 CT 채널의 역할을 고정 이름으로 보낸다: `SIMPLELAY_DONE_WATCH=microwave:outlet`. 이 이름이 판정값·`heat_complete`·기존 시나리오를 고른다.
사용자가 추가한 가전의 ID는 허브에서 정해져 RPi4가 알 수 없다. 그래서 허브가 기록 때 옮겨 적는다(`observed_target`):

- 세트를 사람이 묶지 않았으면(env 구성) 프레임 ID 그대로.
- 묶었으면 `GET /kit`의 맡은 가전으로. 실행 겹침은 프레임 ID와 맡은 가전 둘 다 대조한다.
- 세트가 비었거나 종류가 전자레인지·기타가 아닌 가전에 묶였으면 아무것도 남기지 않는다.

루틴·자동 실행 규칙에는 프레임 ID가 그대로 간다. 사용자 추가 전자레인지에 세트를 묶어도 `after_done`·`wait_until_done`은 `microwave` 기준인 것은 이번에 바꾸지 않았다.
