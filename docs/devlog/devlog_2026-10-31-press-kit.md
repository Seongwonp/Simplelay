# 2026-10-31 누름 장치 세트 연결

보드에 닿지 않는 날이라 코드와 시험 조건까지만 했다. **실물 확인 없음.**

## 왜

세트(RPi4 실행기 + 모션 ESP32 + 콘센트 ESP32)는 한 제품이고 가전 하나를 맡는다. 물리 가전을 추가하면 세트를 찾지도 않고 바로 등록됐고,
세트는 여전히 옛 가전을 가리켜 새 가전이 움직이지 않았다. 어느 가전을 맡았는지가 env 목록뿐이고 세트라는 개념이 없었다.

## 바뀐 동작

- **세트 보고:** RPi4가 고정 `kit_id`(데이터 폴더에 한 번 만든다, `SIMPLELAY_KIT_ID`로 덮어쓰기)와 모션 연결·콘센트 응답·원점·비상 버튼 구성을
  `act_info`와 새 `kit_query`/`kit_status`로 알린다. 값은 캐시만 읽는다 — 수신 루프가 묶이면 abort가 늦어진다.
- **허브 연결 저장:** `settings.kit_binding`에 `kit_id → appliance_id`. 저장값이 없으면 env 판정 그대로라 전자레인지는 설정 없이 계속 돈다.
  처음 연결한 뒤로는 저장값만 본다. env가 여러 가전을 적어도(시뮬레이터) 사람이 연결하기 전까지 동작이 같다.
- **`GET /kit`·`POST /kit/bind`:** [프로토콜](../protocol.md)의 '세트 연결' 절. 실행과 같은 제어권을 잡고 바꾼다. 실행 시작 게이트가 제어권을 잡은 뒤
  한 번 더 대조한다(판정과 게이트 사이에 연결이 바뀌어도 옛 좌표로 누르지 않는다). 저장은 서비스 잠금 밖이다(정지가 그 잠금을 쓴다).
- **풀린 가전:** 버튼 자리는 남고 '세트 없음' 사유로 실행을 거절한다. 사용자 등록 가전까지 넓혔다. 자리를 맞춘 적 없는 가전은 세트 문제가 아니라 종전 판정이다.
  루틴 카드는 만들기 전에 같은 이유로 거절하고, 이미 뜬 카드·도는 루틴은 실행 경로의 412로 멈춘다.
- **자리 확인 전:** 새로 이은 가전은 모든 자리에 도착한 확인 주행 뒤에만 실행한다. 자리를 다시 저장해도 다시 확인 전이다. 주행 결과는 모션 도착 응답이고
  버튼 위였는지는 사람이 본다.
- **CT:** `execute`의 `press_appliance`로 대상이 세트 가전임을 알린다. RPi4는 그 가전이 대응표에 없어도 누르는 가전 자리의 CT를 쓴다. 옛 허브는 env 그대로.
  비상정지·L3 판정은 건드리지 않았다. 열 나는 가전의 '네' 확인도 그대로다.
- **비상 버튼을 쓰지 않는 구성:** `/kit`의 `estop_note`와 `/readiness`의 `estop_button` 칸이 그렇게 말한다.
- **`/readiness` 원점:** RPi4가 보내지 않던 값을 읽어 늘 '받지 못했어요'였다. 이제 `kit_query`의 실제 값이다.
- **폰:** 가전 추가 첫 단계 '누름 장치 찾기'. 못 찾으면 넘어가지 못한다. 다른 가전이 쓰면 확인 창을 거치고, 연결은 버튼 자리를 저장한 뒤에 한다. 가전 상세에
  '세트 다시 연결'. 위치 짐작 문구('다른 가전 위에 있어요')는 뺐다 — 사용자 등록 가전이 맡으면 기본 가전 판정만으로는 틀리게 말한다.
- **키오스크:** 타일 '세트 없음', 대표 동작에서 제외, 조작판 실행 불가.

## 남은 것

- `SIMPLELAY_DONE_WATCH`의 가전 이름은 env 그대로다. 세트를 옮기면 끝 관찰이 옛 가전 이름으로 온다 — 옮길 때 env를 고친다.
- 소프트 리밋·작업 범위는 세트 공통이라 가전별로 달라지지 않는다.
- 세트 하나 전제다. 링크를 여럿 다루지 않는다.
- 데이터 폴더를 쓸 수 없으면 `kit_id`가 호스트 이름에서 나온다. 컨테이너 호스트 이름이 바뀌면 다른 세트로 보여 다시 연결해야 한다.

## 배포

RPi4·RPi5·폰·키오스크 **같은 커밋**. RPi4 데이터 폴더(`/data`)가 쓰기 가능한지, 첫 시작 뒤 `/kit`의 `kit_id`가 재시작해도 같은지 본다. 기존 연결은 env로 이어진다.

## 시험

수정 전 실패는 결함을 되살린 변형(판정·게이트·거절 조건·원점 읽기·CT 대상·`press_appliance`·대표 동작·저장 뒤 연결)으로 확인했다.
