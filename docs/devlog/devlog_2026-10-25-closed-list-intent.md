# 닫힌 동작 목록 기반 의도 이해

## 범위

기존 실행 경로가 알아듣지 못한 말에만 선택적으로 사용하는 읽기 전용 해석 API다. 새 모델을 학습하지 않으며, 모델은 현재 허브가 할 수 있는 후보 번호 하나만 고른다. 이 작업은 보드 배포·실물 동작 시험을 포함하지 않는다.

## API 계약

인증: 기존 API 키 검사를 그대로 받는다.

`POST /intent/understand`, JSON `{"text":"공기가 텁텁하네"}`. 문자열은 공백만이 아닌 1–200자, 추가 필드는 거절한다.

응답 공통 필드:

```json
{"understood":true,"action":{"kind":"thinq","appliance_id":"air","action":"set_power","args":{"power":"POWER_ON"}},"label":"공기청정기 전원 켜기","question":"공기청정기 전원 켜기를 할까요?","source":"llm"}
```

- `source`: `off`(URL 미설정), `rules`(결정론적 일치 또는 해석 거절), `llm`(모델 조회). 모르면 `understood:false`, `action/label/question:null`이다.
- `action.kind=buttons`: `appliance_id`, `buttons` → 기존 `/execute-buttons` 요청 필드.
- `action.kind=thinq`: `appliance_id`, `action`, `args` → 기존 `/thinq/command` 요청 필드.
- `action.kind=routine`: `routine_id`, `fingerprint` → 기존 `/routines/{id}/trigger`로 카드 생성 후 해당 카드의 지문을 비교하고 `/suggestions/{id}/approve`. 변경된 카드는 승인하지 않는다.
- 위 응답은 실행 접수 영수증이 아니다. API는 실행·승인·카드 생성·사용 기록 쓰기를 하지 않는다.

## 후보와 추론

- 현재 표시 가능한 등록 가전, 기존 준비 판정, 등록 기능/검증된 기본 목적, ThinQ 쓰기 프로필의 허용값 교집합, 유효한 저장 루틴을 사용한다. 가전 이름으로 새 기능을 추측하지 않는다.
- 후보는 최대 20개. 결정론적으로 같은 동작인 후보를 중복 제거한다. 삭제·연결 불가·프로필 미지원 대상은 제외한다. 후보 번호는 요청마다 만드는 임시 번호로 영속 저장하지 않는다.
- `SIMPLELAY_LLM_URL` 미설정이면 꺼진다. `SIMPLELAY_LLM_TIMEOUT_SECONDS` 기본 20초. 동기 HTTP를 이벤트 루프 밖에서 실행한다.
- 서비스의 `/invoke`로 `messages`와 `stream:false`를 보내며 모델 출력의 첫 정수만 해석한다. 0·범위 밖·숫자 없음·HTTP 오류·시간 초과·응답 형식 오류는 모름으로 끝낸다. 정지어와 부정문은 모델에 보내지 않는다.
- 질문은 서버의 고정 한국어 템플릿이다. 모델이 쓴 버튼 이름·명령·질문·URL을 실행하지 않는다. INFO 로그에는 후보 수와 지연만 남긴다.
- 준비/프로필 조회는 이해 시점의 스냅샷이다. 사용자 확인 뒤 실제 실행은 기존 서버의 현재 준비·승인·중복 요청 검사를 다시 받는다. ‘이해됨’이 실제 수행 성공을 보증하지 않는다.

## 검증 기록

백엔드 새 테스트는 기능 모듈을 저장소 밖에 잠시 옮기고 새 라우터 포함을 제거했을 때 28개 경우 모두 실패(모듈 부재)함을 확인한 뒤 복원했다. 기존 LLM 시퀀스 테스트는 그대로 보존한다. 최종 전체 시험 수는 커밋 전 실행 로그를 기준으로 보고한다.

최종 백엔드 전체: 4,020 통과, 기존 조건부 건너뜀 18, 의존성 경고 2. 새 테스트 28건은 모두 통과했다. 캐시 플러그인을 끄고 저장소 밖 ASCII 임시 경로로 실행했다. 새 파일을 추적 목록에 넣은 뒤 저장소 가드·문서 링크·전체 경로 인증 12건도 통과했다. 실보드 LLM의 정확도·지연이나 가전 실행은 이 시험의 증거가 아니다.
