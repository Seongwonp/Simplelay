# devlog 2026-10-19 — 처음 쓰는 사람 기준 다듬기·검토 결함 수리·같은 커밋 배포

**사용자 결정(10/19):** 새 기능은 더 넣지 않는다. 있는 기능(말하기·작동·기기 추가·루틴)을 처음 쓰는 사람이 막히지 않게 다듬는 일만 한다.
일은 세 갈래로 나눠 진행했다. 이 세션은 나누기·합치기·보드 배포를 맡았고, 두 번째 계정의 로컬 세션은 화면과 문서를, 원격 세션은 서버 검토와 수리를 맡았다(병행 규칙은 [병행 작업 인계](../인계-2026-10-19-병행-작업.md)).

## 1. 화면

- **가전 타일(폰·키오스크 같은 규칙):** 상태 글자 띠를 없애고 아이콘과 이름만 남겼다. 켜짐·작동 중이면 밝게, 꺼짐·쉬는 중이면 흐리게 보인다. 문제가 있을 때만 작은 '!'·'?'·설정 아이콘이 붙고, 누르면 말풍선으로 설명한다.
- **못 알아들은 음성(폰):** 본체가 준 '혹시 이것인가요?' 후보와 할 수 있는 일을 버튼으로 보여 준다. 골라도 바로 실행하지 않고 '이대로 실행할까요?'부터 묻는다. 옛 본체에는 종전 안내가 그대로 나온다.
- **실행 화면:**
  - 폰에 실제 버튼 이름이 나온다. 이름을 끝내 받지 못한 칸만 'N번째 버튼'으로 남는다.
  - 키오스크는 '눌렀어요, 확인 중이에요'를 마지막 버튼 뒤에만 보여 준다. 그 전에는 '누르고 있어요'다.
  - LG 가전을 보내는 중의 정지 안내는 '정지를 누르면 더 보내지 않아요. 이미 보낸 것은 되돌리지 못할 수 있어요'로 바꿨다(문구).
- **건너뛴 다음 루틴:** 한 번만 말한다. 아래에는 작은 회색 굵은 '되돌리기'만 남겼다.
- **누름 장치 끊김 표시:** 끊김 칩의 가전 수와 '쓸 수 없어요' 표시는 누름 장치가 실제로 누르는 가전만 센다.

## 2. 음성 해석(본체 안 규칙 계층)

처리 순서는 이렇다.

1. 정지어를 먼저 본다.
2. 말을 다듬는다(띄어쓰기·끝맺음).
3. 같은 뜻 사전에서 찾는다.
4. 없으면 자모 거리로 후보를 고른다. 점수 0.8 이상이고 둘째 후보와 0.1 이상 차이 날 때만 후보로 낸다. 반대말·부정은 후보에서 빼고, 후보는 실행하지 않는다.

못 알아들으면 422 응답에 후보와 동작 목록을 함께 싣는다. 시험 문장 모음에서 잘못 맞춘 것은 0건이다.
기기 내장 대화형 에이전트는 실측해 보니 클라우드에 기대고 응답이 없어, 결선 경로에서 끈다. 이 판단은 [추론 경계](../inference-boundary.md)에 적었다.

## 3. 사람이 '확인함'을 본체에 저장(/acks)과 검토 결함 수리

- **새 기능:** 확인한 알림과 실행 답을 본체에 저장한다. 폰과 키오스크가 같은 확인 상태를 보게 하려는 것이다.
- **검토 결함:** 원격 검토에서 12건이 나왔다(높음 2건, 중간 2건). 고친 것은 이렇다.
  - 대상 가전 없이 들어온 실행도 누름 장치 대상 판정을 거친다. 내장 갠트리 가전으로 풀어 보고, 목록에 없으면 412로 거절한다.
  - 한 실행에 답하면 그 실행만 바뀐다. 다른 실패 알림은 그대로 남는다.
  - 확인은 화면에 실제로 보인 데까지만 적는다. 폰은 가장 새 실패 번호(`failures_seen_id`)와 화면에 보인 실행 목록을 보내고, 키오스크는 화면의 그 실행 하나만 적는다.
  - 확인 기준을 시각 대신 알림 번호로 바꿨다. RPi5에는 시계 배터리가 없어 시각이 뒤로 갈 수 있는데, 그래도 새 실패가 숨지 않는다.
  - 단계 실행 번호(`기본-N`)로 답하면 기본 번호도 함께 확인된다.
  - 루틴 건너뛰기와 회차 표시 저장은 한 저장 잠금 안에서 한다.
- **남은 것:** 검토 결함 중 낮음 등급 6건(#5·#6·#7·#9·#11·#12)은 아직 고치지 않았다. 폰 실행 답 경고, 단계 실행 방식 덮어쓰기, ThinQ 전원 응답 방식 등이다.

## 4. 배포와 시험

- **배포:** RPi5·RPi4 백엔드, 키오스크, 폰(에뮬레이터)에 같은 커밋 `d23506da`를 올렸다.
  - 되돌리기 태그는 `simplelay-backend:1019b`다.
  - 배포 뒤 `/health/detail`에서 `ok`, `actuator_ready`, `act_mode=uart`를 확인했다.
- **시험(골든 제외):**
  - 백엔드+rpi4 3,689개 통과. `d23506da`보다 앞 단계의 서버 코드에서 돌렸고, 그 뒤 커밋은 폰·키오스크만 바꿨다.
  - 폰 1,266개, 키오스크 1,164개 통과.
  - 골든은 폰 69장, 키오스크 83장이 갱신 없이 맞는다. 키오스크 골든 6장은 화면 수정 때 갱신했고 한 장씩 눈으로 확인했다.
- **시연 데이터 정리(사용자 승인):** 미설정 '세탁기'와 '인터폰'을 지웠다. DB 백업은 `simplelay-backup-2026-10-19-before-demo-cleanup.db`다. 연습 세탁기는 10/20 촬영 대본(장면 F)이 쓰므로 남겼다.

## 5. 별도 내부 검토(이전 점수를 제공하지 않은 AI 도구 세션)

| 기준 | 점수 | 수상권 |
|---|---|---|
| 하드웨어가 설계대로 된다고 가정 | 78 | 동상, 은상 문턱 |
| 현재 실물 기준 | 60 | 수상권 밖 |

- **두 평가가 같이 꼽은 약점:**
  - 실물 누름과 가열 감지가 실제로 돈 적이 없다.
  - 활용성 숫자(원가·설치 시간·팀 밖 사용자 점검)가 비어 있다.
  - 함께 쓰는 하드웨어와 새로 만든 하드웨어의 구분이 약하다.
  - 문서가 길고 내부 용어가 많다.
  - 시연 화면에 미완성 흔적이 보인다.
- **후속:** 문서를 한 흐름으로 재구성하는 일은 두 번째 계정 세션에 맡겼다.

## 6. 다음에 정할 것

- **개발자 모드를 끄면 내장 가전(전자레인지·인덕션)이 '내 가전' 목록에서 숨는다**(`builtin_appliances_visible`, UI 확정 §1-6). 결선 전에는 `SIMPLELAY_DEV_MODE`를 끄기로 했는데, 그러면 시연할 전자레인지 타일이 사라진다. 둘 중 하나를 정해야 한다.
  - 시연에서 '가전 추가'로 전자레인지를 등록한다(기기 추가 흐름 시연을 겸함).
  - 목록 규칙을 조정한다.
- 연습 세탁기는 촬영 뒤 숨길지 정한다.
- **루틴 시각을 바꾸면 자동 실행 허용이 풀린다.** 허용 지문에 시각이 들어 있어서다. 촬영 대본 장면 A처럼 시각을 바꿨다면 폰에서 한 번 다시 허용해야 한다.
