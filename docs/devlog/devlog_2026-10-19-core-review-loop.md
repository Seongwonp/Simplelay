# devlog 2026-10-19 오후 — 핵심 로직 검토·수리 반복, 발표 준비

**목표(사용자):** 오늘 중요 로직은 완벽하게. 새 기능 없이 다듬기만.
**검토 방법:** AI 도구(Codex)의 읽기 전용 검토와 계획을 바탕으로 별도 로컬·원격 세션에서 수정했다. 통합 세션은 합치기와 보드 배포를 맡았다. 아래 참고 점수·수상 전망은 공식 심사 결과가 아니며, 시험·배포 사실과 구분한다.

- **수리 원칙:** 검토 지적은 모두 고치기 전에 시험으로 재현했다(실패 먼저). 재현되지 않은 것은 건너뛰었다.
- **합치기:** 원격 세션의 수리는 브랜치로 받아 main에 체리픽했다. 브랜치 삭제는 사용자가 마지막에 한다.

**첫 사용 관점의 과업 경로 검토(AI 도구 사용):** 기기 추가·연결·조용한 시간·음성·자동 실행 허락 문구를 다듬었다. 실제 사용자 시험은 아니다. 아래는 고치지 않았다.

- **새 기능이라 뺀 것:** 화면 읽기로 사진 위 귀퉁이를 고르는 입력, 키오스크에서 여러 버튼을 한 번에 고르는 판. 키오스크에는 대신 '루틴으로 한 번에' 안내를 넣었다.
- **사용자 결정을 따른 것:** '기록 보기'를 열면 본 것으로 치는 동작은 오늘 아침 결정대로 그대로 둔다.

## 2. 실보드

- **배포:** RPi5·RPi4·키오스크·폰을 여러 번 같은 커밋으로 맞췄다. 되돌리기 태그는 `simplelay-backend:1019b`~`1019e`다.
- **점검(모션 모의):** 승인 → RPi4 실행 → 결과까지 정상이다. 실행 중 정지는 확인하지 못했다. 모의 누름이 0.3 s 안에 끝나서 정지가 닿기 전에 실행이 끝난다(하드웨어 필요).
- **주의:** 점검용 `/stop`이 설계대로 자동 실행 규칙을 끈다('비상정지로 자동으로 하기를 껐어요'). 꺼진 공기청정기 시각 규칙 두 개(22:00 켜기·07:00 끄기)는 다시 허용했고, 오늘 밤 건너뛰기는 유지했다. **실보드 점검에서 `/stop`을 쓰면 자동 규칙 상태를 꼭 확인한다.**
- **데이터 정리(사용자 승인):** 연습 세탁기를 env에서 끄고(백업 `env.bak-20261019-remove-practice`), 시험용 TestOven을 지웠다. 지운 세탁기·인터폰에 묶인 루틴 세 개도 지웠다(DB 백업 `simplelay-backup-2026-10-19-before-routine-cleanup.db`).

## 7. 밤 추가분

**검토 6·7바퀴(회귀·시연 위험).** 수리끼리 부딪쳐 생긴 문제를 고쳤다.
- 늦은 응답이 새 실행을 덮던 것, 다시 확인할 때 남의 실행을 잡던 것, 중복 누름 잠금, 페어링 멈춤, 방해 금지 요청 실패를 성공처럼 보이던 것.
- 서버: 승인+자동 허락에도 요청 번호 멱등.
- 7바퀴: 여러 단계 루틴을 첫 구간 끝에서 '완료'로 보이던 것 — `GET /jobs/{root}`가 루틴 전체 수명을 나타내고, `/status`에 `routine_run_id`·`routine_segment`를 싣는다. 폰·키오스크는 중간에 넘겨받아도 루틴 끝까지 '실행 중'. 페어링 키 재수령(`POST /pair/ack`), LG 직접 조작 요청 번호.

**문구(사용자 결정).**
- '잠시 쉬기' → '방해 금지'. 범위 부제는 항상 보이게 하고, 키오스크는 메뉴 한 곳에만 둔다.
- 토스·삼성·KRDS를 조사해 [UX 문구 기준](../UX-문구-기준-2026-10-19.md)을 만들고, 번역투 약 120줄을 고쳤다.
- 상태 표시는 명사형(완료·실패·멈춤·연결됨·끝남), '됐어요'·'못 써요' 같은 줄인 말끝은 쓰지 않는다(R12).
- 키오스크 도움말을 처음 쓰는 어르신 기준으로 다시 썼다.
