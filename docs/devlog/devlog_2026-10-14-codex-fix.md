# 2026-10-14 데스크톱 — 재평가 수리 마무리(승인 카드 회귀·정지 문장·실제/연습 모름 표시), 배포·흐름 확인

10/15 기능 동결 전에 미커밋 수리만 마쳤다. 탭바 변경과 쉬기 통합(M 항목 3개)은 시작하지 않았다. 시험 데이터도 그대로 두었다.

## 커밋

| 커밋 | 내용 |
|---|---|
| `b5f5c2c` | **키오스크 승인 카드** — 버튼 누름 단계에서 잘못 붙던 '경로 확인 필요' 칩을 없앴다. 경로를 정말 모를 때만 경고한다. 직접 실행한 루틴은 근거 줄을 숨기고, 자동 제안은 근거를 그대로 보인다. 목록 제목은 버튼만 있으면 '누를 버튼', 아니면 '할 일'이다. 완료 문구 두 개는 확신 수준을 올리지 않는 말로 바꿨다 |
| `f6c2100` | **폰** — 사용자 화면의 정지 문장에서 ms를 뺐다(개발자 도구에만 남김). '실행 환경 미확인' 띠는 실행 상태 화면에서 생략한다. 대신 기록과 단계 결과에는 '실제 기기 동작 여부를 확인하지 못했어요'를 남긴다. 연습 표시는 그대로다. 옛 계약(모름이면 줄 없음)을 고정하던 시험은 새 계약으로 고쳤다 |

## 시험

- 새 시험이 수정 전 코드에서 실패하는 것을 먼저 확인했다(키오스크 2건, 폰 7건).
- 키오스크: **312 통과**(골든 제외). 골든 3장은 렌더를 눈으로 보고 갱신했고, 재비교 **44 통과**.
- 폰: **787 통과**(골든 제외). 골든 13장은 렌더를 눈으로 보고 갱신했고, 재비교 **55 통과**.
- analyze: 두 앱 모두 error·warning 0.
- 백엔드는 바뀌지 않아 다시 돌리지 않았다.

## 배포 (바뀐 것만)

- 키오스크 ipk: `f6c2100`, RPi5 실패널 `arc install` 성공. 빌드 컨테이너가 다시 쓴 `pubspec.lock`은 되돌렸다.
- 폰 APK: `f6c2100`, 에뮬레이터(x86_64, split-per-abi)에 설치.
- RPi5 백엔드는 다시 배포하지 않았다. RPi4는 재부팅 뒤 docker를 켜고 실행기만 다시 띄웠다(같은 이미지).

## 미검증

- **키오스크 승인 카드(직접 실행 루틴)는 실패널에서 보지 못했다.** API로 루틴을 실행해 카드를 만들었지만, 키오스크가 직전 실패 화면에 40초 넘게 머물러 새 카드를 띄우지 않았다. 판단 근거는 위젯 시험과 골든뿐이다.
  - **[발견, 중간]** 결과 화면이 사람이 '닫기'를 누를 때까지 남아 있어, 그동안 들어온 승인 카드를 놓친다. 10/13 발견 3의 남은 부분이다. 동결 뒤 결함 수리로 다룬다.
  - 위 시험으로 만든 '아침 데우기' 승인 카드가 서버에 남아 있다(시험 데이터와 함께 정리 대기).
- 성공 결과의 완료 문구('끝났다는 보고를 받았어요' 등)는 실물에서 보지 못했다. 원점이 없어 실행이 처음부터 멈췄다.
- 실제/연습 모름 기록 줄은 실물 기록에 없어(오늘 실행은 실제 모드) 시험·골든으로만 확인했다.
- 실폰, TalkBack 제스처 낭독.
- 에뮬레이터 시간대가 UTC로 돌아가 있었다(기록 시각 02:35). 앱 결함이 아니라 에뮬레이터 설정이다.
