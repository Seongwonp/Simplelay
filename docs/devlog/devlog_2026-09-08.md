## 코드 검토 HIGH 6건 반영 — 실행 확인·중단·실패 복구

리뷰의 핵심 진단은 *"기능 수에 비해 실행 확인·중단·실패 회복 경험이 약하다"* 였다.
아키텍처 문제나 재작성 제안은 한 건도 없었고, 대부분 **이미 있는 데이터를 화면에
연결**하거나 **확인 단계를 하나 넣는** 작업이었다. 6건 모두 반영했다.

### #4 폐루프 증거를 실행 화면까지 (커밋 5ae70e0)
서버는 current_button·total_steps·verification_*을 보내는데 앱에서 끊겨 화면에
도달하지 못했다(모델·provider에 필드 자체가 없음). 그 결과 이 제품의 차별점이
가장 중요한 경로에서 "빙글빙글 돌다 완료되는 앱"으로 보였다. 키오스크는 이미
같은 정보를 보여주고 있어 그 구현을 기준으로 맞췄다.
- "'1분 추가' 버튼을 누르고 있어요." + 검증 근거(센서 93%) 표시
- 진행을 total_steps 기준으로 → 음성 실행처럼 미리보기가 없어도 보인다
- 원시 mA/dB가 없는 HTTP 경로에선 빈 센서 차트를 숨김
- 완료 문구 "실행 완료" → **"버튼 조작을 마쳤어요."** (조리가 끝난 뜻이 아니다)

### #2 음성 실행 경계 (커밋 27d03b2)
5초 침묵이 곧바로 실행이었다. 물리 버튼을 대신 누르는 기기에서 되돌릴 수 없는
동작이고, 오인식을 고칠 자리도 없었다. 침묵은 **듣기 종료**로만 처리하고 실행은
사용자가 고른다(이대로 실행 / 다시 말하기 / 취소).
- 탭을 떠나도 마이크가 살아 있던 버그: 탭은 StatefulShellBranch라 dispose로
  안 잡힌다 → shell이 "보이는 탭"을 알리고 화면이 스스로 정리(앱 백그라운드 포함)
- 전송 재진입 잠금(연타·중복 경로가 같은 명령을 두 번 실행하던 것)
- 응답 유실(timeout)을 '미접수'로 단정하고 BLE 재전송하던 동작 제거 —
  연결 자체가 안 된 실패는 기존대로 폴백(오프라인 동작 유지)

### #1 정지 동선 보존 (커밋 61c929e)
통신이 끊기면 failed로 뭉개고 추적 대상까지 지워, 정지 버튼이 사라지고
emergencyStop이 HTTP 경로를 잃었다. **통신 실패는 물리 동작의 종료가 아니다.**
- ExecutionPhase.unknown 신설(실패가 아니라 '모름') + 대상 유지로 정지·재확인 가능
- 정지 버튼을 스크롤 밖 **하단 고정**으로
- 수동 조작 실행도 공용 실행 상태에 등록(뒤로 나가면 멈출 방법이 없었다)
- 늦게 온 BLE 센서가 종료된 실행을 되살리던 문제 수정

### #3 제안과 실행 대상 가전 결합 (커밋 96fc3d6)
제안에 대상 가전이 없어 화면은 전역 선택으로 지도를 그리고 승인은 purpose만
넘겼다(오늘 넣은 에어컨 제안으로 드러남). appliance_id를 제안에 싣고 승인 실행까지
연결했다. 화면 상단에 대상 가전명을 먼저 보여준다.
남은 한계: 사용 이력에 가전이 없어 패턴 제안은 대상을 모른다(선택 가전으로 폴백).

### #5 글자 200% 접근성 (커밋 16fe033)
390x844·200%에서 **실제로 넘쳤다**. 먼저 재현 테스트를 만들고 고쳤다.
- 첫 실행 안내 423px / 음성 화면 182px: 본문 스크롤 + 주요 행동 하단 고정
- 재시도 배너 가로 53px: 줄바꿈 공간
- 가전 선택 칩: Semantics(selected:) 노출 + 최소 높이 48
- 기준 정정: WCAG 2.2 AA 하한은 24 CSS px, 44가 AAA. 48은 **우리 목표치**다.

### #6 두 조작 경로를 항상 보이게 (커밋 1b3211a)
주 행동이 하나만 떠서, 말이 안 되는 사용자에게 다른 길이 없었다. 보조 행동으로
다른 경로를 같은 자리에 두고, 쓸 수 없으면 이유를 붙인다.
