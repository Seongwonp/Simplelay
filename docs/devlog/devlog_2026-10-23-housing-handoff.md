# 2026-10-23 — 노트북 인계: 하우징 선출력·DHT22·모션 현재 상태

1. 최신 main을 받고 이 문서와 [통합 재설계 실행계획](../통합-재설계-실행계획-2026-10-23.md)을 읽는다.
2. 업체 견적 답변을 확인한다. **문의만 남긴 상태이며 주문·결제·출력 완료가 아니다.** 업체에 자동으로 추가 문의나 파일 업로드를 하지 않는다.
3. 하우징 남은 설계는 RPi5 정품 케이스용 고정대·뒤판, 모니터 클립 맞춤, 핀 공차다. 이번 왼쪽 선출력으로 케이블·모니터 맞춤부터 확인한다.
4. 모션은 HW 원본 유지 원칙을 따른다. 운영 어댑터 미배포 상태를 실제 배포 완료로 오해하지 않는다. 모터를 임의로 움직이거나 펌웨어를 올리지 않는다.

## 1. 업체 견적 문의와 전달 파일

- 사용자 직접 [굿쓰리디](https://good3d.co.kr/contact/contact.php)에 문의 완료. 첨부는 `SimpleLay_vendor_first_print_R2.zip`이다. 저장소 ZIP 금지 규칙을 유지하므로 압축 전 [전달 파일 폴더](../../housing/print-order-r2/README.md)와 [재생성 스크립트](../../housing/pack-vendor-r2.ps1)를 올린다. 노트북에서 저장소 루트 기준 `powershell -ExecutionPolicy Bypass -File housing/pack-vendor-r2.ps1`을 실행하면 같은 파일 구성을 묶는다(압축 바이트 해시까지 같다는 뜻은 아니다).
- 의뢰 내용: `01_left_shell_r2.stl` 1개 + `02_panel_clip.stl` 1개. 도색 없는 조립 확인용, 100% 배율, 임의 축소·분할 금지. 재료·가격·서포트·납기·배송비는 업체 답변 대기다.
- 상세는 [출력 안내](../../housing/print-order-r2/README.md). ZIP에는 직접 만든 STL·SCAD·렌더·안내문만 있으며 사용자 사진·제품 일련번호·비공개 자료는 넣지 않았다.

## 2. R2 하우징 변경

- 모니터 크기·두께는 사용자 실물 확인으로 맞는다. 해당 치수는 유지했다.
- 왼쪽 포트 여유 총20→60mm(+40), 전체 폭396→436mm.
- 왼쪽 아래 클립 받침은 패널 아래 기준35→105mm(+70). 왼쪽 위190mm·오른쪽 받침 위치는 유지.
- 기존 위·아래 이음에 걸치지 않게 **왼쪽 절반 통짜**로 선출력. 실제 크기218×170×260.225mm. 소형 시험편이나 완성 상자 전체가 아니다.
- 최종 몸통은 좌·우2조각 방식. 불필요한 몸통 가로 이음 덧살·핀을 제거했고 뒤판4분할은 유지한다. 기존 폭396 부품과 호환되지 않는다. 나머지 부품도 R2로 생성해야 한다.
- [R2 설정 원본](../../housing/vendor-first-print-2026-10-23.scad)은 [기본 원본](../../housing/simplelay_box.scad)을 포함한다. 기존 `housing/stl/shell_*`는 구형 STL이며 R2 전체 출력 묶음으로 사용하면 안 된다.
- 모니터 뒤 고정은 별도 클립이다. ZIP에는 클립 STL이 포함돼 있다. 견적 의뢰는 시험용1개, 최종 전체 수량은4개다. 실제 패널 뒤 두께에 따른 클립 턱·폼 보정은 미검증이다.
- 구멍Ø4/핀Ø3.8은 아직 실물 방향별 끼움 차이가 남아 있다. [공차 시험편](../../housing/stl/dowel_calibration.stl)을 추가했으나 이번 업체 ZIP에는 넣지 않았다. 이를 해결됐다고 보고하지 않는다.

### CAD 검증

- 왼쪽 통짜 OpenSCAD 렌더 성공, Simple=yes, 고체1개. 메시5488삼각형, 모서리 공유 수가2가 아닌 경우0.
- 패널 몸체와 고정 받침 사이 교집합 비어 있음. 의도된 지지 턱은 제외했다. 실제 플러그 모델이 없어 케이블 간섭까지 증명한 검사는 아니다.
- 기존 기본 맞춤 시험편을 다시 렌더해 기존 STL과 정점 집합 동일 확인.
- 업체 전달 STL과 검증 STL 해시 동일. 미리보기 내부 형상 확인.
- 실물 선출력·모니터 체결·케이블 삽입·열 시험은 아직 미검증이다.

## 3. RPi5 정품 케이스

사진에서 정품 팬 내장 케이스임을 확인했다. 포장지12×17×4mm는 방열판 치수다.

[공식 제품 자료 5쪽](https://datasheets.raspberrypi.com/case/case-for-raspberry-pi-5-product-brief.pdf): 케이스 외형 약98.5×70.3×33mm. 제조사도 참고 치수이며 생산 도면으로 쓰지 말라고 명시한다. 케이스를 씌운 상태를 고려한 여유·통풍·커넥터·GPIO 접근이 필요하다. 기존 뒤판은 보드 직접 고정 방식이므로 그대로 체결 완료로 간주하지 않는다. **케이스용 뒤판·고정대는 아직 만들지 않았다.** 왼쪽 선출력 ZIP을 케이스 장착까지 완료한 전체 모델로 설명하지 않는다.

## 4. 온습도 배선·기기 설정

- RPi5 DHT22: VCC→물리1(3.3V), DAT→물리7(GPIO4), GND→물리9.
- 최초 안내 때 코드 기본값GPIO4만 보고 실제 배포값GPIO17을 확인하지 않아 센서가 안 나왔다. 기기 env를 백업하고 `SIMPLELAY_DHT22_GPIO=4`로 수정했다. 다른 GPIO·원점 설정은 바꾸지 않았다.
- 같은 백엔드 이미지로 정상 재시작, `/sensors` 두 번에서24.2°C·50.1%, `mocked=false` 확인. 센서 라이브러리는 lgpio, GPIO chip0, 센서만 활성화 상태다.
- 설정은 기기 안에 영속 저장돼 재부팅 뒤에도 유지된다. 접속 주소·인증키·전체 env는 공개 로그에 넣지 않는다.

## 5. 모션·인계 상태

- [모션 상세 로그](devlog_2026-10-23-touchbridge-host.md), [RPi4 인계 문서](../RPi4-하드웨어-인계-2026-10-23.md), 통합 계획을 함께 읽는다.
- 콘솔 설치·상태 조회 완료. 새TouchBridge v2 어댑터 구현·시험 완료. **운영 실행기에는 아직 배포하지 않았다.** 실제 좌표 이동·Bot 누름은 미검증이다.
- 사용자는 RPi4를 다시 받아 보유하고, HW 담당자에게 ESP32만 맡기는 방향으로 변경했다. 향후 CT 작업에도 RPi4가 필요하다.
- 담당자가 확정한 전체 펌웨어 묶음과 시험 결과를 받은 뒤 P2개발자 조작→수동 재방문→사진 매핑 순서로 이어간다. HW 소스 수정·재업로드 금지.

## 6. 종료·시험 범위

- 사용자 요청으로 RPi5 정상 종료 명령 전달 성공. 화면 분리·하우징 확인 중이며 임의 재가동하지 않는다.
- 마지막 요청으로 RPi4에도 저장 완료·정상 종료 명령 전달 성공. 전원 제거 여부는 사용자 현장 확인 사항이다.
- 에뮬레이터는 종료 명령에 `OK: killing emulator, bye bye`로 응답했다.
- 인계 직전 콘솔·새 어댑터·링크·개발자 서비스 관련66시험 통과. 이전 모션 로그의125시험과 별도 실행이며 합산하지 않는다.
- 폰 개발자 화면 기존 WIP 관련35시험 통과. 홈 버튼 제거·상태/센서 유지 등 변경이며 개발자 모드 전체 재설계 완료가 아니다. Flutter 전체·골든은 이번에 실행하지 않았다.
- Flutter analyze는 error·warning0, 기존 info4건이다. info 때문에 명령 종료값은1이므로 이를 오류 없이 종료값0인 실행으로 보고하지 않는다.
- 공개 저장소 가드·문서 링크8시험 통과. 최초에는 업체 ZIP 추적이 금지 확장자 검사에 걸려 제외했고, 검사 규칙은 변경하지 않았다.
- 비공개 문서·사용자 원본 사진·실기기 env·장치별 식별값·배포 tar·임시 시험 디렉터리는 Git에 넣지 않는다.
