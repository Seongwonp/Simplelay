# 2026-10-26 — 맡기기 신뢰 강화: 되돌리기·사람 없으면 미루기·연속 거절·무반응 7일 쉬기

[고도화 계획](../고도화-계획-2026-10-26.md) §3의 1·2·4번. 모두 **시험 조건(모의 ThinQ·가짜 시계)** 에서만 확인했다 — 보드 배포·실가전 확인 전.

## 1. 자동 실행 뒤 5분 '되돌리기'

- **무엇:** 맡긴 일(자동 실행 규칙)이 알아서 끝나면 결과 알림이 5분 동안 '되돌리기'를 보인다 — 키오스크 결과 한 줄(평소 12초 대신 되돌릴 수 있는 동안 남는다), 폰은 루틴 탭 자동 실행 줄의 '최근 결과' 아래.
- **누르면:** 먼저 그 규칙을 끈다(꺼짐 사유 "되돌리기를 눌러 자동 실행을 껐어요. 이 일은 다시 물어볼게요."). 루틴은 그대로라 다음 회차는 카드로 다시 묻는다. 그다음 반대 동작이 분명할 때만 보통 승인 실행 경로(`submit_approved` — 실행 잠금·비상정지·정지 세대)로 보낸다.
  - 전원: 켜기 ↔ 끄기.
  - 바람 세기·모드: 실행기가 보내기 전 조회로 **본** 원래 값(`CommandResult.before_value` → 완료 이벤트 → 기록)이 있을 때만. 모르면 끄기만.
  - 이미 그 값이라 보내지 않은 실행(`already_at_target`)·비상정지 걸림·가전이 바뀜이면 보내지 않고 끄기만. 화면 문장은 서버가 준다("되돌리고, 이 일은 다시 물어볼게요." 등).
  - 되돌리는 실행은 사용 기록(습관 학습)에 넣지 않는다 — '밤에 끄기' 습관이 생기지 않게.
- **API:** `POST /routines/auto-runs/{run_id}/undo`(5분 지남·이미 되돌림 409, 없음 404). `/status`의 `last_auto_run`과 `GET /routines/auto-rules/runs`·규칙 `last_run`에 `run_id`·`undo_until`·`undo_remaining_s`(본체 시계로 잰 남은 초 — 화면은 자기 시계 대신 이것으로 센다)·`undone`.
- **조용한 시간:** 되돌리기는 사람이 누른 일이라 직접 조작과 같이 조용한 시간에 막지 않는다(자동 실행 자체는 조용한 시간에 일어나지 않는다).
- 가열·누름 가전은 자동 실행 대상이 아니므로 되돌리기도 없다.

## 2. 사람 없으면 미루기

- 묻는 때(평소 시각 10분 전)에 사람 감지가 '없음'이면 그 습관을 기억해 두고, 평소 시각 +30분 안에 사람이 오면 **한 번** 묻는다(`rpi/intent/suggestions.py` `_absent_due`). 그 카드를 자리를 비워 거둔 뒤 다시 와도 그날은 다시 묻지 않는다.
- +30분이 지나면 그날은 건너뛴다 — 카드를 만들지 않으니 거절·무반응으로 세지 않는다. 기억은 메모리만(재시작하면 평소 묻는 시간대 규칙).
- 감지기가 없거나 꺼져 있으면(모름) 종전과 같다.

## 3. 연속 거절·무반응 → 7일 쉬기

- 예전: 이틀 연속 거절 → 3일 쉼, 무시 두 번 → 다음 물을 날 하루 건너뜀. 이제 하나로: 거절 또는 답 없이 지나간 카드가 **물은 차례로 연달아 두 번**이면 두 번째 응답 시각부터 7일 쉰다(`habit_timing.rest_pause`, `REST_DAYS = 7`). '이미 했어요'·예·나중에는 이어짐을 끊는다. 쉬기를 만든 두 응답은 다시 세지 않는다.
- 평일 습관은 평일만 물으므로 '연달아'는 달력 날짜가 아니라 물은 차례다(금요일 거절 → 월요일 거절도 이어짐).
- 상황 카드(공기질 등, 질문 문장 기준)의 '무시 두 번이면 다음 날 하루 건너뜀'은 그대로다.
- 문서의 '3일 쉼' 문장을 고쳤다: README, 작품소개서 초안, 발표 대본·슬라이드 구성·근거 자료, 시연 계획 v4, 질의응답 대비, 노트북 인계. 지난 devlog는 기록이라 두었다.
