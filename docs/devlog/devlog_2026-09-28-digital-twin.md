# 2026-09-28 — 브라우저 디지털 트윈(개념 모션) 화면

> **개념 모션 · 실제 동역학 아님.** 이 화면은 모의 실행기(`SimulatorController`)가 기록한 누름을 따라 CoreXY 캐리지를 그려 줄 뿐이다. 실제 모터·센서·벨트·속도를 재현하거나 검증하지 않는다. 커밋·푸시는 하지 않았다.

## 무엇을 보여 주나

`GET /simulator/twin` — 이전 팀 프로젝트(TouchBridge 시뮬레이션)의 **표현 방식**(가전 본체 + 조작부 버튼판 + XY 레일 + 캐리지 + 누를 때 초록으로 바뀌는 누름봉 + 단계 목록 + 기록 + 확인/취소)을 빌려, 이 저장소의 바닐라 HTML/SVG로 다시 만들었다. React·npm은 쓰지 않았다.

- **가전과 버튼맵**: `GET /appliances`의 버튼맵을 그대로 그린다. 내장 전자레인지는 편집기 격자 칸(`x`,`y`, `rows`·`cols`)만 있고 mm 좌표가 없으므로 화면에 "편집기 격자 칸 배치 · 실제 mm 좌표 아님(보정 전)"이라고 적는다. 모든 버튼에 `x_mm`·`y_mm`가 있을 때만 mm를 정규화해 쓰고, 좌표가 전혀 없으면 "임시 배치"로 표시한다.
- **CoreXY**: 모터 A/B는 프레임 아래에 고정. 이번 이동의 ΔA/ΔB와 원점 기준 누적 A/B를 숫자로 보인다(ΔA=ΔX+ΔY, ΔB=ΔX−ΔY, 조작부 범위 0~1 상대 단위). 벨트 경로·모터 회전 각도는 정지·보관 화면과 같은 개념도다.
- **Z 누름 모터**: 이동 → Z 누름 → Z 복귀를 버튼마다 반복한다. 옆 Z 막대는 가상의 전체 스트로크다.
- **원점 복귀**: 새 실행을 볼 때마다 Z를 먼저 올리고 원점(0,0)으로 가는 개념 모션부터 재생한다. **서버가 원점 복귀를 보고한 것이 아니다.**
- **정지**: 화면의 정지 버튼은 캐리지를 그 자리에 즉시 고정하고 기존 `POST /stop`을 부른다. 다른 창에서 보낸 중단(abort 프레임)을 봐도 고정한다. 이미 기록된 누름은 기록 창에 남는다.
- **실행 환경**: `/status`의 `execution_mode`(끝난 뒤에는 `last_execution_mode`)와 통신 방식(`in_memory`)을 위에 표시한다.

## 무엇을 주장하지 않나

- **결과를 만들지 않는다.** 애니메이션이 끝나도 성공·실패가 생기지 않는다. 결과는 RPi4 → RPi5 `result` 프레임(`success`, `retry`)이 있을 때만 적는다. 현행 통신은 시퀀스 전체의 성공 여부 하나뿐이라 **버튼별 성공은 표시하지 않고** 버튼별 "누름 기록 N회(재시도 포함)"만 적는다.
- 누름 기록은 모의 실행기 내부 관측(`act_local.presses`)이다. 허브가 받은 결과와 다른 층의 근거다.
- 같은 이름이 연달아 오는 시퀀스(예: 10초 → 10초)는 재시도와 다음 단계를 구분할 근거가 없어 "구분 불가"로 표시한다.
- 모션은 기록을 뒤따라 재생하므로 서버 보고가 먼저 도착할 수 있다. 재생 시간은 화면 속도이며 장치 속도·정지 지연이 아니다.
- 정지 요청이 마지막 버튼 뒤에 도착하면 서버는 성공을 보고할 수 있다(실제로 확인). 화면은 서버 보고를 그대로 적는다.
- 정지 버튼 대기·가전 종료 확인·보관 이동은 [정지·보관 모의 동작](../archive/정지-보관-모의동작-2026-09-27.md) 화면이 담당한다. 이 화면은 그 상태 기계를 복제하지 않고 링크만 둔다.

## 미리보기 모드

"미리보기(서버 호출 없음)"를 고르면 선택한 시퀀스(가전 버튼맵에 있는 이름만)를 원점 복귀부터 재생한다. `/execute-buttons`를 부르지 않고 결과도 만들지 않으며, 화면에 "미리보기 · 서버 실행 아님"이라고 크게 표시한다. 미리보기 중에 서버에서 모의 실행이 시작되면 실행 따라가기로 자동 전환한다.

## 실행

```powershell
.venv\Scripts\python.exe -m rpi.simulator_main --port 8765
```

브라우저에서 http://127.0.0.1:8765/simulator/twin. "이 시퀀스로 모의 실행" → 확인 후 시작. 재시도는 `/simulator` 패널의 실패 주입(2회 실패 후 성공 · 3회 실패 안전 중단)으로 확인한다.

## 남은 것

- 실제 mm 좌표·보정 결과가 들어오면 같은 화면이 mm 배치로 바뀌지만, 축척·원점은 여전히 개념이다. 실제 트윈에는 모션 MCU의 위치 보고가 필요하다.
- 통신에 버튼별 결과·진행 이벤트가 없어 모션은 누름 기록 폴링(400ms)에 기댄다.
- 실제 모터 방향·풀리 반경·RPM·Z 스트로크는 하드웨어 실측 후에 정한다.

## 2차 개선 (리뷰 반영)

리뷰 4건과 작은 결함 2건을 고쳤다. 하드웨어 구성은 확정(FIT0482 ×3 — CoreXY A·B + Z 누름, JMOD-MOTOR-1 ×2)이지만 **화면은 여전히 개념 모션**이다. 결과는 계속 서버 result 프레임만 옮겨 적는다.

### 1. 서버와 모션의 동기화

- 서버는 약 0.8초(`step_seconds`)마다 누르는데 화면은 버튼당 1.0~1.3초라 결과가 캐리지보다 먼저 왔다. 이제 **대기열에 남은 버튼 수만큼 이동·누름 시간을 줄인다**(버튼 하나당 +0.6배, 최대 6배). 결과가 이미 도착했는데 모션이 뒤처져 있으면 2배 더 서두른다. 32버튼 연속 시험에서 마지막 누름 뒤 지연이 따라잡기 없음 17.6초 → 약 2.4초로 묶였다(화면 재생 속도일 뿐 장치 속도 아님).
- 결과가 도착했지만 모션이 아직 재생 중이면 최종 판정 대신 **"모션 재생 중 · 서버 결과 도착"**을 보이고, 재생이 끝나면 서버 판정을 보인다. 애니메이션이 결과를 만들지 않는다는 불변식은 그대로다(판정 문구는 순수 함수 `verdictText`, 입력은 서버 상태와 "재생 중" 여부뿐).
- **정지**: Z 중간에서 얼리지 않는다. 대기열을 비우고 Z를 먼저 올린 뒤 **서버가 마지막으로 기록한 누름 위치**로 캐리지를 옮겨 고정하고 기록 창에 남긴다. 정지 뒤에 서버 누름 기록이 더 붙어 위치가 바뀌면 다시 정렬한다.

### 2. CoreXY 벨트 배치

- 벨트를 캐리지 위치로 매 프레임 다시 그린다. 두 벨트 모두 양 끝이 캐리지에 물리고, 갠트리 양 끝 풀리 → 프레임 옆 → 모서리 풀리 → 아래 모서리에 **고정된** 모터 → 아래쪽 → 반대편 옆 → 반대편 갠트리 끝 풀리를 지난다. 모터 A 쪽 벨트 길이 변화는 −(ΔX+ΔY), 모터 B 쪽은 ΔX−ΔY라 식과 맞다(배치 자체는 개념도).
- "A만 회전 / B만 회전" 데모 버튼: ΔB=0이면 ΔX=ΔY로 대각선, ΔA=0이면 반대 대각선으로 간다. 서버 호출 없음.
- 갠트리를 반투명으로 하고 버튼 층 아래에 그려 맨 윗줄 버튼 이름을 가리지 않는다.

### 3. 판정 문구·정지 버튼·재시도 표시

- `success=true`인데 결과 전에 abort 프레임이 있으면 "정지 요청이 늦어 모든 버튼 입력 후 성공 보고"로 적는다.
- 정지 버튼은 서버가 실행 중일 때만(미리보기에서는 재생 중일 때만) 켜진다.
- 재시도 누름 사이에 "검증 불합격 추정 → 재시도 N회째"를 보인다(누름 기록이 늘어난 것으로 앞 검증 실패를 **추정**한 것). `SimulatorController`의 실행기는 재시도 누름마다 **정성 보정 요청**(`xy_adjustment_required`, `increase_press_depth`, 거리 없음)을 `PressCommand.correction`에 싣는다 — 이를 스냅샷 `act_local.press_corrections`로 내보내고 누름 기록마다 붙였다. 거리가 없으므로 화면의 XY 오프셋은 **개념 표시(0.03 상대 단위)**이며 "XY 보정 요청 기록 · 거리 미정(개념)"으로 적는다. 보정 기록이 없으면 "보정 오프셋(개념)".
- 기록 창 순서: 화면 정지 시 "[모션] 캐리지 고정 …"이 "[화면] 정지 요청"보다 먼저 남는다. 폴링 결과도 서버 기록을 먼저, 그로 인한 모션 기록을 뒤에 남긴다.
- 폴링: 서버 실행 중 400ms, 그 밖에는 약 2초.
- 실행 환경: 첫 화면에서 `/status`는 실행 전이라 `execution_mode`·`last_execution_mode`가 모두 `unknown`이다(확인함). 이때는 시뮬레이터가 선언한 `mock`을 "시뮬레이터 선언 · 아직 실행 기록 없음"으로 표시한다.

### 4. 하드웨어 요약·mm 비율

- `GET /simulator/twin/hardware`: `CoreXYConfig.from_env()` 설정 상태 + 보고서 A-1·A-2·D절 공식 사양(6 V, 무부하 310 rpm — **상한 표시용, 타이밍에 쓰지 않음**, 정격 180 rpm, 50:1, 공칭 700 counts/출력축 회전 x1, TB6612 short brake / stop(High-Z), 채널 배정 "보드1 A·B / 보드2 Z+예비" **미확정**). 화면에 공식 사양과 **미설정 항목(환경 변수 이름 포함)**을 나열한다.
- `CoreXYConfig`에 `decoding_multiplier`(1/2/4), `max_rpm`, `stop_mode`('brake'|'coast')를 추가했다. 전부 기본 None이고 `SIMPLELAY_MOTION_DECODING_MULTIPLIER`·`_MAX_RPM`·`_STOP_MODE`로 읽는다. **기존 변환 의미는 그대로**다 — 변환은 여전히 배율 포함 실측 `counts_per_output_rev`만 쓰고, 새 필드는 모션 필수 항목(`missing_for_motion`)에 들어가지 않는다.
- `layoutButtons`: 모든 버튼에 mm 좌표가 있으면 **가로세로 비율을 유지**해(균일 축척, 가운데 정렬, 화면 작업 영역 비율 반영) 배치한다. 격자·임시 배치는 그대로다.

### 작은 결함

- 시뮬레이터 trace 상한 80 → 400, 그리고 마지막 execute 프레임을 따로 고정해(`last_execute_frame`) 긴 재시도에서도 execute 프레임을 잃지 않는다.
- 버튼 찾기는 id 우선, 이름은 대체 수단(`findButton`). 통신은 여전히 이름만 보내므로 서버 추종은 이름으로 찾는다.
