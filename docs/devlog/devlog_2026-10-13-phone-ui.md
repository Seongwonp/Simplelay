### M5 — 실물 모션 + 모의 L3를 "가전 동작도 확인했어요"로 (고침)

- 재현: `operationSentence`가 실행 모드가 mock이 아니면 L3 true를 모두 "가전 동작도 확인했어요"로 말했다. RPi4는 L3 입력의 mock 여부를
  모션 모드와 따로 보고한다(`L3_MODE=mock`). 같은 화면 아래 줄은 "모의 판정 — 실제 동작 근거는 아니에요"라 서로 모순이었고, 기존
  `operation_confirmed_test` 첫 시험이 바로 이 모순을 기대하고 있었다.
- 규칙(폰 실행 상태 화면·키오스크 완료 화면·키오스크 동작 중 화면): **출처 real만** "가전 동작도 확인했어요"(확인 아이콘·색),
  출처 mock이면 "가전 동작은 모의로 판정했어요 · 실제 확인 아님", 출처를 모르면 "가전 동작 판정의 근거를 몰라요 · 가전을 확인해 주세요",
  모의 실행이면 종전 "모의 동작 판정 · 실제 가전 아님". 키오스크 동작 중 화면은 출처를 모르는 true를 확인으로 말하던 것도 고쳤다.
- 시험: 기존 기대 문구를 정직한 규칙으로 고치고 출처(real·mock·모름) × 모션 모드(real·unknown·mock) 교차 9건(폰·키오스크 각각),
  키오스크 동작 중 화면 4건. 수정 전 폰 8건·키오스크 10건 실패.

### M4 — 실패한 실행을 "실행을 시작하지 못했어요"+다시 시도로 단정 (고침)

- 재현: `finishedMessage(failed)`가 receipt를 보지 않고 늘 "실행을 시작하지 못했어요. … 다시 시도해 주세요."였다. 접수된 뒤 일부 버튼을
  누르고 실패한 실행도 같은 문장이라, 이미 한 조작을 되풀이하게 할 수 있다. 실행 상태 화면 아래 버튼도 실패면 늘 '다시 시도'였다.
- 규칙: 미전송 근거(`receipt=not_dispatched`)가 있을 때만 "누름 장치에 보내지 못했어요. 연결 상태를 확인하고 다시 시도해 주세요."
  (ThinQ는 "명령을 보내지 않았어요. …")와 '다시 시도' 버튼. 접수됨·원인 불명은 기록 화면(`display_status.dart`)과 같은 근거 수준으로
  "끝까지 실행하지 못했어요. 가전 상태를 확인해 주세요."(ThinQ는 "가전이 명령을 실행하지 않았어요. …"), 버튼은 '확인'. 안전 정지는 종전대로.
- 시험: `failed_message_test.dart` 6건(접수 뒤 부분 실행을 실제 provider·가짜 /status로 1건 포함), `ux_result_test.dart` +4.
  수정 전 6건·3건 실패. BLE 실패·옛 서버 실패의 기존 기대 문구 2곳을 새 규칙으로 고쳤다. 골든 `status_failed` 장면 문장도 바꿨다(이미지는 데스크톱 갱신).

### M2 — 같은 주소·키로 허브가 꺼졌다 켜져도 연결 상태가 그대로 (고침)

- 재현: `RpiConnectionNotifier`는 처음·주소/키 변화·사용자 확인 때만 판정했다. 주기 `/status` 실패도 연결 상태를 바꾸지 않아, 허브가
  꺼졌다 켜져도 '연결됨'에 머물고 연결을 듣는 확인 주행 조회가 다시 묻지 않았다. 앞 절 M3 시험은 가짜 연결을 직접 바꿔 이 배선을 보지 못했다.
- 수정: 기존 5초 `/status` 조회(`estopProvider`, AppShell 배너가 늘 띄운다)의 통신 결과를 `reportHubPoll`로 넘긴다 — **연속 2번** 닿지 않으면
  '닿지 않음', 다시 닿으면 '연결됨'. 허브가 오류 코드·해석 불가로 답한 것은 닿은 것, 키 거절(401)은 연결 판정(`check`)에 맡긴다.
  (정정, 2차 평가 L-N1: 당시 '해석 불가'는 FormatException만이었다 — 200 + 필드 타입 오류(TypeError)는 끊김으로 셌다. `079b5b1`에서 고침)
  확인 중·미설정·키 필요 상태는 건드리지 않는다. 새 화면·새 주기 조회 없음.
- 시험: `connection_poll_test.dart` 3건 — 실제 연결 provider·실제 걸림 조회·가짜 HTTP로 켜짐 → 꺼짐(닿지 않음, 확인 주행 모름) → 켜짐(연결됨,
  확인 주행 재조회), 한 번 실패는 그대로, 500은 닿지 않음 아님. 수정 전 첫 시험 실패(기한 초과). 고정 연결 대역(`FixedRpiConnection`)은
  주기 결과로 바뀌지 않게 했다. (정정, 2차 평가: 시험 주기는 100 ms다 — 실제 5초 타이머·요청 timeout·inFlight를 넣은 허브 재시작 실측이 아니고,
  실제 네트워크에서 '연속 2번' 정책의 오탐률도 재지 않았다)
- 한계: 폰이 실패를 두 번 보기 전에 돌아오는 짧은 재시작은 여전히 모른다(정정: '약 10초'는 조회 위상·timeout에 따라 달라지는 설명값이지 경계 시간 보장이 아니다). 앱 복귀(resume) 때 재확인은 넣지 않았다(주기 조회가
  앱이 살아 있는 동안 돈다). 확인 주행 기록의 서버 저장은 남은 일 그대로.

### M3 — 첫 실행 중 마이크 권한 창이 실행·정지 화면을 가림 (고침, 기본 규칙)

- 결정(팀 결정 전 기본 규칙): **실행 중에는 OS 권한 창을 띄우지 않는다.** 실행 중 '멈춰' 듣기는 마이크 권한이 **이미** 있을 때만
  (`SpeechToText.hasPermission` — 묻지 않는 확인) 엔진을 열고, 없으면 그 실행은 조용히 건너뛴다. 화면 정지 버튼은 그대로다.
- 근거: ① 고령·저시력 사용자에게 실행 중 새 결정을 요구하지 않는다. ② 권한 창이 떠 있는 동안 앱의 정지 버튼에 손이 닿지 않는다 —
  정지 접근이 음성 정지보다 우선이다. ③ 권한 요청 자리는 이미 있다: '말로 조작하기' 화면의 마이크 버튼이 누를 때 `initialize()`로
  묻는다(`voice_screen.dart` `_toggle`). 거기서 허용하면 다음 실행부터 음성 정지가 듣는다. ④ 새 화면·설정(실행 전 안내, 설정 토글)은
  팀 결정 사항이라 넣지 않았다. 대가: 마이크 버튼을 한 번도 누르지 않은 사용자는 음성 정지를 못 쓴다 — 화면 정지·키오스크 정지는 그대로.
- 시험: `voice_stop_test.dart` 권한 3건 — 미허용(엔진 초기화 0회, 화면 정지 호출은 그대로), 거부 후 실행을 거듭해도 다시 묻지 않음,
  나중에 허용하면 다음 실행부터 듣고 "멈춰"가 정지로 간다. 수정 전 3건 실패. 실기기에서 권한 창이 실제로 뜨지 않는지는 미확인(에뮬레이터 날).
  (정정, 2차 평가: `VoiceService`는 한 번 초기화되면 그 프로세스에서 권한 검사를 생략한다(`voice_service.dart` 초기화 캐시) — 같은 프로세스에서
  권한을 회수한 경우까지 매번 OS 권한을 다시 확인한다고 말하지 않는다. 캡처 18은 그 모의 실행에서 권한 창이 없었다는 근거까지다.)

### L3 — '단계' 말의 혼동·숫자와 단위의 줄바꿈 (고침)

  "총 N단계 중 K단계" → **"조작 N개 중 K개"**로 바꿨다(낭독 이름은 "조작 N개 중 K개 마침"). 루틴 쪽은 그대로 '단계'.

  본다 — 결합 문자가 없으면 폭 530에서 나뉨을 확인했다. 기존 기대 문구 7곳을 고쳤다. 실기기 200% 캡처는 다시 찍지 않았다(데스크톱 날).
