# 2026-10-13 — ThinQ 가전 자동 발견 + 사용자 확인 후 추가 (데스크톱)

사용자 결정: ThinQ 계정에 등록된 가전을 **자동으로 찾고, 사용자가 확인(추가 버튼)한 것만** 쓴다. 지금까지는
서버 환경 변수(`SIMPLELAY_THINQ_DEVICE_*`)에 기기 ID를 손으로 적었다. 환경 변수 방식은 그대로 둔다.

> **검증 수준: 모의 클라우드까지(공식 SDK → 저장소 안 모의 ThinQ 클라우드 127.0.0.1). 실제 ThinQ 클라우드·실가전 미검증.**
> 범위는 공기청정기 한 대의 흐름. 세탁기·제습기는 기존 동작 그대로이고 지원 표시만 프로필 판정대로 나온다.

## 2. 서버 API

| 경로 | 하는 일 |
|---|---|
| `GET /thinq/discovered` | 계정 기기 목록 + 기기별 프로필로 지원 판정. **등록하지 않는다.** 항목: `key`(기기 ID의 SHA-256 앞 16자 — 원문 아님), `kind`·`kind_label`, `alias`(계정 별칭), `model_name`, `support`(`controllable`·`status_only`·`unsupported`·`unknown`), `support_reason`, `actions`, `added`, `source`(`added` 사용자 추가 / `config` 환경 변수), `appliance_id`, `name`, `can_add`, `reason`(추가 못 하는 이유). 머리: `mode`·`execution_mode`·`mock_cloud`·`reachable`·`error` |
| `POST /thinq/added {"key"}` | 사용자가 누른 기기 하나 추가. 목록·프로필을 다시 확인 → 서버 DB 저장 → 서버 구성 가전 등록. 이미 있으면 그대로(중복 없음). 지원 안 함·상태만·같은 종류가 이미 있음 409, 계정에 없음 404, 클라우드 오류 503(사람 말 이유) |
| `DELETE /thinq/added/{key}` | 사용자가 추가한 기기 빼기(등록·DB 둘 다). 환경 변수 기기 409, 없음 404 |

- ThinQ가 꺼져 있으면(off) 셋 다 404 — 기존 `/thinq/devices`와 같다.
- **조회 실패는 '0대'가 아니다:** 목록 조회가 실패하면 200에 `reachable: false`와 이유(토큰 오류면 "ThinQ 토큰(PAT)이
  유효하지 않아요…", 연결 끊김이면 "…연결하지 못했어요…"), `devices: []`.
- **지원 판정**(`classify`): 우리 종류(공기청정기·세탁기·제습기)이고 우리 동작 중 하나 이상을 프로필이 쓰기로
  허용하면 제어 가능(실행기 `_resolve`와 같은 판정). 쓸 동작은 없고 우리가 읽는 상태 칸만 있으면 상태만, 그 밖은
  지원 안 함. 다른 종류(냉장고 등)는 이름만 보이고 지원 안 함 — 새 종류로 넓히지 않았다.
- **자리:** 종류마다 가전 ID가 하나(`air_purifier`·`thinq_washer`·`dehumidifier`). 환경 변수 기기가 먼저 그 자리를 잡고,
  추가한 기기는 빈 자리에만 들어간다 → 둘 다 있어도 중복 없음. 같은 종류 두 번째 기기는 "한 종류에 한 대만".
- **영속:** 서버 DB `settings` 칸 `thinq_added_devices:<모드>`(JSON). 모드별이라 모의 클라우드에서 추가한 가짜 ID가
  real에 섞이지 않는다. DB가 없으면(개발 PC 기본) 메모리. 기동 때 다시 등록한다.
- **기기 ID 원문:** 서버 DB에만. API는 `key`, 로그는 가전 ID만. 공식 SDK가 요청마다 DEBUG 로그에 주소(기기 ID 포함)를
  남기는 것을 발견해 `thinqconnect` 로거를 INFO 위로 묶었다(시험이 로그에 ID가 없음을 본다).
- 추가한 기기는 환경 변수 기기와 **같은 `ApplianceDef`**로 등록되므로 준비 판정·승인 카드·제어·상태 재조회·기록이
  기존 경로 그대로다. 추가는 실행이 아니다 — 실행은 종전처럼 승인(카드·직접 명령)을 거친다.

## 3. 앱

- 위치: 설정 → **LG ThinQ 연결**(기존 화면) 안, 기존 'ThinQ 가전' 목록 아래 구획 **ThinQ에서 찾은 가전**
  (`app/lib/widgets/thinq_discovered_section.dart`). 새 탭·새 화면·팔레트 변경 없음.
- 기기마다 별칭·종류·모델명. 추가 가능 → 지원 동작 한 줄 + **추가** 버튼. 지원 안 함·상태만·같은 종류가 이미 있음 →
  버튼 없이 이유 한 줄. 추가됨 → "추가됨 · 홈과 루틴에 나와요"와 **빼기**(사용자 추가만), 환경 변수 기기 →
  "연결됨 · 허브 설정으로 넣은 가전이에요".
- 실패는 "가전을 찾지 못했어요 — <이유>" + **다시 찾기**(토큰 오류·허브 닿지 않음·ThinQ 꺼짐·허브 키). 정말 비었을
  때만 "등록된 가전이 없어요 (0대)".
- 추가 뒤 찾은 목록·ThinQ 요약·서버 가전 목록을 다시 받는다 → 홈에 'ThinQ' 배지 타일, 루틴 대상(설치 가전 목록)에
  바로 나온다. 모의 클라우드면 제목에 '(모의 클라우드)'.
- 키오스크: 바꾸지 않았다. 추가한 가전의 `GET /appliances` 항목이 환경 변수 가전과 같음을 서버 시험으로 확인.

## 5. 남은 것

1. 실물 날: [실물 확인 절차](ThinQ-실물-확인-절차.md) §4-3 — real 모드에서 발견 목록에 AS186HWWA가 보이는지, 프로필 판정이
   '제어할 수 있어요'인지, 추가 → 승인 → 제어 → 확인.
2. 같은 종류 두 대 이상(예: 공기청정기 2대)은 한 대만 추가된다 — 필요하면 가전 ID 자리 규칙을 넓힌다(이번 범위 밖).
3. 계정에서 지워진 기기는 발견 목록에서 사라지지만 추가 기록은 남는다(준비 판정이 "계정에서 찾지 못했어요"로 막는다).
   앱에서 빼려면 목록에 있어야 한다 — 서버 `DELETE /thinq/added/{key}`로는 뺄 수 있다.
4. 실행 중인 가전을 빼는 경우의 화면 문구는 따로 다듬지 않았다(실행 기록·준비 판정은 등록 해제 뒤 404·거절).
5. 별칭이 바뀌어도 추가 당시 이름을 쓴다(빼고 다시 추가하면 새 별칭).
