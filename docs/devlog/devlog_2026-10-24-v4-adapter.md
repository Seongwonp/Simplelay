# 2026-10-24 — 최신(v4) 스케치 기준 RPi4 모션 어댑터 보완 (시험 조건만)

[통합 재설계 계획](../통합-재설계-실행계획-2026-10-23.md)의 "원본 통신 어댑터" 단계만 다뤘다. 하드웨어 없이 가짜 시리얼로만 시험했다. 펌웨어·핀·PID는 읽기만 했고 수정·업로드하지 않았다.

## 1. 확인한 사실

- HW 담당자에게 받은 최신 3파일(스케치·설정 헤더·Bot 헤더)은 부팅 문구에 `v4`가 찍히지만, 10/23에 [호스트 어댑터](devlog_2026-10-23-touchbridge-host.md)를 만들 때 쓴 파일과 **해시가 같다.** 새 펌웨어가 아니라 같은 파일이다.
- 선 위의 JSON은 여전히 `"version":2`다. `v4`는 펌웨어 빌드 이름이지 통신 규약 버전이 아니다.
- 그래서 새 선택값(`touchbridge-v4` 같은)을 만들지 않았다. 같은 규약을 두 이름으로 고르게 하면 어느 쪽이 맞는지 헷갈린다. 선택은 그대로 `SIMPLELAY_MOTION_MODE=serial` + `SIMPLELAY_MOTION_PROTOCOL=touchbridge-v2`이고, 기본값 `line-json/v0`는 바뀌지 않았다.
- RPi4↔RPi5 링크 규약(`line-json/v0`·`run_ref`·생존 신호·링크 인증)은 바꾸지 않았다.

## 2. 고친 점 ([어댑터](../../rpi/controller/touchbridge_motion.py))

스케치의 실제 응답 모양과 대조해 빈 곳을 메웠다. 새 운영 안전 정책(이동마다 원점·범위 제한 등)은 넣지 않았다.

| 상황 | 전 | 후 |
| --- | --- | --- |
| 누름 거절이 `RECEIVED` 전에 옴(`ERROR_INVALID_TOKEN`, `AUTH_REQUIRED` 등) | `AUTH_REQUIRED`는 '눌렸는지 모름' | 모두 '누르지 않음' — 스케치는 이 거절들을 Bot 요청 전에 보낸다 |
| 누름을 받은 뒤 오류(`BOT_*`, `ERROR_TIMEOUT`) | '눌렸는지 모름' | 그대로. 재누름 없음 |
| 누름 응답이 기한 안에 안 옴 | 시간 초과, 결과 표시 없음 | 시간 초과 + '눌렸는지 모름' 표시, 정지 전송 |
| 이쪽이 정지를 보내지 않았는데 `STOPPED`가 옴(같은 보드의 다른 조작 경로 등) | 폐루프가 다시 이동·누름을 시도할 수 있었음 | 중단 원인 `motion_stopped`로 실행을 끝냄(재시도 없음). 앱은 기존 일반 문장 '누름 장치가 멈췄어요'로 보인다 |
| 누름을 받은 뒤 `STOPPED` | '정지'만 | '정지' + '눌렸는지 모름' |
| `ERROR_POSITION`에 실린 실제 위치 | 버림 | 마지막 위치로 보관(조정 화면에서 볼 수 있게) |
| 부팅 문구 | 고정 문자열 기록 | 실제 빌드 이름(예: `v4`)을 연결 정보에 기록 |

정지는 이전처럼 어떤 상태에서도(이동 대기 중, 재연결 대기 중) 바로 쓴다. 이쪽이 보낸 정지의 의미(`mcu_ack`까지만, 엔코더 검증 없음)는 바꾸지 않았다.

## 3. 시험

- [어댑터 시험](../../rpi/tests/test_touchbridge_motion.py)에 스케치가 실제로 보내는 줄 모양으로 21건을 더했다: 이동 오류 4종(`ERROR_STALL`·`ERROR_TIMEOUT`·`ERROR_LIMIT`·`ERROR_POSITION`), `ERROR_NOT_HOMED`·`BUSY` 거절, 누름 거절 2종·누름 뒤 오류 5종, 누름 무응답, 보드 쪽 정지·이쪽 정지, 재연결 대기 중 정지, 깨진 줄·모르는 commandId, 재부팅 뒤 원점 없이 다시 연결.
- 새 동작을 확인하는 6건은 수정 전 코드에서 실패하는 것을 먼저 확인했다. 나머지는 이미 맞던 동작을 고정하는 시험이다.

## 4. 미검증 (실물 확인 전)

- 실제 보드에서 이동·도착·누름·Bot 응답·정지는 아무것도 확인하지 않았다. 모두 가짜 시리얼 시험 조건이다.
- Bot 오류 문자열과 `ERROR_TIMEOUT`/`ERROR_PROTOCOL` 구분은 스케치 소스를 읽어 맞춘 것이다. 실제 로그로 확인해야 한다.
- 다른 조작 경로(같은 보드의 무선 조작 등)가 실제로 `STOPPED`를 보내는 상황은 소스 읽기로만 추정했다.
- 개발자 조작의 누름 실패는 아직 '조작 중 오류'라는 일반 문장으로 보인다(기존 동작).
