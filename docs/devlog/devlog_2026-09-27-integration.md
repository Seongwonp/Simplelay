# 2026-09-27 — 독립 명령 계약 통합·실행 출처 표시

사용자 승인: 계약과 통신 시뮬레이터 통합 후 실제/모의 표시부터 진행한다. UI 변경은 실행 출처·시연 제안·센서의 사실 표시로 한정했다. 팔레트·아이콘·탭 구조는 바꾸지 않았다.

## 통합

별도 Claude worktree에서 검토·수정한 `rpi/commands` 4파일과 테스트 3파일을 현재 작업 폴더에 복사했다. 원본 worktree는 변경하지 않았다. Receipt와 Confirmation은 독립이며 집계 보고를 센서 검증으로 승격하지 않는다. 정지 요청은 요청 사실로만 남는다. 기존 서비스는 아직 이 계약으로 실행하지 않으며 승인 원장·DB 이전도 미구현이다.

기존 `rpi4.simulator`와 함께 테스트했다. 모션·센서·UART 실물 검증은 아니다. 시뮬레이터를 앱/키오스크 서버에 연결하는 기능과 정지 버튼 대기/보관 흐름은 후속 단계다.

## 서버 → 화면의 출처 전달

- `/status`에 실행 중 `execution_mode`와 완료된 작업의 `last_execution_mode`를 추가했다. 실행 게이트에서 선택한 컨트롤러의 모드를 고정하고 완료 시 이전 작업 ID와 함께 보존한다. UART/local 같은 연결 방식으로 real/mock을 추정하지 않는다. 다음 작업이 시작돼도 이전 작업의 모드를 덮어쓰지 않는다.
- 앱·키오스크는 일치하는 job ID의 모드를 읽어 모의/실기기/환경 미확인으로 표시한다. 모드 누락·알 수 없는 값은 실기기로 승격하지 않는다. 실행 환경이 real이라는 사실도 가전 동작 확인을 뜻하지 않는다.
- HTTP 모의 완료 음성은 실제 조작이 없었음을 명시한다. 환경 미확인은 실행기 완료 보고와 실제 조작 여부를 구분한다. 키오스크 완료 화면의 일괄적인 '센서로 확인' 문구는 제거했다.
- 앱 실행 기록에 real/mock/unknown 구분을 추가했다. 오래된 기록은 unknown이다.
- `/suggestions`, `/demo/suggest`, `/demo/environment` 응답의 `is_demo`를 앱·키오스크 제안 화면에 전달한다. 환경 시연과 강제 생성 모두 표시한다. **시연 제안 데이터라는 사실은 그 승인이 실제 기기를 실행하지 않는다는 뜻이 아니다.** 실행 모드는 별도로 판단한다.
- 센서 `mocked`를 두 클라이언트가 보존한다. 모의 또는 필드 누락 센서값은 일반 온습도 표시에서 숨긴다. 실측 값 0은 숨기지 않는다.

## 검증

- 통합 및 서버 변경 후 백엔드 전체: 1,507건 통과(기존 의존성 경고 2건).
- 이후 추가한 작업별 모드·실제 폐루프→독립 계약 매핑·API 응답 출처 회귀 포함 관련 64건 통과. 추가 테스트 4건이며 이 추가 뒤 전체는 재실행하지 않았다.
- 앱 전체 비골든: 378건 통과, 변경 전 완료 문구 기대값 2건 실패. 기대값을 새 불명/출처 안내로 수정한 뒤 해당 파일과 출처 테스트 12건 모두 통과.
- 키오스크 전체 비골든: 136건 통과, 변경 전 완료 문구 기대값 2건 실패. 수정 후 해당 파일과 출처 테스트 50건 모두 통과.
- 키오스크 모의 실행·완료를 일반/큰 글씨(1.0/1.6)로 렌더하는 새 시각 테스트 4건 통과. 기존 골든을 일괄 갱신하지 않았다. 변경 화면의 기존 골든은 추후 화면 묶음 검토 시 맞춰야 한다.
- 앱 정적 분석: 오류/경고 없이 기존 info 5건. 키오스크도 오류/경고 없이 기존 info 1건.
