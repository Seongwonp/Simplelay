# 결선 질의응답 대비 (2026-10-16)

결선 평가는 시연·발표 10분, 질의 10분이다. 이 문서는 **심사위원이 반드시 물을 질문**에 1분 안에 답하는 기준이다.
질문 목록은 10/16 외부 냉정 평가(하드웨어 완성 가정 74점)가 "점수 상한을 정하는 것은 질의응답"이라며 꼽은 것이다.

**원칙**
- 실측하지 않은 수치는 말하지 않는다. "측정 필요"라고 말하고, 실측표에 값이 생기면 그 값만 쓴다([실측 기록표](실측-기록표.md)).
- 상용 제품과는 **설계 차이**로만 비교한다. 성능·가격 우위를 주장하지 않는다. 상용품 기능은 공개 사양으로만 말한다(출처·확인 날짜).
- 모르는 것은 "아직 확인하지 않았습니다"라고 말한다. 확인하지 않은 것을 확인했다고 말하는 것이 가장 큰 감점이다.

## 질문별 1분 답변

### Q1. "갠트리와 모션 펌웨어는 팀원의 이전 작품(Touch Bridge) 것 아닙니까?"

**답:** 맞습니다. 누르는 몸(CoreXY 갠트리)과 모션 제어 핵심(PID·기구학·궤적)은 팀원의 이전 작품과 공유합니다.
보고서 첫머리에 재사용 경계를 표로 밝혔습니다. 이번 대회에서 새로 만든 것은 그 위 계층입니다.
- 무엇을 누를지 **승인받은 그 명령만** 실행하는 승인 결속(명령 지문)
- 눌렸는지를 층별로 확인하고, 모르면 다시 누르지 않는 폐루프 정책
- 사용 기록 기반 제안과, 사용자가 허용한 조건에서만 도는 자동 실행 규칙
- RPi5 허브·RPi4 실행기·ESP32 모션의 3단 경로와 정지 확인 단계(보냄 → 모션 보드 응답 → 멈춤 확인)
- 콘센트 전력(CT)으로 가전 동작을 확인하는 모듈, 키오스크·폰 앱

**한 줄:** "몸은 공유하고, 판단하고 확인하는 머리는 새로 만들었습니다."
**근거:** [재사용 경계](reuse-boundary.md) 경계 표.
**하면 안 되는 말:** "기구는 따로 설계했다", "펌웨어는 독립"(10/10에 철회한 문장).

### Q2. "SwitchBot 같은 버튼 누름 로봇 몇 개 사면 되지 않습니까?"

**답(설계 차이만):**
- 버튼 로봇은 **버튼 하나에 장치 하나**를 붙입니다. SimpleLay는 **팔 하나가 패널의 여러 버튼**을 순서대로 누릅니다(전자레인지 '즉석밥 → 시작' 같은 순서).
- 버튼 로봇은 눌렀다는 사실까지입니다. SimpleLay는 **가전이 실제로 동작했는지**를 콘센트 전력으로 확인하고, 확인하지 못하면 같은 버튼을 다시 누르지 않습니다(이중 조리 방지).
- ThinQ 같은 스마트 가전과 오래된 버튼식 가전을 **같은 승인·자동 실행 규칙**으로 묶습니다.

**인정할 것:** 설치 간편함과 가격은 상용 버튼 로봇이 낫습니다. 저희 원가와 설치 시간은 아직 측정하지 않았습니다.
**하면 안 되는 말:** 가격·속도·정확도 비교 수치(실측·출처 없음).

### Q3. "LG ThinQ ON도 사용 패턴을 학습해 자동화합니다. 차이가 뭡니까?"

**답:** 스마트 가전끼리는 제조사 플랫폼이 이미 잘 합니다. 저희가 푸는 문제는 **그 바깥**입니다.
- 집에 있는 가전 대부분은 통신이 없는 버튼식입니다. SimpleLay는 그 가전을 **고치지 않고** 앞에서 눌러 같은 자동화에 넣습니다.
- 그래서 시연은 "버튼식 전자레인지 가열 종료(전력으로 감지) → ThinQ 공기청정기 강풍"처럼 **두 세계를 잇는 장면**입니다.
- 자동 실행은 사용자가 카드에서 조건·동작을 보고 **허용한 것만**, 낮은 위험 동작(공기청정기 풍량·전원)만 합니다. 버튼 누름은 매번 승인입니다.

**근거:** [시연 계획 v4](본선-시연-계획-v4.md), 자동 실행 규칙 [devlog](devlog/devlog_2026-10-13-auto-rule.md).
**하면 안 되는 말:** "ThinQ ON보다 똑똑하다", "AI가 학습한다"(지도교수 방침: AI 고도화 없음. 기록을 세는 규칙이다).

### Q4. "CT로는 취소나 문 열림과 정상 종료를 구분 못 하는데, 그걸 '확인'이라 부릅니까?"

**답:** 구분하지 못합니다. 그래서 '조리 완료'라고 부르지 않고 **'가열 종료 감지(조리 완료가 아닐 수 있음)'**라고만 말합니다. 화면 카드에도 그 문장이 늘 보입니다.
그 신호로 하는 일은 공기청정기 풍량 변경 하나입니다. 낮은 위험 동작이라, 취소로 끝났어도 해가 없도록 정책으로 정했습니다.
'확인'이라는 말은 **누른 버튼에 가전이 반응했는지(가열 시작)**에만 씁니다.

**근거:** [시연 계획 v4](본선-시연-계획-v4.md) 표현 기준(10/14).

### Q5. "전자레인지 빈 가열이나 오작동이 나면 누가 책임집니까?"

**답:** 그래서 **가열을 시작하는 버튼 누름은 자동으로 하지 않습니다.** 매번 사람이 화면에서 승인해야 누릅니다.
- 승인한 그 명령만 누릅니다(명령 지문이 다르면 거절).
- 눌렀는지 확인하지 못하면 다시 누르지 않고 사람에게 확인을 부탁합니다.
- 정지는 화면 어디서나 누를 수 있고, 모션 보드 응답과 멈춤 확인까지 단계로 보여 줍니다.
- 솔레노이드는 펌웨어가 한 번에 켜 둘 수 있는 시간과 냉각 시간을 제한합니다.

**인정할 것:** 콘센트 차단 릴레이(비상정지 래치)는 펌웨어·호스트 경로까지 만들었고 회로는 아직 제작 전입니다. 솔레노이드 차단 시간·발열은 측정 전입니다.
**근거:** [솔레노이드 안전 전달표](솔레노이드-안전-전달표-2026-10-16.md), [정지 확인 단계 devlog](devlog/devlog_2026-10-13-stop-confirm.md).

### Q6. "버튼 위치가 1~2 mm 어긋나면 어떻게 됩니까? 성공률은요?"

**답:** 누름 성공률은 **아직 측정하지 않았습니다**. 측정 계획과 기록표는 준비돼 있습니다([실측 기록표](실측-기록표.md)).
어긋났을 때의 동작은 이렇습니다.
- 가전이 반응하지 않으면(전력 변화 없음) '확인 못 함'으로 끝내고 **다시 누르지 않습니다**. 잘못 눌러 두 번 동작하는 것보다 멈추는 것을 택했습니다.
- 버튼 좌표는 앱의 버튼판 편집기에서 가전마다 맞춥니다.
- 모터가 걸리면(스톨) 재시도 없이 멈추고 알립니다. 실물로 확인했습니다(10/12~14).

**하면 안 되는 말:** 정밀도·성공률 숫자(실측 전).

| "AI는 어디에 썼습니까?" | 판단은 사용 기록을 세는 규칙입니다. 온디바이스·클라우드 경계는 [추론 경계](inference-boundary.md)에 정리했습니다. 개발 도구로 AI를 쓴 사실은 서류에 밝혔습니다. |

| "누가 승인했는지 압니까?" | 모릅니다. 그래서 화면에 '최근 기록: 이 제안 승인 N번'처럼 기록만 말하고, 사람을 단정하지 않습니다. |
