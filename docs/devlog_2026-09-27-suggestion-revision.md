# 공감지능 피드백 2단계: 이번 동작 수정과 재승인

## 구현

앱·키오스크에 '이번 동작 바꾸기'를 추가했다. 같은 가전의 등록 동작 선택 → 새 카드의 대상·버튼 순서 확인 → '지금 실행' 재승인 순서다. 수정 API는 모터를 구동하지 않는다.

- GET `/suggestions/{id}/revision-options`: 해당 가전의 명시적인 기능만 반환. 내장 전자레인지는 기존 결정론적 규칙도 지원한다. 다른 가전은 '전원' 같은 버튼 이름이 같아도 기능을 추측하지 않는다.
- POST `/suggestions/{id}/revise`: `purpose`만 받는다. 대상 가전이나 임의 버튼 목록을 추가하면 거절한다. 환경 제안은 상황과 목적이 직접 묶여 있어 이번 수정 기능에서 제외한다.
- 이전 pending ID를 폐기하고 새로운 ID로 교체한다. 동시 수정은 하나만 성공한다. 기존 만료 시각·시연 구분·대상은 유지한다.
- 수정된 동작에는 기존 사용 횟수를 붙이지 않는다. 횟수는 0, 이유는 '이번 요청에서 바꾼 동작'으로 표시한다.
- 원래 제안은 해당 시간대에 재생성되지 않도록 기존 영속 쿨다운에 기록한다. 영구 억제·습관 기록 변경은 하지 않는다.
- 수정 카드 승인에는 미리 본 버튼 튜플을 전달한다. 동기·비동기 실행 모두 현재 해석 및 허용된 동작과 다르면 실행 전에 거절한다. 준비 상태·실행 중재·재실·만료 등 기존 게이트도 유지한다.
- 수정 실행은 기존 제안 출처로 기록한다. 수정 자체는 성공 실행이나 자연 사용 이력이 아니다.

## 검증

백엔드 전체 1,562개 통과(벤더 dbus_fast 경로 포함, 기존 경고 2개).

새 서버 회귀: 원래 승인 무효화, 수정만으로 실행/학습 없음, 새 승인 1회 실행, 동기·비동기 해석 변경 차단, 부적절한 동작 거절, 만료·부재 검사, 동시 수정, API 대상 변경 거절, 공통 버튼 이름으로 다른 가전의 기능 추측 금지.

앱 관련 34개, 키오스크 관련 52개 통과. 키오스크는 수정 선택 후 실행이 없고 새 ID에 별도 승인하는 화면 흐름을 검증했다. 앱은 화면 회귀·API·HTTP 목록 교체를 검증했다. analyze 오류·경고 없음(기존 info 앱 5개, 키오스크 1개). 실제 휴대폰·RPi 터치 및 가전은 아직 검증하지 않았다.

## 남은 범위

- '두 가전 중 선풍기만 빼기'는 다가전 묶음 제안 모델과 부분 성공 표시가 필요하다. 이번 변경은 한 가전의 등록 동작 수정이다.
- 일반 제안 전체의 미리보기 계약은 이번에 교체하지 않았다. 버튼 순서 대조는 수정된 제안에 적용된다.
- 버튼 좌표·기구·센서는 기존 준비/보정 체계를 따른다. 이번 대조가 실제 동작·안전성 확인을 대신하지 않는다.
- 동작 선택 중에도 서버 만료는 연장되지 않는다. 통신 응답 유실 시 목록을 다시 확인해야 한다.
- 브라우저 배포본 재빌드·실물 시연은 별도 단계다. 커밋·푸시는 하지 않았다.
