2. **입체적인 시연 무대.** 책상 두 개 위에 가짜 거실을 꾸며 멀리서도 보이게 한다. 3종을 가져가되 하나가 안 되면 영상으로 대신한다.

4. **발표는 CEO 관점.** 집 전체 그림 → 스마트 가전의 정의 → ThinQ 가전은 비싸고 저가 가전은 기능이 없다(가격 표시) → SimpleLay → 기기 사진 → 가전별 확대 → 실제 동작 순서로 간다. 그림 위주로 하고 글자는 줄인다.

6. **질의응답.** "이런 고민 끝에 이렇게 선택했다"를 결과물과 연결해서 답한다.
7. **CT 잔여 전류.** 켜짐과 꺼짐만 구분하면 충분하다.
8. 제출 전에 모의 발표로 한 번 더 피드백을 받는다(교수님이 PPT 검토).

## 2. 하드웨어 통신 경로 (9/30 확정 구성)

```
폰 앱 ─Wi-Fi(HTTP)─┐
키오스크(RPi5 화면) ┤
                   ▼
            RPi5 허브 ──인터넷──▶ ThinQ 클라우드 ─▶ LG 가전(API 경로)
         (해석·제안·게이트·이력)
                   │ UART 줄 단위 JSON 115200  (시험 중에는 LAN + socat)
                   ▼
            RPi4 실행기 ← 전류(ADS1115)·마이크: L1·L2
                   │ USB 시리얼(모션 규약: home/move/press/stop/ping/limits)
                   ▼
            Arduino ─▶ TB6612 ─▶ FIT0482 ×2 (CoreXY)
                    ─▶ H브리지 ─▶ 스위치봇 모듈 (Z 누름, 시간 기반)
            ESP32 콘센트 모듈 ─ CT 전력 ─Wi-Fi─▶ RPi4(L3 판정)·RPi5(기록)
```

- RPi4↔모션 MCU 규약과 호스트 코드는 그대로 쓴다. `firmware-motion/`(ESP32용)은 Arduino로 옮긴다.
- **결정 대기:** CT 값을 어디로 보낼지. 추천은 ESP32에서 RPi4로 바로 보내는 것이다(L3 판정이 RPi4에서 이뤄지므로).
- **결정 대기:** 물리 비상정지 위치. 발표 자료 5장(ESP32 브릿지)과 4장(ESP32 콘센트 모듈)이 서로 다르다. 추천은 콘센트 모듈에 버튼과 전원 차단 릴레이를 두는 것이다.

## 3. 새로 정한 기능 설계

### 3-1. 정지 버튼 대기와 보관 위치 (사용자 제안, 9/30)

9/27 모의 모델([정지·보관 모의 동작](정지-보관-모의동작-2026-09-27.md))을 실제 실행 경로에 연결한다.

1. **등록.** 가전을 등록할 때 정지(취소) 버튼 위치, 정지까지 누를 횟수(예: 전자레인지 1회 일시정지·2회 취소), 보관 위치를 받는다. 보관 위치는 버튼과 표시창을 가리지 않는 모서리여야 한다.
2. **대기.** 버튼 시퀀스가 끝난 뒤 CT로 가전이 동작 중인 게 확인되는 동안, 캐리지는 Z를 올리고 잠근 채 정지 버튼 위에서 기다린다.
3. **정지.** 폰, 키오스크, 음성, 전력 이상 중 어디서 요청이 와도 같은 경로를 탄다. Z를 내려 등록한 횟수만큼 누른다. CT 전력이 떨어져야 "정지됨"으로 판정한다.
4. **보관.** CT가 대기 전력으로 돌아오면 보관 위치로 이동한다.
5. **분리 원칙.** "가전 정지"(정지 버튼 누름)와 "구동부 비상정지"(모터 전원 차단)는 별개다. 갠트리가 고장 나면 가전 정지를 누를 수 없으므로 최후 수단으로 전원 차단을 둔다.

서버 작업은 네 가지다.
- 가전 레지스트리에 `stop_button`·`stop_presses`·`park_xy` 추가
- 실행기에 대기·보관 단계 추가
- `/stop`을 가전 정지 누름 경로와 연결
- 트윈 표시

앱 등록 화면은 데스크톱 작업이다.

### 3-2. 카메라 매핑 — 사진 위를 터치해 버튼 배치 (추천안)

**방식.**
1. 사용자가 기구를 붙인 상태로 조작부 사진을 찍는다.
2. 사진에서 **갠트리 프레임 네 모서리**를 터치한다. 프레임 치수(mm)를 알고 있으므로 기존 `rpi/calibration/transform.py`의 `fit_homography`로 사진 좌표를 mm로 바꾼다. 원근 왜곡도 여기서 흡수된다.
3. 각 버튼 위치를 **사진 위에서 터치하고 이름을 붙인다.** 정지 버튼과 보관 위치도 같은 화면에서 지정한다.
4. **확인 주행.** 갠트리가 Z를 올린 채 버튼 위를 하나씩 지나가고, 사용자가 맞는지 확인한다. 틀린 버튼은 조그로 미세 조정한다.

**이 방식을 권하는 이유.**
- 외부 인식 서비스 없이 오프라인으로 동작한다.
- 인터폰, 세탁기처럼 모양이 다른 조작부에도 같은 방식이 통한다.
- 사람이 지정한 좌표라 결과를 설명할 수 있다.
- 기존 `/panel-scan`(AI 인식 초안)은 "후보 표시" 보조 기능으로만 남긴다. 사용자가 확인한 것만 저장한다.

**위험.**
- 사진 속 프레임 모서리가 가려지면 기준점을 잡을 수 없다. 이때는 모서리에 기준점 스티커를 붙인다.
- 버튼이 작으면 터치 오차가 클 수 있다. 사진을 확대해서 찍도록 안내하고, 확인 주행으로 보정한다.
- 확인 주행은 실물 모터가 필요하다.

### 3-3. 음성 "멈춰" 정지 (결정: 실행 중에만 듣기)

- 버튼 시퀀스를 실행하는 동안과 정지 버튼 위에서 대기하는 동안에만 마이크를 연다. 평소에는 듣지 않는다.
- 키워드는 "멈춰·정지·그만"으로 좁히고, 신뢰도가 문턱을 넘을 때만 받는다.
- 잘못 알아들어 멈추는 쪽은 감수한다(안전한 방향). 재개는 반드시 화면 승인으로 한다. 음성으로 실행을 시작하는 것은 허용하지 않는다.
- 잘못 멈춘 경우는 기록해 비율을 낸다.
- 위험 신호음 감지, 원시 기록기, 음성 정지가 같은 마이크를 쓰므로 입력 하나를 나눠 쓰는 구조로 만든다.
- 플랫폼 음성 서비스를 쓸지, 직접 구현할지는 통신 확인 때 마이크 접근 방식을 본 뒤 정한다.

### 3-4. 날씨 보조 조건

- 에어컨·제습기 제안의 주 조건은 실내 온습도(DHT22)다. 날씨는 보조로만 쓴다.
  - 예: 폭염 예보 + 귀가 감지 → 냉방 제안
  - 예: 비 오는 날 + 세탁 완료 → 제습기 제안
- 날씨를 받지 못하면 실내 센서만으로 판단하고, 제안 근거에 "날씨 정보 없음"을 표시한다.

- **키오스크 평소 화면의 한 줄 안내(9/30 결정).** 시계 위 빈자리에 인사말과 생활 안내를 한 줄씩 둔다.
  - 예: "좋은 아침이에요." 아래에 "오후 3시부터 비 예보가 있어요. 우산 챙기세요."
  - 날씨 출처 후보는 두 가지다. Open-Meteo는 키가 필요 없어 시연용으로 간단하다. 기상청 단기예보는 국내 기준이지만 키 발급과 격자 변환이 필요하다.
  - 마지막 예보를 저장해 두고, 오래된 예보는 안내하지 않는다. 인터넷이 없으면 인사말만 보여 준다.
  - 안내는 한 번에 하나다. 우선순위는 주의가 필요한 가전 → 비·폭염 같은 날씨 → 인사말 순이다.

### 3-5. 피드백 반영 계획 발표 자료의 항목

| 번호 | 항목 | 할 일 |
|---|---|---|
| ① | 제어 경로 | `physical · api · both`로 나눈다. both면 API가 실패할 때 물리 누름으로 대체한다. API 응답 뒤에도 콘센트 모듈이 붙은 가전은 CT로 동작을 확인해야 완료로 본다 |
| ② | 시나리오 | 아침 루틴과 귀가 시나리오를 추가한다(아래 참고) |
| ③ | 잔여 전류 | 켜짐·꺼짐 판정, 꺼질 때까지 걸린 시간, 전후 기준선을 기록기 열로 추가한다 |
| ④ | 긴급 제어 4종 | 사용자 정지(음성 포함, 3-3), 위험 신호음, 전력 이상 중단(신규), 확인 두절 잠금(있음) |
| ⑤ | 스토리텔링 | 시연 대본을 "사람의 하루" 순서로 다시 짠다 |

②의 두 시나리오는 이렇다.
- **아침 루틴:** 데우기 → CT 완료 → 복약 안내 음성 → 확인이 없으면 보호자 알림함. 복약 안내는 시간 알림과 확인 수준까지이며 의료 판단은 하지 않는다.
- **귀가:** 지오펜싱 → 28°C 이상 또는 습도 70% 이상 → ThinQ 에어컨 → 저녁 제안.

### 3-6. 키오스크 제품형 재설계 (9/30 결정)

"즉석밥·우유" 같은 명령 버튼은 데모 리모컨처럼 보인다. 그래서 메뉴를 우리가 정하지 않는다. 화면은 사용자의 가전과 습관에서 만들어진다.

화면은 네 가지다.

1. **평소.** 시계, 실내 온습도, 날씨, 그리고 아래에 등록된 가전 아이콘이 있다. 레이더로 사람이 다가오면 깨어난다.
2. **다가가면.** 제안 카드 **하나**만 보여 준다. 이름은 사용자가 만든 루틴 이름이거나 이력에서 나온 설명이다(예: "최근 2주 아침 5번").
3. **동작 중.** 남은 시간을 보여 준다(CT 추정). 정지 버튼 위에서 대기 중이라는 표시와 큰 정지 버튼이 있다. 끝나면 보관 위치로 이동했다고 짧게 알리고 평소 화면으로 돌아간다.
4. **내 가전.** 등록 때 찍은 조작부 **실제 사진** 위에 버튼 위치를 표시한다. 정지 버튼은 빨강, 보관 위치는 점선이다. 사진 속 버튼을 눌러 원격 조작하고, "루틴 녹화"로 누르는 순서를 저장해 이름을 붙인다. 프리셋은 없다.

**가전 아이콘은 앱에서 등록해야 생긴다.**
- 물리 가전은 사진 터치 등록 → 서버 → 키오스크 순서로 나타난다.
- ThinQ 가전은 PAT 연결 뒤 사용자가 고른 것만 나타난다.
- 아무것도 없으면 "앱에서 가전을 추가해 주세요"를 보여 준다.
- 코드에 미리 넣은 내장 가전은 시연·개발 모드에서만 보이게 바꾼다.

**상태 표시 규칙.**
- 글자 "대기"는 쓰지 않는다. 회색 아이콘이 쉼이다.
- 동작 중에는 강조색 아이콘에 남은 시간 숫자를 붙이고, 필요하면 진행 링을 두른다. 색만으로 구분하지 않는다.
- 은은한 깜빡임(1초에 한 번 이하, 몇 초 뒤 멈춤)은 완료, 확인 필요, 오류일 때만 쓴다. 초당 3회 이상 깜빡이는 표현은 쓰지 않는다.

시나리오 진행 화면은 키오스크에 넣지 않는다. 폰 앱에 둔다.

### 3-7. 센서 구매 권장 (9/30, 팀원에게 전달함)

- **가전 동작(L3, 콘센트 모듈).**
  - 분할형 CT SCT-013-030(전압 출력형)과 ADS1115를 쓴다. 전선에 직접 닿지 않는다.
  - **AC 라인 스플리터** 연장선을 끼우고 한 가닥에만 물린다. 코드를 통째로 물리면 전류가 상쇄된다.
  - 전자레인지(약 1~1.5kW)는 켜짐과 꺼짐이 확실히 구분된다. 세탁기는 몇 초 평균과 "일정 시간 이상 낮음"으로 종료를 판정한다.
  - 인터폰은 몇 W라 30A CT로는 판정할 수 없다. 카메라로 표시창 변화를 보거나 L1만 쓴다. 전류로 꼭 보려면 5A CT를 쓴다.
  - PZEM-004T는 220V 직접 배선이 필요해서, 쓴다면 절연 케이스와 안전 점검을 전제로 한다.
- **버튼 눌림(L1, 모터 전류).** INA219를 쓴다. 정격 170mA 모터라 ACS712(5A)로는 변화가 거의 안 잡힌다.
- **카메라.**
  - 조작부 등록 사진은 폰으로 찍는다. 웹캠은 개발용이다.
  - ESP32 카메라 모듈은 표시창을 비춰 누르기 전후 영역이 바뀌었는지 비교하는 L2 후보로 쓸 수 있다. 비프음 대신 쓰는 방법이며, 채택 여부는 결정 대기다.

### 3-8. 폰 앱 제품형 구조와 개발자 모드 (9/30 결정)

- **탭은 네 개다: 홈, 루틴, 기록, 설정.** 화면 시안은 사용자 개인 Artifact에 있다(저장소 밖).
  - 홈: 제안 카드 한 장과 가전 카드 두 열로 구성한다. 카드를 눌러도 실행하지 않고 상세만 연다.
  - 루틴: 위에 "다음 실행", 아래에 "내 루틴/추천"을 둔다. 편집기는 문장형 카드(언제·무엇을·그다음)이고, "승인 후 실행/알림만"을 고른다. 루틴은 사진 위를 짚어 녹화한다.
  - 기록: 날짜별 타임라인에 제안 → 승인 → 실행 → 확인 결과를 한 줄씩 남긴다.
  - 설정: 가전 추가, 허브, ThinQ 연결, 음성으로 멈추기, 보호자, 글자 크기.
- **가전 추가는 5단계다.** 사진 → 프레임 모서리 4점 → 버튼 짚고 이름 붙이기 → 정지 버튼과 쉬는 자리 → 확인 주행.
- **개발자 모드는 서버 환경 변수 하나로 켜고 끈다.** 기존 `SIMPLELAY_DEV_MODE`를 쓴다.
  - 서버가 `/status`로 개발자 모드 여부를 알려 주고, 앱은 켜져 있을 때만 설정 옆에 **다섯 번째 탭 "개발자"**를 띄운다. 꺼져 있으면 탭과 경로가 모두 사라진다. 서버는 이미 이 경우 `/dev/*`를 404로 막는다.
  - 개발자 탭으로 옮길 것: 개발자 콘솔(조그·원점·정지), 실패 주입, 시연 제안(`/demo/*`), 장애 주입(ThinQ fault), 통신 기록, 트윈 링크, 서버 주소 직접 입력.
  - 시연 날에는 개발자 모드를 끈 상태로 제품 화면만 보여 준다. 필요하면 리허설용으로만 켠다.
