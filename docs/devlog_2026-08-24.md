## 교차 리뷰(Codex) 반영 — Phase B 중요 7건 수리 완료 (커밋 5개)

Phase A(치명 4건)에 이어 중요 항목 전부 해소. 백엔드 테스트 **397 → 442** (+45).

1. **제안 승인·거부 원자화(#8)** — `_claim_for_approval()`이 락 안에서 pending 확인+APPROVED 전이를 원자 수행. "폰에서 거부했는데 키오스크 승인이 되살려 실행" 레이스 차단. 실행(느림)은 락 밖. 배리어 2스레드 ×50라운드 레이스 회귀 테스트 — 정확히 하나만 승리, 물리 실행 1회 보장
2. **입력 상한 + 노드 URL 검증(#9·10)** — 발화 200자 / 실행 버튼 20개 / 라벨 40자 / known_buttons 50개 / DND 24시간. base_url은 http(s)+호스트 필수, 자격증명·비정상 포트 거부 (실행 트래픽 오배송 방지)
3. **lifespan 종료 정리(#11)** — 신규 차단 → emergency_stop → 최대 5초 대기 → 컨트롤러·DB close. systemd 재시작 시 물리 실행이 정지 명령 없이 증발하던 구멍 봉합
4. **배포 env 파일 + act_mode 노출(#7)** — systemd `EnvironmentFile=-/etc/simplelay/environment` + setup_rpi.sh가 주석 템플릿 생성(ACT_MODE/API_KEY/PRESENCE). `/health`에 `act_mode` 노출 — **"화면은 성공인데 실물이 안 움직이는" 모드 오설정을 curl 한 번으로 탐지** (시연 전 체크리스트 항목)
5. **UART 동적 타임아웃(#12)** — `ActClientConfig.timeout_for(n) = 30s + 6s×버튼수`. 고정 30/35s는 6버튼 이상 정상 실행을 timeout으로 오판. timeout 시 abort 전송(실물·화면 불일치 방지), 동기 브리지는 클라이언트 대기+5s 여유로 항상 나중에 포기
6. **ESP 노드 긴급 정지(#2)** — 펌웨어에 STOP_PORT(HTTP+1) 원시 리스너 신설. 단일 스레드 WebServer는 /execute 블로킹 중 새 연결을 못 받아 같은 포트로는 정지가 불가능했음 — 별도 포트를 실행 대기 루프에서도 폴링. `EspNodeController.request_stop()`은 정지 포트로 POST, 실패는 로그만(브로드캐스트 보호)
7. **UART 실패 주입(#6)** — `inject_failure`/`clear_failure` UART 메시지 신설(단방향), act_main이 FailureInjectionVerifier+DemoFailureState 동일 배선, `/demo/inject-failure`가 로컬 무장+UART 전달(duck-type). **리허설 장치가 실기기 구성에서도 같은 API 한 번으로 성립** — protocol.md 갱신
