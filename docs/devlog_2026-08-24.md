5. **UART 동적 타임아웃(#12)** — `ActClientConfig.timeout_for(n) = 30s + 6s×버튼수`. 고정 30/35s는 6버튼 이상 정상 실행을 timeout으로 오판. timeout 시 abort 전송(실물·화면 불일치 방지), 동기 브리지는 클라이언트 대기+5s 여유로 항상 나중에 포기
6. **ESP 노드 긴급 정지(#2)** — 펌웨어에 STOP_PORT(HTTP+1) 원시 리스너 신설. 단일 스레드 WebServer는 /execute 블로킹 중 새 연결을 못 받아 같은 포트로는 정지가 불가능했음 — 별도 포트를 실행 대기 루프에서도 폴링. `EspNodeController.request_stop()`은 정지 포트로 POST, 실패는 로그만(브로드캐스트 보호)
7. **UART 실패 주입(#6)** — `inject_failure`/`clear_failure` UART 메시지 신설(단방향), act_main이 FailureInjectionVerifier+DemoFailureState 동일 배선, `/demo/inject-failure`가 로컬 무장+UART 전달(duck-type). **리허설 장치가 실기기 구성에서도 같은 API 한 번으로 성립** — protocol.md 갱신

## 최종 교차 리뷰(Codex 2차) 반영 — 치명 1 + 중요 3 + 사소 4 완료

2차 교차 리뷰 재채점 **8.0/10**(1차 6.8). 기존 수리 16건은 코드 대조로 전부 올바르게 반영된 것으로 확인됐고, 아래 신규 지적을 수리했다. 백엔드 테스트 **442 → 464**.

### 치명
1. **ESP 노드 경로의 타임아웃 불일치** — Phase B에서 UART 경로에만 적용했던 원칙(버튼 수 비례 + 포기 시 정지)을 ESP 경로에 넣지 않은 누락이었다. RPi5의 고정 10초 HTTP 타임아웃이 펌웨어의 30초 대기보다 짧아, **RPi5가 실패로 보고한 뒤에도 노드와 RPi4는 계속 버튼을 눌렀다**(화면과 실물 불일치 — 임베디드 제품에서 가장 위험한 종류). 수리: 실행 타임아웃을 `30 + 6×버튼수`로 UART와 통일, 타임아웃·504 시 STOP_PORT로 abort 전송, 펌웨어 대기도 버튼 수 비례(기저 20초)로 낮춰 **항상 RPi5보다 먼저 504를 회신**하고 자체적으로도 UART abort를 보내게 했다.

### 중요
2. **UART 송신 실패 시 `_pending` 영구 잔존** — `_send()`가 try 밖에 있어 drain 실패 시 finally에 도달하지 못했다. 케이블 접촉 불량 한 번이 재부팅 전까지 모든 실행을 `ActLinkBusyError`로 거부시키는 구조. 송신을 try 안으로 옮기고, 정리 시 자기 sequence인지 확인하도록 했다.
3. **긴급 정지가 락을 쥔 채 순차 네트워크 요청** — 죽은 노드 하나당 2초씩 실제 실행 노드의 정지가 밀리고, 그동안 `/status`와 신규 실행 판정까지 같은 락에서 굶었다. 로컬 컨트롤러 정지는 락 안에 유지(`_begin_run`의 `reset_stop`과 직렬화가 필요)하고, 노드 정지만 락 밖에서 병렬 전송 + 전체 상한 2.5초로 분리했다.
4. **종료 시 실행 스레드가 실제로 멈추지 않음** — `task.cancel()`은 `asyncio.to_thread` 안의 동기 실행을 못 죽인다. 코루틴만 끝나 `_busy`·`wait_idle()`이 "끝남"으로 보이는 동안 실물은 계속 눌렸다. `shutdown()`을 신설해 정지 요청 후 shield로 실제 반환을 기다리고, 유예(5초) 초과 시에만 취소하며 성공 여부를 반환한다 — False면 **물리 E-STOP이 최종 권한**임을 명시.

### 사소
5. **키오스크 설정 저장 비원자성·무음 실패** — 덮어쓰기 중 정전 시 잘린 JSON으로 전 설정이 초기화됐다. 임시 파일 기록 후 교체 + `.bak` 복구 경로, `save()` 성공 여부 반환·`lastSaveFailed` 노출. 배포 경로는 `SIMPLELAY_KIOSK_SETTINGS`로 명시(현재 디렉터리 폴백 회피).
6. **타임아웃 상수 실측 미검증** — `SIMPLELAY_UART_BASE_TIMEOUT`/`_PER_BUTTON_TIMEOUT`으로 현장 조정 가능하게(잘못된 값은 기본값 폴백). 실기기에서 버튼 1개 소요의 p95를 재서 확정할 것.
7. **음성 세션 타이머 재무장 레이스** — 세션 세대 카운터로 오류 후 콜백이 타이머를 되살리지 못하게 차단.
8. **정지 포트 무조건 정지** — TCP 연결만으로 실행이 끊겨 시연장 포트 스캔에 취약했다. 요청 경로 확인을 넣되, 요청 라인을 못 읽은 경우는 여전히 정지 쪽으로 판단(덜 멈추는 것이 더 위험).

검증: 백엔드 **464** · 폰 **123** · 키오스크 **24** 전부 통과, analyze 신규 이슈 0.

## 디자인 리뷰(Codex 3차) 반영 — 지금 당장 고쳐야 할 것 9건 완료

디자인 종합 **7.6/10**. 객관적 지적은 전수 사실로 확인됐다(문서 구버전, Semantics 1곳,
Size.zero 17곳, 라이트 모드 토큰 우회 34곳, 실패 화면 3초 소멸). 팀 판단이 필요한
항목은 결정 후 반영: 카운트다운 = 설정 선택(기본 20초), 설정 진입 = 톱니바퀴 + 2초 길게.

### 시연 임팩트
1. **폐루프 재시도 연출** — 제품의 핵심 기술이 14px 보조문구 한 줄이라 심사석에서는
   우측 '시도 횟수'가 1→2로 바뀌는 것으로만 보였다. 재시도 중 **"자동 보정 중"을 38px
   앰버 배너**로 승격(liveRegion 포함), 버튼명·시도 횟수·이유를 함께 표시.
2. **실패 화면 복구 동선** — 성공과 똑같이 3초 뒤 사라져 고령 사용자는 이유도 대처법도
   모른 채 화면을 놓쳤다. 실패는 **자동 복귀하지 않고** [다시 시도] [버튼으로 조작]
   [닫기]를 제공하며, 원인별(실행 확인 실패 / 연결 끊김 / 안전 정지)로 문구를 분리했다.
   연결이 끊긴 경우엔 재시도가 또 실패할 가능성이 높아 수동 조작을 앞세운다.
3. **"재시도 N회 후 성공" 배지** 11px→13px + 테두리 — 폐루프 회복의 유일한 기록 증거인데
   화면 미러링 시 읽히지 않았다.

### 접근성
4. **Semantics/liveRegion** — 앱 전체에 Semantics가 **마이크 버튼 한 곳뿐**이었다(체크리스트의
   "부분 적용" 평가가 후했다). 상태 화면에 liveRegion(실행 상태·재시도·진행 단계 낭독),
   수동 조작 셀에 상태별 라벨, 키오스크 상태 dot·실행·완료 화면에도 추가.
5. **터치 타깃 48dp** — `minimumSize: Size.zero`로 원칙을 우회하던 10곳 보정.
6. **라이트 모드 대비** — `AppColors.primary`(다크 전용 골드) 직접 사용 34곳을
   `context.appPrimary`로 교체. 크림 배경 위 골드는 대비 약 2:1이었다.
7. **소형 글씨** — 제안 순서 배지 9px→12px(배지째 확대), 학습 통계 라벨 10px→12px.
8. **제안 표시 시간** 기본 20초 + 설정에서 10/20/30초 — 음성 안내를 듣고 걸어와서 읽고
   판단하기에 10초는 짧다.
9. **설정 진입 발견성(#15 해소)** — 5px 점 3연타는 사실상 기능 은폐였다. 48px 톱니바퀴를
   노출하되 2초 길게 눌러야 열린다. 타이밍은 Listener로 잡는다 — GestureDetector로 하면
   대기 화면의 길게 누르기(방해 금지)가 제스처 경합에서 이겨 설정이 열리지 않는다
   (실기기에서도 발생했을 문제).
