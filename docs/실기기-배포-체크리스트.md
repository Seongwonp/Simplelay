# 실기기 배포 체크리스트

> 이 문서는 **라즈베리파이를 처음 켜는 날** 순서대로 따라가는 용도다.
> 준비 작업(PC 쪽)은 2026-08-30에 끝내뒀다 — 아래 0번은 확인만 하면 된다.

무엇이 무엇으로 가는지 먼저:

| 대상 | 전달 방법 | 왜 |
|---|---|---|
| 백엔드 (`rpi/`) | **git pull** | `setup_rpi.sh`가 clone/pull 한다 |
| 키오스크 화면 | **PC에서 빌드 → scp** | Pi에 Flutter 툴체인이 없다. 36MB라 git에 넣지 않는다 |
| 펌웨어 (ESP32 ×2) | **USB 플래시** | PlatformIO에서 직접 |
| 폰 앱 | **APK 빌드 → 설치** | git과 무관 |

## 1. RPi5 — 백엔드 + 키오스크

### 1-1. 첫 설치

Pi에 SSH로 붙어서:

```bash
curl -sSL https://raw.githubusercontent.com/Seongwonp/Simplelay/main/scripts/setup_rpi.sh -o setup_rpi.sh
chmod +x setup_rpi.sh && sudo ./setup_rpi.sh
```

스크립트가 하는 일: hostname → 패키지 → git clone → venv → systemd 유닛 →
logrotate → cage+Chromium 키오스크 → 동작 확인.

**확인**: 마지막에 `/health`가 JSON을 돌려주면 백엔드는 산 것이다.
키오스크 화면에는 "키오스크 화면이 아직 없어요"가 뜬다 — 정상이다(다음 단계에서 넣는다).

### 1-2. 키오스크 화면 넣기

PC에서:

```powershell
.\scripts\deploy_kiosk.ps1 -PiHost simplelay.local
```

`simplelay.local`이 안 잡히면 `-PiHost <IP>`로. 그다음 Pi에서:

```bash
sudo systemctl restart simplelay simplelay-kiosk
```

- [ ] 7인치 화면에 시계가 뜨는가
- [ ] 화면을 누르면 수동 조작으로 들어가는가
- [ ] **글자가 서서 보는 거리에서 읽히는가** ← 크기는 권고값으로 정했지 실측이 아니다.
      안 되면 `rpi5-touchscreen-app/lib/widgets/kiosk/*.dart`의 fontSize를 올리고
      `deploy_kiosk.ps1` 다시 실행
- [ ] 설정(오른쪽 아래 톱니 2초 길게) → 큰 글씨 모드에서도 안 깨지는가

**느리면 즉시 후퇴:**

```bash
sudo systemctl edit simplelay-kiosk    # ExecStart 의 /kiosk/ → /ui
sudo systemctl restart simplelay-kiosk
```

구형 HTML 키오스크는 백엔드에 딸려 있어 항상 뜬다. 대신 오늘 한 접근성·카피 개편은
그쪽에 없다(`rpi/touchscreen/index.html`에 아직 `✦ AI 제안`이 있다).

### 1-3. 재부팅 내성

- [ ] `sudo reboot` 후 전원만으로 키오스크가 다시 뜨는가
- [ ] `sudo systemctl kill -s SIGKILL simplelay` 후 되살아나는가 (Restart=always)

## 5. 검증 우선순위 — 여기가 진짜 목적

**컴파일과 렌더는 PC에서 다 확인했다. 아래는 실기기에서만 알 수 있는 것들이고,
위에서부터 위험한 순서다.**

### 1순위 — 정지가 실제로 통하는가

이 프로젝트에서 정지 관련 결함이 **네 번** 나왔다. 매번 다른 이유였다.

- [ ] 실행 중 키오스크 **긴급 정지** → 실물이 즉시 멈추는가
- [ ] 실행 중 폰 **긴급 정지** → 같은가
- [ ] 게이트웨이 보드의 **물리 E-STOP 버튼** → 전체 노드가 멈추는가
      (8/29에 배선했다. 그 전에는 RPi5에 그 신호를 읽는 코드가 아예 없었다)
- [ ] 유휴 상태에서 정지를 눌러도 다음 실행이 정상 시작되는가
- [ ] **승인 직후~시작 직전**에 정지 → 실행이 아예 시작되지 않는가
      (여기가 마지막으로 막은 구멍이다)

### 2순위 — ESP-NOW 왕복

- [ ] BLE 광고와 ESP-NOW가 **동시에** 도는가 (겸용의 유일한 진짜 위험)
- [ ] 버튼 20개 × 긴 라벨로 250바이트를 넘겨 **조각 분할 왕복**이 되는가
- [ ] 노드 전원을 끈 채 실행 → 25초 기다리지 않고 **즉시** 오류가 올라오는가
      (송신 콜백 기반으로 바꿨다)
- [ ] 대기 중인 `rid`와 다른 응답이 버려지는가 (로그 `dropping node response`)

### 3순위 — 크로스코어 동기화 (펌웨어)

- [ ] 실행이 블로킹하는 동안 도착한 프레임이 버려지는가
      (로그 `frame dropped -- still handling`)
- [ ] `esp_now_register_recv_cb` 콜백이 ISR이 아니라 Wi-Fi 태스크에서 불리는가
      — `portENTER_CRITICAL`(비-ISR판)을 쓴 전제다

### 4순위 — 폐루프

- [ ] 센서 캘리브레이션 (전류·음향 임계값)
- [ ] 버튼 1개 소요 시간 p95 측정 → `SIMPLELAY_UART_*_TIMEOUT` 조정
- [ ] 재시도가 실제로 좌표를 보정하는가

## 알아둘 함정 (이미 겪은 것들)

- **`install.platformio.org`는 죽었다.** DNS 레코드가 없다. PyPI로 받아야 한다
- **PlatformIO는 Python 3.14를 지원하지 않는다.** 3.11 전용 venv를 썼다
  (`%USERPROFILE%\.pio-venv`)
- **`SIMPLELAY_ACT_MODE`를 안 켜면 실물이 안 움직인다.** 기본값이 mock이라 화면상으로는
  전부 성공한 것처럼 보인다 — 가장 헷갈리는 실패 모드다
- **백엔드에 CORS 미들웨어가 없다.** 키오스크를 다른 포트로 띄우면 `/status`·`/events`가
  전부 막힌다. `/kiosk`로 같은 오리진에서 서빙하는 이유가 이것이다
