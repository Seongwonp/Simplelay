# SimpleLay UI 전면 재설계 실행계획

작성 2026-10-23. 사용자 승인: UI 변형 금지, 기존 탭·팔레트 고정 제약 해제. ‘복잡하고 보기 힘들다’는 반복 피드백을 해결한다. 사용자를 위한 승인·정지·실제/연습 구분이나 HW 원본 유지 원칙을 해제한 것은 아니다.

**후속 사용자 확정:** 기본은 **‘할 일 먼저’**. 설정 진입은 글자 없이 톱니바퀴 아이콘(48dp 터치 영역·‘설정’ 접근성 이름 유지). 설정은 탭 바깥 독립 화면으로 열어 이전 탭의 선택 상태를 보여 주지 않고, 뒤로 가면 들어온 탭·가전 상세로 돌아간다. 키오스크는 한 번 조작한 뒤 첫 화면을 거쳐 다시 가전을 고르게 하지 않고 **같은 가전에서 추가 조작**을 이어가는 것이 필수다.

## 1. 목표와 현상

[국내 앱 비교](국내앱-UI-비교와-SimpleLay-적용안-2026-10-23.md)·[독립 UI 평가](UI-독립평가-2026-10-23.md)를 읽고 현재 홈·루틴 골든과 코드를 확인했다. 홈에서 환경·예약·설정 안내·가전 뒤에 실행 동작이 놓이고, 루틴/자동 실행의 내부 구분을 설명문·범례로 배우게 한다. 독립 평가 점수는 사용성 실측이 아니며 기존 테스트 통과를 쉽다는 증거로 사용하지 않는다.

목표는 **원하는 가전 조작을 찾고 → 무엇을 할지 확인하고 → 실행·정지·결과를 이해하는 일**을 쉽게 만드는 것이다. 카드 몇 개를 없애는 작업으로 축소하지 않는다. 새 기능·추천 알고리즘·서버 데이터 모델을 늘리지 않는다.

## 2. 정보 구조 후보

폰 기본 후보는 `홈 / 가전 / 자동 실행 / 기록`, 설정은 상단의 이름 있는 진입점이다. 기존 ‘루틴’ 탭에 섞인 목적을 분리한다. 이 4개는 예전 4탭 규칙을 유지한 결론이 아니라 이번 동선 설계 후보이며 샘플 확인 후 확정한다.

| 영역 | 사용자 의도 | 기본에 보일 것 | 상세로 옮길 것 |
|---|---|---|---|
| 홈 | 지금 무엇을 할까 | 실행 중 작업·정지, 중요한 연결/차단, 제안이 있으면 제안, 저장한 동작 바로 실행 | 환경 자세히, 전체 예약, 보정/설정 목록 |
| 가전 | 이 가전을 직접 조작 | 등록한 가전의 이름·위치, 선택 후 주 조작 경로 | 종류·내부 ID·연결 방법·노드·보정·삭제 |
| 자동 실행 | 언제/어떤 조건에 실행할까 | 대상 동작과 시간/조건, 허용 여부, 명시적 편집 | 학습 근거·기술 경로·고급 조건 |
| 기록 | 무엇을 했고 결과는 어떤가 | 대상·행동·시각·결과 한 줄, 필요한 다음 행동 | 버튼별 단계·재시도·센서 원문·전송 경로 |
| 설정 | 연결·앱·알림을 관리 | 목적별 묶음, 현재 상태 | 개발자 도구·상세 진단 |

### ‘루틴’을 잃어버리지 않게 하기

- 저장한 순서 자체와 자동 실행 허용은 다른 데이터다. UI를 합쳐도 삭제·저장 의미를 합치지 않는다.
- 저장한 동작의 전체 목록·이름 변경·순서 편집은 홈의 ‘저장한 동작 전체’에서 접근한다. 자동 실행 탭에서도 연결된 동작의 상세로 이동할 수 있게 한다.
- ‘루틴’ 대신 ‘저장한 동작’ 또는 ‘자주 하는 일’은 **표시 이름 후보**다. 사용빈도에 따른 실제 즐겨찾기 기능을 새로 만들거나 모든 항목을 자주 사용했다고 주장하지 않는다.
- 자동 실행은 ‘정해진 시간’과 ‘상황에 따라’의 사용자 관점으로 묶되, 기존 API가 지원하는 조건만 표시한다. 시간 루틴과 조건 규칙의 서버 출처는 어댑터에서 구분한다.
- ‘오늘만 건너뛰기’는 오늘 해당 예약만, 자동 실행 끄기는 앞으로의 허용 해제다. 같은 스위치·같은 확인 문장으로 통합하지 않는다. 스위치는 가전 전원이 아니라 자동 실행 허용임을 표시한다.

## 3. 화면 표현 원칙

1. 평상시 홈의 첫 선택은 실행 가능한 동작 또는 가전이다. 연결·설정 패널이 항상 상단을 점령하지 않는다. 긴급 차단과 진행 중 정지는 예외로 최우선이다.
2. 대상·한 일·주 행동이 한 묶음이다. 실행하기/편집/삭제/자동 실행을 동일 비중으로 늘어놓지 않는다. 주 행동1개, 보조 행동은 명시적인 상세에서 제공한다.
3. 색은 장식보다 선택·행동·상태를 구분한다. 상태를 색만으로 전달하지 않는다. 배지와 안내문으로 같은 사실을 반복하지 않는다.
4. 사용자 문장은 한 줄 결과와 다음 행동으로 나눈다. ‘미확인’은 실패·성공·꺼짐이 아니고, 누름 완료는 조리·세탁 완료가 아니다.
5. 물리 버튼 누름과 ThinQ 직접 제어는 사용자 목표를 중심으로 보이되 확인 가능한 결과·조작 가능 여부는 거짓으로 통일하지 않는다.
6. 큰 글씨는 글자를 줄여 끼우지 않고 줄·행·버튼을 재배치한다. 사진 조작의 접근성 대체 버튼 목록은 유지한다.
7. 핵심 버튼은48dp 이상을 설계 목표로 하고 실측한다. 새 폰 본문은18sp를 출발점으로 실제 화면에서 검토한다. 이는 표준 인증 완료 주장이 아니다.

## 4. 샘플 범위와 선택

서버·실물 가전에 연결하지 않는 인터랙티브 샘플 두 안을 비교한다.

- **할 일 먼저:** 홈에서 저장한 ‘30초 데우기’ 등 목적 행동을 먼저 발견. 가전 직접 조작은 다음 구획.
- **가전 먼저:** 홈에서 전자레인지·공기청정기를 먼저 고르고, 해당 가전 조작으로 들어감. 다수 가전을 직접 다루는 사람에게 적합한지 확인.

두 안 모두 홈/가전/자동 실행/기록, 승인→실행 중→정지 요청, 설정 진입을 누를 수 있다. 같은 샘플 데이터로 비교한다. 상태 선택에서 제안·연결 끊김·결과 미확인도 보고 큰 글씨로 전환한다. 미리보기는 사용자 시험이나 Flutter 구현이 아니다. 사진 매핑·음성 인식·자동 시간 경과·실제 센서 결과를 흉내 내서 완료라고 보고하지 않는다.

## 5. 구현 순서와 완료 게이트

### 키오스크 연속 조작 계약 — R7 필수

현재 `kiosk_screen.dart`의 결과 닫기(`onDismiss: _toIdle`), 사람 확인 완료(`_onDoneChecked`), 성공 결과 타이머가 첫 화면으로 보낸다. 실패에서 수동 조작으로 가는 경로도 가전이 여러 대면 선택값을 비운다. 사용자가 지적한 재진입 비용은 실제 복귀 경로와 일치한다. 모든 결과가 같은 조건으로 자동 복귀하는 것은 아니며 실패·사람 확인 대기는 현재 타이머가 없는 예외다.

- 직접 고른 가전에서 실행했다면 결과 화면의 기본 다음 행동은 **‘이 가전 계속 조작’**. 보조 행동은 **‘다른 가전 고르기’**, 사용 종료는 **‘처음 화면으로’**로 구별한다. 성공 결과를 닫거나 사람 확인을 마쳤을 때 첫 화면을 강제하지 않는다.
- 계속 조작은 **직전 명령 재전송이 아니라 조작 화면으로 돌아가는 탐색**이다. 예: 전자레인지 동작→결과 확인→같은 전자레인지 조작판→다음 명령 선택. 전에 누른 버튼을 다시 누르거나 자동으로 실행하지 않는다.
- 가전 ID·들어온 조작 화면·선택 구획을 별도 복귀 문맥으로 보관하고 실행 job 대상과 섞지 않는다. 복귀 시 최신 설치 목록과 연결/준비 상태를 재확인한다. 삭제·미등록이면 가전 선택으로, 전자레인지 기본값으로 대체하지 않는다.
- 폰에서 시작한 외부 실행이나 자발적 제안은 ‘직접 조작하던 화면’이 없을 수 있다. 단일 대상이 확인되면 **대상 가전 조작 화면 보기**, 여러 가전 루틴이면 **사용한 가전 중 고르기**로 연결한다. 마지막 선택값이나 마지막 단계 가전을 임의로 채택하지 않는다.
- 실패·결과 미확인·정지 미확인은 사실을 유지한다. 조작 화면에 돌아가는 것과 새 실행 허용은 별개다. 차단·비상정지·진행 중 작업 확인을 그대로 적용하고, 연결이 끊겼다고 새 명령을 재전송하지 않는다.
- 사용 중 화면을 자동으로 초기화하지 않는다. 공용 키오스크의 무사용 복귀 시간·남은 시간 안내·연장/취소는 따로 결정한다. 필요한 미확인 결과를 타이머로 지우지 않는다. **복귀 동선 개편을 기존 타이머 숫자 조정으로 끝내지 않는다.**
- 시험: 동일 가전 추가 조작, 다른 가전 전환, 명시적 처음 화면, 실패/정지 후 복귀, 외부 실행, 다중 가전, 대상 삭제, 연결 끊김, 새 제안 대기, 큰 글씨에서 결과/버튼/초점 유지. 계속 조작 버튼만 눌러서는 실행 API 호출이0회여야 한다.

| 순서 | 작업 | 완료 조건 |
|---|---|---|
| R0 | 사용자 승인·샘플·구조 확정 | 두 안 중 기본 방향 선택. 실행·정지·자동 끄기·기록 위치를 설명 없이 찾는지 관찰 |
| R1 | 공통 화면틀·타이포·간격·버튼·탭 | 라이트/다크·360/390/430폭·200%에서 겹침 없음. 기존 경로를 새 경로로 연결 |
| R2 | 폰 홈·가전 목록·상세·저장한 동작 | 기존 등록 가전·빈 상태·서버 전용 가전·긴 이름·미설정·직접 조작·사진/대체 버튼 동선 유지 |
| R3 | 승인·실행·정지·결과 | 승인 시 대상/실행 순서·연습 표시. 실행은 job 대상. 미응답/정지 미확인/동시 요청 회귀 유지 |
| R4 | 자동 실행 통합 표시·편집 | 두 서버 모델 왕복. 오늘 건너뛰기/계속 끄기 구별. 기존 설정·저장 동작을 잃지 않음 |
| R5 | 기록·설정·도움말·가전 추가 | 기록의 결과 신뢰 수준 유지. 진단은 관리로 이동. 신규/기존 가전 추가 흐름 완주 |
| R6 | 개발자 도구의 별도 작업 화면 | 일반 앱에서 분리. 조작/좌표 등록/로그를 작업 중심으로 재배치. HW 원본·프로토콜·모션 정책 변경은 별도 승인 범위 |
| R7 | 키오스크 전면 재배치 | 폰 축소판이 아님. 대기/제안/실행/결과/차단별 주 행동. 실제15.8형에서 거리·버튼·통풍 가림 아닌 UI 가독 확인 |
| R8 | 전과업 회귀·배포·사용성 확인 | 아래 과업·테스트·실기기 확인. 배포는 대상·버전을 기록하고 요청 시 수행 |

단계마다 작은 검증 가능한 커밋. UI 코드 이동과 동작 변경을 섞은 대규모 기계적 치환은 피한다. 기존 provider·service·API를 재사용하고 화면용 표시 모델이 필요할 때만 얇게 추가한다. 동작을 고쳐야 한다면 별도 결함으로 기록한다.

## 6. 회귀·인수 기준

- 먼저 기존 관련 시험을 실행해 기준을 남긴다. 동작 변경 회귀는 수정 전 실패를 확인한다. 시각 변경은 의도된 차이를 검토한 뒤 해당 골든만 갱신한다. 레이아웃 변경을 실패 시험 기대문구 변경만으로 통과시키지 않는다.
- 폰·키오스크 analyze error/warning0, 기존 info는 구분해서 기록. 관련 단위/위젯 시험→해당 앱 전체 비골든→골든 무갱신 재비교. 서버 계약·표시 어댑터를 바꾸면 백엔드 관련·전체도 실행한다.
- 연결 안 됨·가전0대·실행 불가·긴 이름·연습·실행중·정지 요청중·물리정지 미확인·일부실패·데이터 없음/불러오는 중을 기본 상태로 다룬다. 모름을 숨겨 정상처럼 보이게 하지 않는다.
- 화면 읽기 순서·초점 이동·라벨·48dp 목표·라이트/다크 대비·200% 재배치 확인. TalkBack 실기기 확인은 위젯 시험 통과와 별도로 기록한다.
- 처음 쓰는 사람3~5명에게 ①즉석밥 데우기 ②방금 작업 정지 ③오늘만 건너뛰기 ④앞으로 자동 실행 끄기 ⑤어제 결과 미확인 설명을 시킨다. 첫 누름·되돌아감·도움·오해를 기록하고, 팀원이 설명한 성공은 독립 성공으로 세지 않는다. 관찰 전 성공률·소요시간 개선 수치를 쓰지 않는다.
- 가장 쉬워 보이는 샘플을 고르는 것과 사용성이 검증된 것은 다르다. 위젯/골든으로 실기기 사용성·모터 누름 성공을 보증하지 않는다.

## 7. 이번 단계에서 하지 않는 것

샘플 승인 전 Flutter 전체 일괄 교체·골든 대량 갱신·기기 배포를 하지 않는다. UI를 단순하게 보이게 하려고 음성 지원·실제 가전 반응·개인화 성능을 과장하지 않는다. HW 코드·보안 설정·실행 상한을 변경하지 않는다. 비공개 원본 사진·제공 문서를 샘플·외부 서비스에 전송하지 않는다.
