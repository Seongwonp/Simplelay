# 결선 로드맵 (2026-08-20 ~ 10-30)

> 2026-08-20 전체 코드 리뷰 결과를 반영해 수립한 10주 계획.
> 기존 [roadmap.md](roadmap.md)(마일스톤 M1~M6)를 대체하지 않고, **날짜 축으로 실행 순서를 고정**하는 문서다.
> 진행 기록은 `devlog_YYYY-MM-DD.md`에 남긴다.

## 원칙

1. **기능 추가보다 데모 경로 소생이 먼저.** 리뷰에서 확인된 죽은 기능(선제 제안·긴급 정지·폐루프 실배선)을
   8월에 살리고, 9월에 실기기를 배선하고, 신규 기능은 10월 초 안정된 토대 위에만 얹는다.
2. 각 스프린트는 **"이번 주가 끝나면 무엇이 시연 가능해지는가"(완료 기준)** 로 정의한다.
3. 8/18 지도교수 미팅 방향 준수 — AI는 지금 수준을 "그대로 쓰는 모듈"로 고정. W3의 의도해석 작업은
   새 AI 개발이 아니라 **이미 구현된 모듈(Tiered/Vectordb)을 deps에 꽂는 배선 작업**이다.
4. 매 작업 세션마다 devlog에 기록한다.

## W0 — 8/20~8/24 · 긴급 수리 스프린트

**완료 기준: 릴리즈 APK로 폰→RPi5 mock 실행이 성공하고, 제안이 화면에 뜨고, 정지 버튼이 실제로 멈춘다.**

- [ ] ① 매니페스트 수정 — main AndroidManifest에 INTERNET 권한 + cleartext 허용. 직후 릴리즈 APK 실기기 리허설 1회
- [ ] ⑧ BLE 데모 래치 해제 — `connect()`에 `_isSimulated = false` + connectionState 구독 정리
- [ ] ③ `/stop` 실구현 — 협조적 취소 플래그(버튼 사이 체크) + UART 모드 abort. UI는 응답 확인 후에만 "정지됨"
- [ ] ④ 제안 생성 스케줄러 — lifespan 주기 태스크로 `create_suggestions()` + 데모용 `POST /demo/suggest`
- [ ] 키오스크 `_finishExecuting` phase 가드 / reject의 private 접근을 서비스 메서드로 / 승인·거부 try-catch

## W1 — 8/25~8/31 · Job 모델 전환

**완료 기준: 폰이 시작한 실행을 키오스크가 실시간으로 같이 보여주고, 30초짜리 실행도 타임아웃 없이 완주.**

- [ ] ⑥ `POST /execute` → 즉시 job_id 반환, 백그라운드 실행, `/status`에 job_id·진행 단계 포함. 실행 가드 락으로 원자화
- [ ] ⑦ 폰 실행 상태 화면을 HTTP `/status` 폴링으로 전환 (BLE는 보조 채널로 강등)
- [ ] 키오스크 상시 `/status` 폴링(폰 발 실행 감지) + job_id 대조로 stale-result 레이스 제거
- [ ] 키오스크 에러 배너 + 30초 무진전 탈출 타임아웃, 폴링 오버랩 가드
- [ ] 진행바를 가짜 애니메이션 대신 실제 completed_steps 데이터로

## W2 — 9/1~9/7 · 키오스크 실기기 확정

**완료 기준: RPi5 전원만 꽂으면 Flutter 키오스크가 자동으로 뜨고, 크래시해도 되살아난다.**

- [ ] ⑤ Flutter 키오스크 ipk 빌드 → RPi5 첫 구동. **이번 주 중반까지 안 되면 HTML 키오스크 후퇴 결정** — 병존은 이번 주로 종료
- [ ] `setup_rpi.sh`에 키오스크 설치·자동실행 단계 — systemd(`Restart=always`), 화면 절전 해제, 온스크린 키보드 옵션. 백엔드 유닛도 always + logrotate
- [ ] ② mDNS 의존 제거 — unreachable 카드에서 IP 직접 입력 동선 + `multicast_dns` 앱 내 조회
- [ ] 라이트 모드 색상 수리(수동 조작·제안 버튼맵) / 가전 등록 사진 문서 폴더 복사 저장
- [ ] 카운트다운·복귀 상수 단일화 / 키오스크 API 서비스 생성자 주입

## W3 — 9/8~9/14 · 실기기 배선 스프린트
