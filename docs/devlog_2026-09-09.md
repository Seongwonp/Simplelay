## B1. 사용 이력이 '어떤 가전에서' 했는지까지 기록 (`31ef267`)

제안↔가전 결합(9/8, `0b87bd3`)으로 환경 제안은 대상을 들고 다니게 됐지만,
**사용 이력에 가전이 없어** 패턴 제안은 여전히 대상을 몰랐다. 화면은 현재 선택
가전으로 폴백해 그렸다 — 가전 한 대만 쓸 때는 대개 맞지만, 전자레인지와 에어컨을
함께 쓰기 시작하면 "저녁마다 하던 그것"이 엉뚱한 가전의 버튼 지도를 달고 나온다.

사슬 전체를 이었다: **실행 → 이력 → 패턴 후보 → 제안 → 승인 실행 대상.**

- `UsageRecord.appliance_id` 추가, 동기·비동기(job 스레드) 두 경로에서 기록
- SQLite `usage_log`에 열 추가 + **기존 DB용 ALTER 마이그레이션**.
  `CREATE TABLE IF NOT EXISTS`는 기존 테이블을 손대지 않으므로, 마이그레이션이
  없으면 실기기에 이미 깔린 DB는 열자마자 깨진다. 파일을 지우게 하면 그동안
  쌓인 학습 이력이 날아간다.
- `PatternDetector`가 목적별 **가장 최근** 실행 가전을 후보에 싣는다.
  최빈값이 아니라 최신인 이유: 같은 루틴을 다른 가전으로 옮겨 쓰기 시작했다면
  사용자가 뜻하는 대상은 최신 쪽이다. 실패한 실행은 횟수에서 빠지므로 대상
  추정에서도 뺀다.
- 가전 없이 쌓인 옛 기록만 있으면 `None` — **대상을 지어내지 않는다.**
  그때만 클라이언트가 현재 선택 가전으로 폴백한다.
- `POST /demo/suggest`도 `appliance_id`를 받는다 → 가전 여러 대를 번갈아
  보여주는 연출이 가능해졌다.

목적 없는 버튼 직접 실행은 종전대로 학습에서 제외한다(패턴 제안은 되풀이 가능한
'말'을 전제로 한다).

## A3. 왜 추천했는지, '안 받기'가 무엇을 약속하는지 (`99ca843`)

서버는 `time_band`·`occurrences`를 주는데 앱이 옮기며 **버리고 있었다.**

- **"최근 저녁 시간에 4번 하셨어요."** 한 문장으로 표시.
- **데모 제안은 일부러 비운다.** 데모 트리거는 패턴 감지를 우회하려고 횟수를
  지어내는데, 그 숫자를 "이만큼 하셨어요"로 보여주면 화면이 사실이 아닌 말을
  하게 된다. 리뷰가 안티패턴으로 지목한 "앱에서 못 받는 데이터를 데모 값으로
  보충"과 같은 부류다.
- '다시 받지 않기'를 **영구 억제를 실제로 지킬 수 있는 제안에만** 내건다.
  BLE 경로에서는 '이번만 넘기기'와 똑같은 `approved: false` 메시지라, 버튼이
  있으면 지키지 못할 약속이 된다.
- 억제 직후 **"앞으로 표시하지 않아요 · 되돌리기"**. 설정 화면까지 찾아
  들어가야 되돌릴 수 있으면 되돌릴 수 있는 게 아니다.
- 억제 목록의 **불러오는 중 / 조회 실패 / 없음**을 구분. 셋을 빈 목록으로
  뭉개면, 조회가 실패한 화면이 "억제한 게 없다"고 단언한다.

### 키오스크도 같은 문장으로 (`536678e`)

키오스크는 "이 시간대에 3번 하셨어요."라고 했는데 **무슨 시간대인지 알려주지
않았고**, 데모 제안에서도 그대로 나왔다. `occurrences` 기본값이 1이라 횟수를
모르는 제안이 "1번 하셨어요"라고 말하기까지 했다. 폰과 같은 규칙으로 맞췄다.

## A5. 실제 위젯의 색 대비 (`99ca843`)

리뷰가 짚은 3건을 재현해 보니 **원인이 하나**였다: 강조색을 면으로 쓸 때 얹는
글자색이 모드와 무관하게 검정 고정. 다크 모드의 강조색(골드 `#D9A356`, 브릭
레드 `#D9605C`)은 밝아서 검정이 맞지만, 라이트 모드 전용 변형(`#8B6010`,
`#B93A34`)은 어두워서 흰색이 맞다.

`context.appOnAccent`(다크=검정 / 라이트=흰색) 토큰으로 통일했다. 테마가 이미
`onPrimary`에 같은 규칙을 쓰고 있었는데 위젯들만 안 따르고 있었다.

| 위치 | 전 | 후 |
|---|---|---|
| 제안 지도 순서 배지 | 3.78:1 | 9.32 / 5.56 |
| 홈 알림 개수 배지 | 3.63:1 | 5.78 / 5.65 |
| 홈 주요 실행 버튼 | 3.78:1 | 9.32 / 5.56 |
| 첫 실행 시작 버튼·스피너 | 4.93:1 | 9.32 / 5.56 |
| 설정 억제 빈 상태 | 2.38:1 | 8.22 / 7.44 |
| 제안 단계 타임라인 순서 원 | 4.23:1 | 9.32 / 5.56 |

마지막 둘은 조사하다 나온 것이다. 타임라인 원은 18% 틴트 위에 같은 강조색
숫자를 얹는 구조라, 틴트를 옅게 해도 강조색 자신이 상한(5.41:1)이라 여유가
없었다 — 면을 채우고 대비색을 얹는 쪽으로 바꿨다.

`test/theme/contrast_test.dart`에 **실제 위젯 조합** 그룹을 추가하고, 예전 값도
"이렇게 하면 미달"로 함께 박아 회귀를 막는다. (기존 그룹은 토큰 쌍만 봤다 —
팔레트는 통과하는데 위젯은 떨어지는 상황이 실제로 그래서 생겼다.)

## B7. 가짜 센서 주입을 명시적 데모 세션으로 (`1b7f8b3`)

데모 실행 흐름(가짜 센서·가짜 성공)이 `kDebugMode`에만 걸려 있었다. **실기기에
물린 디버그 빌드에서도 섞인다** — 실제로는 버튼이 안 눌린 실행이 화면에서
성공으로 끝날 수 있다. 폐루프의 존재 이유가 "눌림을 확인했는가"인데, 그 확인을
화면이 위조하게 되는 셈이라 위험도가 크다.

- `demoModeProvider`: 기본 꺼짐. `--dart-define=SIMPLELAY_DEMO=true`로 기본값을
  켜거나 설정에서 토글(기기에 저장). 백엔드 `SIMPLELAY_*` env 게이트와 같은 규칙.
- 데모 섹션을 디버그 빌드 조건 → **고급 설정**으로. 결선 리허설은 릴리즈 APK로
  하는데 디버그에만 있으면 정작 필요한 곳에서 못 켠다.
- 켜져 있는 동안 실행 화면 상단에 **"데모 모드 — 실제 조작이 아닙니다"** 를
  계속 표시(스크린리더에도 알린다).

## A4 일부. 맡긴 작업을 잃지 않기 (`370183e`, `34268ee`)

**진행 중 job 보존** — 실행은 수 초~수십 초 걸리고 그 사이 앱이 내려갈 수 있다
(사용자가 홈으로 나가거나 OS가 정리). job_id를 잃으면 물리 조작은 계속되는데
화면은 "실행한 적 없음"으로 돌아온다. 가전 앞에 서 있는 사람에게 가장 나쁜
상태다.

- 실행 시작 시 job_id·이름을 기기에 남기고, **결말이 나면** 지운다.
  '확인 불가'는 아직 결말이 아니므로 남긴다 — 앱을 다시 열면 또 확인해야 한다.
- 앱 시작 시 남은 job을 되읽어 폴링을 이어붙인다. 서버 주소는 기기에서 비동기로
  읽히므로 준비되는 시점을 기다렸다 붙는다.
- 추적기를 **앱 시작부터** 살려둔다. 상태 화면을 열어야 만들어지면 앱을 다시 연
  사용자는 홈에서 아무 흔적도 못 본다.

**실패한 이력의 단계별 확인 결과** — 폐루프는 버튼마다 눌림을 확인하고 필요하면
다시 누른다. 그 기록이 이미 `/history`에 들어 있는데 화면은 결과 한 줄만
보여줬다. 끝이 안 좋았던 실행에만 단계를 펴고(확인됨 / N번 만에 확인 / 확인
못 함) 아래에 '버튼으로 직접 조작'을 둔다. 성공한 이력은 그대로 한 줄이다 —
전부 펼치면 목록이 다시 개발 도구처럼 보인다.

'눌렀지만 확인 못 함'과 '아예 못 누름'을 가를 재료는 아직 없어서, 확인 여부까지만
말한다.

## 곁가지로 잡은 것 — `pip install -e .` 가 통째로 실패하고 있었다 (`2eb5207`)

리포 루트 `.venv`를 다시 만들다 드러났다. `pyproject.toml`에서 `dependencies`가
`[project]` 안의 배열이 아니라 **`[project.dependencies]` 테이블로 감싸여 있어**
setuptools가 `must be array`로 거절한다.

`scripts/setup_rpi.sh:89`가 `pip install -e "$REPO_DIR"` 로 기기를 세팅하므로,
**실기기 초기 설치 경로가 막혀 있었다.** 개발 PC에서는 시스템 파이썬에 이미 깔린
패키지로 테스트가 돌아 드러나지 않았다.

- `dependencies`를 `[project]` 안으로
- 패키지 지정이 `[tool.poetry]`에 있었다(빌드 백엔드는 setuptools) →
  `[tool.setuptools.packages.find]`. 리포 루트에 `app/`·`docs/` 등 비-파이썬
  최상위 디렉터리가 많아 자동 탐색은 실패한다
- `test` extra에 `dbus-fast` 추가 — D-Bus 인코딩 테스트가 실제 `Variant` 타입을
  쓰는데, 깨끗한 venv에서는 그 테스트만 조용히 실패했다

검증: 새 venv에 `pip install -e ".[test]"` 후 652개 통과.
