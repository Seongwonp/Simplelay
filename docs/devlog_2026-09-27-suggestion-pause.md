# 공감지능 피드백 1단계: 제안 30분 쉬기

## 이번 구현

2차 조사 검토 후 기존 습관 제안·피드백 기록·상황 철회·영구 억제를 재사용했다. 새 학습 모델이나 다가전 실행기를 만들지 않고, 앱과 키오스크에서 서버 제안을 30분 쉬는 흐름을 추가했다.

- `POST /suggestions/{id}/snooze`: 현재 pending 카드만 처리. 기간은 이번 버전에서 30분 고정이며 실행 예약 API가 아니다.
- 적용 범위는 같은 가전·목적·시간대다. 다른 가전·시간대까지 끄는 기능이 아니다.
- 기존 영속 쿨다운 저장을 먼저 완료하고 카드를 제거한다. 저장 실패 시 카드를 유지한다.
- 이벤트는 `snoozed / user_pause_30_minutes`. 거절, 승인, 무응답이나 음의 학습 보상으로 변환하지 않는다.
- 예전 카드의 승인은 거부된다. 기한 후에도 기존 패턴·재실·실행 이력 등의 조건을 통과해야 새 카드가 생성된다. 새 승인 없이 실행하지 않는다.
- 앱·키오스크에 '이 제안 30분 쉬기' 추가. BLE 및 명시적 시연 카드에는 이 기능을 내걸지 않는다. 앱 HTTP 404는 오래된 카드를 정리하되 쉬기 성공 메시지를 표시하지 않는다. 키오스크 실패는 카드와 오류 안내를 유지한다.

## 검증

- 백엔드 전체 1,551 통과, 기존 경고 2개. 벤더 dbus_fast 경로 포함.
- 새 백엔드 회귀 8개: 기한 경계, 이전 승인 무효, 상황 변화 3종, 저장/복원 및 범위 분리, 저장 실패, 동시 처리, API 인증·중복 처리(매개변수화 포함 총 8건).
- 앱 관련 23개 통과: 제안 화면 및 API 서비스.
- 키오스크 관련 51개 통과: 제안 화면·화면 전이, API 실패 후 재시도, 실행/거절 경로와 구분, 작은 화면·큰 글씨 회귀 포함.
- analyze 오류·경고 없음. 기존 info 앱 5개, 키오스크 1개.
- 실제 휴대폰·RPi 터치 및 브라우저 배포본은 이번 변경으로 재검증하지 않았다. SW 테스트는 실제 가전 동작·안전성·사용성 검증이 아니다.

## 다음 단계와 보고서 적용 조건

1. '이번 구성 수정'은 승인 대상·동작·인자를 명시한 새 미리보기를 만들고 재승인을 받는다. 오늘 선택을 영구 선호로 바꾸지 않는다.
2. 저녁 휴식 시나리오의 관측 가능한 맥락부터 선정한다. 재실 센서 없이 '거실에 왔다'고 단정하지 않는다.
3. 두 가전의 실제 실행은 부착 장치 수·제어 경로 확보가 조건이다. 한 장치만 있으면 실물 한 대와 모의 한 대를 구분한다.
4. 가전별 준비 상태·결과를 표시하고 일부 성공/결과 불명 상태를 전체 성공으로 합치지 않는다.
5. 실행 전 취소, 실행 중 정지 요청, 설정 복구를 구분한다. 물리 동작에 보편적인 '되돌리기'를 약속하지 않는다.
6. 무응답·직접 조작을 임의의 부정/긍정 학습 레이블로 바꾸지 않는다. 승인/표시 비율은 정밀도가 아닌 수락률이다.

이번 단계에는 제안 점수 갱신·개인 식별·5분/1시간 선택·다중 가전 계획 수정이 포함되지 않는다. 기존 CoreXY·하드웨어 문서 미커밋 변경과 함께 작업 트리에 남아 있으며 커밋·푸시는 하지 않았다.
