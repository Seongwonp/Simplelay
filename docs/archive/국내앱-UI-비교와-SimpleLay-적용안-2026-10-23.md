# 국내 앱 UI 비교와 SimpleLay 적용안

확인일: 2026-10-23. 대상: 폰·키오스크 정보 구조와 조작의 발견 가능성. 코드 수정 없이 조사했다.

## 먼저 적용할 결론

1. 홈에서는 관리 정보보다 지금 실행할 일을 먼저 찾게 한다. 실행 중 정지·차단 경고·제안의 우선순위는 유지한다.
2. 루틴은 설명문을 늘리기보다 실행·편집·자동 실행 설정의 차이를 배치와 행동 이름으로 드러낸다.
3. 같은 상태를 긴 본문·칩·보조 줄에서 반복하지 않는다. 미확인이라는 사실과 다음 행동은 남긴다.
4. 누르는 곳과 읽기만 하는 상태 표시를 구별한다. 작은 ‘편집’ 글씨나 버튼처럼 보이는 상태 칩을 피한다.
5. 아래 앱의 겉모양을 복제하지 말고, 팀 밖 사람이 설명 없이 과업을 끝내는지 확인한 뒤 적용한다.

## 조사 범위와 한계

- 국내에서 서비스하는 실제 앱 7개를 조사했다. 공공 가이드·논문 대신 운영사의 공개 안내, 앱스토어 공개 화면, 실무자의 사용자 관찰을 중심으로 봤다.
- **공개 화면을 브라우저에서 확인한 것과 설치된 앱을 직접 사용한 것은 다르다.** 로그인·송금·주문·기기 제어는 하지 않았다. 앱스토어 화면은 홍보용 예시이며 최신 배포 앱 전체를 대표하지 않는다.
- KB 자료는 2023년, ThinQ 개편 자료는 2025년 자료다. 현재 화면과 완전히 같다고 주장하지 않는다. SmartThings는 공식 기능 설명만 확인했으므로 세부 화면 배치를 관찰했다고 쓰지 않는다.
- ‘쉬워 보임’, ‘복잡해 보임’은 디자인 판단이다. 유명 앱이라는 이유로 고령자·저시력 사용자에게 쉽다고 결론 내리지 않는다. 시각장애인의 화면 읽기 경험은 이미지로 검증할 수 없다.
- SimpleLay의 당시 문제 근거는 [UI 검토 기록](UI-독립평가-2026-10-23.md)이다. 아래 제안은 추가 수리를 마쳤다는 보고가 아니다.

## 실제 국내 서비스의 사용자 관찰도 함께 볼 것

[토스: 시니어 사용자가 어려워하는 UX 5가지](https://toss.tech/article/senior-usability-research), 박서현, 2024-12-23.

운영사 UX 리서처가 대면 사용성 점검에서 관찰한 사례다. 글씨·화살표를 누를 수 있는지 모르는 경우, 태그를 버튼으로 오인하는 경우, 예시 내용을 실제 정보로 받아들이는 경우, 설명을 질문으로 읽는 경우, 아래 내용이 있다는 것을 모르고 스크롤하지 않는 경우를 다룬다. 글의 ‘시니어’는 50대 이상이며, 이를 우리 대상 사용자 전체의 결과로 일반화하지 않는다.

SimpleLay에 적용할 판단:

- ‘봐 주세요’ 칩이 행동이면 실제 버튼이어야 하고, 상태면 버튼처럼 보이지 않아야 한다.
- 화면 아래에 루틴이 있다는 사실을 모른다면 스크롤 기능이 있어도 충분하지 않다. 홈의 순서를 먼저 고친다.
- 연습 화면은 실제 실행과 구분되게 표시한다. 예시 가전과 실제 등록 가전도 혼동시키지 않는다.
- 실제 승인 질문은 유지한다. 도움말 진입점까지 질문형으로 만들 필요는 없다. ‘근거 전체 보기’처럼 행동을 명시한다.

## SimpleLay 화면별 최소 적용안

관련 줄 번호는 [UI 검토 기록](UI-독립평가-2026-10-23.md)의 검토 시점 기준이다. 변경 직전 다시 확인한다.

| 우선순위·화면 | 구체적인 배치·문구 방향 | 근거 사례 | 관련 코드 | 확인할 것 |
|---|---|---|---|---|
| 1 · 폰 홈 | 실행 중 상태·정지는 최우선. 평상시 제안이 있으면 먼저, 없으면 기존 실행 가능 루틴을 가전 목록보다 앞에 둔다. 환경·예약·설정 안내의 반복을 줄인다. 새 추천 순위는 만들지 않는다. | ThinQ의 사용/관리 구분, KB의 대표 과업 우선 | `app/lib/screens/home_screen.dart` | 일반 높이와 200%에서 실행할 루틴을 찾는가. 연결 실패·차단 경고가 밀리지 않는가. |
| 2 · 폰 루틴 | 이름 → 조건 → 해당 루틴 실행 순서. 편집은 보조 행동. 범례·배지·스위치 옆 같은 뜻의 문구가 겹치는지 정리한다. 내부 구획 이름 변경은 먼저 이해도를 확인한다. | 토스의 대상/행동 연결, 당근의 목록 위계 | `app/lib/screens/routines_screen.dart` | ‘오늘만 실행하지 않기’와 ‘앞으로 자동 실행 끄기’를 구별하는가. 두 개념을 합치지 않는다. |
| 3 · 가전 상세 | 빈 루틴 안내와 저장 버튼을 세로로 배치해 ‘없/어요’ 줄바꿈을 없앤다. 사진 조작을 주 경로, 버튼판을 보조로 구분하되 접근성 대체 경로는 유지한다. | KB의 세로 메뉴, 토스 관찰의 클릭 가능성 | `app/lib/screens/appliance_detail_screen.dart` | 200%에서 이름·실행·저장이 읽히고, 보조 경로도 찾을 수 있는가. |
| 4 · 승인·기록 | 같은 대상·실행 설명의 반복을 줄인다. 기록은 무엇을 함 → 결과 → 필요한 다음 행동. ‘확인하지 못했어요’를 실패나 성공으로 바꾸지 않는다. | 토스의 정보 묶음, 카카오 T의 목적 중심 묶음 | `app/lib/screens/suggestion_screen.dart`, `app/lib/screens/history_screen.dart` | 사용자에게 ‘실제로 됐다는 뜻인가요?’를 물어 확인 수준을 오해하지 않는지 본다. |
| 5 · 키오스크 결과·비상 안내 | 지금 해야 할 행동 하나를 먼저 보여 준다. 본문과 상단 공통 띠 모두 연습/실제를 구분한다. 전자레인지에 모호한 ‘움직이는지’ 대신 실제 확인 대상에 맞는 문구를 쓴다. | KB의 과업 우선, 토스의 예시/실제 혼동 관찰 | `rpi5-touchscreen-app/lib/widgets/kiosk/done_view.dart`, `estop_banner.dart`, `hold_view.dart` | 촬영 거리에서 결과와 다음 행동을 읽는가. 실제 결과를 확인했다고 과장하지 않는가. |
| 6 · 폰 설정 | 공통 연결 문제와 각 메뉴의 같은 오류 설명이 반복되지 않도록 위계를 정리한다. 모르는 값을 ‘꺼짐’으로 바꾸지는 않는다. | ThinQ의 관리 분리 | `app/lib/screens/settings_screen.dart` | 공통 오류가 있어도 설정 메뉴를 찾는가. 인증 실패와 미설정을 혼동하지 않는가. |

위 내용은 정보 구조·배치·문구 정리다. 4탭과 기존 팔레트, 승인·정지 정책을 유지한다. 새 즐겨찾기·검색·간편 모드·푸시·알람은 추가하지 않는다. 승인이나 중요한 제한을 ‘더 보기’에 숨겨 탭 수만 줄이지 않는다.

## 앱을 참고한 뒤 실제 사람에게 확인할 최소 과업

팀 밖 처음 쓰는 사람 3~5명의 짧은 점검을 권한다. 가능하면 고령 사용자를 포함하되, 이 인원으로 전체 사용자에 대한 성능을 주장하지 않는다. 먼저 정답 경로나 메뉴 이름을 알려 주지 않는다.

| 과업으로 말할 것 | 기록할 관찰 | 통과 판단 방향 |
|---|---|---|
| ‘즉석밥을 데우려고 해요. 시작해 주세요.’ | 첫 누름, 되돌아감, 도움 요청, 승인 대상 설명 | 스스로 루틴을 찾아 무엇이 실행되는지 설명하고 승인하는가. |
| ‘방금 시작한 작업을 멈추고 싶어요.’ | 정지 위치 발견, 잘못 누름, 정지 결과 해석 | 정지를 찾고 ‘요청’과 ‘멈춤 확인’을 구별하는가. 모의로만 진행하며 실제 시간 보장은 별도다. |
| ‘오늘은 하지 않고 싶어요. 내일부터는 계속되면 좋겠어요.’ / 별도로 ‘앞으로도 자동으로 하지 않았으면 해요.’ | 두 과업에서 고른 조작, 범위에 대한 설명 | 일시 건너뛰기와 자동 실행 끄기를 혼동하지 않는가. 실제 제공되는 경로로 점검하고 없는 기능은 만들지 않는다. |
| ‘어제 한 일이 제대로 됐는지 알아봐 주세요.’ | 기록 찾기, 결과 읽기, 미확인 해석 | 버튼 조작과 실제 가전 반응을 구별하는가. |

처음 시도 뒤에만 ‘무엇을 누를 수 있다고 생각했나요?’, ‘이 결과가 무슨 뜻인가요?’를 묻는다. 전후 비교 시 과업·데이터·화면 크기를 맞추고 학습 효과를 기록한다. 팀원이 설명해서 성공한 경우를 독립 성공으로 세지 않는다.

골든은 배치 회귀를 잡는 도구다. 위 과업 성공·실폰 터치·TalkBack 낭독·실패널 가독성을 대신하지 않는다. 키오스크는 별도로 실제 촬영 거리에서 관찰한다.
