## 1. HIGH — 음성 정지 HTTP 실패를 성공으로 처리
- `app/lib/providers/execution_status_provider.dart:367`의 `emergencyStop()`이 `api.stop()` 예외를 잡고 정상 반환한다. `voice_stop_provider.dart:214`는 이를 성공으로 받아 `_sent=true` → 같은 실행에서 다음 "멈춰"를 무시한다.
- 음성 경로가 실패를 알 수 있게(반환값 또는 예외) 하고, 실패면 `_sent`를 세우지 않아 다시 말하면 재요청되게. 화면 정지 버튼 동작은 바꾸지 않는다.
- 시험: 기존 `app/test/providers/voice_stop_test.dart:109`는 `emergencyStop()`을 카운터로 덮어써서 이걸 못 잡았다 — 실제 provider와 가짜 API(실패→성공)로 시험.

## 2. MEDIUM — 음성 정지가 키오스크에서 시작한 실행을 못 봄
- `voice_stop_provider.dart:101`은 폰이 추적하는 작업과 `hovering_stop`만 본다. 서버 `/status`의 실행 중 상태(키오스크·루틴에서 시작한 것 포함)로 듣기를 켜고 끄게. `hold_state` 조회 실패 시 이전 값을 유지해 듣기가 남는 것도 정리(실패면 끄는 쪽).

## 3. LOW — "듣는 중" 표시와 부분 인식
- UI가 엔진 실제 상태 대신 자체 `listening` 값을 쓰고 엔진 `done`을 무시한다(`voice_stop_provider.dart:151`, `voice_service.dart:88`). 엔진 종료 시 표시도 끄고 재시작.
- 부분 결과가 "그만"이면 "그만 데워줘" 완성 전에 정지 요청이 나간다(`voice_service.dart:140`). 부분 결과로는 정지하지 않고 최종 결과(또는 짧은 무음 뒤)로만. 정지 지연이 조금 늘어나는 건 감수.
