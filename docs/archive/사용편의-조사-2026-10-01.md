# 사용 편의 조사와 리팩터링 계획 — 2026-10-01

이 문서는 두 조사를 합친 것이다. 하나는 외부 리서치(토스 UX 원칙, 스마트홈 앱의 첫 연결, 결과 화면, 시니어 접근성)이고, 다른 하나는 현재 폰 앱(`app/lib`)과 키오스크(`rpi5-touchscreen-app/lib`)의 마찰 점검이다.
리팩터링의 기준은 [UI 확정](UI-확정-2026-09-30.md)이고, 이 문서는 그 위에 "사용자가 할 일을 줄인다"는 원칙을 더한다.

**그 밖의 마찰**
- 온보딩 문구가 옛 기능과 RPi5 같은 전문 용어를 말한다.
- 키오스크의 숨은 동작(길게 누르기)을 화면에서 찾을 수 없다.
- 키오스크 동작 중 화면이 남은 시간이 아니라 흐른 시간을 보여 준다.
- 키오스크 "내 가전"이 사진이 아니라 버튼 격자다.
- 키오스크 성공 화면이 3초 만에 사라진다.
- 키오스크 시나리오 카드에 내부 id가 노출된다.
- 폰에 48dp 미만 터치 대상과 11px 글자가 남아 있다.

## 3. 리팩터링 단계 (Codex 작업 단위)

- **R1 문구와 용어 통일 (S).** 상태: 반영, analyze 오류·경고 0건. 위젯 실행·골든은 데스크톱 확인 대기. `docs/` 용어표를 하나 만들고, 폰과 키오스크가 함께 쓰는 문구를 정리한다. 고칠 것은 이렇다.
  - 같은 대상의 이름을 하나로 맞춘다: 허브, 누름 장치, 플러그.
  - 같은 행동의 이름을 하나로 맞춘다: 실행, 다음에, 정지.
  - 결과 문구를 사실대로 나눈다: "버튼을 눌렀어요" / "켜진 것을 확인했어요" / "눌렀지만 켜졌는지 확인하지 못했어요".
  - 온보딩과 옛 안내 문구를 고친다.
  - 에러 문구는 무슨 일이 생겼는지 → 왜 → 무엇을 하면 되는지 템플릿으로 바꾼다.
- **R2 연결 상태 정확히 하기 (S).** 상태: 반영, analyze 0건·인증 pytest 25건 통과. 위젯 실행은 데스크톱 대기.
  - 연결 확인을 키가 필요한 경로로 한다. 401이면 "허브 키가 필요해요" 상태로 따로 보여 준다.
  - API 키 칸에서 "선택" 표기를 지우고, 키를 보여 주는 토글을 단다.
  - mDNS로 찾은 값은 기본값을 덮어쓰지 않고, 실패하면 다시 찾는다.
- **R3 첫 연결 짝짓기 (L).** 상태: 반영, 짝짓기·인증 pytest 38건 통과·analyze 오류·경고 0건. QR은 폰 카메라의 링크 열기 또는 연결 주소 입력을 사용한다. 위젯·실물·모바일 QR 링크 열기는 데스크톱 확인 대기.
  - 키오스크 설정에 "폰 연결하기"를 둔다. 누르면 5분 동안 유효한 1회용 6자리 코드와 QR(`simplelay://pair?host=…&code=…`)을 띄운다.
  - 폰은 QR이나 코드를 입력해 `/pair`로 API 키를 받는다.
  - 키오스크에서 "이 폰을 연결할까요?"를 승인해야 끝난다.
  - 서버 API, 폰 화면, 키오스크 화면을 함께 만든다. 자동 발견에 실패해도 QR이 대안이 된다.
- **R4 실행 결과 화면 (S).** 상태: 반영, analyze 오류·경고 0건. 위젯 실행·골든은 데스크톱 대기. 폰도 키오스크와 같은 규칙을 따른다.
  - 실행 중에는 "정지" 하나만 둔다(이름 통일).
  - 끝나면 결과 한 줄 + 다음 행동 하나(성공: 확인, 실패·안전 정지: 다시 시도) + 닫기를 둔다.
  - 뒤로 가기는 시작한 화면으로 돌아간다.
  - 키오스크 성공 화면은 남은 시간을 보여 주고, 사라지기 전 시간을 늘린다(예: 10초).
- **R5 입력 보호와 마법사 줄이기 (M).** 상태: 반영, analyze 오류·경고 0건. 위치 맞추기는 사진 매핑을 일반 화면에서 다시 여는 방식이며 모터 미세 조그는 범위 밖. 위젯 실행·실물은 데스크톱 대기.
  - PopScope로 입력 중 나가기를 확인한다.
  - 종류를 고르면 이름을 미리 채운다.
  - 정지 버튼은 버튼 이름에서 추론해 미리 고른다.
  - 프레임 크기는 허브 설정값을 쓰고, 없을 때만 묻는다.
  - "사진 없이" 경로로 가도 입력값을 넘긴다.
  - 등록 뒤에는 홈에 "설정이 N개 남았어요" 카드를 띄워, 남은 일(위치 맞추기·확인 주행)로 바로 가게 한다. 개발자 콘솔에만 있던 보정을 일반 화면으로 뺀다.
- **R6 키오스크 거리 가독성 (M).** 상태: 부분 반영. 평소 화면 본문·가전 이름·연결 안내를 33px로 확대하고 보이는 설정·방해 금지 입구, 모름 표시, 내부 id 숨김을 반영했다. 전체 화면의 33px 하한 적용·거리 실측은 남았다. 서버에 남은 시간 추정값이 없어 숫자 대신 모름을 표시한다. analyze 0건.
  - 본문 최소 글자를 2m 기준 약 12mm로 올린다(설계 px 기준 재계산).
  - 숨은 길게 누르기 동작에 보이는 입구를 둔다.
  - "!"는 확인이 필요할 때만 띄우고, "모름"은 회색 아이콘에 문구로 표시한다.
  - 동작 중 화면은 남은 시간을 보여 준다.
  - 시나리오 카드에서 내부 id 노출을 막는다.
- **R7 설정 정리 (S).** 상태: 반영, analyze 0건. 위젯 실행·200% 화면은 데스크톱 대기.
  - 가전 추가 입구를 하나로 줄인다.
  - ThinQ 목록 중복을 없앤다.
  - 옛 "제어 가전" 칩을 지운다.
  - 개발자 탭은 `developer_mode`일 때만 연다.
  - 준비 안 된 줄은 숨긴다.
  - 48dp 미만 터치 대상과 11px 글자를 고친다.
- **R8 루틴 기본값 (M).** 상태: 반영, analyze 오류·경고 0건. 실제 기록 기반 제안과 근거 부족 시 선택 안내를 추가했다. 위젯 실행은 데스크톱 대기. "언제"의 기본값을 기록에서 가장 자주 쓴 시각으로 제안한다. 확실하지 않으면 묻는다.

**검증 기준:** 각 단계마다 위젯 테스트로 동작을 고정하고, 수정 전 코드에서 테스트가 실패하는지 확인한다. 노트북은 Windows 애플리케이션 제어 정책 때문에 `flutter test`를 실행하지 못하므로, 테스트 실행과 골든 갱신은 데스크톱에서 한다. `flutter analyze` 오류·경고는 0건이어야 한다. 서버 변경은 pytest로 확인하고, 저장소 가드도 통과해야 한다.
