# 키오스크 날씨 줄·제안 단추 개편 계획 (2026-10-25)

사용자 요청(10/25): ① 처음 화면 '바깥 날씨' 줄이 길고 "오후 12시 예보"처럼 어색하다 — 아이콘·온도·특보만 한 줄에, `>`를 누르면 자세한 날씨 창.
비·눈 예보나 한파·폭염·강풍 같은 특보가 있으면 "우산 챙기세요" 같은 안내. ② 제안 단추를 **아니요 / 네**로, 다시 받고 싶지 않은 제안을 위해
**'이 제안 앞으로 받지 않기'** 체크. ③ 특보 구역은 서울 고정이 아니라 **폰 앱이 저장한 허브 위치**로 정한다.

문구 수정(어색한 문장 약 70곳, 같은 날)이 끝난 뒤 이 순서로 한다. 안전 계약(승인 없이 누르지 않음·정지 경로·실제/연습 구분)은 바꾸지 않는다.

## 1. 서버 — 기상특보

| 할 일 | 내용 | 상태 |
|---|---|---|
| 특보 받기 | 기상청 기상특보 조회서비스 특보코드조회(`getPwnCd`), 지난 7일 발표 → 구역·종류마다 마지막 발표로 지금 걸린 것만(발표·연장·정정·변경발표, 취소 제외). 30분마다, 실패하면 직전 값(3시간 지나면 버림) | 코드·시험 작성, 미커밋 |
| 구역 정하기 | 허브 위치(폰 '현재 위치로 설정', 없으면 env 위경도) → 가장 가까운 행정동 → 시·군·구 → 특보구역. 표는 기상청 공개 자료(단기예보 격자·위경도, 특보구역코드)에서 만들어 저장소에 둔다 | 격자·위경도 엑셀 받기 대기 |
| 세부 구역 | 같은 시·군을 더 나눈 구역(서울 4권역, 파주동북부 등)은 시·군 단위로 묶어 본다 — 넉넉하게 알리는 쪽 | 계획 |
| 응답 | `/ambient`에 `warnings`(종류·단계·제목·아이콘·안내 한 문장), `weather_tip`(확인할 일에 밀려도 따로), `today`(오늘 최고·최저) | `weather_tip`·`today` 커밋, `warnings` 미커밋 |
| 끄기 | 실제 날씨 모드·키·구역이 있을 때만. 신청 안 한 키(403)는 특보 없이 예보 안내만 | 시험 |

특보 안내 문장(한 문장, 명령조 대신 권유): 강풍 "바람이 강해요. 외출할 때 조심하세요." · 호우 "비가 많이 와요. 우산을 챙기고 외출을 줄이세요." ·
한파 "많이 추워요. 따뜻하게 입으세요." · 건조 "공기가 건조해요. 불조심하세요." · 태풍 · 대설 · 황사 · 폭염 · 열대야. 바다 특보(풍랑·폭풍해일)는 넣지 않는다.

## 2. 키오스크 — 날씨 줄과 자세히 창

- **처음 화면 한 줄:** `[날씨 아이콘] 18° · 강풍주의보  >` — 특보가 없으면 `[아이콘] 18° · 맑음  >`. '바깥 날씨' 제목·'○시 예보' 꼬리는 뺀다.
  지금 칸이 없어 예보 칸을 쓸 때만 작게 "낮 12시 예보"(12시는 '낮 12시', 0시는 '밤 12시' — 서버 `_hour_label`과 같은 규칙).
- **안내 한 줄(있을 때만):** 특보가 있으면 특보 안내, 없으면 비·눈·더위·추위 안내("오후 3시부터 비 예보가 있어요. 우산 챙기세요.").
- **`>` 누르면 자세한 날씨 창(모달):** 지금 날씨(아이콘·기온·하늘), 오늘 최고·최저, 3시간 간격 예보 4칸(기온·강수확률), 특보 목록과 안내, 예보 받은 시각.
  닫기 단추 하나, 바깥을 눌러도 닫힘. 큰 글씨·어두운 화면·조용한 시간 규칙을 그대로 따른다. 줄 전체가 누르는 자리(60px 이상).
- **알림:** 특보·비 안내는 오른쪽 '알림' 줄과 겹치지 않게 날씨 줄 아래에만 둔다(종전 규칙 유지). 음성은 읽지 않는다(제안 때만 소리).
- **예보가 없을 때:** 줄을 숨기지 않고 "날씨 정보를 받지 못했어요"를 작게, 특보만 있으면 특보만.

## 3. 키오스크 — 제안 단추 아니요 / 네, 다시 받지 않기

- 단추 글자: '이번엔 안 할게요' → **아니요**, '지금 하기' → **네**. 배치·크기·색(네가 주 단추)은 그대로. 접근성 이름은
  "네. ‹가전› 버튼을 눌러요" / "아니요. 이번에는 하지 않아요"처럼 무엇이 일어나는지 말한다.
- **'이 제안 앞으로 받지 않기' 체크:** '아니요' 바로 위 한 줄, 줄 전체가 누르는 자리(60px 이상). 체크하고 '아니요' → 서버 `reject(mute=true)`
  (이미 있는 기능 — 폰 앱 '숨긴 제안'에서 되돌림). 체크하고 '네' → 실행만 하고 숨기지 않는다. 체크는 제안이 바뀌면 풀린다.
  직접 연 카드(사용자가 고른 동작)와 루틴 카드에는 두지 않는다.
- 결과 안내: 숨기면 "이 제안은 다시 띄우지 않아요. 휴대폰 앱에서 다시 켤 수 있어요." 실패하면 "숨기지 못했어요. 다시 눌러 주세요."
- 같이 바꿀 곳: 음성 안내("…하시려면 화면의 '네'를 눌러 주세요"), 제안 화면 도움말("'네'를 누르기 전에는 아무것도 하지 않아요"),
  도움말 화면, 서버가 보내는 '지금 하기' 언급(제안 내용이 바뀌었을 때), 시험·골든.

## 4. 확인

- 서버: 특보 판정 시험(지역 거르기·해제·변경발표·취소·단계), 구역 정하기 시험(서울 4권역·시·군·세부 구역), 403일 때 빈 목록. 전체 백엔드 시험.
- 키오스크: analyze 0, 전체 시험·골든 갱신, 실패 확인(바꾸기 전 코드에서 새 시험이 깨지는지).
- 실패널: 날씨 줄·창, 큰 글씨·어두운 화면, 제안 아니요/네·체크, 다시 받지 않기 뒤 같은 제안이 안 뜨는지, 폰에서 되돌리기.
- 화면을 원격 웹으로 띄워 단추를 하나씩 누르고 문구·로그를 함께 본다(사용자 요청).
