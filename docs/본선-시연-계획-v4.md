## 1. 장면 대본

### ① 제안 거절 (0:00–0:20)

- 제안 카드가 뜬다(사용자 루틴 또는 습관 근거). 발표자가 "이번엔 안 할게요"(키오스크·폰 같은 말)를 누른다 — 화면 글자 그대로 말한다.
- 보일 것: 장치는 움직이지 않는다. 이후 같은 조건에서 자동 실행도 일어나지 않는다(허용한 적이 없으므로).
- 말할 것: "승인하지 않으면 누르지 않습니다. 거절한 제안이 나중에 몰래 실행되지도 않습니다. 승인은 카드에 적힌 그 명령에 묶여 있어서, 카드가 나온 뒤 내용이 바뀌면 실행하지 않고 다시 묻습니다."

### ② 첫 조리 승인 → 공기청정기 + "다음부터 자동으로" (0:20–2:40)

> 이 대본은 **11/6 CT 갈래**다. 10/28 영상과 CT가 준비 안 된 결선은 §0-A대로 누름 장치 확인까지만 실물이고, 공기청정기는 가열 종료와 잇지 않는다.


1. 전자레인지 조리 제안을 승인한다. **가열은 짧게(예: 30초).** 허브의 시연 루틴 '30초 데우기'(전자레인지 '30초 → 시작' 두 버튼)를 쓴다 — 화면에 나오는 버튼 순서와 말하는 가열 시간이 같아야 한다(10/16 3차 평가).
2. CoreXY 갠트리가 버튼을 실제로 누른다(솔레노이드 Z). 화면은 누름 확인(L1)을 보인다. 이 부분은 짧게 지나간다(기구는 공유 자산, §0-0).
3. 콘센트 모듈 CT가 가열 시작을 확인한다(L3). 발표자: "버튼을 눌렀다는 것과 가전이 실제로 전기를 쓰기 시작했다는 것을 따로 확인합니다." 30초 뒤 **가열 종료는 CT 판정으로만** 감지한다 — 버튼 누름 완료는 조리 완료가 아니다. 지금 판정은 취소·문 열림 종료와 구분하지 못하므로 카드 근거는 '전자레인지가 멈춘 것 같아요. 조리 완료가 아닐 수 있어요.'라고만 말한다.
4. 가열 종료가 감지되면 카드 '공기청정기 바람을 세게 할까요?'가 뜬다. 발표자가 '다음부터도 자동으로'를 고르면 확인 시트('이번에 실행하고 다음부터 자동으로 할까요?')가 나온다:

## 3-1. 정지·실패 장면 리허설 (주 시연 리허설마다 함께)

| 리허설 | 방법 | 통과 기준 | 기록 |
|---|---|---|---|
| 이동 중 정지(무대 기구) | ⑤-가와 같게, 실행 직후 키오스크 정지. 폰 정지·`POST /stop`도 한 번씩 | 정지 결과 화면의 말이 `/status` 정지 단계와 맞다(`verified`일 때만 '멈췄어요'). 정지 뒤 추가 누름 없음 | 단계·모션 보드 응답 시간·눌림 여부 — 측정 뒤 기입 |

## 4. 원칙

**장애 결과 문구를 대본에 고정하지 않는다.** 실제 얻은 근거대로 읽는다.

| 상황 | 표시(폰 결과 배지 — 근거 줄) |
|---|---|
| 보내기 전에 연결 불가 | '못 했어요' — '보내지 않았어요' |
| 접수됐지만 상태를 확인하지 못함 | '몰라요' — '보냈지만 설정이 바뀌었는지 몰라요. 집에서 가전을 확인해야 해요.' |
| 상태 재조회로 바뀐 것을 확인 | '됐어요' — '상태를 확인했어요' |
| 보내기 전 조회에서 이미 그 설정 | '이미 그 설정이라 보내지 않았어요' |

키오스크 LG 가전 실행 화면은 확인했을 때만 체크를 보이고, 확인하지 못하면 '공기청정기에 켜 달라고 했어요' + '켜졌는지는 아직 몰라요'로 말한다.
폰과 키오스크의 문장이 조금 다르다(폰 '보냈지만 설정이 바뀌었는지 몰라요. 집에서 가전을 확인해야 해요.' / 키오스크 '보냈지만 됐는지 몰라요. 가전을 봐 주세요.') — 둘을 함께 보일 때는 각 화면의 글자를 그대로 읽는다.

- **버튼 누름 완료 ≠ 조리 완료.** 가열 종료는 CT 판정으로만 말한다. **CT 가열 종료 ≠ 정상 조리 완료**(취소·문 열림과 구분 근거가 생기기 전까지). 정책: 취소·문 열림 종료에도 공기청정기 풍량 변경(낮은 위험)은 일어날 수 있고, 그렇게 말한다.
- **풍량 변경 ≠ 공기가 깨끗함.** 사용자 습관이라고 단정하지 않는다 — 카드는 제안과 감지 근거만, 승인 기록이 있을 때만 그 횟수(3차 평가 M4).
- **가열 시간은 짧게**(예: 30초). 빈 상태 가열 금지 등 런북 안전 체크리스트를 따른다([결선 운영 런북](결선-운영-런북.md)).
- 연습 표시(폰 배지 '연습', 키오스크 띠 '연습이에요. 실제 가전은 그대로예요')를 가리지 않는다. 서버가 보고하지 않은 성공을 말로 만들지 않는다.

## 5. 보조 시연

| 장면 | 내용 | 한계 |
|---|---|---|
| 인터폰 문 열기 | 접근성 사례. 승인 뒤 누름, **자동 실행 없음** | '버튼을 눌렀어요'까지만 말한다(문이 열렸는지는 확인하지 않음) |
| 실패 장면 실연 | 연결 끊김·상태 미확인을 실제로 일으켜 §4 문구를 보인다 | 그날 얻은 문구 그대로 |
| 세탁 → 제습기 확장안 | 슬라이드로만 | 실물·API 없음 |

**10/16 결정 — 공기청정기 켜기 제안은 주 시연에서 제외한다.** 보조 녹화 영상 또는 명확히 '모의'로 표시한 장면으로만 보완한다.
실물 기록은 노트북 허브·API 승인까지이며 폰·키오스크 승인과 RPi5는 미검증이다. 본체 변화가 클라우드에 반영되기까지 수 분,
허브 판독 기본 120초가 더해질 수 있다. 켜기 승인 직후 강풍 카드도 바로 뜨지 않는다([근거](devlog/devlog_2026-10-15-air-off-power.md) §0·§8).

**새 키오스크 대사 기준:** 결과 띠는 확인한 근거만큼만 말한다 — 전력 변화를 본 것은 '전력 확인', 확인하지 못한 것은 앰버 '확인 필요', 연습은 청록이다.
정지 결과는 엔코더로 본 때만 '누름 장치가 멈췄어요', 그 밖은 '누름 장치가 멈췄는지 몰라요'와 '다시 멈추기'다. 비상 대기 중에는 버튼 누름 장치를 움직여 취소할 수 있다고 안내하지 않는다.
새 키오스크는 10/16~18 실패널에 설치했고 처음 화면·LG 가전 실행 화면은 실패널에서 보았다. 실패·정지·비상 화면 상당수는 골든·시험 조건만이다([기록](devlog/devlog_2026-10-18-professor-ui.md) §3·§5).

## 6. 무대 배치 — 함께 맞출 항목

- 책상 150×55cm ×2: 전자레인지 + CoreXY 갠트리 + 콘센트 모듈을 한 책상, 공기청정기를 관객이 풍량 변화를 볼 수 있는 자리에.
- 키오스크 패널과 폰 화면(미러링)이 관객 쪽을 향하게.

## 9. 깨끗한 시연 준비 점검표 (심사위원 도착 전)

> 10/19 추가. 심사위원이 보는 화면에는 **오늘 보일 가전·규칙·기록만** 있어야 한다. 연습 흔적·미설정 가전·옛 알림이 남아 있으면 무엇이 실물인지 헷갈린다.
> 설치 순서는 [결선 운영 런북](결선-운영-런북.md) §3, 발표 흐름은 [결선 발표 대본](발표/결선-발표-대본.md). 설치 시간(14:50~15:20) 마지막 10분에 아래를 한 사람이 읽고 다른 사람이 화면으로 확인한다.

### 9-1. 가전·규칙·기록

- [ ] **가전 목록**(키오스크 '내 가전'·폰): 오늘 시연하는 가전만 — 전자레인지, 공기청정기. 미설정·시험 가전(세탁기·인터폰 등)이 없다(10/19에 한 번 정리, 그 뒤 생긴 것 확인).
- [ ] **연습 기기 표시:** 연습 세탁기(본체 env의 연습 기기 설정)가 목록에 남아 있으면 '연습' 표시가 보이는지 확인하거나, **팀 결정으로** 설정을 빼고 env를 `env.bak-날짜-이유`로 백업한다. 가리지 않는다 — 연습이면 연습으로 보인다.
- [ ] **개발자 모드:** 꺼짐(폰에 개발자 탭이 안 보임). **개발자 모드를 끄면 내장 전자레인지가 목록에서 숨는 문제**는 결선 전 결정 사항이다 — 결정한 방식대로 전자레인지가 목록에 보이는지 확인한다.
- [ ] **자동 규칙(갈래 A):** '가열 종료 → 공기청정기'는 **꺼짐**으로 시작한다(장면 ②에서 무대 위에서 허락하므로). 지난 리허설에서 켠 채 남아 있으면 장면 ②의 '다음부터도 자동으로'가 의미가 없다.
- [ ] **시각 규칙:** '저녁 공기청정기 켜기'(22:00)·'아침 공기청정기 끄기'(07:00)는 평가 시간(15:40~16:00)에 울리지 않는다. 갈래 B에서 시각 자동 실행 기록을 보이려면 그 실물 기록이 기록 탭에 남아 있는지 확인한다.
- [ ] **기록 탭:** 맨 위가 오늘 장면과 상관없는 연습·실패 기록이 아니다. 갈래 B에서 보일 실물 기록(시각 자동 켜기 `state_confirmed` 등)은 지우지 않는다.
- [ ] **제안 카드:** 장면 ①에서 쓸 제안이 준비돼 있다(시연 데이터면 화면의 '제안 · 시연 데이터' 표시를 가리지 않는다). 공기청정기 재알림 기억 때문에 장면 ②의 카드가 막혀 있지 않은지 리허설에서 한 번 본다.

### 9-2. 연습 기록 지우기 — 팀 승인과 DB 백업이 있을 때만

연습 기록을 지우는 것은 되돌리기 어려운 일이다. **아래 순서를 다 지킬 때만** 한다. 하나라도 빠지면 지우지 않고, 연습 기록이 보이면 "연습 기록입니다"라고 말한다.

1. **팀 둘 다 승인**(박성원·서예솔). 무엇을 지울지(가전·규칙·기록 중 어느 것) 말로 정한다. 실물 근거가 되는 기록(ThinQ `state_confirmed`, 시험대 정지 기록 등)은 지우지 않는다.
2. **본체 DB 백업을 먼저** 만든다 — 이름은 지금까지와 같은 꼴 `simplelay-backup-YYYY-MM-DD-before-<이유>.db`(예: `…-before-stage-cleanup.db`). 백업 파일이 실제로 생겼고 크기가 0이 아닌지 본다.
3. 앱 화면의 삭제(가전·규칙 삭제)로 지운다. 화면에 없는 방식으로 DB를 직접 고치지 않는다.
4. 지운 뒤 본체 `/health/detail` 준비 확인 → 키오스크·폰에 반영됐는지 본다.
5. 무엇을 지웠고 백업 이름이 무엇인지 그날 기록에 남긴다(되돌리기는 그 백업으로).

### 9-3. 날씨·알림·시간

- [ ] **본체 시각이 맞다**(RPi5는 RTC 배터리가 없다 — 대회장 인터넷에 붙었는지, 아니면 노트북 시각으로 맞춤). 시각이 틀리면 기록 시각·시각 규칙·날씨가 다 어긋난다.
- [ ] **날씨:** 날씨 카드가 대회장 기준으로 실제 값이거나, 인터넷이 없으면 대체 문구가 그대로 보인다. 오래된 값·집 위치 날씨면 위치·인터넷을 고치거나, 질문받으면 그대로 말한다. 날씨는 시연 주장이 아니므로 둘러보지 않는다.
- [ ] **기상·경보 알림:** 키오스크·폰에 오래된 경보·주의 알림이 떠 있지 않다. 떠 있으면 화면에서 닫는다(지우지 않는다).
- [ ] **조용한 시간·잠시 쉬기:** 평가 시간대(15:40~16:00)에 조용한 시간이 걸려 있지 않고 '잠시 쉬기'가 꺼져 있다 — 걸려 있으면 장면 ②③의 카드·자동 실행이 막힌다.
- [ ] **시연 폰:** 개인 알림 끔(방해 금지 + 미러링 중 알림 숨김), 충전 100%, 릴리스 APK.
- [ ] **연습 표시:** 연습 장면을 쓸 때 키오스크 띠 '연습이에요. 실제 가전은 그대로예요'·폰 배지 '연습'이 보인다. 실물 장면 직전에는 연습 상태가 풀려 있다.
- [ ] **결선 전에 닫을 것:** 본체 env의 개발자 실물 조작 끔, API 문서 페이지 닫힘(결선 전 결정 사항 — CLAUDE.md '평가 전에 끌 것').
- [ ] 마지막: 키오스크 첫 화면으로 돌아가 있고, 실행 중·정지 대기·비상 대기 표시가 없다.
