## 1. 장면 대본

### ① 제안 거절 (0:00–0:20)

- 제안 카드가 뜬다(사용자 루틴 또는 습관 근거). 발표자가 "이번엔 안 할게요"(키오스크·폰 같은 말)를 누른다 — 화면 글자 그대로 말한다.
- 보일 것: 장치는 움직이지 않는다. 이후 같은 조건에서 자동 실행도 일어나지 않는다(허용한 적이 없으므로).
- 말할 것: "승인하지 않으면 누르지 않습니다. 거절한 제안이 나중에 몰래 실행되지도 않습니다. 승인은 카드에 적힌 그 명령에 묶여 있어서, 카드가 나온 뒤 내용이 바뀌면 실행하지 않고 다시 묻습니다."

### ② 첫 조리 승인 → 공기청정기 + "다음부터 자동으로" (0:20–2:40)

1. 전자레인지 조리 제안을 승인한다. **가열은 짧게(예: 30초).** 허브의 시연 루틴 '30초 데우기'(전자레인지 '30초 → 시작' 두 버튼)를 쓴다 — 화면에 나오는 버튼 순서와 말하는 가열 시간이 같아야 한다(10/16 3차 평가).
2. CoreXY 갠트리가 버튼을 실제로 누른다(솔레노이드 Z). 화면은 누름 확인(L1)을 보인다. 이 부분은 짧게 지나간다(기구는 공유 자산, §0-0).
3. 콘센트 모듈 CT가 가열 시작을 확인한다(L3). 발표자: "버튼을 눌렀다는 것과 가전이 실제로 전기를 쓰기 시작했다는 것을 따로 확인합니다." 30초 뒤 **가열 종료는 CT 판정으로만** 감지한다 — 버튼 누름 완료는 조리 완료가 아니다. 지금 판정은 취소·문 열림 종료와 구분하지 못하므로 카드 근거는 '전자레인지가 멈춘 것 같아요. 조리 완료가 아닐 수 있어요.'라고만 말한다.
4. 가열 종료가 감지되면 카드 '공기청정기 바람을 세게 할까요?'가 뜬다. 발표자가 '다음부터도 자동으로'를 고르면 확인 시트('이번에 실행하고 다음부터 자동으로 할까요?')가 나온다:
   조건(전자레인지 가열 종료 — '가전이 전기를 덜 쓰면 가열이 끝났다고 봐요. 요리가 다 된 건 아닐 수 있어요.')·대상(등록 이름 '공기청정기')·동작(바람 세게) → '허락하고 이번에도 하기'.
5. ThinQ로 바람 세기 명령 → 상태 재조회로 바뀐 것을 확인한 뒤에만 '됐어요'·'상태를 확인했어요'로 표시한다.
- 말할 것: "가열이 끝난 것을 감지해 공기청정기 풍량 변경을 제안합니다. 사용자의 습관이라고 단정하지 않습니다 — 이 제안을 승인한 기록이 있을 때만 그 횟수를 카드에 적습니다. 풍량을 바꾼 것이지 공기가 깨끗해졌다고 확인한 것은 아닙니다."
  (3차 평가 M4: 근거는 가열 종료 감지 문장뿐이고, 같은 제안을 허락한 기록이 있으면 '지금까지 N번 허락받은 제안이에요.'가 붙는다 — 습관이라고 단정하지 않는다. 카드 질문은 10/18 쉬운 말 개편으로 '풍량을 강으로 바꿀까요?'에서 지금 말로 바뀌었다.)

### ③ 같은 조건에서 다시 (2:40–4:20)

1. 준비 동작: 공기청정기를 약풍으로 되돌린다. 발표자: "같은 조건에서 다시 자동으로 바뀌는지 보겠습니다."
2. 두 번째 조리를 승인한다(조리 자체는 매번 승인 — 물리 버튼 누름은 자동 실행 대상이 아니다).
3. 가열 종료 감지 → **추가 승인 없이** 공기청정기 바람 세게 → 상태 재조회로 확인('됐어요').

### ④ 기록 확인 → 자동 실행 끄기 (4:20–4:50)

- 기록 탭에서 전자레인지(누름·가열 시작·가열 종료 감지)와 공기청정기('됐어요', 출처 '자동 실행') 결과를 각각 보인다.
- 루틴 탭 '자동 규칙'에서 이 규칙을 끈다(시각 루틴의 자동은 '내 루틴' 줄의 '자동'). "언제든 끌 수 있고, 조건이 바뀌면 다시 허용을 받습니다."

### ⑤ 정지 · 일부 실패 (4:50–5:40)

**가. 정지(0:20).** 키오스크에서 실행을 하나 시작하고 누름 장치가 움직이는 동안 키오스크 정지를 누른다(전자레인지 안에는 런북대로 부하를 둔다 — 정지 전에 눌렸을 수 있다).
- 보일 것: 정지 결과 화면. 엔코더로 멈춤을 본 때만 '누름 장치가 멈췄어요', 모션 보드 응답까지만 왔거나 보내기만 했으면 '누름 장치가 멈췄는지 몰라요'와 '다시 멈추기'. 어느 쪽이 나와도 그 글자를 그대로 읽는다.
- 말할 것: "정지 명령을 보냈다는 것, 모션 보드가 받았다는 것, 실제로 움직임이 멈춘 것을 엔코더로 본 것을 구분합니다. '멈췄어요'는 마지막 것을 봤을 때만 말합니다. 최종 권한은 물리 비상정지 버튼입니다."
- 무대 기구로 정지 리허설(§3-1)을 통과하지 못했으면 이 장면은 10/14 시험대 기록 화면으로 대신하고 그렇게 말한다.

**나. 일부 실패(0:30).**
- 사전 녹화 영상 또는 준비된 기록으로 설명한다. 예: 공기청정기 명령은 보냈지만 상태 재조회가 실패한 경우 → '몰라요' — '보냈지만 설정이 바뀌었는지 몰라요. 집에서 가전을 확인해야 해요.'로 남고 자동으로 다시 보내지 않는다.
- 대본에 결과 문구를 미리 고정하지 않는다 — 그날 실제로 얻은 근거대로 읽는다(§4).

## 3-1. 정지·실패 장면 리허설 (주 시연 리허설마다 함께)

정지와 실패는 무대에서 처음 해 보는 장면이 되면 안 된다. 리허설마다 아래를 하고 결과를 [실측 기록표](실측-기록표.md)에 적는다(값은 측정 뒤 기입, 미리 정하지 않는다).

| 리허설 | 방법 | 통과 기준 | 기록 |
|---|---|---|---|
| 이동 중 정지(무대 기구) | ⑤-가와 같게, 실행 직후 키오스크 정지. 폰 정지·`POST /stop`도 한 번씩 | 정지 결과 화면의 말이 `/status` 정지 단계와 맞다(`verified`일 때만 '멈췄어요'). 정지 뒤 추가 누름 없음 | 단계·모션 보드 응답 시간·눌림 여부 — 측정 뒤 기입 |
| 쉬는 중 정지 | 움직이지 않을 때 정지 | '멈췄는지 몰라요'(엔코더 움직임을 본 실행이 아니므로 `mcu_ack`)로 나오고 '멈췄어요'로 부풀리지 않는다 | 단계 — 측정 뒤 기입 |
| 물리 비상정지 | 런북 §3-7·안전 보고 PS-1(S4·S5·엔코더 뽑기) | 릴레이 차단·래치, `POST /stop/ack` 전에는 다시 실행되지 않음 | PS-1 표에 — 측정 뒤 기입 |
| 누름 실패(모의 보드 리허설) | 실행 직전 `POST /demo/inject-failure`(1회용) → 실행 → 끝나면 `DELETE /demo/inject-failure` | 재시도·안전 정지 화면이 나오고, 남은 주입이 다음 판에 없다 | 화면 문구 그대로 |
| 공기청정기 결과 미확인 | 런북의 모의 서버 ThinQ 장애 주입, 끝나면 정상으로 | '몰라요'로 남고 자동으로 다시 보내지 않는다 | 화면 문구 그대로. 녹화해 ⑤-나 영상 후보로 |

주입·모의로 만든 실패는 무대에서 실제 장애라고 말하지 않는다. ⑤-나에 쓸 영상·기록은 리허설에서 실제로 얻은 것만 쓴다.

## 3. 선행 조건 (우선순위)

1. **CoreXY 실제 누름** — 레일·배선 확인 → SimpleLay 모션 펌웨어 확인 → 방향·짧은 이동·원점 시험 → 솔레노이드 안전 전달표 확인 → 실제 버튼 누름. 기록은 [실측 기록표](실측-기록표.md) §4 성공률.
2. **CT 가열 시작·종료 판정 실측** — 짧은 가열(30초) 정상, **가열 중 전력 감소**(출력 조절로 전력이 내려가는 구간), **종료 후 팬 동작**을 가열 종료로 잘못 잡지 않는지(B·D — 잘못 잡으면 실패). **중간 취소(취소 버튼)·중간 문 열림**(C1·C2)은 위 정책에 따라 가열 종료로 잡혀 제안·자동 실행이 일어나도 실패가 아니다 — **발생 여부와 지연을 기록**한다. 지금 판정은 취소·문 열림을 구분하지 못한다(코드 확인) — '가열 종료 감지(조리 완료가 아닐 수 있음)'로만 말한다. 기록은 [실측 기록표](실측-기록표.md) §6.
   B·D를 못 맞추면 자동 실행 조건(가열 종료 감지)을 다시 설계한다 — 버튼 누름 완료로 대신하지 않는다.
3. **공기청정기 ThinQ 실물 제어 + 대회장 인터넷** — 여행용 공유기 + 핫스팟. 실가전 제어는 10/15(노트북 허브)·10/16(RPi5 허브) 확인([절차](ThinQ-실물-확인-절차.md) A~E), 남은 것은 대회장 인터넷 조건. 인터넷이 안 되면 모의 클라우드 대비 모드로 돌리고 "오늘은 모의 클라우드입니다"라고 먼저 말한다.
4. **자동 실행 규칙 구현** — 가열 종료 감지(취소·문 열림 포함 가능, 위 정책) → 공기청정기 풍량 변경 하나만(사건 규칙. 시각 규칙은 따로 공기청정기 전원 켜기·끄기 — 10/16). 사용자가 고를 때만 켜지고, 물리 누름 단계는 자동 대상이 아니며, 같은 사건에 한 번만, 결과 미확인이면 다시 보내지 않는다.
   **상태(10/13): 모의 끝-끝까지 구현·시험**([devlog](devlog/devlog_2026-10-13-auto-rule.md)). 남은 것은 ②(실제 CT 판정)·③(실가전)과 함께 보드·실물로 같은 흐름을 한 번 도는 것.

## 4. 원칙

**장애 결과 문구를 대본에 고정하지 않는다.** 실제 얻은 근거대로 읽는다.

| 상황 | 표시(폰 결과 배지 — 근거 줄) |
|---|---|
| 보내기 전에 연결 불가 | '못 했어요' — '보내지 않았어요' |
| 접수됐지만 상태를 확인하지 못함 | '몰라요' — '보냈지만 설정이 바뀌었는지 몰라요. 집에서 가전을 확인해야 해요.' |
| 상태 재조회로 바뀐 것을 확인 | '됐어요' — '상태를 확인했어요' |
| 보내기 전 조회에서 이미 그 설정 | '이미 그 설정이라 보내지 않았어요' |

키오스크 LG 가전 실행 화면은 확인했을 때만 체크를 보이고, 확인하지 못하면 '공기청정기에 켜 달라고 했어요' + '켜졌는지는 아직 몰라요'로 말한다.
폰과 키오스크의 문장이 조금 다르다(폰 '보냈지만 설정이 바뀌었는지 몰라요. 집에서 가전을 확인해야 해요.' / 키오스크 '보냈지만 됐는지 몰라요. 가전을 봐 주세요.') — 둘을 함께 보일 때는 각 화면의 글자를 그대로 읽는다.

- **버튼 누름 완료 ≠ 조리 완료.** 가열 종료는 CT 판정으로만 말한다. **CT 가열 종료 ≠ 정상 조리 완료**(취소·문 열림과 구분 근거가 생기기 전까지). 정책: 취소·문 열림 종료에도 공기청정기 풍량 변경(낮은 위험)은 일어날 수 있고, 그렇게 말한다.
- **풍량 변경 ≠ 공기가 깨끗함.** 사용자 습관이라고 단정하지 않는다 — 카드는 제안과 감지 근거만, 승인 기록이 있을 때만 그 횟수(3차 평가 M4).
- **가열 시간은 짧게**(예: 30초). 빈 상태 가열 금지 등 런북 안전 체크리스트를 따른다([결선 운영 런북](결선-운영-런북.md)).
- 연습 표시(폰 배지 '연습', 키오스크 띠 '연습이에요. 실제 가전은 그대로예요')를 가리지 않는다. 서버가 보고하지 않은 성공을 말로 만들지 않는다.
