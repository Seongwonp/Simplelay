## 1. 장면 대본

### ① 제안 거절 (0:00–0:20)

- 제안 카드가 뜬다(사용자 루틴 또는 습관 근거). 발표자가 "이번엔 안 할게요"(키오스크·폰 같은 말)를 누른다 — 화면 글자 그대로 말한다.
- 보일 것: 장치는 움직이지 않는다. 이후 같은 조건에서 자동 실행도 일어나지 않는다(허용한 적이 없으므로).
- 말할 것: "승인하지 않으면 누르지 않습니다. 거절한 제안이 나중에 몰래 실행되지도 않습니다."

### ② 첫 조리 승인 → 공기청정기 + "다음부터 자동으로" (0:20–2:40)

1. 전자레인지 조리 제안을 승인한다. **가열은 짧게(예: 30초).** 허브의 시연 루틴 '30초 데우기'(전자레인지 '30초 → 시작' 두 버튼)를 쓴다 — 화면에 나오는 버튼 순서와 말하는 가열 시간이 같아야 한다(10/16 3차 평가).
2. CoreXY 갠트리가 버튼을 실제로 누른다(솔레노이드 Z). 화면은 누름 확인(L1)을 보인다.
3. 콘센트 모듈 CT가 가열 시작을 확인한다(L3). 30초 뒤 **가열 종료는 CT 판정으로만** 감지한다 — 버튼 누름 완료는 조리 완료가 아니다. 지금 판정은 취소·문 열림 종료와 구분하지 못하므로 화면은 "가열 종료를 감지했어요(조리 완료가 아닐 수 있어요)"라고만 말한다.
4. 가열 종료가 감지되면 공기청정기 강풍 제안이 뜬다. 발표자가 "다음부터도 자동으로"를 고르면 확인 화면이 나온다:
   조건(전자레인지 가열 종료가 감지됐을 때 — 조리 완료가 아닐 수 있음)·대상(거실 공기청정기)·동작(풍량 강) → "허용하고 이번에도 실행".
5. ThinQ로 강풍 명령 → 상태 재조회로 바뀐 것을 확인한 뒤에만 "공기청정기 풍량을 바꿨어요"라고 표시한다.
- 말할 것: "가열이 끝난 것을 감지해 공기청정기 풍량 변경을 제안합니다. 사용자의 습관이라고 단정하지 않습니다 — 이 제안을 승인한 기록이 있을 때만 그 횟수를 카드에 적습니다. 풍량을 바꾼 것이지 공기가 깨끗해졌다고 확인한 것은 아닙니다."
  (3차 평가 M4, 10/14: 카드 질문은 "공기청정기 풍량을 강으로 바꿀까요?", 근거는 가열 종료 감지 문장뿐이고, 같은 제안을 승인한 기록이 있으면 "최근 기록: 이 제안 승인 N번"이 붙는다(10/16 결함 ④ — 누가 눌렀는지 단정하지 않는다).)

### ③ 같은 조건에서 다시 (2:40–4:20)

1. 준비 동작: 공기청정기를 약풍으로 되돌린다. 발표자: "같은 조건에서 다시 자동으로 바뀌는지 보겠습니다."
2. 두 번째 조리를 승인한다(조리 자체는 매번 승인 — 물리 버튼 누름은 자동 실행 대상이 아니다).
3. 가열 종료 감지 → **추가 승인 없이** 공기청정기 강풍 변경 → 상태 재조회로 '변경 성공'.

### ④ 기록 확인 → 자동 실행 끄기 (4:20–4:50)

- 기록 탭에서 전자레인지(누름·가열 시작·가열 종료 감지)와 공기청정기(변경 성공) 결과를 각각 보인다.
- 루틴 목록에서 자동 실행을 끈다. "언제든 끌 수 있고, 조건이 바뀌면 다시 허용을 받습니다."

### ⑤ 일부 실패 처리 (4:50–5:20)

- 사전 녹화 영상 또는 준비된 기록으로 설명한다. 예: 공기청정기 명령은 보냈지만 상태 재조회가 실패한 경우 → '결과 확인 불가'로 남고 자동으로 다시 보내지 않는다.
- 대본에 결과 문구를 미리 고정하지 않는다 — 그날 실제로 얻은 근거대로 읽는다(§4).

## 3. 선행 조건 (우선순위)

1. **CoreXY 실제 누름** — 레일·배선 확인 → SimpleLay 모션 펌웨어 확인 → 방향·짧은 이동·원점 시험 → 솔레노이드 안전 전달표 확인 → 실제 버튼 누름. 기록은 [실측 기록표](실측-기록표.md) §4 성공률.
2. **CT 가열 시작·종료 판정 실측** — 짧은 가열(30초) 정상, **가열 중 전력 감소**(출력 조절로 전력이 내려가는 구간), **종료 후 팬 동작**을 가열 종료로 잘못 잡지 않는지(B·D — 잘못 잡으면 실패). **중간 취소(취소 버튼)·중간 문 열림**(C1·C2)은 위 정책에 따라 가열 종료로 잡혀 제안·자동 실행이 일어나도 실패가 아니다 — **발생 여부와 지연을 기록**한다. 지금 판정은 취소·문 열림을 구분하지 못한다(코드 확인) — '가열 종료 감지(조리 완료가 아닐 수 있음)'로만 말한다. 기록은 [실측 기록표](실측-기록표.md) §6.
   B·D를 못 맞추면 자동 실행 조건(가열 종료 감지)을 다시 설계한다 — 버튼 누름 완료로 대신하지 않는다.
3. **공기청정기 ThinQ 실물 제어 + 대회장 인터넷** — 여행용 공유기 + 핫스팟. 실가전 제어는 10/15 확인([절차](ThinQ-실물-확인-절차.md) A~E), 남은 것은 RPi5 허브에서·대회장 인터넷 조건. 인터넷이 안 되면 모의 클라우드 대비 모드로 돌리고 "오늘은 모의 클라우드입니다"라고 먼저 말한다.
4. **자동 실행 규칙 구현** — 가열 종료 감지(취소·문 열림 포함 가능, 위 정책) → 공기청정기 풍량 변경 하나만(사건 규칙. 시각 규칙은 따로 공기청정기 전원 켜기·끄기 — 10/16). 사용자가 고를 때만 켜지고, 물리 누름 단계는 자동 대상이 아니며, 같은 사건에 한 번만, 결과 미확인이면 다시 보내지 않는다.
   **상태(10/13): 모의 끝-끝까지 구현·시험**([devlog](devlog/devlog_2026-10-13-auto-rule.md)). 남은 것은 ②(실제 CT 판정)·③(실가전)과 함께 보드·실물로 같은 흐름을 한 번 도는 것.

## 4. 원칙

**장애 결과 문구를 대본에 고정하지 않는다.** 실제 얻은 근거대로 읽는다.

| 상황 | 표시 |
|---|---|
| 보내기 전에 연결 불가 | 명령을 보내지 못함 |
| 접수됐지만 상태를 확인하지 못함 | 결과 확인 불가 |
| 상태 재조회로 바뀐 것을 확인 | 변경 성공 |

- **버튼 누름 완료 ≠ 조리 완료.** 가열 종료는 CT 판정으로만 말한다. **CT 가열 종료 ≠ 정상 조리 완료**(취소·문 열림과 구분 근거가 생기기 전까지). 정책: 취소·문 열림 종료에도 공기청정기 풍량 변경(낮은 위험)은 일어날 수 있고, 그렇게 말한다.
- **풍량 변경 ≠ 공기가 깨끗함.** 사용자 습관이라고 단정하지 않는다 — 카드는 제안과 감지 근거만, 승인 기록이 있을 때만 그 횟수(3차 평가 M4).
- **가열 시간은 짧게**(예: 30초). 빈 상태 가열 금지 등 런북 안전 체크리스트를 따른다([결선 운영 런북](결선-운영-런북.md)).
- 모의 표시("모의 실행 · 실제 조작 아님")를 가리지 않는다. 서버가 보고하지 않은 성공을 말로 만들지 않는다.

## 5. 보조 시연

| 장면 | 내용 | 한계 |
|---|---|---|
| 인터폰 문 열기 | 접근성 사례. 승인 뒤 누름, **자동 실행 없음** | '버튼을 눌렀어요'까지만 말한다(문이 열렸는지는 확인하지 않음) |
| 실패 장면 실연 | 연결 끊김·상태 미확인을 실제로 일으켜 §4 문구를 보인다 | 그날 얻은 문구 그대로 |
| 세탁 → 제습기 확장안 | 슬라이드로만 | 실물·API 없음 |

**10/16 결정 — 공기청정기 켜기 제안은 주 시연에서 제외한다.** 보조 녹화 영상 또는 명확히 '모의'로 표시한 장면으로만 보완한다.
실물 기록은 노트북 허브·API 승인까지이며 폰·키오스크 승인과 RPi5는 미검증이다. 본체 변화가 클라우드에 반영되기까지 수 분,
허브 판독 기본 120초가 더해질 수 있다. 켜기 승인 직후 강풍 카드도 바로 뜨지 않는다([근거](devlog/devlog_2026-10-15-air-off-power.md) §0·§8).

**새 키오스크 대사 기준:** 파랑 '버튼 누름 완료'와 녹색 '가전 상태 확인'을 구분한다. 앰버는 확인 필요, 청록은 연습이다.
비상 hold는 팔을 움직여 취소할 수 있다고 안내하지 않는다. 정지 확인은 받은 근거까지만 읽는다.
화면 수정은 위젯·골든까지이며 최신 실패널은 아직 확인하지 않았다([기록](devlog/devlog_2026-10-16-kiosk-eval5.md)).

## 6. 무대 배치 — 함께 맞출 항목

- 책상 150×55cm ×2: 전자레인지 + CoreXY 갠트리 + 콘센트 모듈을 한 책상, 공기청정기를 관객이 풍량 변화를 볼 수 있는 자리에.
- 키오스크 패널과 폰 화면(미러링)이 관객 쪽을 향하게.
- 여행용 공유기 + 핫스팟(ThinQ 클라우드용), RPi5·RPi4 같은 망.
- 사전 녹화 영상(⑤·백업)과 노트북 모의 서버를 1분 안에 전환할 수 있게.
