# 인계 2026-10-07 노트북 → 데스크톱 (4차)

데스크톱(RPi4·RPi5 LAN 연결)에서 순서대로. 단계마다 1커밋, 회귀 테스트는 수정 전 코드에서 실패 확인 뒤 수리. 끝나면 5줄 보고.

노트북에서 리뷰 후속 3건(target-binding devlog #3 전류 스레드 세대, #5 누름 중 오류 뒤 재누름 차단, #6 L3 관찰 창)을 진행 중이다. **먼저 `git pull`로 그 커밋이 들어왔는지 확인하고, 그 파일(`rpi/verifier/current_sensor.py`, 폐루프·실행기 쪽)은 노트북 커밋이 올라온 뒤에 건드린다.**

## 1. 음성 "멈춰" 정지
- 9/30 결정: 실행 중·정지 대기 중에만 듣는다. **음성으로 실행 시작은 금지.** 듣는 동안 화면에 "듣는 중" 표시.
- "멈춰"·"정지"·"그만" 같은 짧은 말을 인식하면 기존 `/stop` 경로(화면 정지 버튼과 같은 경로)를 탄다. 별도 정지 경로를 만들지 않는다.
- 어디서 들을지: 먼저 RPi5에서 보드 플랫폼의 음성 인식 서비스가 앱 권한으로 쓸 수 있는지 board_probe 결과로 확인한다. 쓸 수 있으면 그걸로(가산점 (1)·(2) 증거가 된다), 안 되면 폰 앱 음성 인식으로. 어느 쪽인지 devlog에 이유와 함께 적는다. 공개 문서·코드에 플랫폼 내부 명칭은 쓰지 않는다.
- 오인식 대비: 실행 중이 아니면 무시, 정지 요청은 여러 번 와도 한 번만 처리(멱등), 인식 실패는 조용히 무시하고 정지 버튼은 그대로.
- 시험: 실행 중 "멈춰" → 정지 요청, 대기 상태에서 "멈춰" → 무시, 실행 시작 문장 → 무시. 실물 마이크 인식률은 실측 필요로 둔다.
- 시연 v3 ⑤⑥ 장면이나 질의응답에서 보여 줄 수 있으면 v3 문서에 한 줄.

## 2. 가산점 (1) 증거 — 앱 권한 플랫폼 서비스 최소 호출
- board_probe "시스템 서비스 호출" 칸이 미검증이다. 로컬 설정의 인터페이스 지정 오류를 고치고 RPi5·RPi4에서 **앱 계정으로** 최소 호출 1건 성공을 기록한다.
- 원본 결과·비공개 설정은 저장소 밖 로컬에만, 커밋 금지. `docs/가산점-증거-대장.md`에는 일반 문장(측정 시각·보드·성공/실패)만.
- 1번에서 플랫폼 음성 서비스를 쓰게 되면 그 호출도 같은 방식으로 증거 대장에.

## 3. (가능하면) 콘센트 모듈 ESP32 USB 연결 확인
- ESP32를 데스크톱 USB에 꽂고 콘센트 모듈 펌웨어 플래시 → 시리얼로 줄 단위 JSON이 나오는지만(CT 미배선이면 값은 의미 없음, 그렇게 표기). 됐으면 RPi4에 붙여 `SIMPLELAY_L3_MODE=real` 기동까지. 증거 대장에 기록.
