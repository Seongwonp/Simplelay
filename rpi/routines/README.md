# rpi/routines — 사용자 루틴과 자동 실행 허용 규칙

> 역할: 사용자가 만든 루틴(여러 가전 순서)을 저장·트리거·승인 뒤 실행하고, 사용자가 허용한 조건에서만 낮은 위험 동작을 자동으로 하는 규칙을 둔다.

| 파일 | 무엇 |
| --- | --- |
| `model.py` | 루틴 값 객체·검증·지문. `steps_fingerprint`는 단계 전체와 실행 방식으로 만든다(이름·아이콘·트리거 제외) — 승인이 여기에 묶인다 |
| `store.py` | 저장소 — `SIMPLELAY_DB_PATH`가 있으면 SQLite, 없으면 메모리 |
| `engine.py` | 트리거 → 제안 카드 또는 알림. **실행하지 않는다** |
| `runner.py` | 승인된 루틴 실행 — 명령 실행 위의 얇은 순서기. 진입점은 제안 승인뿐. 가전 끝 기다리기 상한은 환경 변수 |
| `wiring.py` | 루틴을 제안·실행 서비스·ThinQ 사건·공간 상태에 잇는다. 시각·다가옴 트리거 루프(`routine_tick_loop`) |
| `candidates.py` | 사용 기록 반복 순서 → 루틴 초안 |
| `templates.py` | 추천 루틴 템플릿(사용자 데이터 아님, 저장·실행 안 됨) |
| `auto_rules.py` | **자동 실행 허용 규칙** — 범위는 하나: 가열 종료 감지(CT) → ThinQ 공기청정기 동작 하나. `AutoRuleEngine.on_appliance_done`이 사건을 받아 허용한 규칙만 승인 명령으로 제출 |

## 자동 실행 경계 (`auto_rules.py`)

- 승인 없이 하는 것은 **낮은 위험 ThinQ 동작**(`LOW_RISK_ACTIONS`: 공기청정기 풍량·운전 모드·전원 켜기)뿐이고, 사용자가 카드에서 '다음부터 자동으로'를 고르고 조건·동작 확인을 본 뒤에만 규칙이 생긴다. 물리 버튼 누름은 매번 승인한다.
- **모의 사건 → 모의 ThinQ만** — 대상이 실물이면 사건도 RPi4 실물 판정이어야 한다.
- **같은 사건 한 번**(사건 키 멱등). 사건 나이는 허브 단조 시계로 옮긴 끝 시각부터 재고(`rpi/services/event_clock.py`), 근거가 없거나 오래됐으면(`SIMPLELAY_AUTO_RULE_MAX_EVENT_AGE_S`) 보내지 않는다. 결과가 미확인이어도 다시 보내지 않는다.
- **허용은 지문에 묶인다** — 조건·대상·동작·값이 바뀌면 꺼진다. **비상정지**는 아직 보내지 않은 자동 실행을 막고 켜진 규칙을 모두 끈다.
- 비정상 종료 뒤에는 켜져 있던 규칙을 끈 채 시작한다(세션 표시) — 사용자가 다시 허용해야 한다.
- **검증 수준:** 모의 ThinQ·모의 클라우드 끝-끝까지(두 보드 실물 + 주입 사건은 10/14). 실제 CT 판정·실가전 미검증.
- 흐름 전체는 [코드 구조](../../docs/코드-구조.md) §3-4, 설계 근거는 [자동 실행 허용 규칙 devlog](../../docs/devlog/devlog_2026-10-13-auto-rule.md).
